# Разбор задачи: Merge Two Sorted Lists (LeetCode 21)

Ссылка на оригинал: https://leetcode.com/problems/merge-two-sorted-lists/description/

## Уровень сложности
Easy (лёгкий)

## Алгоритм / паттерн

**Two Pointers** (два указателя) — по одному указателю в каждом из двух списков, которые синхронно двигаются вперёд по мере сравнения элементов.

Дополнительно используется классический приём **Dummy Node** (фиктивный узел-заглушка) — вспомогательный "пустой" узел перед началом результирующего списка. Он упрощает код, избавляя от необходимости отдельно обрабатывать "а что если результат пока пуст, куда цеплять первый элемент?".

## Суть задачи простыми словами

Даны два уже **отсортированных** связных списка. Нужно "склеить" их в один — тоже отсортированный — список, переиспользуя существующие узлы (создавать новые узлы не нужно, только перецеплять ссылки `next`).

Представьте две очереди людей, выстроенных по росту (от меньшего к большему). Нужно слить их в одну очередь, тоже по росту — на каждом шаге сравниваем, кто ближе стоит к началу своей очереди (то есть меньше), забираем этого человека в общую очередь, и продолжаем сравнивать дальше.

```
list1: 1 → 2 → 4
list2: 1 → 3 → 4

Результат: 1 → 1 → 2 → 3 → 4 → 4
```

## Пошаговый разбор решения

```js
const createNode = (val = 0, next = null) => ({ val, next });
// 1. Фабричная функция для узла — обычный объект, без использования class.

const mergeTwoLists = (list1, list2) => {
  const dummy = createNode(0);
  // 2. dummy — фиктивный узел-заглушка. Он никогда не попадёт в ответ,
  //    а служит "точкой опоры", чтобы не думать отдельно про первый элемент.

  let current = dummy;
  // 3. current — указатель на последний узел уже собранного результата.
  //    Изначально он указывает на dummy.

  while (list1 && list2) {
    // 4. Пока ОБА списка не закончились — сравниваем текущие значения.
    //    Обратите внимание: list1 и list2 здесь одновременно играют роль
    //    "бегунков" — переменные, переданные в функцию, переиспользуются
    //    как указатели на текущий узел в каждом из списков.
    if (list1.val < list2.val) {
      current.next = list1; // 5. Меньший узел цепляем к результату.
      list1 = list1.next;    // 6. Двигаем указатель list1 на следующий узел.
    } else {
      current.next = list2;
      list2 = list2.next;
    }
    current = current.next;
    // 7. В любом случае двигаем "хвост" результата на только что добавленный узел.
  }

  if (list1) {
    current.next = list1;
    // 8. Если list1 ещё не закончился — значит, list2 уже пуст.
    //    Прицепляем весь оставшийся (уже отсортированный!) хвост list1 разом.
  }

  if (list2) {
    current.next = list2;
    // 9. Симметрично для list2 — сработает только одно из двух условий (8) или (9),
    //    так как цикл выше уже гарантировал, что один из списков закончился.
  }

  return dummy.next;
  // 10. Настоящий результат начинается СЛЕДУЮЩИМ узлом после dummy.
};
```

### Визуализация по шагам для `list1 = [1, 2, 4]`, `list2 = [1, 3, 4]`

| Шаг | list1.val | list2.val | Кого берём | Результат (собранная часть) |
|---|---|---|---|---|
| 1 | 1 | 1 | `list2` (т.к. `1 < 1` — ложь, идём в `else`) | `1(из list2)` |
| 2 | 1 | 3 | `list1` | `1 → 1` |
| 3 | 2 | 3 | `list1` | `1 → 1 → 2` |
| 4 | 4 | 3 | `list2` | `1 → 1 → 2 → 3` |
| 5 | 4 | 4 | `list2` (т.к. `4 < 4` — ложь, идём в `else`) | `1 → 1 → 2 → 3 → 4` |
| 6 | 4 | — (list2 закончился) | цикл завершён, остаток `list1` прицепляем блоком `if (list1)` | `1 → 1 → 2 → 3 → 4 → 4` |

**Важный нюанс**: в этой версии решения используется строгое сравнение `list1.val < list2.val`. Это значит, что при **равных** значениях элемент всегда берётся из `list2` (срабатывает `else`-ветка). Итоговая последовательность чисел от этого не меняется (она всё равно отсортирована), но конкретный узел-объект, который окажется в этой позиции, будет взят из второго списка. Если бы использовалось `<=`, то при равенстве побеждал бы `list1`. Для задачи это не имеет значения (LeetCode проверяет только значения), но полезно понимать, на что влияет знак сравнения.

## Зачем нужен `dummy`-узел

Без фиктивного узла пришлось бы отдельно решать, "а что присвоить `head` результата на самом первом шаге, если результат ещё пуст?" — то есть добавлять дополнительную ветку кода для первой итерации. `dummy` решает эту проблему элегантно: мы всегда что-то "цепляем" к `current.next`, а в конце просто отбрасываем сам фиктивный узел, возвращая `dummy.next` — то, что оказалось прицеплено первым.

## Почему в конце два отдельных `if`, а не один

После завершения цикла `while (list1 && list2)` **как минимум один** из списков точно закончился (стал `null`) — иначе цикл продолжал бы работать. Поэтому:

- если `list1` ещё не `null` — цикл прервался из-за того, что закончился `list2`, и нужно прицепить остаток `list1`;
- если `list2` ещё не `null` — аналогично, нужно прицепить остаток `list2`.

Оба `if` физически никогда не выполнятся одновременно (кроме случая, когда оба списка изначально пусты — тогда не выполнится ни один), поэтому такой код полностью эквивалентен более компактной записи через `current.next = list1 || list2`, только чуть более "явный" и читаемый для новичка.

## Сложность алгоритма

| Показатель | Значение |
|---|---|
| Время | O(n + m), где n и m — длины list1 и list2. Каждый узел из обоих списков посещается ровно один раз. |
| Память | O(1) дополнительной памяти — используем только несколько переменных-указателей и один служебный узел `dummy`, новых узлов для самих данных не создаём. |

Это оптимальное решение по времени и по памяти: слить два отсортированных списка быстрее, чем за один проход по обоим, в общем случае невозможно.

## Частые ошибки при решении этой задачи

- Забыть создать `dummy`-узел и попытаться вручную обрабатывать первую итерацию отдельным условием — код становится длиннее и легче допустить ошибку.
- Перепутать `<` и `<=` и не осознавать, что это влияет только на то, из какого списка берётся узел при равных значениях, а не на итоговую последовательность чисел.
- Забыть довести `current` до последнего добавленного узла (`current = current.next`) — тогда следующий узел прицепится не туда, и часть уже собранного результата "потеряется".
- Вернуть `dummy` вместо `dummy.next` — тогда в начало ответа попадёт лишний узел со значением `0` (то самое значение, с которым явно создан `dummy` в этой версии решения).
- Забыть про хвост: если убрать оба `if (list1)` / `if (list2)` после цикла, "лишний" остаток более длинного списка просто потеряется, и в ответе не хватит элементов.
- Присваивать `list1`/`list2` новым переменным без необходимости — в этом решении они и так безопасно переиспользуются как указатели, поскольку JavaScript передаёт аргументы функции по значению ссылки, а сам вызывающий код (`mergeTwoLists(l1, l2)`) при этом не теряет переменные `l1`/`l2` снаружи функции.
