## Какой алгоритм используется

**Binary Search (Бинарный поиск)**

## Суть задачи

Дан отсортированный по возрастанию массив уникальных чисел `nums` и число
`target`.

- Если `target` есть в массиве — нужно вернуть его индекс.
- Если `target` в массиве нет — нужно вернуть индекс, **на который его нужно
  было бы вставить**, чтобы массив остался отсортированным.

Как и в задаче *Binary Search*, здесь отдельно указано требование —
решение должно работать за **O(log n)**. Это прямая подсказка на бинарный
поиск: простой перебор циклом дал бы `O(n)` и не прошёл бы по требованиям
задачи.

## Разбор решения

Это модификация классического бинарного поиска. Разница всего в одном месте
— что вернуть, если элемент **не найден**.

В обычном бинарном поиске, если элемент не найден, мы возвращаем `-1`. Здесь
же нужно вернуть **позицию для вставки**. Ключевое наблюдение: в момент,
когда цикл поиска завершается (диапазон `[left, right]` стал пустым,
`left > right`), переменная `left` как раз указывает на то место, куда нужно
вставить `target`, чтобы массив остался отсортированным.

Почему так происходит? На каждом шаге, когда `nums[mid] < target`, мы
сдвигаем `left = mid + 1` — то есть `left` всегда "подтягивается" к первому
элементу, который **не меньше** `target`. Когда цикл заканчивается, `left`
как раз останавливается на первой подходящей позиции для вставки — будь то
существующий больший элемент, или конец массива, если `target` больше всех
элементов.

## Пошаговый разбор кода

```js
const searchInsert = (nums, target) => {
  // left и right — границы диапазона поиска.
  // В начале это весь массив
  let left = 0;
  let right = nums.length - 1;

  while (left <= right) {
    // Безопасное вычисление середины (подробнее — см. разбор задачи Binary Search)
    const mid = Math.floor(left + (right - left) / 2);

    if (nums[mid] === target) {
      return mid; // элемент найден — возвращаем его индекс
    }

    const isSmaller = nums[mid] < target;

    if (isSmaller) {
      // средний элемент меньше target — target (если есть) находится правее
      left = mid + 1;
    }

    if (!isSmaller) {
      // средний элемент больше target — target (если есть) находится левее
      right = mid - 1;
    }
  }

  // Элемент не найден. К этому моменту left "остановился"
  // ровно на той позиции, куда нужно вставить target
  return left;
};
```

### Пошаговая трассировка: `target` есть в массиве

`nums = [1,3,5,6]`, `target = 5` (индексы `0..3`)

| шаг | left | right | mid | nums[mid] | сравнение | действие |
|---|---|---|---|---|---|---|
| 1 | 0 | 3 | 1 | 3 | 3 < 5 | left = 2 |
| 2 | 2 | 3 | 2 | 5 | 5 === 5 | **найдено!** возвращаем 2 |

### Пошаговая трассировка: `target` нужно вставить в середину

`nums = [1,3,5,6]`, `target = 2`

| шаг | left | right | mid | nums[mid] | сравнение | действие |
|---|---|---|---|---|---|---|
| 1 | 0 | 3 | 1 | 3 | 3 > 2 | right = 0 |
| 2 | 0 | 0 | 0 | 1 | 1 < 2 | left = 1 |

После шага 2 `left = 1`, `right = 0` — диапазон опустел (`left > right`),
цикл завершается. Возвращаем `left = 1`. Действительно: `2` нужно вставить
между `1` (индекс 0) и `3` (индекс 1), то есть на позицию `1`.

### Пошаговая трассировка: `target` больше всех элементов

`nums = [1,3,5,6]`, `target = 7`

| шаг | left | right | mid | nums[mid] | сравнение | действие |
|---|---|---|---|---|---|---|
| 1 | 0 | 3 | 1 | 3 | 3 < 7 | left = 2 |
| 2 | 2 | 3 | 2 | 5 | 5 < 7 | left = 3 |
| 3 | 3 | 3 | 3 | 6 | 6 < 7 | left = 4 |

После шага 3 `left = 4`, `right = 3` — цикл завершается. Возвращаем
`left = 4`: число `7` больше всех элементов массива, поэтому его нужно
вставить в самый конец, сразу за последним элементом.

## Сложность

- **Время:** O(log n) — та же логика бинарного поиска, диапазон сужается
  вдвое на каждом шаге.
- **Память:** O(1) — используются только несколько переменных.

## Чем это отличается от обычного Binary Search

| | Binary Search (#704) | Search Insert Position (#35) |
|---|---|---|
| Если элемент найден | возвращаем индекс | возвращаем индекс |
| Если элемент не найден | возвращаем `-1` | возвращаем `left` — позицию для вставки |
| Смысл `left` в конце цикла | не используется | это и есть ответ |

По сути, задача *Search Insert Position* — это чуть более полезная версия
обычного бинарного поиска: вместо того чтобы просто сказать "элемента нет",
она подсказывает, куда его можно было бы вставить. Такая логика лежит в
основе встроенных функций многих языков программирования (например,
`bisect.insort` в Python) и часто используется там, где нужно поддерживать
отсортированную структуру данных при добавлении новых элементов.
