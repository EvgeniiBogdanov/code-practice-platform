# Stack (Стек) — полный разбор на JavaScript

## Что такое стек простыми словами

Представь стопку тарелок на кухне. Ты моешь тарелку и кладёшь её **сверху**
стопки. Когда нужна чистая тарелка — берёшь её тоже **сверху**. Ты физически
не можешь вытащить тарелку из середины стопки, не сдвинув всё, что лежит
над ней.

Это и есть стек — структура данных, где:
- новый элемент добавляется только сверху (в конец),
- удалить можно только тот элемент, который сейчас сверху (в конце).

Такой принцип называется **LIFO** — **L**ast **I**n, **F**irst **O**ut
("последним пришёл — первым ушёл"). Последняя добавленная тарелка будет
первой, которую ты используешь.

Стек — это **абстрактный тип данных** (ADT). Это значит, что "стек" —
не какая-то конкретная встроенная структура в JavaScript, а *договорённость
о том, какие операции разрешены и как они себя ведут*. Реализовать стек
можно поверх обычного массива — что мы и сделаем.

## Зачем нужен стек — примеры из жизни и из кода

- **Кнопка "Отменить" (Undo)** в редакторе — каждое действие кладётся
  в стек, отмена достаёт последнее действие сверху.
- **Кнопка "Назад" в браузере** — история страниц устроена как стек.
- **Стек вызовов функций (Call Stack)** — сама среда выполнения JavaScript
  использует стек, чтобы помнить, какая функция вызвала какую.
- **Проверка правильности скобок** `(){}[]` в коде, калькуляторе, парсере.
- **Обход графов и деревьев в глубину (DFS)** — можно реализовать как
  рекурсией, так и явным стеком.
- **Reverse Polish Notation / вычисление выражений** — калькуляторы
  на стеке (как в старых инженерных калькуляторах HP).

## Основные операции стека

| Операция    | Что делает                                    | Сложность |
|-------------|------------------------------------------------|-----------|
| `push`      | добавить элемент на вершину стека              | O(1)      |
| `pop`       | удалить и вернуть элемент с вершины стека      | O(1)      |
| `peek`      | посмотреть элемент на вершине, не удаляя его   | O(1)      |
| `isEmpty`   | проверить, пуст ли стек                        | O(1)      |
| `size`      | узнать количество элементов                    | O(1)      |

Все операции стека выполняются за **O(1)** — это его главное преимущество.
Работа идёт только с одним концом структуры, поэтому ничего не нужно
сдвигать или пересчитывать.

## Реализация стека на JavaScript (стрелочные функции)

### Вариант 1: простой стек на основе массива

Самый честный способ понять стек — написать его "с нуля", ограничив
себя только теми операциями, которые стек разрешает. Используем
JS-классы, но с методами через свойства-стрелочные функции, чтобы `this`
был предсказуемым:

```javascript
class Stack {
  #items = []; // приватное поле — доступ к нему только изнутри класса

  push = (item) => {
    this.#items.push(item);
    return this.#items.length;
  };

  pop = () => {
    if (this.isEmpty()) return undefined;
    return this.#items.pop();
  };

  peek = () => {
    if (this.isEmpty()) return undefined;
    return this.#items[this.#items.length - 1];
  };

  isEmpty = () => this.#items.length === 0;

  size = () => this.#items.length;
}

const stack = new Stack();

stack.push(1);
stack.push(2);
stack.push(3);

console.log(stack.peek()); // 3 — верхний элемент, стек не меняется
console.log(stack.pop());  // 3 — достали и удалили верхний элемент
console.log(stack.pop());  // 2
console.log(stack.size()); // 1
console.log(stack.isEmpty()); // false
console.log(stack.pop());  // 1
console.log(stack.isEmpty()); // true
console.log(stack.pop());  // undefined — стек уже пуст
```

**Почему `#items` приватное?** Если оставить массив публичным
(`this.items`), кто угодно снаружи сможет сделать `stack.items[0] = 999`
или `stack.items.splice(1, 1)` — и сломать главное правило стека
(доступ только к вершине). Приватное поле `#items` гарантирует,
что доступ будет строго через разрешённые методы.

### Вариант 2: функциональный стек (фабричная функция)

Если не хочется возиться с классами и `new`, можно сделать стек
через фабричную функцию и замыкание (closure). Переменная `items`
спрятана внутри функции и снаружи к ней нет прямого доступа:

```javascript
const createStack = () => {
  const items = [];

  const push = (item) => {
    items.push(item);
    return items.length;
  };

  const pop = () => (items.length ? items.pop() : undefined);

  const peek = () => (items.length ? items[items.length - 1] : undefined);

  const isEmpty = () => items.length === 0;

  const size = () => items.length;

  return { push, pop, peek, isEmpty, size };
};

const myStack = createStack();
myStack.push("A");
myStack.push("B");
console.log(myStack.peek()); // "B"
console.log(myStack.pop());  // "B"
console.log(myStack.pop());  // "A"
```

## Классические паттерны применения стека

### 1. Парные скобки и вложенные структуры (Parentheses matching)

Самый известный учебный пример: проверить, правильно ли расставлены
скобки в строке. Каждая открывающая скобка кладётся в стек, а каждая
закрывающая — снимает последнюю открытую скобку с вершины стека и
проверяет, совпали ли их типы.

### 2. Монотонный стек (Monotonic Stack)

Продвинутый, но очень популярный на собеседованиях паттерн. Это стек,
в котором элементы всегда поддерживаются строго возрастающими или
строго убывающими.

Используется для задач вида:
- "найти ближайший больший элемент справа/слева" (Next Greater Element),
- "найти самый большой прямоугольник под гистограммой" (Largest Rectangle in Histogram),
- "посчитать количество дней до потепления" (Daily Temperatures).

Вместо `O(n²)` наивного перебора монотонный стек решает такие задачи за **O(n)**.

### 3. Min Stack (стек с поддержкой минимума за O(1))

Задача спроектировать стек, где метод `getMin()` работает за `O(1)`.
Решается приёмом со **вспомогательным стеком** (auxiliary stack), который
растёт синхронно с основным и хранит минимум на каждом уровне.

## Подводные камни

### 1. `pop()` и `push()` в JS меняют исходный массив

`array.pop()` и `array.push()` — **мутирующие** методы: они не
возвращают новый массив, а изменяют существующий "на месте". Если
где-то в коде массив используется в нескольких местах, случайный
`pop()` может незаметно "съесть" данные, которые нужны были ещё
кому-то. Переменная-массив передаётся по ссылке.

### 2. Забыть проверить пустой стек перед `pop`/`peek`

`[].pop()` в JavaScript не выбросит ошибку, а просто вернёт `undefined`.
Это удобно, но опасно: если не проверять `isEmpty()` явно, легко
получить `undefined`, который "тихо" протечёт дальше по коду и упадёт
с ошибкой совсем в другом, неожиданном месте.

### 3. Стек вызовов (Call Stack) и переполнение стека

Сам JavaScript-движок использует стек для отслеживания вызовов функций —
это называется **Call Stack** (стек вызовов). Когда функция вызывает
другую функцию, новый "кадр" (frame) кладётся на вершину стека вызовов;
когда функция завершается — кадр снимается.

```javascript
const countdown = (n) => {
  if (n < 0) return;
  countdown(n - 1); // кладём новый кадр в стек вызовов на каждый вызов
};

countdown(100000); // Uncaught RangeError: Maximum call stack size exceeded
```

Это и есть ошибка **"Maximum call stack size exceeded"** — переполнение
стека вызовов из-за слишком глубокой рекурсии.

### 4. Стек ≠ Очередь (Queue)

Стек работает по принципу **LIFO** (Last In, First Out — "последним пришёл,
первым ушёл"), а очередь (Queue) — по принципу **FIFO** (First In, First Out —
"первым пришёл, первым ушёл"). У стека удаление идёт с того же конца, куда
добавляли (`push`/`pop`), а у очереди — с противоположного (`push`/`shift`).

## Сложность операций — итог

- `push`, `pop`, `peek`, `isEmpty`, `size` — все за **O(1)** по времени
- Память — **O(n)**, где `n` — число элементов в стеке
