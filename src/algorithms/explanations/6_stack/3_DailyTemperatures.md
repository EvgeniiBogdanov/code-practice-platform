## Какой алгоритм используется

**Monotonic Stack (Монотонный стек)** — стек как приём поиска "ближайшего большего элемента" (Next Greater Element)

## Суть задачи

Дан массив температур по дням. Для каждого дня нужно узнать: через сколько
дней наступит более тёплый день. Если такого дня в будущем нет — ответ `0`.

```
temperatures = [73, 74, 75, 71, 69, 72, 76, 73]
result       = [1,  1,  4,  2,  1,  1,  0,  0]
```

Например, для дня с температурой `75` (индекс 2) более тёплый день
наступит только через 4 дня, когда будет `76`. А для дня с `76`
(индекс 6) впереди больше нет ничего теплее — там остаётся `0`.

## Почему это задача на монотонный стек

### Наивное решение и почему оно медленное

Первое, что приходит в голову: для каждого дня `i` пройтись вперёд
по всем следующим дням, пока не найдём более тёплый — это `O(n²)`,
слишком медленно при `n` до `10^5` (по условию задачи).

### Идея монотонного стека

Хочется пройтись по массиву **всего один раз** и при этом не терять
информацию о днях, для которых мы ещё не нашли "более тёплый день
в будущем". Именно для этого используют **монотонный стек** — стек,
в котором элементы всегда упорядочены по какому-то правилу (в этой
задаче — по убыванию температуры сверху вниз).

Идея: идём по дням слева направо и держим в стеке **индексы дней**,
для которых ещё не нашли более тёплый день. Стек устроен так, что
температуры дней в нём всегда идут по убыванию от низа к верху —
то есть на вершине стека температура **самая низкая** среди тех,
что там лежат (мы "ждём" потепления именно для неё в первую очередь).

Когда встречаем новый день:
- пока на вершине стека лежит день с температурой **ниже**, чем
  сегодня — значит, для него мы наконец нашли более тёплый день.
  Снимаем его со стека и записываем ответ (разницу индексов);
- как только вершина стека оказывается "теплее или равна" сегодняшнему
  дню — выходим из цикла, дальше в стеке лежат дни, которым ещё рано
  "закрываться";
- кладём индекс текущего дня в стек — теперь он тоже "ждёт" своего
  потепления.

## Разбор решения

Пошагово:

1. Создаём массив `result`, заполненный нулями — это ответ по
   умолчанию ("более тёплого дня не будет").
2. Заводим пустой стек — в нём храним **индексы** дней.
3. Проходим по `temperatures` циклом `for`.
4. На каждом дне `i` заходим во внутренний `while (stack.length > 0)`:
   - берём индекс `lastIndex` — вершину стека;
   - сравниваем температуру сегодняшнего дня с температурой дня
     на вершине стека и сохраняем результат в `isWarmer`;
   - если `isWarmer` истинно — значит день `lastIndex` дождался
     потепления: снимаем его со стека (`pop`) и записываем ответ;
   - если `isWarmer` ложно (то есть `!isWarmer` истинно) — сегодня
     не теплее вершины стека, дальше снимать нечего, выходим из
     `while` через `break`.
5. После выхода из `while` кладём индекс текущего дня в стек.
6. Когда проход по всем дням закончен, возвращаем `result`.

### Почему каждый элемент обрабатывается только один раз

Индекс кладётся в стек ровно один раз (`push`) и снимается со стека
тоже ровно один раз (`pop`) за всё время работы алгоритма. Суммарно
все `push` и все `pop` за весь проход по массиву — это не более `2n`
операций, а не `n²`. Именно поэтому итоговая сложность — `O(n)`.

## Код с комментариями

```javascript
const dailyTemperatures = (temperatures) => {
  // Заранее заполняем результат нулями — это значение "по умолчанию"
  // для дней, для которых более тёплый день не найдётся
  const result = new Array(temperatures.length).fill(0);

  // Стек хранит ИНДЕКСЫ дней, для которых мы ещё не нашли
  // более тёплый день. Температуры этих дней в стеке идут
  // по убыванию от низа к верху
  const stack = [];

  for (let i = 0; i < temperatures.length; i++) {
    // Пока в стеке есть хоть один день — пробуем "закрыть" его,
    // если сегодня теплее
    while (stack.length > 0) {
      // Индекс дня, который сейчас на вершине стека
      const lastIndex = stack[stack.length - 1];

      // Проверяем: сегодня теплее, чем в тот "ожидающий" день?
      const isWarmer = temperatures[i] > temperatures[lastIndex];

      if (isWarmer) {
        // Да, сегодня теплее — снимаем ожидавший день со стека
        const prevIndex = stack.pop();

        // Записываем для него ответ: сколько дней пришлось ждать
        result[prevIndex] = i - prevIndex;
      }

      // Если сегодня НЕ теплее — снимать больше нечего, выходим из while
      if (!isWarmer) break;
    }

    // Кладём индекс текущего дня в стек — теперь он тоже
    // "ожидает" более тёплого дня в будущем
    stack.push(i);
  }

  return result;
};
```

### Пошаговая трассировка для `[73, 74, 75, 71, 69, 72, 76, 73]`

| День (i) | Температура | Что происходит | Стек после шага (индексы) |
|---|---|---|---|
| 0 | 73 | стек пуст, просто push | `[0]` |
| 1 | 74 | 74 > 73 → pop(0), result[0] = 1 - 0 = 1; затем push | `[1]` |
| 2 | 75 | 75 > 74 → pop(1), result[1] = 2 - 1 = 1; затем push | `[2]` |
| 3 | 71 | 71 не теплее 75 → `!isWarmer` → break, push | `[2, 3]` |
| 4 | 69 | 69 не теплее 71 → break, push | `[2, 3, 4]` |
| 5 | 72 | 72 > 69 → pop(4), result[4]=1; 72 > 71 → pop(3), result[3]=2; 72 не теплее 75 → break, push | `[2, 5]` |
| 6 | 76 | 76 > 72 → pop(5), result[5]=1; 76 > 75 → pop(2), result[2]=4; стек пуст → push | `[6]` |
| 7 | 73 | 73 не теплее 76 → break, push | `[6, 7]` |

После прохода в стеке остались индексы `6` и `7` — для них более
тёплый день так и не встретился, их `result` остаётся `0`.
Итоговый результат: `[1, 1, 4, 2, 1, 1, 0, 0]` — совпадает с ожидаемым.

## Сложность

- **Время:** O(n) — каждый индекс кладётся в стек и снимается со стека максимум один раз
- **Память:** O(n) — в худшем случае (температуры строго убывают) все индексы окажутся в стеке
