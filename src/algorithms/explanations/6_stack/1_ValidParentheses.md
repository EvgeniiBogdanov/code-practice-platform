## Какой алгоритм используется

**Stack (Стек)** — структура данных LIFO

## Суть задачи

Дана строка, состоящая только из скобок трёх видов: `()`, `{}`, `[]`.
Нужно проверить, "валидна" ли строка — то есть расставлены ли скобки
правильно.

Строка валидна, если:
1. каждая открывающая скобка закрывается скобкой **того же типа**;
2. скобки закрываются **в правильном порядке** (последняя открытая
   скобка должна закрыться первой — самая "внутренняя" пара закрывается
   раньше самой "внешней");
3. у каждой закрывающей скобки есть своя пара — открывающая скобка.

Примеры:
```
"()"     -> true
"()[]{}" -> true
"(]"     -> false  (типы не совпадают)
"([])"   -> true   (вложенность соблюдена)
"([)]"   -> false  (скобки закрылись не в том порядке — "перехлёст")
```

## Почему это задача на стек

Обрати внимание на правило №2 — "последняя открытая скобка должна
закрыться первой". Это дословное описание принципа **LIFO**
(Last In, First Out — "последним пришёл, первым ушёл"), а LIFO —
это и есть определение стека.

Представь стопку тарелок: пока не снимешь верхнюю, до следующей не
доберёшься. Так же и здесь: пока не "закрыл" самую последнюю
открывшуюся скобку, следующая закрывающая скобка обязана относиться
именно к ней — иначе порядок нарушен, как в примере `"([)]"`, где
`)` пытается закрыть `(`, хотя последней открылась `[`.

## Разбор решения

В этом решении объект `pairs` устроен **наоборот** по сравнению
с самым очевидным вариантом — не "закрывающая → открывающая",
а **"открывающая → ожидаемая закрывающая"**:

```javascript
const pairs = {
  '(': ')',
  '[': ']',
  '{': '}',
};
```

Идея такая: как только встречаем открывающую скобку, сразу знаем,
какая закрывающая скобка должна её закрыть в будущем — и кладём
в стек **не саму открывающую скобку**, а сразу **её "ожидаемую пару"**.
Это удобно, потому что потом не нужно отдельно смотреть в `pairs`
при встрече закрывающей скобки — достаточно сравнить её напрямую
с тем, что лежит в стеке.

Пошагово:

1. Заводим пустой стек (обычный массив) и объект `pairs`
   (открывающая скобка → ожидаемая закрывающая).
2. Идём по строке символ за символом (`for...of`).
3. Смотрим, есть ли текущий символ среди ключей `pairs`
   (`expectedClose = pairs[char]`). Если символ — открывающая скобка,
   `expectedClose` будет строкой (`")"`, `"]"` или `"}"`), а если
   закрывающая — `undefined`. Так и определяем `isOpen`.
4. Если скобка открывающая (`isOpen === true`) — кладём в стек **не
   сам символ**, а `expectedClose`, то есть закрывающую скобку,
   которую мы ожидаем увидеть позже.
5. Если скобка закрывающая (`isOpen === false`) — снимаем верхушку
   стека (`stack.pop()`) и сравниваем её напрямую с текущим символом
   (`last === char`). Если не совпало — значит, скобки расставлены
   неправильно, сразу возвращаем `false`.
6. После прохода по всей строке валидность зависит от того, остался
   ли стек пустым: `!stack.length`. Если что-то осталось в стеке —
   значит, какие-то открывающие скобки так и не были закрыты
   (пример: `"((("`).

### Почему проверка "стек пуст в конце" обязательна

Строка `"((("` состоит из одних открывающих скобок. Ни одна
закрывающая скобка не встретится, поэтому сравнение `last === char`
ни разу не сработает — переберём строку без единого `false`.
Но результат всё равно должен быть `false`, потому что скобки не
закрыты. Именно поэтому в конце дополнительно проверяем `!stack.length`.

## Код с комментариями

```javascript
const isValid = (s) => {
  // Стек, в который складываем ОЖИДАЕМЫЕ закрывающие скобки —
  // а не сами открывающие символы
  const stack = [];

  // pairs хранит соответствие "открывающая скобка -> её закрывающая пара"
  const pairs = {
    '(': ')',
    '[': ']',
    '{': '}',
  };

  for (const char of s) {
    // Если char есть среди ключей pairs — это открывающая скобка,
    // и expectedClose будет строкой вида ")", "]" или "}".
    // Если char закрывающая скобка — expectedClose будет undefined
    const expectedClose = pairs[char];
    const isOpen = expectedClose !== undefined;

    // Символ открывающий — кладём в стек ожидаемую закрывающую скобку
    isOpen ? stack.push(expectedClose) : null;

    if (!isOpen) {
      // Символ закрывающий — снимаем верхушку стека.
      // Если стек уже пуст, last будет undefined
      const last = stack.pop();

      // Сравниваем то, что ожидали увидеть (last),
      // с тем, что реально встретили (char)
      const isMatch = last === char;

      // Несовпадение — скобки расставлены неправильно
      if (!isMatch) return false;
    }
  }

  // Строка валидна, только если в стеке не осталось
  // "незакрытых" ожиданий закрывающих скобок
  return !stack.length;
};
```

### Пошаговая трассировка для `"([)]"`

| Символ | `expectedClose` | Действие | Стек после действия |
|---|---|---|---|
| `(` | `")"` | открывающая → push(")") | `[")"]` |
| `[` | `"]"` | открывающая → push("]") | `[")", "]"]` |
| `)` | `undefined` | закрывающая → pop() даёт `"]"`, сравниваем с `")"` | `[")"]` |

На третьем символе `last === char` даёт `"]" === ")"` → `false`,
поэтому функция сразу возвращает `false` — порядок скобок нарушен.

## Сложность

- **Время:** O(n) — один проход по строке длины n, каждая операция со стеком (`push`/`pop`) выполняется за O(1)
- **Память:** O(n) — в худшем случае (например, `"((((("`) все символы строки сохранятся в стеке
