## 1. Что это такое и зачем нужно

**Two Pointers (два указателя)** — это техника решения задач на массивах,
строках и связных списках, при которой вместо одного индекса-счётчика мы
используем **два индекса одновременно** и двигаем их по определённым
правилам, вместо того чтобы перебирать все возможные пары элементов
вложенными циклами.

Главная цель приёма — превратить решение, которое перебирает все пары
элементов за **O(n²)**, в решение, которое проходит по данным **один или
два раза** за **O(n)**, почти не тратя лишней памяти (**O(1)**).

Представьте наивное решение задачи "найти пару чисел с нужной суммой":

```js
// Наивно: перебираем все пары — O(n²)
function findPairSimple(array, target) {
  for (let i = 0; i < array.length; i++) {
    for (let j = i + 1; j < array.length; j++) {
      if (array[i] + array[j] === target) {
        return [i, j];
      }
    }
  }
  return [];
}
```

Для массива из 30 000 элементов это до 900 миллионов операций. Two Pointers
позволяет решить ту же задачу за один проход, если массив отсортирован —
и это будет уже не миллионы, а десятки тысяч операций.

## 2. Идея на пальцах

Представьте, что вам нужно найти двух людей с одинаковым номером дома в
списке из 40 пронумерованных по возрастанию домов, где нужная пара
существует. Можно идти от первого дома к последнему и проверять каждый
дом против всех остальных — долго. А можно поставить одного человека у
дома №1, а другого — у дома №40, и пусть они идут **навстречу друг
другу**, созваниваясь на каждом шаге. Это в разы быстрее, потому что вы
используете упорядоченность списка домов, а не проверяете всё подряд.

Именно так работают "два указателя" — это просто два индекса (`left` и
`right`, либо `slow` и `fast`), которые двигаются по массиву по
осмысленным правилам, опираясь на структуру данных (чаще всего —
на отсортированность).

## 3. Когда применять

Two Pointers почти всегда подходит, если выполняется хотя бы одно из
условий:

- Массив (или строка) **отсортирован**, и нужно найти пару/тройку
  элементов, удовлетворяющих условию (сумма, разница и т.д.).
- Нужно сравнивать элементы **с начала и с конца** структуры (палиндромы,
  разворот массива).
- Нужно **удалить/переместить/сжать** элементы массива "на месте"
  (без создания нового массива) — например, убрать дубликаты, убрать нули.
- Есть два отдельных отсортированных массива/списка, которые нужно
  **слить** в один (merge).
- Нужно найти цикл в связном списке или середину списка (вариант
  "быстрый/медленный указатель").

Если в задаче фигурируют слова "отсортированный массив", "константная
память", "на месте (in-place)", "палиндром", "пара/тройка элементов с
суммой X" — это почти наверняка Two Pointers.

## 4. Виды Two Pointers

### 4.1 Указатели с двух концов навстречу друг другу (opposite direction)

Самый частый вариант. `left` стартует в начале, `right` — в конце.
На каждом шаге указатели анализируют текущую пару элементов и либо
находят ответ, либо сдвигаются навстречу друг другу, пока не встретятся.

```
[ 2,  7, 11, 15]   target = 9
  ^left        ^right
```

Применяется в задачах:
- поиск пары с заданной суммой в отсортированном массиве (Two Sum II);
- проверка палиндрома;
- задача "Container With Most Water" (наибольшая площадь между двумя
  столбиками);
- разворот массива/строки на месте.

### 4.2 Медленный / быстрый указатель (slow / fast)

Оба указателя стартуют **с одного конца** (обычно с начала), но
двигаются с разной "скоростью" или по разным правилам: один
(`fast`) активно сканирует структуру, второй (`slow`) отмечает позицию,
куда нужно записать/оставить "полезный" элемент.

```
slow=0                     
 v
[1, 1, 2, 2, 3]
    ^fast
```

Применяется в задачах:
- удаление дубликатов из отсортированного массива на месте;
- перемещение нулей в конец массива;
- фильтрация массива по условию на месте;
- поиск цикла в связном списке (алгоритм Флойда, "черепаха и заяц") —
  здесь `fast` идёт на 2 шага, `slow` — на 1 шаг за итерацию;
- поиск середины связного списка.

### 4.3 Скользящее окно (Sliding Window) — родственник Two Pointers

Это отдельная, но очень похожая техника: оба указателя (`left` и
`right`) двигаются **в одном направлении**, образуя "окно" — непрерывный
подотрезок массива/строки. `right` расширяет окно, `left` сжимает его,
когда условие нарушается.

```
[a, b, c, d, e, f]
    ^left  ^right
```

Применяется в задачах на подстроки/подмассивы: "самая длинная подстрока
без повторяющихся символов", "минимальный подмассив с суммой ≥ target"
и т.д. Формально это часто выделяют в отдельную тему, но по механике это
тоже два указателя, поэтому важно уметь отличать её от "opposite
direction".

## 5. Сложность алгоритма

| Характеристика | Наивный подход (два вложенных цикла) | Two Pointers |
|---|---|---|
| Время | O(n²) | O(n) (в большинстве задач) |
| Память | O(1) или O(n) (если используется хеш-таблица) | O(1) |

Важно понимать, **почему** это работает за O(n), а не путать с "у нас
два цикла — значит O(n²)". Указатели не создают вложенности: `left`
и `right` двигаются **навстречу друг другу**, а не независимо. Суммарное
число шагов обоих указателей не превышает `n` — то есть весь массив
"обрабатывается" один раз, а не `n` раз для каждого элемента.

Для варианта slow/fast логика та же: `fast` проходит по массиву один
раз (n шагов), `slow` двигается не быстрее, чем `fast`, поэтому суммарная
работа — линейная.

## 6. Разбор на примерах

### 6.1 Пример 1: сумма двух чисел в отсортированном массиве

**Задача:** дан отсортированный по возрастанию массив `numbers` и число
`target`. Найти индексы двух чисел, сумма которых равна `target`.

```js
function twoSum(numbers, target) {
  let left = 0;
  let right = numbers.length - 1;

  while (left < right) {
    const sum = numbers[left] + numbers[right];

    if (sum === target) {
      return [left, right];
    } else if (sum < target) {
      // сумма слишком маленькая — увеличиваем её,
      // сдвигая левый указатель к бОльшим числам
      left++;
    } else {
      // сумма слишком большая — уменьшаем её,
      // сдвигая правый указатель к меньшим числам
      right--;
    }
  }

  return [];
}

console.log(twoSum([2, 7, 11, 15], 9)); // [0, 1]
```

**Почему это работает.** Массив отсортирован, значит, если сумма
`numbers[left] + numbers[right]` меньше цели, то **никакая** пара с
текущим `right` и индексом левее `left` не даст меньшую сумму — она
будет ещё меньше. А вот если увеличить `left`, сумма гарантированно
вырастет (или останется той же при равных числах). Это позволяет на
каждом шаге безопасно отбрасывать один из вариантов, не проверяя его
явно — в этом и есть выигрыш по сравнению с перебором всех пар.

**Трассировка** для `numbers = [2, 7, 11, 15]`, `target = 9`:

| left | right | numbers[left] | numbers[right] | sum | Что делаем |
|------|-------|----------------|------------------|-----|------------|
| 0 | 3 | 2 | 15 | 17 | 17 > 9 → right-- |
| 0 | 2 | 2 | 11 | 13 | 13 > 9 → right-- |
| 0 | 1 | 2 | 7  | 9  | 9 === 9 → ответ [0, 1] |

### 6.2 Пример 2: проверка палиндрома

**Задача:** проверить, является ли строка палиндромом (без учёта
регистра и не буквенно-цифровых символов).

```js
function isPalindrome(s) {
  const isAlphanumeric = (char) => /[a-z0-9]/i.test(char);
  let left = 0;
  let right = s.length - 1;

  while (left < right) {
    while (left < right && !isAlphanumeric(s[left])) left++;
    while (left < right && !isAlphanumeric(s[right])) right--;

    if (s[left].toLowerCase() !== s[right].toLowerCase()) {
      return false;
    }
    left++;
    right--;
  }
  return true;
}

console.log(isPalindrome("race a car")); // false
```

Здесь указатели тоже идут навстречу друг другу, но перед каждым
сравнением "подтягиваются" ближе к центру, пропуская мусорные символы —
это распространённый паттерн: базовая логика Two Pointers плюс
дополнительная фильтрация внутри цикла.

### 6.3 Пример 3: удаление дубликатов из отсортированного массива

**Задача:** дан отсортированный массив. Удалить дубликаты на месте так,
чтобы каждое число встречалось один раз, и вернуть новую длину.

```js
function removeDuplicates(nums) {
  if (nums.length === 0) return 0;

  let slow = 0; // указывает на последний "уникальный" элемент

  for (let fast = 1; fast < nums.length; fast++) {
    if (nums[fast] !== nums[slow]) {
      slow++;
      nums[slow] = nums[fast];
    }
  }

  return slow + 1; // длина уникальной части массива
}

const arr = [0, 0, 1, 1, 1, 2, 2, 3, 3, 4];
console.log(removeDuplicates(arr)); // 5
console.log(arr.slice(0, 5));       // [0, 1, 2, 3, 4]
```

Это классический пример **slow/fast**: `fast` бежит вперёд и ищет новое
уникальное значение, `slow` отмечает, куда его нужно записать. Оба
указателя двигаются в одну сторону, а не навстречу друг другу — важно не
путать этот вариант с предыдущими.

### 6.4 Пример 4: разворот массива на месте

```js
function reverse(arr) {
  let left = 0;
  let right = arr.length - 1;

  while (left < right) {
    [arr[left], arr[right]] = [arr[right], arr[left]];
    left++;
    right--;
  }

  return arr;
}

console.log(reverse([1, 2, 3, 4, 5])); // [5, 4, 3, 2, 1]
```

Простейший пример варианта "навстречу друг другу": меняем местами
элементы под указателями и сдвигаем их к центру.

## 7. Как распознать задачу на Two Pointers

Полезный чек-лист вопросов, которые стоит задать себе при чтении условия:

- Массив/строка **отсортированы**? → вероятно, вариант "навстречу друг
  другу".
- Нужно найти **пару/тройку** элементов с определённой суммой/условием?
  → вероятно, Two Pointers (возможно, после сортировки).
- Нужно **изменить массив на месте** (убрать элементы, переместить)
  с требованием O(1) памяти? → вероятно, slow/fast.
- Задача про **палиндром** или "читается одинаково в обе стороны"? →
  вариант "навстречу друг другу".
- Есть **связный список**, и нужно найти середину, цикл или
  N-ный элемент с конца? → slow/fast с разной скоростью движения.
- Есть **два отдельных отсортированных массива**, которые нужно
  объединить или сравнить? → два указателя, по одному на каждый массив.
- В условии явно написано "your solution must use only constant extra
  space" — это почти всегда подсказка, что ожидается Two Pointers, а не
  решение через хеш-таблицу/множество.

## 8. Подводные камни и типичные ошибки

1. **Забыли, что массив должен быть отсортирован.**
   Классический вариант "навстречу друг другу" с логикой
   "sum < target → left++, sum > target → right--" работает **только**
   на отсортированных данных. На неотсортированном массиве такая логика
   даст неверный ответ. Если массив не отсортирован, а сортировать
   нельзя (например, нужно вернуть исходные индексы) — нужен другой
   подход (хеш-таблица) или сортировка пар "(значение, исходный индекс)".

2. **Условие цикла `left < right` vs `left <= right`.**
   Если использовать `<=`, при `left === right` указатели укажут на один
   и тот же элемент, и вы можете случайно "найти пару" из одного и того
   же элемента с самим собой, если такое не разрешено условием задачи.
   Обычно для поиска **разных** элементов нужен именно `<`.

3. **Бесконечный цикл из-за отсутствия сдвига указателя.**
   Если в одной из веток условия забыть `left++` или `right--`,
   указатели не сдвинутся, и цикл зациклится. Особенно легко допустить
   такую ошибку во вложенных `while` (как в примере с палиндромом) —
   нужно всегда убедиться, что каждая ветка кода в итоге меняет хотя бы
   один индекс.

4. **Выход за границы массива.**
   Во вложенных циклах пропуска "мусорных" символов (палиндром) легко
   забыть проверку `left < right` внутри внутреннего `while` — тогда
   указатель может выйти за пределы массива/строки. Всегда добавляйте
   границу в условие внутреннего цикла.

5. **Одинаковые (дублирующиеся) значения приводят к повторным
   ответам.**
   В задачах вроде "3Sum" (найти все уникальные тройки с суммой 0)
   после нахождения подходящей пары нужно **дополнительно** сдвигать
   указатели, пропуская повторяющиеся значения, иначе в ответе появятся
   дубликаты троек.

6. **Путаница между "навстречу друг другу" и "slow/fast".**
   Это две разные механики с разными правилами движения указателей.
   Если задача про "удалить/переместить элементы на месте" — это
   почти всегда slow/fast (оба указателя идут в одну сторону), а не
   "навстречу друг другу". Использование не того варианта — частая
   причина неправильного или переусложнённого решения.

7. **Попытка использовать Two Pointers там, где данные не позволяют
   принять решение о направлении движения.**
   Приём работает, потому что на каждом шаге понятно, **в какую
   сторону** двигать указатель (мы это можем обосновать, опираясь на
   сортировку или другое свойство данных). Если такого обоснования нет —
   скорее всего, задача не решается двумя указателями "в лоб", и нужен
   перебор, динамическое программирование или другой алгоритм.

8. **Забыли особые случаи: пустой массив/строка, массив из одного
   элемента.**
   Перед стартом цикла стоит проверять `nums.length === 0`, а сам цикл
   `while (left < right)` естественным образом ничего не выполнит для
   массива из 0 или 1 элемента — но полезно явно продумать эти случаи,
   а не полагаться "само сработает".

## 9. Шпаргалка-шаблон кода

**Навстречу друг другу:**

```js
let left = 0;
let right = arr.length - 1;

while (left < right) {
  // Обработка на основе условия
  if (условие_выполнено) {
    // нашли ответ / зафиксировали результат
  } else if (нужно_увеличить_сумму) {
    left++;
  } else {
    right--;
  }
}
```

**Медленный / быстрый (in-place фильтрация):**

```js
let slow = 0;

for (let fast = 0; fast < arr.length; fast++) {
  if (условие_для_arr_fast) {
    arr[slow] = arr[fast];
    slow++;
  }
}
// slow — новая длина "полезной" части массива
```

**Быстрый/медленный для связного списка (поиск цикла/середины):**

```js
let slow = head;
let fast = head;

while (fast && fast.next) {
  slow = slow.next;
  fast = fast.next.next;
  if (slow === fast) {
    // цикл найден
  }
}
```
