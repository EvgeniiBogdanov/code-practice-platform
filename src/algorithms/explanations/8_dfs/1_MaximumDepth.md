# Разбор задачи: Maximum Depth of Binary Tree (LeetCode 104)

Ссылка на оригинал: https://leetcode.com/problems/maximum-depth-of-binary-tree/description/

## Уровень сложности
Easy (лёгкий)

## Алгоритм / паттерн

**DFS (Depth-First Search, обход в глубину)** — рекурсивный обход дерева в стиле **postorder** ("сначала дети, потом сам узел"). Точнее, здесь используется приём, который часто называют **"снизу вверх" (bottom-up recursion)**: мы сначала узнаём глубину обоих поддеревьев, а затем на их основе вычисляем глубину текущего узла.

## Суть задачи простыми словами

Дан корень (`root`) бинарного дерева. Нужно найти его **максимальную глубину** — количество узлов на самом длинном пути от корня до самого дальнего листа (листом называется узел без детей).

```
       3
      / \
     9  20
        / \
       15  7
```

Самый длинный путь здесь — `3 → 20 → 15` (или `3 → 20 → 7`) — это **3 узла**, поэтому ответ равен `3`. Обратите внимание: узел `9` тоже на пути от корня, но его "ветка" короче — глубина считается по **самому длинному** пути, а не по любому.

Представьте дерево как настоящее дерево в лесу: "глубина" — это сколько "этажей" веток нужно пройти от ствола до самой дальней веточки с листом.

## Пошаговый разбор решения

```js
const createNode = (val = 0, left = null, right = null) => ({ val, left, right });
// 1. Фабричная функция для узла — обычный объект, без использования class.

const maxDepth = (root) => {
  if (!root) {
    return 0;
    // 2. Base case (базовый случай рекурсии): у пустого дерева (или пустого
    //    поддерева) глубина равна 0. Именно на этом условии рекурсия
    //    "разворачивается назад" и перестаёт углубляться дальше.
  }

  const leftDepth = maxDepth(root.left);
  // 3. Рекурсивно узнаём глубину левого поддерева.

  const rightDepth = maxDepth(root.right);
  // 4. Рекурсивно узнаём глубину правого поддерева.

  return Math.max(leftDepth, rightDepth) + 1;
  // 5. Глубина текущего узла — это глубина БОЛЕЕ ГЛУБОКОГО из двух
  //    поддеревьев, плюс 1 (сам текущий узел тоже считается "этажом").
};
```

### Визуализация по шагам для дерева `[3, 9, 20, null, null, 15, 7]`

```
       3
      / \
     9  20
        / \
       15  7
```

Рекурсия сначала "спускается" до самых глубоких узлов, а потом "поднимается" обратно, вычисляя глубину на каждом уровне:

| Вызов | Что происходит | Возвращает |
|---|---|---|
| `maxDepth(15)` | у узла 15 нет детей → `maxDepth(null)` дважды вернёт 0 | `max(0, 0) + 1 = 1` |
| `maxDepth(7)` | аналогично | `1` |
| `maxDepth(9)` | у узла 9 тоже нет детей | `1` |
| `maxDepth(20)` | `leftDepth = maxDepth(15) = 1`, `rightDepth = maxDepth(7) = 1` | `max(1, 1) + 1 = 2` |
| `maxDepth(3)` | `leftDepth = maxDepth(9) = 1`, `rightDepth = maxDepth(20) = 2` | `max(1, 2) + 1 = 3` |

Финальный ответ — `3`, именно то, что возвращает самый первый (внешний) вызов `maxDepth(root)`.

### Почему это DFS, а не BFS

Мы не идём "по уровням" (сначала все узлы глубины 1, потом все узлы глубины 2 и т.д. — так работал бы BFS). Вместо этого мы **полностью углубляемся** в одно поддерево (например, всё левое), и только когда оно полностью обработано — переходим к другому. Это классический признак DFS, реализованный здесь через обычную рекурсию (стек вызовов JavaScript берёт на себя роль явного стека).

## Как устроена вспомогательная функция `createBinaryTree`

LeetCode кодирует деревья специальным способом — массивом в **level-order** (по уровням), где `null` означает "у этого узла нет ребёнка в этой позиции". Например, `[3, 9, 20, null, null, 15, 7]` означает: у корня `3` есть дети `9` и `20`; у `9` нет детей (`null, null`); у `20` есть дети `15` и `7`.

```js
const createBinaryTree = (arr) => {
  if (arr.length === 0 || arr[0] === null) {
    return null;
    // 1. Пустой массив или корень = null → пустое дерево.
  }

  const root = createNode(arr[0]);
  const queue = [root];
  // 2. Заводим очередь из ещё не "заполненных" узлов — она нужна,
  //    чтобы знать, к какому узлу цеплять следующих детей из массива.

  let i = 1;

  while (i < arr.length) {
    const current = queue.shift();
    // 3. Берём следующий узел из очереди — ему предстоит "раздать" детей.

    if (i < arr.length) {
      const leftVal = arr[i];
      i++;

      if (leftVal !== null) {
        current.left = createNode(leftVal);
        queue.push(current.left);
        // 4. Если значение не null — создаём левого ребёнка
        //    и добавляем его в очередь (ему тоже могут понадобиться дети).
      }
    }

    if (i < arr.length) {
      const rightVal = arr[i];
      i++;

      if (rightVal !== null) {
        current.right = createNode(rightVal);
        queue.push(current.right);
        // 5. Аналогично для правого ребёнка.
      }
    }
  }

  return root;
};
```

Здесь используется **BFS-подход** (обход по уровням, через очередь `queue`) — но не для решения самой задачи, а для **построения** тестового дерева. Забавный момент: задача просит найти глубину через DFS, а вспомогательная функция для сборки дерева сама устроена как BFS — это хороший пример того, что разные подзадачи внутри одной программы могут использовать разные алгоритмы.

## Альтернатива: итеративный DFS через явный стек

Если нужно избежать рекурсии (например, для очень глубоких деревьев, где есть риск переполнения стека вызовов), задачу можно решить и итеративно:

```js
const maxDepthIterative = (root) => {
  if (!root) {
    return 0;
  }

  const stack = [[root, 1]]; // пары [узел, его глубина]
  let depth = 0;

  while (stack.length > 0) {
    const [node, currentDepth] = stack.pop();

    depth = Math.max(depth, currentDepth);

    if (node.left) {
      stack.push([node.left, currentDepth + 1]);
    }

    if (node.right) {
      stack.push([node.right, currentDepth + 1]);
    }
  }

  return depth;
};
```

Здесь каждый элемент стека хранит не только узел, но и его текущую глубину — это заменяет неявное "накопление" глубины через возвращаемые значения рекурсии.

## Сложность алгоритма

| Показатель | Значение |
|---|---|
| Время | O(n), где n — количество узлов в дереве. Каждый узел посещается ровно один раз. |
| Память (рекурсивная версия) | O(h), где h — высота дерева (глубина стека вызовов). В худшем случае (вырожденное дерево-цепочка) — O(n). |
| Память (итеративная версия) | O(h) в среднем, до O(n) в худшем случае — размер собственного стека тоже зависит от формы дерева. |

## Частые ошибки при решении этой задачи

- Забыть base case `if (!root) return 0` — тогда рекурсия попытается обратиться к `.left`/`.right` у `null` и упадёт с `TypeError`.
- Перепутать `Math.max(leftDepth, rightDepth) + 1` с `leftDepth + rightDepth + 1` — второй вариант считает **суммарное** количество узлов в поддеревьях, а не глубину самого длинного пути. Это довольно частая, но принципиальная ошибка.
- Забыть `+ 1` в конце — тогда глубина будет занижена на единицу, ведь сам текущий узел тоже входит в путь.
- Путать понятия "глубина" (depth, считается от корня вниз) и "высота" (height, иногда считается от листа вверх) — в этой задаче они по сути совпадают (максимальная глубина = высота дерева), но в других задачах на деревьях эти термины иногда используют по-разному, и это стоит уточнять по условию.
- Не проверять пустое дерево (`root = null`) отдельно перед стартом обхода в итеративной версии — без такой проверки код может попытаться обратиться к `root.left` у `null`.
