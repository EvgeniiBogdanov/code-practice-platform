## Идея простыми словами

Представь свою банковскую карту. Каждый день у тебя есть **баланс на конец дня** —
это сумма всех пополнений и трат с самого начала. Тебе не нужно каждый раз
пересчитывать всю историю операций с нуля, чтобы узнать баланс сегодня —
достаточно взять баланс вчера и прибавить/вычесть сегодняшнюю операцию.

Префиксная сумма — это ровно то же самое, только для массива чисел:

> `prefix[i]` — это сумма всех элементов массива от начала **до индекса i включительно**.

Например, для массива `[2, 4, 1, 6, 3, 5]`:

```
индекс:        0   1   2   3   4   5
исходный:       2   4   1   6   3   5
префиксная сумма: 2   6   7  13  16  21
```

`prefix[3] = 13` — это сумма первых четырёх элементов (`2+4+1+6`).

Мы один раз "проходим" по массиву и запоминаем накопленную сумму на каждом шаге.
После этого можно очень быстро узнать сумму **любого куска массива**, не
пересчитывая его заново.

## Зачем это нужно

Представь, что у тебя большой массив (миллион чисел), и тебе нужно **много раз**
спрашивать: "какая сумма элементов с индекса `l` по индекс `r`?".

**Наивный способ** — каждый раз в цикле складывать элементы от `l` до `r`.
Если таких запросов `q`, а размер массива `n`, то это `O(n * q)` — очень медленно
при больших объёмах данных.

**С префиксными суммами** — один раз тратим `O(n)` на подготовку массива, а
дальше каждый запрос суммы отрабатывает за `O(1)` (мгновенно, без цикла).
Итоговая сложность: `O(n + q)` — на порядки быстрее.

Это классический **компромисс между временем и памятью** (time-space tradeoff):
тратим немного дополнительной памяти, чтобы кардинально ускорить вычисления.

## Как строится массив префиксных сумм

Есть два популярных способа — с эффектом "сдвига на 1" и без него. Разберём тот,
что **проще для новичка и не требует особых проверок на границы** — с
дополнительным нулём в начале.

```js
const buildPrefixSum = (nums) => {
  // Массив длиной nums.length + 1, весь заполнен нулями
  const prefix = new Array(nums.length + 1).fill(0);

  for (let i = 0; i < nums.length; i++) {
    prefix[i + 1] = prefix[i] + nums[i];
  }

  return prefix;
};

const nums = [2, 4, 1, 6, 3, 5];
console.log(buildPrefixSum(nums));
// [0, 2, 6, 7, 13, 16, 21]
```

Почему в начале стоит `0`? Это специальный "искусственный" элемент — сумма
**нуля** элементов массива. Он нужен, чтобы формула суммы отрезка (см. ниже)
работала одинаково для любого `l`, включая `l = 0`, без отдельного `if`.

Так выглядит соответствие индексов:

| i (индекс в prefix)   | 0 | 1 | 2 | 3 | 4  | 5  | 6  |
|---|---|---|---|---|---|---|---|
| значение prefix[i]     | 0 | 2 | 6 | 7 | 13 | 16 | 21 |
| означает сумму nums[0..?] | ничего | nums[0..0] | nums[0..1] | nums[0..2] | nums[0..3] | nums[0..4] | nums[0..5] |

То есть `prefix[i]` хранит сумму первых `i` элементов исходного массива
(индексы `nums[0..i-1]`).

## Формула суммы на отрезке

Хотим узнать сумму элементов `nums` на отрезке `[l, r]` (включительно, оба конца
входят). Раз `prefix[i]` — это сумма первых `i` элементов, то:

- `prefix[r + 1]` — сумма всех элементов от начала до индекса `r` включительно;
- `prefix[l]` — сумма всех элементов от начала до индекса `l - 1` (то есть всё,
  что **до** нужного нам отрезка).

Если вычесть одно из другого, останется ровно сумма на отрезке `[l, r]`:

$$\text{sum}(l, r) = \text{prefix}[r + 1] - \text{prefix}[l]$$

### Пример вычисления

Для `nums = [2, 4, 1, 6, 3, 5]` и `prefix = [0, 2, 6, 7, 13, 16, 21]`:

- Сумма на отрезке `[1, 3]` (элементы `4 + 1 + 6 = 11`):
  `prefix[3 + 1] - prefix[1] = prefix[4] - prefix[1] = 13 - 2 = 11` ✅

- Сумма на отрезке `[0, 2]` (элементы `2 + 4 + 1 = 7`):
  `prefix[2 + 1] - prefix[0] = prefix[3] - prefix[0] = 7 - 0 = 7` ✅
  (благодаря нулю в `prefix[0]` не нужен специальный `if` для `l = 0`!)

- Сумма всего массива `[0, 5]` (элементы `2+4+1+6+3+5 = 21`):
  `prefix[5 + 1] - prefix[0] = prefix[6] - prefix[0] = 21 - 0 = 21` ✅

## Готовая функция на JavaScript

Вот как выглядит удобная структура для многократных запросов суммы на
неизменяемом массиве:

```js
const createRangeSumQuery = (nums) => {
  const prefix = new Array(nums.length + 1).fill(0);

  for (let i = 0; i < nums.length; i++) {
    prefix[i + 1] = prefix[i] + nums[i];
  }

  return {
    sumRange: (l, r) => prefix[r + 1] - prefix[l],
  };
};

const query = createRangeSumQuery([2, 4, 1, 6, 3, 5]);
console.log(query.sumRange(1, 3)); // 11
console.log(query.sumRange(0, 2)); // 7
console.log(query.sumRange(4, 5)); // 8
```

## Пошаговая трассировка

Посмотрим, как строится `prefix` для массива `nums = [3, -1, 2, 4]`:

| Шаг | i | nums[i] | Было в prefix | Что вычисляем | Стало в prefix |
|---|---|---|---|---|---|
| старт | — | — | `[0, 0, 0, 0, 0]` | `prefix[0] = 0` | `[0, 0, 0, 0, 0]` |
| 1 | 0 | 3 | `[0, 0, 0, 0, 0]` | `prefix[1] = prefix[0] + nums[0] = 0 + 3 = 3` | `[0, 3, 0, 0, 0]` |
| 2 | 1 | -1 | `[0, 3, 0, 0, 0]` | `prefix[2] = prefix[1] + nums[1] = 3 + (-1) = 2` | `[0, 3, 2, 0, 0]` |
| 3 | 2 | 2 | `[0, 3, 2, 0, 0]` | `prefix[3] = prefix[2] + nums[2] = 2 + 2 = 4` | `[0, 3, 2, 4, 0]` |
| 4 | 3 | 4 | `[0, 3, 2, 4, 0]` | `prefix[4] = prefix[3] + nums[3] = 4 + 4 = 8` | `[0, 3, 2, 4, 8]` |

Результат: `prefix = [0, 3, 2, 4, 8]`.

Теперь ответим на запрос `sumRange(1, 2)` (элементы `-1 + 2 = 1`):
`prefix[2 + 1] - prefix[1] = prefix[3] - prefix[1] = 4 - 3 = 1` ✅.

## Сложность алгоритма

- **Препроцессинг (построение массива):**
  - Время: `O(n)` — один проход по массиву длины `n`.
  - Память: `O(n)` — массив `prefix` длины `n + 1`.

- **Один запрос суммы отрезка (`sumRange`):**
  - Время: `O(1)` — ровно одна арифметическая операция (вычитание).
  - Память: `O(1)` — никаких дополнительных структур.

- **Итого для `q` запросов:**
  - Время: `O(n + q)` вместо `O(n * q)` в наивном решении.

## Подводные камни

1. **Сдвиг индексов на 1.**
   Самая частая ошибка новичков — написать `prefix[r] - prefix[l]`.
   Правильно с дополнительным нулём в начале: `prefix[r + 1] - prefix[l]`.
   Запомнить просто: у правого индекса всегда `+ 1`.

2. **Изменяемый массив.**
   Префиксные суммы рассчитаны на **неизменяемый** (static / immutable) массив.
   Если элементы массива часто меняются (происходят операции update), то после
   каждого изменения придётся пересчитывать `prefix` за `O(n)`. Для часто
   меняющихся массивов используют другие структуры данных — **дерево Фенвика
   (Binary Indexed Tree)** или **дерево отрезков (Segment Tree)**, которые
   позволяют и обновлять элемент, и запрашивать сумму отрезка за `O(log n)`.

3. **Отрицательные числа.**
   Префиксные суммы **отлично работают с отрицательными числами и нулями** —
   формула `prefix[r + 1] - prefix[l]` остаётся верной независимо от знака чисел
   в массиве.

## Классические задачи с Prefix Sum

Префиксные суммы — это не только про сумму отрезка. Это мощный паттерн, на
котором строится множество типовых задач:

### 1. Range Sum Query - Immutable (LeetCode 303) — базовый уровень

Прямая реализация того, что мы только что разобрали. Даётся массив, и нужно
отвечать на вызовы `sumRange(left, right)` за `O(1)`.

```js
const createNumArray = (nums) => {
  const prefix = new Array(nums.length + 1).fill(0);
  for (let i = 0; i < nums.length; i++) {
    prefix[i + 1] = prefix[i] + nums[i];
  }
  return {
    sumRange: (l, r) => prefix[r + 1] - prefix[l],
  };
};
```

### 2. Find Pivot Index (LeetCode 724) — средний уровень

Задача: найти такой индекс `i`, чтобы сумма элементов слева от него была равна
сумме элементов справа от него.

Идея с префиксными суммами:
1. Считаем общую сумму массива `total` за один проход.
2. Идём по массиву и поддерживаем накопленную сумму слева `leftSum`.
3. Сумма справа от индекса `i` — это `total - leftSum - nums[i]`.
4. Если `leftSum === rightSum` — нашли опорный индекс!

```js
const pivotIndex = (nums) => {
  const total = nums.reduce((acc, x) => acc + x, 0);
  let leftSum = 0;

  for (let i = 0; i < nums.length; i++) {
    const rightSum = total - leftSum - nums[i];
    if (leftSum === rightSum) return i;
    leftSum += nums[i];
  }

  return -1;
};

console.log(pivotIndex([1, 7, 3, 6, 5, 6])); // 3
console.log(pivotIndex([1, 2, 3]));          // -1 (такого индекса нет)
```

### 3. Subarray Sum Equals K (LeetCode 560) — Prefix Sum + Map (продвинутый уровень)

Задача: посчитать, сколько подмассивов (непрерывных участков) имеют сумму
ровно `k`. Массив может содержать **отрицательные** числа, поэтому
Sliding Window тут не подходит (в отличие от Minimum Size Subarray Sum, где все
числа положительные) — а вот Prefix Sum отлично справляется, если добавить
`Map` для хранения "сколько раз мы уже видели такую-то префиксную сумму".

Ключевая идея: если на текущем шаге накопленная сумма `sum`, и где-то раньше
уже была префиксная сумма `sum - k`, значит между этими точками лежит
подмассив с суммой ровно `k`.

```js
const subarraySum = (nums, k) => {
  const seen = new Map(); // какая префиксная сумма сколько раз встречалась
  seen.set(0, 1);          // "пустой" префикс (сумма 0) уже встретился один раз
  let sum = 0;
  let count = 0;

  for (let i = 0; i < nums.length; i++) {
    sum += nums[i];
    const need = sum - k; // ищем: была ли раньше такая префиксная сумма

    if (seen.has(need)) {
      count += seen.get(need);
    }

    seen.set(sum, (seen.get(sum) || 0) + 1);
  }

  return count;
};

console.log(subarraySum([1, 1, 1], 2));  // 2
console.log(subarraySum([1, 2, 3], 3));  // 2
console.log(subarraySum([1, -1, 0], 0)); // 3
```

Эта задача — хороший следующий шаг после базовых префиксных сумм: она
показывает, как комбинировать Prefix Sum с хеш-таблицей (`Map`), чтобы решать
задачи с отрицательными числами за `O(n)`.

## Prefix Sum vs Sliding Window — когда что использовать

Обе техники ускоряют работу с подмассивами, но подходят для разных ситуаций:

| Признак | Prefix Sum | Sliding Window |
|---|---|---|
| Массив меняется? | Нет, массив статичен | Обычно тоже нет, но окно "двигается" по нему |
| Числа могут быть отрицательными? | Да, спокойно работает | Обычно нет (сумма должна расти при добавлении) |
| Нужно много запросов суммы на разных отрезках? | Да, это его основная сила | Не для этого предназначен |
| Ищем подмассив с условием на сумму (мин. длина, конкретная сумма и т.д.)? | Подходит, часто вместе с Map | Отлично подходит, если числа положительные |

Например, задача **Minimum Size Subarray Sum** (которую мы разбирали ранее)
решается через Sliding Window именно потому, что все числа положительные —
там сумма окна предсказуемо растёт или уменьшается. А вот
**Subarray Sum Equals K** (выше) требует Prefix Sum + Map, потому что там
допускаются отрицательные числа, и окно вести себя предсказуемо не будет.
