## 1. Что такое Hash Map простыми словами

**Hash Map (хеш-таблица, хеш-карта)** — это структура данных, которая хранит пары **ключ → значение** и позволяет находить значение по ключу практически мгновенно, не перебирая все элементы по очереди.

Представь телефонную книгу без хеш-таблицы: чтобы найти номер Иванова, тебе пришлось бы листать страницы одну за другой (это называется **линейный поиск**, O(n)).

Хеш-таблица работает иначе — как будто у каждого имени есть "формула", которая сразу говорит, на какой странице искать. Это называется **O(1)** — поиск за примерно постоянное время, независимо от размера данных.

**Аналогия:** гардероб в театре. Ты сдаёшь пальто — получаешь номерок (это хеш). Когда возвращаешься, называешь номерок — гардеробщик сразу идёт к нужной вешалке, а не перебирает все пальто подряд.

## 2. Как хеш-таблица устроена изнутри

Чтобы понимать _подводные камни_, важно знать механизм под капотом (даже если в JS ты не будешь реализовывать это руками).

### 2.1 Хеш-функция

**Хеш-функция** превращает ключ (строку, число, объект) в число — индекс ячейки массива, где будет храниться значение.

```
hash("apple") → 42
```

Требования к хорошей хеш-функции:

- **Детерминированность** — один и тот же ключ всегда даёт один и тот же хеш.
- **Быстрота вычисления**.
- **Равномерное распределение** — чтобы разные ключи не скапливались в одних и тех же ячейках.

Пример упрощённой хеш-функции для строк:

```js
const simpleHash = (str, tableSize) => {
  let hash = 0;
  for (let i = 0; i < str.length; i++) {
    hash = (hash * 31 + str.charCodeAt(i)) % tableSize;
  }
  return hash;
};

console.log(simpleHash("apple", 100)); // например, 47
```

### 2.2 Коллизии

**Коллизия** — ситуация, когда два разных ключа дают один и тот же хеш (попадают в одну ячейку). Это неизбежно (см. [принцип Дирихле](https://ru.wikipedia.org/wiki/Принцип_Дирихле)) — ключей может быть бесконечно много, а ячеек — конечное число.

Два основных способа решения коллизий:

**Метод цепочек (Separate Chaining)** — в каждой ячейке хранится не одно значение, а список (или мини-массив) пар ключ-значение. Если два ключа попали в одну ячейку — они просто оба лежат в этом списке.

```
Ячейка #47: [("apple", 10), ("banana", 3)]
```

**Открытая адресация (Open Addressing)** — если ячейка занята, алгоритм ищет следующую свободную по определённому правилу (линейное пробирование, двойное хеширование и т.д.).

> Именно движки JavaScript (V8, SpiderMonkey) внутри используют похожие техники для реализации `Object` и `Map` — но это уже детали конкретной реализации, не специфицированные стандартом ECMAScript напрямую.

### 2.3 Изменение размера (rehashing)

Когда таблица заполняется (обычно больше ~70% — это называется **load factor**), происходит **рехеширование**: создаётся новый, больший массив, и все элементы пересчитываются и перекладываются заново. Это дорогая операция (O(n)), но она случается редко, поэтому _в среднем_ (amortized) вставка остаётся O(1).

## 3. Hash Map в JavaScript: Object vs Map

В JS есть два основных инструмента для хеш-таблиц.

### 3.1 Обычный объект `{}`

```js
const freq = {};
freq["apple"] = 1;
freq["apple"]++;
console.log(freq); // { apple: 2 }
```

### 3.2 `Map` (ES6+)

```js
const freq = new Map();
freq.set("apple", 1);
freq.set("apple", (freq.get("apple") || 0) + 1);
console.log(freq); // Map(1) { 'apple' => 2 }
```

### 3.3 Сравнение

| Критерий                                | `Object`                                                                                                                             | `Map`                                              |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------- |
| Тип ключей                              | только строки и символы (числа/объекты приводятся к строке)                                                                          | **любой тип**: числа, объекты, функции, NaN и т.д. |
| Порядок обхода                          | не гарантирован строго (хотя на практике движки часто сохраняют порядок, кроме числовых ключей — они идут первыми и по возрастанию!) | **гарантированно** порядок вставки                 |
| Размер                                  | нет встроенного свойства, надо `Object.keys(obj).length`                                                                             | `map.size`                                         |
| Наследование                            | есть цепочка прототипов — риск конфликтов с `toString`, `hasOwnProperty` и т.д.                                                      | нет прототипных ключей, чистая структура           |
| Производительность на частых add/delete | хуже                                                                                                                                 | **лучше**, особенно на больших объёмах             |
| Итерация                                | `for...in`, `Object.keys/values/entries`                                                                                             | нативно итерируемый: `for...of`, `.forEach()`      |
| JSON                                    | `JSON.stringify` работает "из коробки"                                                                                               | нужно сначала конвертировать в объект/массив       |

**Правило выбора:**

- Нужен JSON, простая конфигурация, ключи всегда строки → `Object`.
- Нужны нечисловые/непредсказуемые ключи, частые вставки/удаления, важен порядок, нужен точный размер → `Map`.

Для частотного словаря **оба варианта рабочие**, но `Map` считается более "безопасным" выбором по умолчанию в современном JS.

## 4. Частотный словарь: что это и зачем

**Частотный словарь (frequency map / frequency counter)** — это применение хеш-таблицы, где:

- **ключ** — элемент, который мы считаем (символ, слово, число, объект);
- **значение** — сколько раз этот элемент встретился.

### Зачем он нужен

- Найти самый часто встречающийся элемент (мода).
- Проверить, являются ли две строки анаграммами.
- Найти первый неповторяющийся символ.
- Посчитать частоту слов в тексте (word count, как в поиске или NLP).
- Найти дубликаты за один проход.
- Решить задачи вроде "Two Sum", "Group Anagrams", "Top K Frequent Elements".

### Общий паттерн построения

```js
const buildFrequencyMap = (items) => {
  const freq = new Map();
  for (const item of items) {
    freq.set(item, (freq.get(item) || 0) + 1);
  }
  return freq;
};
```

Этот паттерн — **один проход по данным (O(n)) вместо вложенных циклов (O(n²))**. Это ключевая идея, ради которой вообще используют хеш-таблицы в алгоритмах.

## 5. Практика: считаем частоту символов, слов, чисел

### 5.1 Частота символов в строке

```js
const charFrequency = (str) => {
  const freq = new Map();
  for (const char of str) {
    freq.set(char, (freq.get(char) || 0) + 1);
  }
  return freq;
};

console.log(charFrequency("banana"));
// Map(3) { 'b' => 1, 'a' => 3, 'n' => 2 }
```

> Обратите внимание: используется `for...of`, а не `for (let i = 0; ...)`, потому что `for...of` корректно работает с **суррогатными парами Unicode** (эмодзи, некоторые иероглифы), а индексация по `.charAt(i)` может разрезать символ пополам. Подробнее — в разделе "Подводные камни".

### 5.2 Частота слов в тексте

```js
const wordFrequency = (text) => {
  const words = text
    .toLowerCase()
    .replace(/[.,!?;:()"']/g, "") // убираем пунктуацию
    .split(/\s+/) // разбиваем по пробелам
    .filter(Boolean); // убираем пустые строки

  const freq = new Map();
  for (const word of words) {
    freq.set(word, (freq.get(word) || 0) + 1);
  }
  return freq;
};

const text = "Кот сидел на окне. Кот смотрел на птиц, а кот мурлыкал.";
console.log(wordFrequency(text));
// Map(6) { 'кот' => 3, 'сидел' => 1, 'на' => 2, 'окне' => 1, 'смотрел' => 1, 'птиц' => 1, 'а' => 1, 'мурлыкал' => 1 }
```

### 5.3 Частота чисел в массиве

```js
const numberFrequency = (arr) => {
  const freq = new Map();
  for (const num of arr) {
    freq.set(num, (freq.get(num) || 0) + 1);
  }
  return freq;
};

console.log(numberFrequency([1, 2, 2, 3, 3, 3, 4]));
// Map(4) { 1 => 1, 2 => 2, 3 => 3, 4 => 1 }
```

### 5.4 Более компактная запись через reduce

```js
const freq = [..."banana"].reduce((acc, char) => {
  acc[char] = (acc[char] || 0) + 1;
  return acc;
}, {});

console.log(freq); // { b: 1, a: 3, n: 2 }
```

### 5.5 Поиск самого частого элемента

```js
const mostFrequent = (arr) => {
  const freq = new Map();
  let maxItem = null;
  let maxCount = 0;

  for (const item of arr) {
    const count = (freq.get(item) || 0) + 1;
    freq.set(item, count);

    if (count > maxCount) {
      maxCount = count;
      maxItem = item;
    }
  }

  return { item: maxItem, count: maxCount };
};

console.log(mostFrequent(["a", "b", "a", "c", "a", "b"]));
// { item: 'a', count: 3 }
```

Ключевая идея: считать максимум **прямо во время построения словаря**, а не отдельным проходом после — это экономит один полный обход массива.

## 6. Сложность алгоритма (Big O)

| Операция                                     | Массив (без хеш-таблицы) | Hash Map (в среднем) | Hash Map (худший случай) |
| -------------------------------------------- | ------------------------ | -------------------- | ------------------------ |
| Поиск по ключу                               | O(n)                     | **O(1)**             | O(n)                     |
| Вставка                                      | O(1) (в конец)           | **O(1)**             | O(n)                     |
| Удаление                                     | O(n)                     | **O(1)**             | O(n)                     |
| Построение частотного словаря из n элементов | —                        | **O(n)**             | O(n²)                    |

**Почему бывает "худший случай" O(n)?**
Если хеш-функция плохая или специально подобрана атакующим (так называемая **hash flooding атака**), очень много ключей могут попасть в одну ячейку. Тогда поиск внутри этой ячейки превращается в линейный перебор списка — O(n). Современные движки JS защищаются от этого, подмешивая случайное "зерно" (seed) в хеш-функцию при старте процесса, так что предсказать коллизии заранее почти невозможно.

**Важно понимать компромисс:**
Использование частотного словаря почти всегда превращает задачу с наивной сложностью **O(n²)** (вложенные циклы "для каждого элемента проверить все остальные") в задачу со сложностью **O(n)**, но за счёт **дополнительной памяти O(n)** — это классический trade-off "время за память" (time-memory tradeoff).

## 7. Подводные камни

Это самая важная часть для новичка — именно здесь чаще всего возникают баги.

### 7.1 Ключи в Object — это всегда строки

```js
const obj = {};
obj[1] = "число";
obj["1"] = "строка";
console.log(obj); // { '1': 'строка' } — они перезаписали друг друга!
```

Число `1` было автоматически приведено к строке `"1"`. В `Map` этого не происходит:

```js
const map = new Map();
map.set(1, "число");
map.set("1", "строка");
console.log(map.size); // 2 — это разные ключи
```

### 7.2 Опасные "встроенные" ключи в Object

```js
const freq = {};
console.log(freq["toString"]); // function toString() {...} — не undefined!
console.log(freq["constructor"]); // тоже не undefined
```

Это происходит из-за **цепочки прототипов**: обычный `{}` наследуется от `Object.prototype`, где уже есть методы `toString`, `hasOwnProperty`, `constructor` и т.д. Если считать частоту слов и среди них случайно окажется слово `"constructor"`, можно получить неожиданный баг.

**Решения:**

```js
// Вариант 1: объект без прототипа
const freq = Object.create(null);
console.log(freq["toString"]); // undefined — безопасно

// Вариант 2: использовать Map (там нет этой проблемы вообще)
const freq = new Map();

// Вариант 3: проверять hasOwnProperty
if (Object.prototype.hasOwnProperty.call(freq, key)) { ... }

// Вариант 4 (современный, ES2022+): безопасный оператор in
if (key in freq) { ... } // тоже покажет true для "toString"!
// поэтому лучше — Object.hasOwn(freq, key)
if (Object.hasOwn(freq, key)) { ... }
```

Из-за всех этих нюансов **`Map` считается более безопасным выбором по умолчанию** для частотных словарей.

### 7.3 `NaN` как ключ

```js
console.log(NaN === NaN); // false — обычное сравнение не работает

const map = new Map();
map.set(NaN, "значение");
console.log(map.get(NaN)); // "значение" — Map использует SameValueZero, а не === !
```

`Map` (и `Set`) используют алгоритм сравнения **SameValueZero**, который считает `NaN` равным самому себе (в отличие от `===`). Это удобно и предсказуемо — в отличие от массивов и `Object`, где `NaN` как ключ превращается в строку `"NaN"`.

### 7.4 `+0` и `-0`

```js
const map = new Map();
map.set(-0, "минус ноль");
console.log(map.get(0)); // "минус ноль" — они считаются одним ключом
```

SameValueZero также считает `+0` и `-0` **одним и тем же ключом** (в отличие от `Object.is(+0, -0)`, который различает их).

### 7.5 Объекты как ключи — сравнение по ссылке, не по содержимому

```js
const map = new Map();
map.set({ id: 1 }, "первый");
map.set({ id: 1 }, "второй"); // это ДРУГОЙ объект в памяти!

console.log(map.size); // 2, а не 1!
```

Даже если содержимое объектов одинаковое, `Map` сравнивает ключи-объекты **по ссылке**. Если нужно использовать "содержимое" объекта как ключ, надо явно сериализовать его:

```js
const freq = new Map();
const key = (obj) => JSON.stringify(obj);
freq.set(key({ id: 1 }), (freq.get(key({ id: 1 })) || 0) + 1);
```

### 7.6 Итерация по строкам с эмодзи и суррогатными парами

```js
const str = "👨‍👩‍👧‍👦"; // семья — это несколько символов, склеенных ZWJ

console.log(str.length); // 11 (!), а не 1

for (let i = 0; i < str.length; i++) {
  console.log(str[i]); // выдаст "битые" полусимволы
}

for (const char of str) {
  console.log(char); // работает лучше, но составные эмодзи всё равно могут разбиться на части
}
```

Для полностью корректной работы с "визуальными символами" (графемами) нужен `Intl.Segmenter`:

```js
const segmenter = new Intl.Segmenter("ru", { granularity: "grapheme" });
const graphemes = [...segmenter.segment("👨‍👩‍👧‍👦")].map((s) => s.segment);
console.log(graphemes.length); // 1 — теперь правильно
```

### 7.7 Регистр букв и "невидимые" различия

```js
wordFrequency("Кот КОТ кот");
// без .toLowerCase() это будут 3 РАЗНЫХ ключа: "Кот", "КОТ", "кот"
```

Также стоит помнить про **юникод-нормализацию** — визуально одинаковые строки могут быть разными наборами кодовых точек (например, "é" как один символ vs "e" + диакритический знак):

```js
const a = "é"; // U+00E9
const b = "e\u0301"; // "e" + U+0301 (combining acute accent)
console.log(a === b); // false!
console.log(a.normalize() === b.normalize()); // true
```

Для текстовых частотных словарей полезно вызывать `.normalize()` перед подсчётом.

### 7.8 Изменение объекта, использованного как ключ Map

```js
const map = new Map();
const keyObj = { id: 1 };
map.set(keyObj, "значение");

keyObj.id = 999; // изменили объект уже ПОСЛЕ того, как он стал ключом

console.log(map.get(keyObj)); // "значение" — всё ещё находится!
// Потому что ключ хранится по ссылке, а не по "слепку" содержимого
```

Это не баг, но частый источник путаницы: если ты ожидал, что старое "содержимое" ключа сохранится где-то отдельно — нет, ссылка остаётся той же.

### 7.9 `delete` в Object vs Map — производительность

```js
delete obj[key]; // может быть медленнее и переводит объект в "медленный режим" в V8
map.delete(key); // оптимизировано специально под такие операции
```

Движки JS (например, V8) оптимизируют объекты, ожидая, что набор их ключей стабилен ("скрытые классы" / hidden classes). Частые `delete` из обычных объектов могут ухудшать производительность, тогда как `Map` изначально проектировался под динамичные структуры с частыми добавлениями/удалениями.

### 7.10 Порядок ключей в Object — не всегда "как добавили"

```js
const obj = { b: 1, 2: "два", a: 3, 1: "один" };
console.log(Object.keys(obj)); // ['1', '2', 'b', 'a']
```

Числовые (точнее — "похожие на индексы массива") ключи **всегда выводятся первыми и по возрастанию**, независимо от порядка добавления, а строковые — в порядке вставки. Это специфика спецификации ECMAScript (`[[OwnPropertyKeys]]`), про которую часто забывают. `Map`, в отличие от `Object`, **всегда** сохраняет строгий порядок вставки для всех типов ключей.

## 8. Классические задачи с решениями

### 8.1 Two Sum (найти два числа с заданной суммой)

Наивное решение — O(n²) (вложенные циклы). С частотным/индексным словарём — O(n):

```js
const twoSum = (nums, target) => {
  const seen = new Map(); // значение -> индекс

  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];
    if (seen.has(complement)) {
      return [seen.get(complement), i];
    }
    seen.set(nums[i], i);
  }
  return null;
};

console.log(twoSum([2, 7, 11, 15], 9)); // [0, 1]
```

### 8.2 Проверка анаграммы

```js
const isAnagram = (a, b) => {
  if (a.length !== b.length) return false;

  const freq = new Map();
  for (const char of a) {
    freq.set(char, (freq.get(char) || 0) + 1);
  }
  for (const char of b) {
    if (!freq.has(char)) return false;
    freq.set(char, freq.get(char) - 1);
    if (freq.get(char) === 0) freq.delete(char);
  }
  return freq.size === 0;
};

console.log(isAnagram("листок", "столик")); // true
console.log(isAnagram("кот", "кит")); // false
```

### 8.3 Первый неповторяющийся символ

```js
const firstUniqueChar = (str) => {
  const freq = new Map();
  for (const char of str) {
    freq.set(char, (freq.get(char) || 0) + 1);
  }
  for (const char of str) {
    if (freq.get(char) === 1) return char;
  }
  return null;
};

console.log(firstUniqueChar("swiss")); // 'w'
```

### 8.4 Group Anagrams (группировка анаграмм)

```js
const groupAnagrams = (words) => {
  const groups = new Map();

  for (const word of words) {
    const key = [...word].sort().join(""); // "отсортированная" версия слова как ключ
    if (!groups.has(key)) groups.set(key, []);
    groups.get(key).push(word);
  }

  return [...groups.values()];
};

console.log(groupAnagrams(["кот", "ток", "окт", "рот", "торт"]));
// [ [ 'кот', 'ток', 'окт' ], [ 'рот' ], [ 'торт' ] ]
```

### 8.5 Top K Frequent Elements (топ-K частых элементов)

```js
const topKFrequent = (arr, k) => {
  const freq = new Map();
  for (const item of arr) {
    freq.set(item, (freq.get(item) || 0) + 1);
  }

  return [...freq.entries()]
    .sort((a, b) => b[1] - a[1]) // сортировка по частоте, по убыванию
    .slice(0, k)
    .map(([item]) => item);
};

console.log(topKFrequent([1, 1, 1, 2, 2, 3], 2)); // [1, 2]
```

> Для по-настоящему больших данных сортировку всего массива (O(n log n)) заменяют на **min-heap** размера k (O(n log k)) — но для большинства практических и учебных задач сортировки достаточно.

### 8.6 Наличие дубликатов за один проход

```js
const hasDuplicates = (arr) => {
  const seen = new Set(); // Set — частный случай Map, где важен только факт наличия ключа
  for (const item of arr) {
    if (seen.has(item)) return true;
    seen.add(item);
  }
  return false;
};

console.log(hasDuplicates([1, 2, 3, 2])); // true
```

## 9. Шпаргалка

```js
// Создание
const freq = new Map();

// Добавление / инкремент — главный паттерн
freq.set(key, (freq.get(key) || 0) + 1);

// Проверка наличия
freq.has(key);

// Получение значения (undefined, если нет ключа)
freq.get(key);

// Удаление
freq.delete(key);

// Размер
freq.size;

// Перебор
for (const [key, value] of freq) { ... }
freq.forEach((value, key) => { ... });

// В массивы
[...freq.keys()];
[...freq.values()];
[...freq.entries()];

// Сортировка по частоте (по убыванию)
[...freq.entries()].sort((a, b) => b[1] - a[1]);
```

**Когда использовать хеш-таблицу / частотный словарь:**

- нужно быстро проверять "было / не было" (наличие элемента);
- нужно считать количество повторений;
- задача выглядит как "для каждого элемента найти пару / проверить условие среди остальных" — почти всегда это можно свести к O(n) через словарь вместо O(n²) вложенных циклов.
