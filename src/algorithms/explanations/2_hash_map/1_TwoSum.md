# Two Sum — разбор задачи

## Какой алгоритм используется

**Hash Map (хеш-таблица) / One-pass Hash Table**

Иногда этот же подход в контексте задач с массивами называют вариацией паттерна
"Two Pointers" (два указателя), но именно для Two Sum на *неотсортированном* массиве
классическое и самое эффективное решение — это использование хеш-таблицы (`Map`),
а не двух указателей. Two Pointers хорошо подходит, если массив **отсортирован**
(тогда можно двигать указатели с двух концов), но в оригинальной задаче массив
не отсортирован, и сортировка "сломает" исходные индексы, которые нужно вернуть.
Поэтому здесь используется именно **хеш-таблица**.

## Суть задачи

Дан массив чисел и целевое число `target`. Нужно найти два числа в массиве,
сумма которых равна `target`, и вернуть их **индексы**.

Ограничения:
- Ответ существует и единственный.
- Нельзя дважды использовать один и тот же элемент.
- Порядок индексов в ответе не важен.

## Наивное решение (для понимания)

Самый простой способ — перебрать все пары чисел (два вложенных цикла) и
проверить, не равна ли их сумма `target`.

- Время: **O(n²)** — для каждого элемента перебираем все остальные.
- Память: **O(1)**.

Это работает, но медленно на больших массивах. LeetCode прямо просит
предложить решение быстрее, чем O(n²) — отсюда и решение через хеш-таблицу.

## Оптимальное решение — разбор пошагово

Идея: пока идём по массиву **один раз**, для каждого числа `nums[i]` вычисляем,
какое число нам "не хватает" до `target` — это `complement = target - nums[i]`.

Если это недостающее число мы **уже видели раньше** и сохранили в хеш-таблицу —
значит, мы нашли пару! Если ещё не видели — сохраняем текущее число и его индекс
в хеш-таблицу и идём дальше.

```js
const twoSum = (nums, target) => {
  // map хранит пары "число -> его индекс", которые мы уже прошли
  const map = new Map();

  for (let i = 0; i < nums.length; i++) {
    // Какое число нужно найти, чтобы в сумме с nums[i] получить target
    const complement = target - nums[i];

    // Если это число уже встречалось раньше — пара найдена
    if (map.has(complement)) {
      return [map.get(complement), i];
    }

    // Иначе запоминаем текущее число и его индекс для будущих проверок
    map.set(nums[i], i);
  }

  return [];
};
```

### Трассировка на примере `nums = [2, 7, 11, 15], target = 9`

| i | nums[i] | complement (9 - nums[i]) | map.has(complement)? | Действие |
|---|---------|--------------------------|------------------------|----------|
| 0 | 2       | 7                        | нет                    | сохраняем `{2: 0}` |
| 1 | 7       | 2                        | да (2 → индекс 0)      | возвращаем `[0, 1]` |

Готово — нашли ответ за один проход по массиву.

## Сложность

- **Время: O(n)** — проходим по массиву один раз, а поиск и вставка в `Map`
  выполняются в среднем за O(1).
- **Память: O(n)** — в худшем случае храним в `Map` почти все элементы массива.

Это и есть выигрыш по сравнению с наивным O(n²) решением — мы жертвуем
дополнительной памятью ради ускорения по времени.

## Почему `Map`, а не обычный объект `{}`

- `Map` в JavaScript спроектирован специально для частых вставок/поисков по ключу
  и корректно работает с ключами-числами (объект `{}` превращает ключи в строки).
- Методы `.has()` и `.get()` у `Map` быстрые (в среднем O(1)) и явно выражают намерение.
