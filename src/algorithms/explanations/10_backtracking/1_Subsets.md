# Разбор задачи: Subsets (Все подмножества)

Источник: [leetcode.com/problems/subsets](https://leetcode.com/problems/subsets/)
Уровень сложности на LeetCode: **Medium**

---

## 1. Какой алгоритм используется

**Backtracking (перебор с возвратом)**, также его можно назвать вариацией **DFS (поиска в глубину) по дереву решений**.

Идея: на каждом шаге у нас есть два варианта для очередного элемента массива — либо **включить** его в текущее подмножество, либо **пропустить**. Перебирая все такие варианты и "откатывая" выбор после каждой ветки, мы получаем абсолютно все возможные подмножества.

---

## 2. Суть задачи простыми словами

Дан массив чисел, в котором нет повторяющихся значений, например `[1, 2, 3]`.

Нужно вывести **все возможные наборы**, которые можно составить из элементов этого массива, где:
- набор может быть **пустым** (`[]`);
- набор может состоять из **одного** элемента (`[1]`, `[2]`, `[3]`);
- набор может состоять из **нескольких** элементов (`[1,2]`, `[1,3]` и т.д.);
- набор может включать **все** элементы сразу (`[1,2,3]`).

Такой полный список всех наборов называется **множеством всех подмножеств** или **булеаном** (power set). Если исходный массив содержит `n` элементов, то всего подмножеств будет `2^n` — потому что для каждого из `n` элементов есть ровно 2 состояния: "включён" или "не включён", и эти состояния независимы друг от друга.

Для `[1, 2, 3]` (n = 3): всего `2³ = 8` подмножеств:

```
[], [1], [2], [1,2], [3], [1,3], [2,3], [1,2,3]
```

Порядок подмножеств в ответе не важен — главное, чтобы все они присутствовали и ни одно не повторялось.

---

## 3. Разбор решения

### 3.1. Идея через дерево решений

Представим процесс построения подмножеств как дерево, где на каждом уровне мы решаем: "добавить в набор следующий по порядку элемент или нет".

```
                         []
              /      |        \
           [1]      [2]       [3]
          /    \        \
      [1,2]  [1,3]     [2,3]
        |
    [1,2,3]
```

Каждый узел этого дерева — это уже **готовое** подмножество (в отличие, например, от задачи "перестановки", где ответ появляется только в листьях дерева). Поэтому мы сохраняем текущий набор `path` в результат **на каждом шаге рекурсии**, а не только в конце.

Чтобы не получить одинаковые подмножества в разном порядке (например, `[1,2]` и `[2,1]` — это один и тот же набор), на каждом уровне рекурсии мы перебираем элементы **только начиная с текущей позиции и правее** — это гарантирует, что каждое подмножество будет построено ровно один раз.

### 3.2. Пошаговый код с комментариями

```javascript
const subsets = (nums) => {
  // result — сюда складываем все найденные подмножества
  const result = [];

  // path — текущее "строящееся" подмножество на этом шаге рекурсии
  const path = [];

  const backtrack = (start) => {
    // Каждый узел дерева решений — уже готовое подмножество,
    // поэтому сохраняем КОПИЮ path в результат на каждом вызове.
    // Копия обязательна: path будет и дальше меняться (push/pop),
    // а без spread-оператора в result попала бы ссылка на один и тот же массив.
    result.push([...path]);

    // Перебираем элементы массива начиная с индекса start —
    // это не даёт создавать дубликаты подмножеств вроде [1,2] и [2,1]
    for (let i = start; i < nums.length; i++) {
      // Choice: включаем nums[i] в текущий набор
      path.push(nums[i]);

      // Рекурсивно идём дальше, начиная со следующего индекса (i + 1),
      // потому что каждый элемент можно использовать только один раз
      backtrack(i + 1);

      // Backtrack: отменяем выбор перед тем, как попробовать
      // следующий вариант в цикле — "стираем" последний добавленный элемент
      path.pop();
    }
  };

  // Стартуем с пустого набора и индекса 0
  backtrack(0);

  return result;
};
```

### 3.3. Трассировка на примере `[1, 2, 3]`

| Шаг | `path` (текущий набор) | Действие | Что попало в `result` |
|---|---|---|---|
| 1 | `[]` | вход в backtrack(0) | `[]` |
| 2 | `[1]` | push(1), backtrack(1) | `[1]` |
| 3 | `[1,2]` | push(2), backtrack(2) | `[1,2]` |
| 4 | `[1,2,3]` | push(3), backtrack(3) | `[1,2,3]` |
| 5 | `[1,2]` | pop() — откат после шага 4 | — |
| 6 | `[1,3]` | pop() до `[1]`, затем push(3) | `[1,3]` |
| 7 | `[1]` | pop() — откат | — |
| 8 | `[]` | pop() — откат до пустого набора | — |
| 9 | `[2]` | push(2), backtrack(2) | `[2]` |
| ... | ... | и так далее для веток с 2 и 3 | ... |

В итоге получаем все 8 подмножеств.

---

## 4. Почему это решение соответствует условиям задания

- **Без `class`** — используется обычная стрелочная функция `subsets`, а вспомогательная рекурсивная функция `backtrack` объявлена как стрелочная функция внутри неё (замыкание на `result` и `path`).
- **Без `if / else` с отрицанием** — в решении вообще нет конструкций с `!`; условие цикла `for` формулируется в положительной форме (`i < nums.length`).
- **Без тернарного оператора** — логика построена на прямом изменении массива (`push` / `pop`), без `condition ? a : b`.
- **Без `??` и `??=`** — в решении нет обращения к возможно `undefined`/`null` значениям, поэтому эти операторы и не требуются.
- **Современный синтаксис** — стрелочные функции, `const`, spread-оператор (`[...path]`) для копирования массива.

---

## 5. Сложность алгоритма

- **Время:** `O(n · 2ⁿ)` — всего существует `2ⁿ` подмножеств, и на каждое в среднем тратится `O(n)` времени на копирование массива (`[...path]`).
- **Память:** `O(n · 2ⁿ)` — именно столько занимает хранение всех подмножеств в `result` (плюс `O(n)` на глубину стека рекурсии).

---

## 6. Альтернативный способ (для общего развития)

Тот же результат можно получить **без рекурсии**, через побитовую маску: перебрать все числа от `0` до `2ⁿ - 1`, и для каждого числа посмотреть, какие биты в нём включены — эти позиции и войдут в очередное подмножество. Это более компактный, но менее наглядный для новичка способ, поэтому в решении выше выбран классический backtracking — он лучше показывает саму технику перебора с возвратом.
