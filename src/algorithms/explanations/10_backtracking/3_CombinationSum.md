# Combination Sum — разбор задачи

Источник: https://leetcode.com/problems/combination-sum/ (задача №39, сложность Medium)

## Какой алгоритм используется

**Backtracking (поиск с возвратом / бэктрекинг)**.

Это алгоритм полного перебора вариантов, но "умного": мы строим решение шаг за шагом
(добавляем число в текущий набор), и как только видим, что дальше двигаться в эту
сторону бессмысленно (например, сумма уже превысила target), мы "откатываемся" назад
(убираем последнее добавленное число) и пробуем другой вариант.

Проще говоря: это как проходить лабиринт — идём вперёд, если уперлись в тупик,
возвращаемся к последней развилке и идём другим путём.

## В чём суть задачи

Дан массив уникальных чисел `candidates` и число `target`. Нужно найти все возможные
наборы чисел из `candidates`, которые в сумме дают `target`.

Особенности:
- Одно и то же число можно брать несколько раз подряд (например `candidates = [2]`,
  число 2 можно использовать хоть 10 раз, если это нужно для суммы).
- Наборы `[2,2,3]` и `[2,3]` — разные, потому что в них разное количество двоек.
- Порядок чисел внутри набора и порядок самих наборов в ответе не важен.

## Идея решения

Представим это как дерево решений: на каждом шаге мы выбираем — берём мы очередное
число из `candidates` ещё раз или переходим к следующему числу в массиве.

Чтобы не получать дубликаты вроде `[2,3]` и `[3,2]`, мы всегда двигаемся по массиву
"только вперёд" — то есть если взяли число с индексом `i`, то на следующем шаге можем
снова взять число с индексом `i` (оно же ещё раз) или любое число с индексом больше `i`,
но не с индексом меньше.

Условия остановки (базовые случаи рекурсии):
1. Если оставшаяся сумма (`remaining`) стала равна `0` — набор найден, сохраняем его.
2. Если оставшаяся сумма стала меньше `0` — этот путь не подходит, прекращаем его
   исследовать (числа только положительные, дальше сумма будет ещё больше).

## Пошаговый разбор кода

```js
const combinationSum = (candidates, target) => {
  const result = [];   // сюда складываем все найденные наборы
  const current = [];  // текущий набор чисел, который мы сейчас собираем

  const backtrack = (start, remaining) => {
    // remaining — сколько ещё нужно "набрать" до target

    if (remaining === 0) {
      // сумма сошлась — нашли рабочий набор,
      // копируем current (через спред), чтобы дальнейшие изменения
      // current не повлияли на уже сохранённый результат
      result.push([...current]);
      return;
    }

    if (remaining < 0) {
      // "перебрали" сумму — этот путь никуда не ведёт, откатываемся
      return;
    }

    // перебираем числа начиная с индекса start (а не с 0!),
    // чтобы не получать перестановки одного и того же набора
    for (let i = start; i < candidates.length; i++) {
      current.push(candidates[i]);           // пробуем взять число
      backtrack(i, remaining - candidates[i]); // идём глубже; i (не i+1),
                                                 // т.к. число можно повторять
      current.pop();                          // откат: убираем число,
                                                 // чтобы попробовать следующий вариант
    }
  };

  backtrack(0, target);
  return result;
};
```

### Разбор на примере `candidates = [2,3,6,7], target = 7`

1. Начинаем с `current = []`, `remaining = 7`.
2. Берём `2` → `current = [2]`, `remaining = 5`.
3. Берём `2` ещё раз → `current = [2,2]`, `remaining = 3`.
4. Берём `3` → `current = [2,2,3]`, `remaining = 0` → набор `[2,2,3]` сохранён.
5. Откатываемся, пробуем другие ветки: `[2,2,6]` → remaining станет отрицательным,
   отбрасываем. `[2,2,7]` — аналогично.
6. В итоге, перебрав все ветки дерева, получаем `[[2,2,3],[7]]`.

## Сложность алгоритма

- Точную сложность по времени сложно выразить простой формулой (зависит от количества
  найденных комбинаций), но грубо она экспоненциальная: `O(candidates.length ^ (target / min(candidates)))`.
- Память: `O(target / min(candidates))` на глубину рекурсии + место под сам результат.

Для ограничений задачи (`target <= 40`, `candidates[i] >= 2`) это вполне приемлемо.
