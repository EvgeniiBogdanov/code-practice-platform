# Разбор задачи: «Оператор satisfies»

## 1. Что дано

Объект маршрутов аннотирован типом `Routes` с индексной сигнатурой. Аннотация проверяет каждый маршрут, но **заменяет** тип переменной объявленным. Для TypeScript `routes` — словарь с любыми строковыми ключами, поэтому:

- `routes.profle` — не ошибка, а `Route`;
- компилятор «забыл», какие маршруты на самом деле есть.

## 2. Что нужно получить

Две вещи одновременно: проверку соответствия `Routes` и точный тип самого объекта.

## 3. Три способа указать тип

| Запись | Проверяет значение | Тип переменной |
| --- | --- | --- |
| `const routes: Routes = {...}` | да | `Routes` — широкий |
| `const routes = {...} as Routes` | почти нет | `Routes` — широкий |
| `const routes = {...} satisfies Routes` | да | выведенный из литерала — точный |

`satisfies` (TypeScript 4.9) проверяет, что выражение соответствует типу, включая проверку лишних свойств, но оставляет тип выражения таким, каким его вывел компилятор.

## 4. Решение

```ts
const routes = {
  home: { path: "/" },
  profile: { path: "/profile", auth: true },
} satisfies Routes;
```

Тип `routes` теперь `{ home: { path: string }; profile: { path: string; auth: true } }`:

- `routes.profile.path` — `string`;
- `routes.profle` — ошибка: такого свойства нет;
- `{ path: 1 }` или `{ path: "/", role: "admin" }` внутри объекта — ошибка проверки `satisfies`.

Контекстный тип из `Routes` также помогает литералам: TypeScript подсказывает поля маршрута при вводе.

### Полный код

```ts
interface Route {
  path: string;
  auth?: boolean;
}

interface Routes {
  [name: string]: Route;
}

const routes = {
  home: { path: "/" },
  profile: { path: "/profile", auth: true },
} satisfies Routes;

const profilePath = routes.profile.path;
```

## 5. Типичный сценарий: as const satisfies

```ts
const routes = {
  home: { path: "/" },
  profile: { path: "/profile", auth: true },
} as const satisfies Routes;
```

`as const` сохраняет точные значения (`path: "/profile"`), `satisfies` проверяет форму. Так описывают конфиги, темы, словари переводов: данные проверены, а ключи и значения доступны с автодополнением.

## 6. Когда satisfies не подходит

- Если в объект потом будут добавляться ключи: `routes.settings = {...}` — ошибка, ведь тип точный.
- Если значение должно «скрыть» детали и наружу нужен именно широкий контракт, например публичный API модуля.

В этих случаях нужна обычная аннотация.

## 7. Частые ошибки

- Использовать `as Routes`, думая, что это проверка. `as` допускает и сужение, и расширение типа и не проверяет лишние поля.
- Путать порядок: `satisfies Routes as const` — синтаксическая ошибка. Сначала `as const`, потом `satisfies`.
- Ожидать, что `satisfies` изменит тип на `Routes`. Он ничего не меняет, только проверяет.

## 8. Что запомнить

Аннотация — «эта переменная имеет тип X», `satisfies` — «это значение соответствует X, но помни, какое оно на самом деле». Используйте `satisfies` для конфигураций, где важны и проверка, и точные ключи.
