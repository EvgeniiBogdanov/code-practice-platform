# Разбор задачи: «Первый дженерик»

## 1. Что дано

Три функции, которые работают с любыми данными. Без типов параметры неявно получают `any`, и результат тоже `any`: `first([1, 2, 3]).toUpperCase()` скомпилируется и упадёт во время выполнения.

## 2. Что нужно получить

| Вызов | Тип результата |
| --- | --- |
| `first([1, 2, 3])` | `number \| undefined` |
| `last(["a", "b"])` | `string \| undefined` |
| `wrapInArray({ id: 1 })` | `{ id: number }[]` |

## 3. Почему не any и не unknown

| Вариант | Что получится |
| --- | --- |
| `(items: any[]): any` | проверка отключена, ошибки не ловятся |
| `(items: unknown[]): unknown` | безопасно, но результат придётся снова проверять, хотя мы знаем, что передали числа |
| `<T>(items: T[]): T \| undefined` | тип результата связан с типом входа |

Параметр типа `T` — это «переменная для типа». При каждом вызове TypeScript выводит её из аргументов: для `[1, 2, 3]` — `number`, для `["a", "b"]` — `string`.

## 4. Решение по шагам

### Шаг 1. Объявить параметр типа

```ts
const first = <T>(items: readonly T[]): T | undefined => items[0];
```

`<T>` перед списком параметров объявляет параметр типа. Дальше он используется и в типе аргумента, и в типе результата — это и есть связь входа с выходом.

### Шаг 2. Честный тип результата

Массив может быть пустым, тогда `items[0]` вернёт `undefined`. Без флага `noUncheckedIndexedAccess` TypeScript считает, что `items[0]` имеет тип `T`, поэтому `| undefined` добавляем сами — это контракт функции.

### Шаг 3. readonly T[] во входных данных

Функции не меняют массив. `readonly T[]` принимает и обычные массивы, и `readonly`-массивы, например результат `as const`. Обычный `T[]` не принял бы `readonly`-массив, потому что у него нет `push`.

### Полный код

```ts
const first = <T>(items: readonly T[]): T | undefined => items[0];

const last = <T>(items: readonly T[]): T | undefined => items[items.length - 1];

const wrapInArray = <T>(value: T): T[] => [value];
```

## 5. Как TypeScript выводит T

При вызове `wrapInArray({ id: 1 })` компилятор сопоставляет тип аргумента `{ id: number }` с типом параметра `T`. Кандидат один, поэтому `T = { id: number }`, а результат — `{ id: number }[]`.

Параметр можно указать и явно: `first<number>([])`. Это нужно, когда выводить не из чего или вывод даёт не тот тип.

## 6. Частые ошибки

- Объявить параметр типа, который встречается только один раз: `<T>(value: T): void`. Такой дженерик ничего не связывает, достаточно `unknown`.
- Возвращать `T` для `first`, забыв про пустой массив.
- Использовать `T[]` и удивляться, что `readonly`-массив не подходит.
- В `.tsx`-файлах писать `<T>(x: T) => ...`: парсер примет это за JSX. Нужно `<T,>` или `<T extends unknown>`.

## 7. Что запомнить

Дженерик сохраняет связь между типами входа и выхода. Если параметр типа используется хотя бы в двух местах, он работает; если в одном — он не нужен.
