# Разбор задачи: «Опциональные и неизменяемые поля»

## 1. Что дано

Интерфейс `Person` описывает `id`, `name`, `middleName` и `age`. В исходном объекте отчество отсутствует, хотя интерфейс требует его. Ниже код пытается изменить `person.id` с `1` на `2`, хотя идентификатор должен сохраняться.

Это две независимые задачи: разрешить отсутствие одного поля и запретить запись в другое.

## 2. Что нужно получить

- Объект `{ id: 1, name: "Alice", age: 30 }` должен соответствовать `Person`.
- При наличии `middleName` его значением должна быть строка.
- Присваивание `person.id = 2` должно вызывать ошибку типов.
- Остальные поля сохраняют свои исходные требования.

## 3. Почему обходные решения не подходят

Можно добавить в объект `middleName: ""`, но это изменит данные вместо описания реального случая «отчества нет». Можно объявить поле как `middleName: string | undefined`, однако оно всё равно будет обязательным при создании объекта: его придётся явно указывать.

Объявление объекта через `const` тоже не решает задачу с идентификатором. Оно запрещает заменить саму переменную, а не изменить свойства хранящегося в ней объекта.

## 4. Решение по шагам

### Шаг 1. Сделать отчество необязательным

Знак вопроса ставится после имени свойства: `middleName?: string`. Теперь ключ можно пропустить. При чтении, если включён `strictNullChecks`, TypeScript учитывает оба случая и получает `string | undefined`.

### Шаг 2. Ограничить запись в идентификатор

Модификатор `readonly` перед полем разрешает задать `id` при создании объекта, но запрещает последующее присваивание через ссылку типа `Person`.

### Полный код

```ts
interface Person {
  readonly id: number;
  name: string;
  middleName?: string;
  age: number;
}

const person: Person = {
  id: 1,
  name: "Alice",
  age: 30,
};

// person.id = 2; // Ошибка: id доступно только для чтения.
```

## 5. Как работать с результатом

```ts
person.name = "Alicia";
person.age = 31;

const middleNameUpper = person.middleName?.toUpperCase();
const middleNameLabel = person.middleName ?? "Не указано";
```

Изменения `name` и `age` разрешены: `readonly` относится только к `id`. Опциональная цепочка `?.` вызывает метод, только если отчество задано. В нашем объекте `middleNameUpper` получится `undefined`, а `middleNameLabel` — `"Не указано"`.

Если объект содержит `middleName: "Ивановна"`, вызов метода даст `"ИВАНОВНА"`. Одна и та же функция чтения безопасно работает с обеими формами данных.

## 6. Важные детали и частые ошибки

- Не вызывайте `person.middleName.toUpperCase()` без обработки отсутствующего значения. Необязательное поле удобно при создании объекта, но требует внимания при чтении.
- `readonly` действует на этапе проверки типов и не вызывает `Object.freeze`. В скомпилированном JavaScript объект остаётся обычным объектом.
- Ограничение не означает глубокую неизменяемость: если поле с `readonly` содержит вложенный объект, его внутренние свойства автоматически не становятся неизменяемыми.
- Возможность явно записать `middleName: undefined` зависит от настройки `exactOptionalPropertyTypes`. Пропустить поле можно при любом её значении; это основной сценарий задачи.
- Удалять `id` из интерфейса нельзя: идентификатор по-прежнему обязателен, просто доступен только для чтения.

## 7. Что запомнить

`?` отвечает за возможность отсутствия свойства, а `readonly` — за возможность записи в него через данный тип. Эти модификаторы не подменяют друг друга и не меняют объект во время выполнения.
