# Разбор задачи: «Перечисление способов»

## 1. Что дано

Есть текущий статус заказа `"pending"` и функция `changeStatus`, которая выводит переданный статус. Нужно описать четыре состояния: ожидание, отправка, доставка и отмена.

Важная часть условия: набор должен быть доступен и как тип при разработке, и как объект со значениями при выполнении программы.

## 2. Что нужно получить

Нужны именованные значения `OrderStatus.Pending`, `OrderStatus.Shipped`, `OrderStatus.Delivered`, `OrderStatus.Cancelled`. Переменная `status` и параметр `newStatus` должны принимать значения этого перечисления.

| Член перечисления | Значение в JavaScript |
| --- | --- |
| `Pending` | `"pending"` |
| `Shipped` | `"shipped"` |
| `Delivered` | `"delivered"` |
| `Cancelled` | `"cancelled"` |

## 3. Почему одного type недостаточно

Объединение `"pending" | "shipped" | "delivered" | "cancelled"` ограничило бы допустимые строки. Но объявление `type` исчезает при компиляции: обратиться к его значениям через `OrderStatus.Pending` было бы невозможно.

Обычный строковый `enum` закрывает оба требования сразу. Альтернатива — объект с `as const` и отдельно выведенный из него тип, но для данного упражнения достаточно перечисления.

## 4. Решение по шагам

### Шаг 1. Задать читаемые имена и строковые значения

Каждому члену явно назначаем строку. Так статус удобно читать в логах и передавать во внешний код. Порядковые числа нам не нужны.

### Шаг 2. Применить перечисление как тип

В `const status: OrderStatus` имя стоит в позиции типа. В `OrderStatus.Pending` то же имя используется в выражении, чтобы получить конкретное значение.

### Полный код

```ts
enum OrderStatus {
  Pending = "pending",
  Shipped = "shipped",
  Delivered = "delivered",
  Cancelled = "cancelled",
}

const status: OrderStatus = OrderStatus.Pending;

const changeStatus = (newStatus: OrderStatus): void => {
  console.log(`Статус изменён на ${newStatus}`);
};
```

Возвращаемый тип `void` подходит, потому что функция только выводит сообщение.

## 5. Разбор использования

```ts
changeStatus(OrderStatus.Shipped);
// Статус изменён на shipped

const statuses = Object.values(OrderStatus);
// ["pending", "shipped", "delivered", "cancelled"]
```

В первом случае в функцию попадает строковое значение члена перечисления. Во втором JavaScript читает значения реально существующего объекта `OrderStatus`. Этот массив можно использовать, например, для списка вариантов в интерфейсе.

При этом `changeStatus("unknown")` не соответствует контракту. Даже строку `"shipped"` здесь следует передавать через `OrderStatus.Shipped`: строковый enum не равнозначен свободному объединению строковых литералов.

## 6. Важные детали и частые ошибки

- Не используйте `const enum` для этого сценария: его члены могут встраиваться в места использования, а условию нужен объект значений во время выполнения.
- У строкового enum нет автоматического обратного отображения «значение → имя», характерного для числовых enum. Здесь мы используем только прямой доступ.
- Перечисление ограничивает набор состояний, но не описывает разрешённые переходы. Правило «доставленный заказ нельзя снова отправить» потребовало бы отдельной логики.
- Название `changeStatus` не означает, что функция действительно меняет переменную `status`. В приведённом решении она только печатает сообщение, а `status` объявлен через `const`.
- Полученную из сети строку нельзя считать проверенным статусом только потому, что существует enum. Проверка внешних данных остаётся отдельной задачей.

## 7. Что запомнить

Обычный enum одновременно предоставляет тип и значения. Строковые члены делают результат понятным при выполнении, а аннотации параметров ограничивают использование перечисления в TypeScript-коде.
