# Разбор задачи: «Что за тип у переменной»

## 1. Что дано

Функция `formatId` должна принимать идентификатор в одном из двух видов: строку или число. Для строки нужно вернуть текст в верхнем регистре, для числа — строку с двумя знаками после десятичной точки.

В заготовке уже есть `toUpperCase()` и `toFixed(2)`, но отсутствуют тип параметра и условие выбора ветки.

## 2. Что нужно получить

| Вызов | Результат | Почему |
| --- | --- | --- |
| `formatId("ab-12")` | `"AB-12"` | Строка переводится в верхний регистр |
| `formatId(12)` | `"12.00"` | Число форматируется с двумя знаками |
| `formatId(0)` | `"0.00"` | Ноль тоже является числом |
| `formatId("12")` | `"12"` | Строка с цифрами остаётся строковым случаем |

Оба допустимых входных типа приводят к результату типа `string`.

## 3. Почему одного объединения недостаточно

После записи `id: string | number` TypeScript знает набор возможных типов, но ещё не знает конкретный вариант текущего вызова. Метод `toUpperCase` есть только у строки, а `toFixed` — только у числа. Вызвать их без уточнения типа небезопасно.

Утверждение `id as string` не решает проблему: оно ничего не проверит и не превратит число в строку. Нужна реальная проверка значения, понятная и JavaScript, и TypeScript.

## 4. Решение по шагам

### Шаг 1. Ограничить вход и результат

Параметр получает тип `string | number`, а результат — `string`. Тем самым функция не обещает принимать `null`, объекты или логические значения.

### Шаг 2. Сузить тип через typeof

Условие `typeof id === "string"` проверяет значение во время выполнения. TypeScript использует эту же проверку для **сужения типа**: внутри ветки `id` уже считается строкой.

### Полный код

```ts
const formatId = (id: string | number): string => {
  if (typeof id === "string") {
    return id.toUpperCase();
  }
  return id.toFixed(2);
};
```

### Шаг 3. Использовать ранний возврат

Строковая ветка завершается через `return`. Значит, до последней строки дойдёт только число. Дополнительный `else` не обязателен: анализ потока управления уже исключил строковый вариант.

## 5. Разбор двух вызовов «вживую»

Для `formatId("ab-12")` проверка возвращает `true`. Внутри `if` вызывается строковый метод, возвращается `"AB-12"`, и до `toFixed` выполнение не доходит.

Для `formatId(12)` проверка возвращает `false`. Ветка пропускается, число форматируется методом `toFixed(2)`, результат — `"12.00"`. Обратите внимание: этот метод возвращает строку, хотя вызывается у числа.

Именно проверка вместе с ранним возвратом объясняет, почему оба вызова методов безопасны.

## 6. Важные детали и частые ошибки

- `if (id)` проверяет истинность значения, а не его тип. Пустая строка и ноль оба ложные, поэтому такая проверка не разделит нужные случаи.
- Преобразование `String(id)` изменило бы логику: число `12` стало бы `"12"`, и требование двух десятичных знаков потерялось бы.
- Пишите `typeof id === "string"`, а не сравнение с `String`. Результат `typeof` — строка с названием типа.
- `number` включает `NaN` и бесконечности. Если предметная область допускает только конечные идентификаторы, понадобится отдельное правило; в условии упражнения его нет.
- При добавлении нового варианта во входное объединение нужно пересмотреть ветки. Без этого последний путь уже не обязательно будет числовым.

## 7. Что запомнить

Объединение описывает возможные входы, проверка `typeof` выбирает один из них, а ранний `return` помогает TypeScript понять оставшийся путь. Хорошая типизация здесь следует за реальной логикой функции.
