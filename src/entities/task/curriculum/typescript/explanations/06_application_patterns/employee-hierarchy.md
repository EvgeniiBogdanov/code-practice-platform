# Разбор задачи: «Иерархия сотрудников»

## 1. Что дано

Базовый класс `Employee` хранит имя и зарплату, а его метод `calculateBonus` возвращает `0`. Класс `Manager` наследует сотрудника и рассчитывает премию как `20%` зарплаты.

Но исходная модель разрешает создать обычного `Employee`, открыть зарплату снаружи и забыть написать настоящий расчёт премии у нового вида сотрудника.

## 2. Что нужно получить

- `Employee` задаёт общую основу, но не создаётся напрямую.
- `name` доступно снаружи.
- `salary` доступно внутри базового класса и наследников.
- Конкретный класс должен иметь реализацию `calculateBonus(): number`.
- `Manager` сохраняет формулу `salary * 0.2`.

## 3. Почему заглушка return 0 не решает задачу

Обычный метод с готовым телом наследуется автоматически. Новый класс мог бы забыть переопределить его и молча возвращать нулевую премию. Система типов не увидела бы ошибки: реализация уже есть.

Абстрактный метод описывает обязательство без тела. Пока оно не выполнено, класс не может стать конкретной реализацией, которую разрешено создавать.

Для зарплаты также нужен именно `protected`: `public` открыл бы её всем, а `private` не позволил бы `Manager` использовать поле напрямую.

## 4. Решение по шагам

### Шаг 1. Сделать основу абстрактной

`abstract class Employee` запрещает обычный вызов `new Employee(...)` в TypeScript-коде. Такой класс нужен для общей структуры и поведения наследников.

### Шаг 2. Объявить параметры-свойства

Модификаторы в конструкторе одновременно объявляют поля и присваивают им переданные значения. `public name: string` создаёт доступное имя, `protected salary: number` — защищённую зарплату.

Без сокращения пришлось бы отдельно объявить два поля и написать два присваивания через `this`.

### Шаг 3. Потребовать расчёт премии

`abstract calculateBonus(): number` содержит только сигнатуру. Класс `Manager` предоставляет тело с числовым результатом.

### Полный код

```ts
abstract class Employee {
  constructor(
    public name: string,
    protected salary: number
  ) {}

  abstract calculateBonus(): number;
}

class Manager extends Employee {
  calculateBonus(): number {
    return this.salary * 0.2;
  }
}

const manager = new Manager("Bob", 5000);
console.log(manager.calculateBonus());
```

## 5. Что происходит при создании Manager

1. `new Manager("Bob", 5000)` создаёт экземпляр наследника.
2. У `Manager` нет собственного конструктора, поэтому аргументы передаются конструктору базового класса.
3. В экземпляре появляются `name = "Bob"` и `salary = 5000`.
4. Вызов `calculateBonus()` находит метод `Manager`.
5. Метод читает доступное наследнику `this.salary` и возвращает `5000 * 0.2`, то есть `1000`.

Снаружи можно прочитать `manager.name` и вызвать `manager.calculateBonus()`. Прямое чтение `manager.salary` через этот тип запрещено модификатором доступа.

## 6. Как контракт помогает при добавлении сотрудника

Если создать `class Developer extends Employee` и не реализовать абстрактный метод, конкретный класс не выполнит требования основы. Нужно либо добавить расчёт, либо оставить сам `Developer` абстрактным.

При этом наследник уже конкретного `Manager` может унаследовать готовый расчёт. Абстрактный контракт требует наличия реализации в конкретном классе, но не обязывает каждый следующий уровень иерархии заново переписывать метод.

## 7. Важные детали и частые ошибки

- `protected` разрешает доступ базовому классу и наследникам, а не любому коду с экземпляром.
- `abstract` и модификаторы доступа TypeScript в основном задают ограничения проверки типов. Они сами по себе не являются защитой данных от произвольного JavaScript во время выполнения.
- Зарплата здесь не `readonly`: ограничение доступа и запрет изменения — разные требования.
- Если написать собственный конструктор `Manager`, в нём нужно вызвать `super(...)` до использования `this`.
- Метод премии возвращает `number`; вывод в консоль вынесен в вызывающий код. Это позволяет использовать результат дальше, например при расчёте выплаты.
- Для доступа в методе нужно `this.salary`. Просто `salary` означало бы поиск отдельной переменной в области видимости.

## 8. Что запомнить

Абстрактный класс задаёт общую основу, абстрактный метод — обязательную возможность, а `protected` предоставляет данные реализации наследникам. В этой задаче каждый механизм отвечает за отдельное требование.
