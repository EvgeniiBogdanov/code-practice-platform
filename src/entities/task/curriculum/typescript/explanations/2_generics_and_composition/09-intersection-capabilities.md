# Разбор задачи: «Объединение возможностей»

## 1. Что дано

Есть два независимых интерфейса. `Serializable` требует функцию `serialize`, возвращающую строку. `Loggable` требует функцию `log`, результат которой вызывающему коду не нужен.

Объект `entity` умеет и сериализоваться, и писать сообщение в консоль. Нужно описать обе возможности одним типом, сохранив исходные интерфейсы.

## 2. Что нужно получить

Итоговый тип `SerializableAndLoggable` должен требовать оба метода одновременно. Объект только с `serialize` не подходит. Объект только с `log` тоже не подходит.

Сигнатуры важны не меньше имён: `serialize` должен возвращать строку, а `log` должен быть вызываемой функцией.

## 3. Почему union здесь не подходит

`Serializable | Loggable` означает, что значение соответствует хотя бы одному из интерфейсов. Такой контракт разрешил бы объект только с одним методом, и безопасно вызывать оба без уточнения типа было бы нельзя.

Нам нужно логическое «и» для требований. В системе типов это **пересечение**, записываемое через `&`.

| Конструкция | Что требуется от объекта |
| --- | --- |
| `Serializable \| Loggable` | Хотя бы одна из двух возможностей |
| `Serializable & Loggable` | Обе возможности одновременно |

## 4. Решение по шагам

### Шаг 1. Сохранить отдельные контракты

Интерфейсы продолжают описывать самостоятельные возможности. Их можно применять отдельно в других функциях, которым нужен лишь один метод.

### Шаг 2. Назвать их пересечение

```ts
type SerializableAndLoggable = Serializable & Loggable;
```

Мы не копируем объявления методов. Если контракт `Serializable` изменится, составной тип автоматически учтёт изменение.

### Полный код

```ts
interface Serializable {
  serialize: () => string;
}

interface Loggable {
  log: () => void;
}

type SerializableAndLoggable = Serializable & Loggable;

const entity: SerializableAndLoggable = {
  serialize: () => "data",
  log: () => console.log("logged"),
};
```

## 5. Разбор использования

```ts
const serialized = entity.serialize(); // string, значение "data"
entity.log(); // Выводит logged.
```

В первом вызове TypeScript видит обязательный метод из `Serializable`, во втором — обязательный метод из `Loggable`. Дополнительные проверки наличия не нужны: оба требования уже включены в тип переменной.

Если удалить `log` из литерала `entity`, объект перестанет соответствовать пересечению. Если заменить результат `serialize` на число, имя метода сохранится, но нарушится его сигнатура.

## 6. Важные детали и частые ошибки

- Пересечение типов не объединяет два объекта при выполнении. Запись `A & B` описывает требования; реальные методы в `entity` мы создаём сами.
- Если у пересекаемых типов совпадают имена полей, их типы тоже должны выполняться одновременно. Например, для `id: string` и `id: number` пересечение даст невыполнимое поле `id: never`.
- `void` в типе обработчика означает, что вызывающий код не использует его результат. Это не универсальный запрет передавать любую функцию, которая технически возвращает значение.
- Наследование класса и примеси для этой задачи избыточны: нужно составить тип, а не строить иерархию объектов.
- Альтернатива — интерфейс, расширяющий сразу `Serializable` и `Loggable`. Для демонстрации композиции существующих типов пересечение короче и прямо выражает требование.

## 7. Что запомнить

Объединение `|` допускает варианты, а пересечение `&` накапливает требования. Здесь две независимые возможности составляют один контракт без дублирования методов и без нового кода во время выполнения.
