# Разбор задачи: «Доступ к произвольному объекту»

## 1. Что дано

В заготовке снова есть объект `{ a: 1, b: 2, c: "a" }` и функция `getValue(obj, key)`. Но пользоваться функцией нужно с разными объектами: например, с пользователем, настройками или товаром.

Для каждого вызова должны сохраняться собственные ключи и собственные типы значений. Контракт также должен явно говорить, что первый аргумент — объект.

## 2. Что нужно получить

```ts
// getValue({ name: "Alice", age: 30 }, "name") → string
// getValue({ enabled: true, retries: 3 }, "enabled") → boolean
// getValue({ enabled: true }, "name") → ошибка: ключа нет
```

Примитивные значения вроде строки или числа не должны становиться первым аргументом этой объектной утилиты.

## 3. Почему object без дженерика недостаточно

Аннотация `obj: object` исключает примитивы, но не запоминает поля конкретного аргумента. Из одного лишь `object` нельзя узнать, есть ли внутри `name`, `enabled` или `a`.

Обратная крайность — перечислить поля примера прямо в сигнатуре. Тогда функция окажется привязана к `{ a, b, c }` и перестанет решать задачу для других структур.

Нужно одновременно сохранить точный тип и ограничить его объектными значениями. Это делает `T extends object`.

## 4. Решение по шагам

### Шаг 1. Задать объектное ограничение

`T extends object` означает, что `T` может быть разным при каждом вызове, но должен быть непримитивным типом. Сами поля при этом не стираются: для пользователя `T` сохранит `name` и `age`, а для настроек — `enabled` и `retries`.

### Шаг 2. Связать ключ и результат

`K extends keyof T` допускает ключи выбранного объекта. Результат `T[K]` берёт тип именно выбранного свойства.

### Полный код

```ts
const obj = { a: 1, b: 2, c: "a" };

const getValue = <T extends object, K extends keyof T>(
  obj: T,
  key: K
): T[K] => {
  return obj[key];
};

const res1 = getValue(obj, "a"); // number
const res2 = getValue(obj, "c"); // string
```

Тело функции осталось прежним. Изменилась только точность её контракта.

## 5. Один алгоритм, два разных объекта

```ts
const user = { name: "Alice", age: 30 };
const settings = { enabled: true, retries: 3 };

const name = getValue(user, "name"); // string, значение "Alice"
const enabled = getValue(settings, "enabled"); // boolean, значение true
```

В первом вызове `T` — тип пользователя, `K` — `"name"`. Во втором `T` — тип настроек, `K` — `"enabled"`. Параметры типов выбираются заново для каждого вызова; функция не «запоминает» первый переданный объект навсегда.

Если попытаться прочитать `"name"` у `settings`, ограничение ключа остановит вызов. Если передать `"Alice"` первым аргументом, объектное ограничение отвергнет уже его.

## 6. Чем этот контракт отличается от предыдущей задачи

У сигнатуры `<T, K extends keyof T>` нет ограничения на первый параметр. Например, у строки есть типизированное свойство `length`, поэтому такая универсальная сигнатура может допустить чтение свойства примитива.

В этой версии `T extends object` сужает область применения до объектов. При этом `object` не означает исключительно обычный объект `{}`: массивы и функции тоже относятся к непримитивным значениям. Отсечение именно массивов или экземпляров классов потребовало бы других требований.

## 7. Важные детали и частые ошибки

- Не заменяйте `object` на `{}`: пустой объектный тип в TypeScript не равнозначен «только объекты» и допускает многие примитивы.
- Не используйте `Object` с заглавной буквы как замену ограничению этой задачи.
- Не задавайте всем значениям объекта один тип: у разных полей вполне могут быть разные типы.
- Если в вызывающем коде ключ известен только как `string`, сначала нужно сузить его до допустимого ключа. Утверждение типа без основания лишь скроет неопределённость.
- Эта функция читает существующее по типу свойство, но не проверяет произвольный JSON. Типизированный объект и недоверенное внешнее значение — разные исходные условия.

## 8. Что запомнить

Ограничение `extends object` задаёт область применения, дженерик `T` сохраняет конкретную структуру, а `K` связывает ключ с результатом. Можно сделать функцию универсальной и при этом не потерять точность.
