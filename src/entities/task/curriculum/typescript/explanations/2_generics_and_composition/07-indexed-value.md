# Разбор задачи: «Значение по ключу»

## 1. Что дано

Объект `obj` содержит числа в полях `a` и `b`, а в поле `c` — строку. Функция `getValue` уже умеет читать `obj[key]`, но её параметры не типизированы.

```ts
const obj = { a: 1, b: 2, c: "a" };
```

Главная трудность здесь не в JavaScript-операции чтения. Нужно выразить связь между переданным объектом, выбранным ключом и результатом.

## 2. Что нужно получить

- `getValue(obj, "a")` возвращает значение `1` с типом `number`.
- `getValue(obj, "c")` возвращает значение `"a"` с типом `string`.
- `getValue(obj, "missing")` не соответствует сигнатуре: такого ключа нет.

Тип результата должен зависеть от конкретного аргумента, а не всегда быть общим `string | number`.

## 3. Почему очевидная аннотация теряет информацию

Тип `key: string` слишком широк: он допускает любой текст. Даже запись `key: keyof T` вместе с результатом `T[keyof T]` ограничила бы ключи, но вернула объединение типов всех полей объекта.

Для нашего объекта `T[keyof T]` — `number | string`. Тогда после получения поля `a` пришлось бы снова выяснять, число это или строка, хотя выбранный ключ уже всё определяет.

Нужен отдельный параметр типа, который запомнит именно переданный ключ.

## 4. Решение по шагам

### Шаг 1. Сохранить тип объекта в T

`T` — параметр типа, или дженерик. При вызове TypeScript подставляет вместо него структуру аргумента. Мы не перечисляем поля внутри функции и поэтому не привязываем её к единственному объекту.

### Шаг 2. Ограничить K существующими ключами

`keyof T` получает объединение ключей. Для `obj` это `"a" | "b" | "c"`. Ограничение `K extends keyof T` означает: выбранный `K` должен быть совместим с этим набором.

### Шаг 3. Получить тип выбранного поля

`T[K]` — индексированный доступ на уровне типов. Он отвечает на вопрос «какой тип хранится в поле `K` объекта типа `T`». Это описание результата, а `obj[key]` внутри тела — реальное чтение значения.

### Полный код

```ts
const obj = { a: 1, b: 2, c: "a" };

const getValue = <T, K extends keyof T>(obj: T, key: K): T[K] => {
  return obj[key];
};

const res1 = getValue(obj, "a"); // number
const res2 = getValue(obj, "c"); // string
```

## 5. Подстановка типов «вживую»

Для первого вызова TypeScript последовательно получает:

```ts
// T = { a: number; b: number; c: string }
// keyof T = "a" | "b" | "c"
// K = "a"
// T[K] = T["a"] = number
```

Для второго вызова меняется только `K`: он равен `"c"`, поэтому результат — `T["c"]`, то есть `string`. Явно передавать дженерики в угловых скобках при вызове не нужно: они выводятся из аргументов.

Теперь `res1.toFixed(2)` и `res2.toUpperCase()` доступны без дополнительных проверок. Попытка передать `"missing"` отвергается ещё при сопоставлении второго аргумента с ключами.

## 6. Важные детали и частые ошибки

- `keyof` получает имена полей, а `T[K]` — тип значения. Это не взаимозаменяемые конструкции.
- `extends` здесь задаёт ограничение параметра типа. Он не создаёт наследование объектов во время выполнения.
- Если ключ сам имеет тип объединения, например `"a" | "c"`, результат закономерно станет `number | string`: конкретный вариант действительно ещё неизвестен.
- У необязательного поля результат при строгой проверке null будет учитывать `undefined`. Функция не обещает, что необязательное значение присутствует.
- Набор ключей зависит от статического типа аргумента. Если заранее расширить объект до словаря с произвольными строковыми ключами, точный набор имён будет потерян ещё до вызова.

## 7. Что происходит при выполнении

Параметры типов исчезают, и остаётся обычный `return obj[key]`. Функция не копирует объект и не перебирает поля. Вся дополнительная точность получена описанием связи аргументов, а не усложнением алгоритма.

## 8. Что запомнить

Шаблон `T`, `K extends keyof T`, `T[K]` сохраняет зависимость «объект → выбранный ключ → тип результата». Именно отдельный `K` позволяет вернуть точный тип конкретного поля.
