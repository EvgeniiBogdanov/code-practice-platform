# Разбор задачи: «Шаблонные строки»

## 1. Что дано

Исходный тип перечисляет имена событий:

```ts
type EventName = "click" | "focus" | "hover";
```

Для каждого события нужно получить имя обработчика с префиксом `on` и заглавной первой буквой: `onClick`, `onFocus`, `onHover`.

## 2. Что нужно получить

Тип `EventHandlerName` должен разрешать ровно имена, выведенные из `EventName`. Значения `"onclick"`, `"onBlur"` и `"click"` не соответствуют условию.

Если добавить новое исходное событие, его обработчик должен появиться в производном типе автоматически.

## 3. Почему ручной список или string не подходят

Запись `type EventHandlerName = string` потеряет все ограничения. Ручное объединение `"onClick" | "onFocus" | "onHover"` даст правильный текущий набор, но не сохранит зависимость от `EventName`.

Здесь нужно описать правило преобразования строковых **типов**, а не поддерживать второй список. Для этого TypeScript предоставляет шаблонные строковые типы и утилиту `Capitalize`.

## 4. Решение по шагам

### Шаг 1. Сделать первую букву заглавной

```ts
type CapitalizedEvent = Capitalize<EventName>;
// "Click" | "Focus" | "Hover"
```

`Capitalize` меняет первый символ каждого строкового варианта. Он не превращает всё слово в верхний регистр: для этого существовала бы другая утилита, `Uppercase`.

### Шаг 2. Добавить префикс

Шаблонный тип использует обратные кавычки и `${...}`, как знакомые шаблонные строки JavaScript. Но внутри стоит тип, а результатом является другой тип.

### Полный код

```ts
type EventName = "click" | "focus" | "hover";

type EventHandlerName = `on${Capitalize<EventName>}`;

const handler: EventHandlerName = "onClick";
```

Промежуточный `CapitalizedEvent` полезен для объяснения, но в итоговом решении не обязателен.

## 5. Преобразование каждого события

| Исходный вариант | После Capitalize | После добавления on |
| --- | --- | --- |
| `"click"` | `"Click"` | `"onClick"` |
| `"focus"` | `"Focus"` | `"onFocus"` |
| `"hover"` | `"Hover"` | `"onHover"` |

Все полученные строки собираются в объединение. Поэтому функция, принимающая `EventHandlerName`, может рассчитывать на один из этих трёх вариантов.

Если исходный `EventName` дополнить `"blur"`, в результат автоматически войдёт `"onBlur"`. Правило написания обработчика остаётся в одном месте.

## 6. Тип не преобразует реальную строку

Объявление `EventHandlerName` не создаёт объект с обработчиками и не переименовывает значение `"click"` в памяти. Оно только задаёт допустимый вид строк для TypeScript-кода.

Например, выражение JavaScript, которое берёт строку и склеивает её с префиксом, — самостоятельный алгоритм. Его результат может быть выведен как широкий `string`, если TypeScript не способен доказать более точную зависимость. В этом упражнении писать такую функцию не требуется.

## 7. Важные детали и частые ошибки

- Применять `Capitalize` нужно к имени события до добавления префикса. Если преобразовать целиком строку `"onclick"`, получится `"Onclick"`, что не соответствует формату.
- `Uppercase<EventName>` даст `"CLICK" | "FOCUS" | "HOVER"`, а нам нужен другой регистр.
- Если заменить `EventName` на `string`, исчезнет конечный набор событий. Шаблон больше не будет ограничиваться тремя именами.
- Одинарные или двойные кавычки не создают шаблонный тип: нужны обратные кавычки.
- Тип имени обработчика описывает имя, а не сигнатуру функции. Какие аргументы получает `onClick`, эта конструкция сама по себе не определяет.

## 8. Что запомнить

Шаблонные строковые типы позволяют выразить соглашение об именовании. `Capitalize` отвечает за регистр, шаблон добавляет префикс, а исходное объединение определяет конечный набор допустимых обработчиков.
