# Разбор задачи: «Тип элемента массива»

## 1. Что дано

Нужно написать помощник `ElementType<T>`. Если ему передан тип массива, результатом должен стать тип одного элемента. Если передан другой тип, его нужно сохранить.

В условии есть два примера: `number[]` должен превратиться в `number`, а `string` должна остаться `string`.

## 2. Что нужно получить

| Входной тип | Результат |
| --- | --- |
| `number[]` | `number` |
| `string[]` | `string` |
| `string` | `string` |
| `{ id: number }[]` | `{ id: number }` |
| `number[][]` | `number[]` |

Последний пример показывает важную границу: извлекается один уровень массива, а не все уровни рекурсивно.

## 3. Почему прямой T[number] недостаточен

Для известного массива индексированный доступ `T[number]` действительно даёт тип его элемента. Но произвольный `T` может оказаться, например, логическим значением или обычным объектом, у которого нет числового индекса.

Сначала нужно выяснить на уровне типов, соответствует ли `T` форме массива. Для этого используется условный тип. Чтобы одновременно получить неизвестный тип элемента, пригодится `infer`.

## 4. Решение по шагам

### Шаг 1. Записать условие

Форма `T extends SomeType ? Yes : No` напоминает тернарный оператор JavaScript, но работает с типами. Она выбирает результат в зависимости от совместимости `T` с указанной формой.

### Шаг 2. Вывести элемент массива

В форме `(infer U)[]` имя `U` обозначает тип, который TypeScript должен вывести из элементов массива. `infer` вводит это имя прямо при сопоставлении.

### Шаг 3. Сохранить исходный тип в другой ветке

Если массив не подошёл, результатом становится `T`. Так помощник не уничтожает входную информацию для остальных типов.

### Полный код

```ts
type ElementType<T> = T extends (infer U)[] ? U : T;

type A = number[];
type B = string;

type AElement = ElementType<A>; // number
type BElement = ElementType<B>; // string
```

## 5. Как вычисляется результат

Для `number[]` TypeScript сопоставляет `number[]` с `(infer U)[]`. Внешняя форма массива совпадает, поэтому `U` выводится как `number`. Выбирается первая ветка и возвращает этот тип.

Для `string` форма массива не совпадает. Тип строкового значения не является обычным массивом, даже если у строки можно прочитать символ по индексу. Выбирается вторая ветка и возвращает исходный `string`.

Для `number[][]` элемент внешнего массива — `number[]`. Помощник возвращает именно его, потому что повторного вызова `ElementType` в определении нет.

## 6. Дополнительные случаи

```ts
type Mixed = ElementType<string[] | boolean>; // string | boolean
type PairItem = ElementType<[string, number]>; // string | number
type EmptyItem = ElementType<[]>; // never
```

В первом случае условие применяется к каждому участнику объединения отдельно: массив даёт `string`, а `boolean` сохраняется. Это свойство условного типа называется распределением по объединению.

Кортеж тоже соответствует массивной форме, поэтому из разных позиций получается объединение элементов. У пустого кортежа элементов нет — результат `never`.

## 7. Важные детали и частые ошибки

- `infer U` не объявляет переменную JavaScript. В программе не появляется никакого значения `U`.
- Выведенный `U` используется в положительной ветке условия, где сопоставление успешно.
- Исходная версия рассчитана на изменяемые массивы. Для `readonly number[]` она вернёт сам исходный тип, потому что он не совместим с изменяемым массивом.
- Если требуется поддержка обоих видов массивов, условие можно расширить: `T extends readonly (infer U)[] ? U : T`.
- Не заменяйте отрицательную ветку на `never`: тогда `ElementType<string>` потеряет исходный тип и нарушит условие.

## 8. Что запомнить

Условный тип выбирает преобразование, а `infer` извлекает часть структуры. Здесь один короткий помощник снимает один уровень массива и сохраняет остальные входные типы без изменений.
