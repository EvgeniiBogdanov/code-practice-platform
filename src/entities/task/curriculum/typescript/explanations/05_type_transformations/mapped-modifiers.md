# Разбор задачи: «Свои Readonly, Partial и Required»

## 1. Что дано

Встроенные `Readonly`, `Partial` и `Required` уже знакомы. Классический вопрос на собеседовании: «а как они устроены внутри?». Нужно реализовать их самостоятельно и добавить `Mutable`, которого в стандартной библиотеке нет.

## 2. Что нужно получить

| Тип | Что делает с каждым полем `Todo` |
| --- | --- |
| `MyReadonly<Todo>` | добавляет `readonly` |
| `MyPartial<Todo>` | добавляет `?` |
| `MyRequired<Todo>` | снимает `?`, `done` становится обязательным |
| `Mutable<Todo>` | снимает `readonly`, `id` можно менять |

## 3. Отображаемый тип

Отображаемый тип (mapped type) создаёт объектный тип, проходя по объединению ключей:

```ts
type Copy<T> = { [K in keyof T]: T[K] };
```

- `keyof T` — объединение ключей `T`;
- `K in ...` — для каждого ключа создаётся поле;
- `T[K]` — тип значения этого поля в исходном типе.

`Copy<Todo>` повторяет `Todo`, включая модификаторы: тип вида `[K in keyof T]` называется **гомоморфным** и переносит `readonly` и `?` исходных полей.

## 4. Модификаторы

Перед `[K in ...]` и после `]` можно добавить или снять модификаторы:

| Запись | Эффект |
| --- | --- |
| `readonly [K in keyof T]` или `+readonly` | добавить `readonly` |
| `-readonly [K in keyof T]` | снять `readonly` |
| `[K in keyof T]?` или `+?` | сделать необязательным |
| `[K in keyof T]-?` | сделать обязательным |

## 5. Решение

```ts
type MyReadonly<T> = { readonly [K in keyof T]: T[K] };
type MyPartial<T> = { [K in keyof T]?: T[K] };
type MyRequired<T> = { [K in keyof T]-?: T[K] };
type Mutable<T> = { -readonly [K in keyof T]: T[K] };
```

Встроенные утилиты объявлены точно так же. Разница только в именах параметров.

## 6. Тонкости

**-? убирает undefined.** Необязательное поле `done?: boolean` имеет тип `boolean | undefined`. `-?` снимает и модификатор, и добавленный им `undefined`, поэтому в `MyRequired<Todo>` поле `done` — просто `boolean`.

**Массивы и кортежи.** Гомоморфный отображаемый тип, применённый к массиву, возвращает массив: `MyReadonly<string[]>` — это `readonly string[]`, а не объект с полями `length` и `push`.

**Поверхностность.** Все четыре типа меняют только верхний уровень. Для вложенных объектов нужна рекурсия:

```ts
type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K];
};
```

## 7. Где пригодится Mutable

Когда тип пришёл из библиотеки или получен через `as const`, а нужен изменяемый вариант, например для черновика формы. `Mutable` снимает `readonly` только на уровне типов: объект, замороженный через `Object.freeze`, менять всё равно нельзя.

## 8. Частые ошибки

- Писать `[K in T]` вместо `[K in keyof T]`: `in` перебирает объединение ключей, а не сам объект.
- Ставить `?` перед `[`: модификатор необязательности идёт после `]`.
- Использовать `[K in string]`: получится индексная сигнатура, связь с полями `T` потеряется.

## 9. Что запомнить

`{ [K in keyof T]: T[K] }` — основа большинства служебных типов. Знаки `+` и `-` перед `readonly` и `?` добавляют или снимают модификаторы, а гомоморфный обход сохраняет модификаторы исходных полей.
