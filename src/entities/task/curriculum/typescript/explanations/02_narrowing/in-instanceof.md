# Разбор задачи: «Сужение через in и instanceof»

## 1. Что дано

Две функции принимают значения разных видов:

- `move` получает рыбу или птицу. У рыбы есть `swim`, у птицы — `fly`.
- `formatDate` получает либо объект `Date`, либо ISO-строку.

`typeof` здесь не поможет: и `Fish`, и `Bird`, и `Date` — объекты, для всех `typeof` вернёт `"object"`.

## 2. Что нужно получить

| Функция | Тип параметра | Как различать |
| --- | --- | --- |
| `move` | `Fish \| Bird` | есть ли у объекта ключ `swim` |
| `formatDate` | `Date \| string` | создан ли объект конструктором `Date` |

## 3. Инструменты сужения

| Проверка | Что проверяет | Когда использовать |
| --- | --- | --- |
| `typeof x === "string"` | примитивный тип | строки, числа, функции |
| `"key" in x` | наличие ключа в объекте или его прототипах | интерфейсы и объектные формы |
| `x instanceof C` | цепочку прототипов | классы и встроенные конструкторы |
| `x.kind === "..."` | значение литерального поля | дискриминируемые объединения |
| `if (x)` | истинность | отсечение `null` и `undefined`, но осторожно |

TypeScript понимает все эти проверки и сужает тип в соответствующих ветках.

## 4. Решение по шагам

### Шаг 1. in для интерфейсов

```ts
if ("swim" in animal) {
  animal.swim(); // Fish
  return;
}
animal.fly(); // Bird
```

Интерфейсы `Fish` и `Bird` существуют только при проверке типов, поэтому различать их можно лишь по форме. Оператор `in` проверяет ключ во время выполнения, а TypeScript оставляет в ветке `true` только те варианты объединения, у которых этот ключ есть. После `return` в оставшемся коде остаётся `Bird`.

### Шаг 2. instanceof для классов

```ts
const date = value instanceof Date ? value : new Date(value);
```

`Date` — конструктор, существующий во время выполнения. В ветке `true` тип — `Date`, в ветке `false` — `string`.

### Полный код

```ts
const move = (animal: Fish | Bird): void => {
  if ("swim" in animal) {
    animal.swim();
    return;
  }

  animal.fly();
};

const formatDate = (value: Date | string): string => {
  const date = value instanceof Date ? value : new Date(value);
  return date.toLocaleDateString("ru-RU");
};
```

## 5. Ограничения каждого способа

**instanceof и интерфейсы.** `animal instanceof Fish` — ошибка компиляции: `Fish` only refers to a type. Интерфейсы стираются, проверять нечего.

**instanceof и разные окна.** Объект `Date` из iframe создан другим конструктором `Date`, и `instanceof Date` вернёт `false`. Для массивов поэтому используют `Array.isArray`.

**in и необязательные поля.** Если бы у `Bird` было необязательное `swim?: () => void`, проверка `"swim" in animal` оставила бы в ветке `true` оба типа. Ключ может быть у птицы, и TypeScript это учитывает.

**Истинность.** `if (count)` отбросит не только `undefined`, но и `0`. Для чисел и строк сравнивайте явно: `count !== undefined`.

## 6. Частые ошибки

- Проверять `if (animal.swim)`: обращение к `swim` на `Fish | Bird` — ошибка компиляции, этого поля нет у `Bird`.
- Использовать `typeof value === "object"` для различения `Date` и других объектов.
- Приводить `(animal as Fish).swim()` без проверки.

## 7. Что запомнить

Выбор проверки зависит от того, что существует во время выполнения: примитивный тип — `typeof`, класс — `instanceof`, форма объекта — `in` или литеральное поле-дискриминатор. TypeScript понимает все эти проверки и сужает тип в ветках.
