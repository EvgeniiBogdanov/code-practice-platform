# Разбор задачи: «Тип результата и второго параметра»

## 1. Что дано

Функция `log` принимает массив строк и число, выводит оба аргумента и возвращает `false`:

```ts
const log = (data: string[], num: number): boolean => {
  console.log(data, num);
  return false;
};
```

Нужно получить два типа из уже существующей функции: тип возвращаемого значения и тип её второго параметра.

## 2. Что нужно получить

`LogReturnType` должен быть `boolean`, а `LogSecondParam` — `number`. При изменении сигнатуры `log` производные типы должны следовать за ней автоматически.

Например, если второй параметр станет строковым, его извлечённый тип тоже должен стать `string` без ручного редактирования нового объявления.

## 3. Почему boolean и number вручную — неполное решение

Два псевдонима с явно записанными `boolean` и `number` дали бы правильные типы только для текущей версии функции. Они никак не были бы связаны с `log`.

Для извлечения информации существуют `ReturnType` и `Parameters`. Но эти утилиты принимают **тип функции**, тогда как `log` — имя значения. Сначала нужно перейти от значения к его типу.

## 4. Решение по шагам

### Шаг 1. Получить тип функции через typeof

В позиции типа `typeof log` означает всю сигнатуру:

```ts
// (data: string[], num: number) => boolean
```

Это не вызов JavaScript-оператора, который вернул бы строку `"function"`. Здесь `typeof` участвует в описании типов и ничего не вычисляет при выполнении.

### Шаг 2. Извлечь результат

`ReturnType<typeof log>` берёт тип после стрелки из сигнатуры. У функции явно объявлен `boolean`, поэтому результатом будет именно он, а не литеральный тип `false`.

### Шаг 3. Получить кортеж параметров и выбрать позицию

`Parameters<typeof log>` даёт кортеж `[data: string[], num: number]`. Индексы начинаются с нуля, поэтому второй параметр выбирается через `[1]`.

### Полный код

```ts
const log = (data: string[], num: number): boolean => {
  console.log(data, num);
  return false;
};

type LogReturnType = ReturnType<typeof log>;
type LogSecondParam = Parameters<typeof log>[1];
```

## 5. Подстановка типов «вживую»

| Выражение типа | Полученная информация |
| --- | --- |
| `typeof log` | Вся сигнатура функции |
| `ReturnType<typeof log>` | `boolean` |
| `Parameters<typeof log>` | `[data: string[], num: number]` |
| `Parameters<typeof log>[0]` | `string[]` |
| `Parameters<typeof log>[1]` | `number` |

Полученные типы можно использовать как обычные аннотации:

```ts
const secondArgument: LogSecondParam = 3;
const result: LogReturnType = log(["ready"], secondArgument);
```

Объявления `type` сами функцию не вызывают. Единственный реальный вызов в этом примере — выражение справа от `const result`.

## 6. Важные детали и частые ошибки

- `ReturnType<log>` не подходит: в этом месте требуется тип, поэтому нужен `typeof log`.
- `Parameters<typeof log>[2]` означало бы третий параметр, которого в сигнатуре нет. Для второго нужен индекс `1`.
- `ReturnType` извлекает объявленный контракт функции. Для асинхронной функции результатом обычно будет `Promise<...>`; извлечение значения внутри промиса — отдельное преобразование через `Awaited`.
- Для перегруженной функции такие утилиты ориентируются на последнюю сигнатуру перегрузки, а не выбирают перегрузку по конкретным аргументам. В данном упражнении сигнатура одна.
- Если параметр необязательный, при извлечении его позиции нужно учитывать `undefined` в строгом режиме.

## 7. Что запомнить

Связка `typeof` → `ReturnType` или `Parameters` позволяет переиспользовать контракт функции. `Parameters` возвращает кортеж, поэтому выбор конкретного аргумента — обычный индексированный доступ на уровне типов.
