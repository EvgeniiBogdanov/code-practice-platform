# Разбор задачи: «Фильтрация прав доступа»

## 1. Что дано

Тип `Permission` перечисляет пять строковых вариантов: `"read"`, `"create"`, `"update"`, `"delete"` и `"banned"`. Это объединение типов, а не массив строк во время выполнения.

На его основе нужно получить два более узких набора прав.

## 2. Что нужно получить

- `ActivePermission`: все варианты, кроме `"banned"`.
- `WritePermission`: только `"create"` и `"update"`.

Хотя удаление тоже меняет данные в обычном смысле, в этом упражнении набор для второго типа прямо ограничен двумя значениями. `"delete"` в него включать не нужно.

## 3. Почему ручное объединение хуже выражает связь

Можно написать новые объединения вручную, повторив строки. Но если в `Permission` появится ещё одно допустимое право, его придётся отдельно переносить в активный набор.

Встроенные утилиты позволяют описать само правило: исключить нежелательные варианты или оставить подходящие. Для объединений используются `Exclude` и `Extract`.

## 4. Решение по шагам

### Шаг 1. Исключить заблокированный вариант

`Exclude<Permission, "banned">` рассматривает варианты `Permission` и убирает те, которые совместимы с `"banned"`.

### Шаг 2. Выбрать права записи

`Extract<Permission, "create" | "update">` делает обратный выбор: оставляет только совместимые с указанным набором варианты.

### Полный код

```ts
type Permission = "read" | "create" | "update" | "delete" | "banned";

type ActivePermission = Exclude<Permission, "banned">;
type WritePermission = Extract<Permission, "create" | "update">;
```

## 5. Разбор каждого варианта

| Вариант из Permission | ActivePermission | WritePermission |
| --- | --- | --- |
| `"read"` | Остаётся | Исключается |
| `"create"` | Остаётся | Остаётся |
| `"update"` | Остаётся | Остаётся |
| `"delete"` | Остаётся | Исключается |
| `"banned"` | Исключается | Исключается |

Поэтому результат равнозначен следующим типам:

```ts
// ActivePermission = "read" | "create" | "update" | "delete"
// WritePermission = "create" | "update"

const active: ActivePermission = "read";
const writable: WritePermission = "update";
// const forbidden: ActivePermission = "banned"; // Ошибка типов.
```

Если добавить `"archive"` в исходный `Permission`, он автоматически попадёт в активный набор, но не в `WritePermission`: там перечислены конкретные разрешённые варианты.

## 6. Что происходит на уровне типов

Идею можно выразить условными типами:

```ts
type Without<T, U> = T extends U ? never : T;
type Matching<T, U> = T extends U ? T : never;
```

Для параметра `T`, являющегося объединением, такое условие применяется к каждому участнику отдельно. `never` обозначает отсутствие подходящего варианта и исчезает из итогового объединения. Писать эти помощники в решении не требуется: встроенные утилиты уже выполняют эту работу.

## 7. Важные детали и частые ошибки

- `Omit` и `Pick` работают с полями объектных типов; здесь нужно фильтровать варианты объединения, поэтому используются другие утилиты.
- Порядок параметров важен: первый задаёт исходный набор, второй — условие выбора или исключения.
- `Exclude<Permission, string>` даст `never`, потому что все варианты `Permission` являются строками.
- Эти типы не фильтруют массив и не проверяют реальные права пользователя. Для проверки разрешений во время выполнения нужна логика приложения.
- Если среди извлекаемых значений есть вариант, отсутствующий в `Permission`, `Extract` не добавит его в результат.

## 8. Что запомнить

`Exclude` убирает совместимые варианты из объединения, а `Extract` оставляет их. Новые типы выводятся из исходного набора и сохраняют явно заданную политику отбора.
