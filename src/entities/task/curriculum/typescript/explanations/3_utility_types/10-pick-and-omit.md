# Разбор задачи: «Выбор и исключение полей»

## 1. Что дано

Интерфейс `User` содержит четыре поля: `id`, `name`, `email`, `password`. Из него нужно получить две модели для разных сценариев: публичного представления пользователя и формы регистрации.

Это задача о преобразовании **типов**. В условии нет функции, которая должна удалять свойства из реального объекта.

## 2. Что нужно получить

| Новый тип | Нужные поля |
| --- | --- |
| `PublicUser` | `id`, `name`, `email` |
| `RegistrationForm` | `name`, `password` |

Типы самих полей должны браться из `User`. Например, `id` остаётся числом, а `name` — строкой.

## 3. Почему не стоит переписывать интерфейсы вручную

Можно объявить две отдельные копии нужных полей. Но тогда изменение `User.name` придётся повторять в нескольких местах. Связь между исходной моделью и её представлениями будет существовать только в голове разработчика.

В TypeScript уже есть утилиты для таких преобразований: `Omit` исключает перечисленные ключи, а `Pick` выбирает перечисленные ключи. Дополнительные библиотеки или собственный сложный тип здесь не нужны.

## 4. Решение по шагам

### Шаг 1. Исключить пароль из публичной модели

`Omit<User, "password">` читается так: «возьми `User` и оставь все поля, кроме `password`». Мы задаём исключение, потому что публичной модели нужны остальные поля.

### Шаг 2. Выбрать поля формы

`Pick<User, "name" | "password">` выбирает только два ключа. Оператор `|` объединяет имена, а не объединяет значения полей.

### Полный код

```ts
interface User {
  id: number;
  name: string;
  email: string;
  password: string;
}

type PublicUser = Omit<User, "password">;
type RegistrationForm = Pick<User, "name" | "password">;
```

## 5. Как разворачиваются полученные типы

Для понимания можно мысленно подставить результат преобразования:

```ts
// PublicUser:
// { id: number; name: string; email: string }

// RegistrationForm:
// { name: string; password: string }

const profile: PublicUser = {
  id: 1,
  name: "Alice",
  email: "alice@example.com",
};

const form: RegistrationForm = {
  name: "Alice",
  password: "example-password",
};
```

Если убрать `email` из `profile`, обязательного поля не хватит. Если положить число в `form.name`, нарушится исходный контракт `User.name`.

## 6. Почему Omit не удаляет пароль из данных

Это важная граница задачи. Пусть в переменной `user` уже находится полный объект `User`. Присваивание `const publicUser: PublicUser = user` может быть допустимым: в объекте есть все требуемые поля. Но во время выполнения `publicUser` всё ещё ссылается на исходный объект, где хранится пароль.

Для настоящей передачи публичных данных нужно создать объект с нужным содержимым, например:

```ts
const toPublicUser = (user: User): PublicUser => ({
  id: user.id,
  name: user.name,
  email: user.email,
});
```

Это отдельное действие JavaScript. Аннотация результата сама его не выполняет.

## 7. Важные детали и частые ошибки

- Не путайте `Pick` и `Omit`: первый перечисляет то, что оставить, второй — то, что исключить.
- Сохраняются исходные типы полей и их модификаторы. Утилиты не превращают все поля в строки и не делают их автоматически необязательными.
- Проверка лишних свойств у свежего литерала не означает, что тип является строгим запретом любых дополнительных полей у всех объектов. TypeScript в основном сравнивает структуры по необходимым свойствам.
- Если в `User` появится ещё одно секретное поле, `Omit<User, "password">` автоматически включит его. Для реального публичного API часто удобнее явно выбирать разрешённые поля через `Pick` и так же явно формировать объект.

## 8. Что запомнить

`Pick` и `Omit` создают производные типы и сохраняют связь с исходной моделью. Для изменения самих данных нужен код, который создаёт или преобразует объект.
