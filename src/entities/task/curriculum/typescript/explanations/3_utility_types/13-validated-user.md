# Разбор задачи: «Создание пользователя с проверкой полей»

## 1. Что дано

Интерфейс `User` требует `name: string` и `age: number`. Но `createAndValidate` начинает с пустого объекта и добавляет поля независимо:

- имя появляется, только если `name.length > 0`;
- возраст появляется, только если `age > 18`.

Значит, функция может вернуть полный объект, только имя, только возраст или вообще `{}`.

## 2. Что нужно получить

Нужно типизировать параметры и описать результат, в котором поля `User` необязательны. При этом тип значения каждого добавленного поля остаётся прежним: имя не может стать числом, а возраст — строкой.

Сами условия из заготовки менять не нужно. В частности, возраст `18` не проходит строгое сравнение `> 18`.

## 3. Почему User и пустого объекта недостаточно

Аннотация результата `User` обещала бы оба обязательных поля во всех случаях. Исходный алгоритм такого обещания не выполняет.

Объявление `const newUser = {}` тоже не подходит: TypeScript выводит тип пустого объекта, у которого не описаны свойства `name` и `age`. Последующее присваивание этих полей не становится автоматически разрешённым.

Утверждение `{ } as User` скрыло бы несоответствие и создало ложную гарантию. Правильнее честно описать промежуточное и итоговое состояние через `Partial<User>`.

## 4. Решение по шагам

### Шаг 1. Описать вход

`name: string` позволяет читать `length`, а `age: number` — сравнивать значение с `18`. Значения другого типа не соответствуют контракту вызова.

### Шаг 2. Сделать поля результата необязательными

`Partial<User>` преобразует тип в структуру, эквивалентную `{ age?: number; name?: string }`. При создании пустого объекта это допустимо, а известные свойства можно добавлять позже.

### Полный код

```ts
interface User {
  age: number;
  name: string;
}

const createAndValidate = (
  name: string,
  age: number
): Partial<User> => {
  const newUser: Partial<User> = {};

  if (name.length > 0) {
    newUser.name = name;
  }

  if (age > 18) {
    newUser.age = age;
  }

  return newUser;
};
```

Аннотация нужна и у локального `newUser`, и в контракте возвращаемого значения. Тип результата функции сам по себе не меняет выведенный тип отдельно объявленной переменной `{}`.

## 5. Разбор вариантов по шагам

| Вызов | Имя проходит условие | Возраст проходит условие | Результат |
| --- | --- | --- | --- |
| `createAndValidate("Alice", 30)` | Да | Да | `{ name: "Alice", age: 30 }` |
| `createAndValidate("Alice", 18)` | Да | Нет | `{ name: "Alice" }` |
| `createAndValidate("", 25)` | Нет | Да | `{ age: 25 }` |
| `createAndValidate("", 18)` | Нет | Нет | `{}` |

Проверки независимы. `else if` здесь изменил бы поведение: успешное имя помешало бы добавить возраст.

## 6. Как читать полученные данные

```ts
const user = createAndValidate("Alice", 18);
const ageLabel = user.age?.toString() ?? "Возраст не указан";
```

Результат имеет тип `Partial<User>`, даже если в конкретном вызове человеку очевидно прохождение одного из условий. Сигнатура не вычисляет зависимости от значений аргументов. Поэтому вызывающий код должен учитывать отсутствие каждого поля.

## 7. Важные детали и частые ошибки

- `Partial` не выполняет валидацию. Он только описывает форму, а решения о добавлении значений принимают два `if`.
- Строка из пробелов имеет ненулевую длину и проходит исходное условие. Использование `trim()` изменило бы правило упражнения.
- `number` не означает «валидный возраст». Здесь не проверяются конечность, целочисленность или верхняя граница; это дополнительные правила, которых нет в заготовке.
- `Partial` меняет только верхний уровень. Для вложенных частичных объектов нужна другая конструкция, которая разбирается в задаче о глубокой конфигурации.
- Возвращать частичный объект и возвращать только полностью валидного пользователя — разные контракты. Для второго пришлось бы менять и тип результата, и алгоритм.

## 8. Что запомнить

Тип результата должен отражать все ветки функции. `Partial<User>` честно описывает постепенное заполнение объекта и заставляет учитывать отсутствующие поля при дальнейшем использовании.
