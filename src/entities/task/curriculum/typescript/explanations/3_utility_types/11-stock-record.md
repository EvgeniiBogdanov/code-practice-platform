# Разбор задачи: «Склад по артикулам»

## 1. Что дано

Объект `stock` хранит остатки товаров: по артикулу `"SKU-1"` доступно `10` единиц, по `"SKU-2"` — `5`. Функция `addStock` увеличивает количество по переданному ключу.

Новые артикулы могут появляться позже. Поэтому тип не должен ограничиваться двумя именами из исходного объекта.

## 2. Что нужно получить

Нужен словарь со строковыми ключами и числовыми значениями. Функция должна принимать этот словарь, строковый артикул и числовую прибавку, изменяя переданный объект.

Если артикул уже есть, увеличиваем остаток. Если отсутствует, начинаем отсчёт с нуля.

## 3. Почему вывода типа исходного объекта недостаточно

Из литерала без аннотации TypeScript видит конкретные поля `"SKU-1"` и `"SKU-2"`. Но параметр `sku: string` может содержать другое имя. Для произвольного строкового доступа нужен контракт словаря.

Его можно записать индексной сигнатурой `{ [sku: string]: number }`. Встроенный `Record<string, number>` выражает ту же основную идею короче: ключи заданного типа связаны со значениями заданного типа.

## 4. Решение по шагам

### Шаг 1. Объявить Stock

```ts
type Stock = Record<string, number>;
```

Первый параметр `Record` описывает ключи, второй — значения. Здесь `string` оставляет набор артикулов открытым. Если бы вместо него стояло объединение двух конкретных строк, контракт потребовал бы именно эти поля.

### Шаг 2. Типизировать изменение остатка

Параметры получают типы `Stock`, `string` и `number`. Результат — `void`, потому что функция изменяет объект, а не возвращает новый склад.

### Полный код

```ts
type Stock = Record<string, number>;

const stock: Stock = {
  "SKU-1": 10,
  "SKU-2": 5,
};

const addStock = (stock: Stock, sku: string, amount: number): void => {
  stock[sku] = (stock[sku] ?? 0) + amount;
};
```

## 5. Разбор обновлений по шагам

```ts
addStock(stock, "SKU-1", 3);
addStock(stock, "SKU-3", 7);

// stock:
// { "SKU-1": 13, "SKU-2": 5, "SKU-3": 7 }
```

В первом вызове `stock["SKU-1"]` равно `10`, поэтому вычисляется `10 + 3`. Во втором чтение отсутствующего артикула даёт `undefined`; оператор `??` подставляет `0`, затем получается `0 + 7`.

Если остаток уже равен нулю, `??` сохраняет этот ноль. Он выбирает запасное значение только для `null` или `undefined`, а не для всех ложных значений.

## 6. Важные детали и частые ошибки

- `Record<string, number>` не создаёт запись для каждой возможной строки. Отсутствующий ключ в обычном объекте по-прежнему может вернуть `undefined`.
- Настройка `noUncheckedIndexedAccess` помогает отразить возможное отсутствие при чтении по произвольному ключу. Даже без неё логика начального нуля нужна во время выполнения.
- Запись `stock[sku] += amount` без инициализации нового артикула привела бы к `undefined + amount`, то есть `NaN`.
- `amount: number` не запрещает отрицательные или дробные значения. Правила о целых неотрицательных поставках нужно задавать отдельно, если их требует приложение.
- Функция мутирует переданный объект. Если другие переменные ссылаются на тот же склад, они увидят обновлённые остатки.
- В примере ключи имеют формат `SKU-…`. Для совершенно произвольных внешних строк следует также учитывать унаследованные свойства обычного объекта; в таком сценарии может быть уместен `Map` или словарь без прототипа.

## 7. Что запомнить

`Record` задаёт тип словаря, а `?? 0` обрабатывает отсутствие значения в реальных данных. Эти механизмы дополняют друг друга: типизация значений не заменяет логику добавления нового артикула.
