# Разбор задачи: «any, unknown и never»

## 1. Что дано

`parseJson` возвращает `any`. С таким значением TypeScript разрешает всё: `data.name.toUpperCase()`, `data.nmae`, `data()`. Если в JSON окажется `{"name": 42}`, программа упадёт во время выполнения.

Вторая проблема — функция `fail`. Она всегда бросает исключение, но `getUserName` всё равно не компилируется: TypeScript считает, что после вызова `fail` выполнение может дойти до конца функции без `return`.

## 2. Что нужно получить

- Результат разбора JSON нельзя использовать без проверки.
- После вызова `fail` компилятор понимает, что код дальше не выполняется.

## 3. Три особых типа

| Тип | Что в него можно присвоить | Что можно делать со значением |
| --- | --- | --- |
| `any` | всё | всё, проверка отключена |
| `unknown` | всё | почти ничего, пока тип не сужен |
| `never` | ничего | значения не существует |

`any` опасен тем, что «заражает» код: результат любой операции с ним тоже `any`, и ошибки распространяются дальше. `unknown` — честный тип для данных из внешнего мира: «что-то пришло, но что — неизвестно». `never` описывает невозможное: результат функции, которая никогда не завершается нормально, или ветку, в которой не осталось вариантов.

## 4. Решение по шагам

### Шаг 1. Вернуть unknown

```ts
const parseJson = (text: string): unknown => JSON.parse(text);
```

Теперь `data.name` — ошибка компиляции. Чтобы прочитать поле, его нужно доказать.

### Шаг 2. Сузить тип проверками

- `typeof data === "object"` оставляет объекты и `null`, потому что `typeof null === "object"`.
- `data !== null` убирает `null`, остаётся `object`.
- `"name" in data` сообщает TypeScript, что у объекта есть ключ `name`. С версии 4.9 тип сужается до `object & Record<"name", unknown>`.
- `typeof data.name === "string"` сужает само поле до `string`.

После этих проверок `data.name.toUpperCase()` безопасен.

### Шаг 3. Объявить fail как функцию, возвращающую never

```ts
function fail(message: string): never {
  throw new Error(message);
}
```

Тип `never` в результате означает «функция никогда не возвращает управление». Анализ потока управления учитывает такой вызов: код после него недостижим, и ошибка «Function lacks ending return statement» исчезает.

### Полный код

```ts
const parseJson = (text: string): unknown => {
  return JSON.parse(text);
};

function fail(message: string): never {
  throw new Error(message);
}

const getUserName = (json: string): string => {
  const data = parseJson(json);

  if (
    typeof data === "object" &&
    data !== null &&
    "name" in data &&
    typeof data.name === "string"
  ) {
    return data.name.toUpperCase();
  }

  fail("В JSON нет строкового поля name");
};
```

## 5. Ловушка: стрелочная функция и never

Стрелка `const fail = (message: string) => { throw ... }` уже имеет выведенный тип `(message: string) => never`. Но анализ потока управления его не использует. Вызов считается «невозвратным», только если имя функции объявлено **с явным типом**:

```ts
function fail(message: string): never { ... }           // работает
const fail: (message: string) => never = (message) => { ... }; // работает
const fail = (message: string): never => { ... };       // НЕ работает
```

В последнем случае тип есть только у стрелки, а у самой константы `fail` он выведен. Это ограничение сделано для скорости: компилятору не нужно вычислять типы инициализаторов во время построения графа потока управления.

## 6. Частые ошибки

- Заменить `any` на `object` или `{}`. Через `{}` поле `name` тоже не прочитать, а `{}` к тому же принимает строки и числа.
- Написать `const data = parseJson(json) as { name: string }`. Утверждение типа ничего не проверяет — это тот же `any`, только аккуратнее оформленный.
- Проверить `if (data.name)`: на `unknown` это ошибка компиляции, а на `any` проверка пропустит число или объект в `name`.

## 7. Что запомнить

`unknown` — безопасная замена `any` для внешних данных: сначала докажи тип, потом используй. `never` — тип «невозможного»: функция, возвращающая `never`, прерывает поток управления, но только если объявлена с явным типом.
