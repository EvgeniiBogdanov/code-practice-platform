# Разбор задачи: «null и undefined»

## 1. Что дано

Три функции, каждая из которых обращается к значению, которого может не быть:

- `users.find(...)` возвращает `User | undefined`, если подходящего элемента нет;
- `address?: Address` — поле может отсутствовать;
- `nickname: string | null` — поле есть всегда, но может быть `null`.

В strict-режиме включён флаг `strictNullChecks`, и TypeScript сообщает: `'user' is possibly 'undefined'`, `'user.address' is possibly 'undefined'`, `'user.nickname' is possibly 'null'`.

## 2. Что нужно получить

Функции компилируются без `!` и `as`, а для отсутствующих данных возвращают значения по умолчанию.

## 3. Почему не «!»

Самый быстрый способ убрать ошибку — `user!.name`. Оператор `!` (non-null assertion) говорит компилятору: «поверь, здесь нет `null` и `undefined`». Но во время выполнения он ничего не проверяет. Для `getUserName(3)` код упадёт с `Cannot read properties of undefined`. Ошибка не исправлена, а спрятана.

## 4. Решение по шагам

### Шаг 1. Опциональная цепочка ?.

`user?.name` возвращает `undefined`, если `user` равен `null` или `undefined`, и не пытается читать поле. Тип выражения — `string | undefined`.

### Шаг 2. Значение по умолчанию через ??

`a ?? b` возвращает `b`, только если `a` равно `null` или `undefined`. Тип результата — `string`, и функция соблюдает свой контракт.

### Шаг 3. Цепочка для вызова метода

`user.nickname?.toUpperCase()` вызывает метод, только если `nickname` не `null`. Если ника нет, используем имя.

### Полный код

```ts
const getUserName = (id: number): string => {
  const user = users.find((u) => u.id === id);
  return user?.name ?? "Неизвестный пользователь";
};

const getCity = (user: User): string => {
  return user.address?.city ?? "Город не указан";
};

const getDisplayName = (user: User): string => {
  return user.nickname?.toUpperCase() ?? user.name;
};
```

## 5. Как вычисляется результат

| Вызов | Промежуточное значение | Результат |
| --- | --- | --- |
| `getUserName(1)` | `user` найден, `user?.name` = `"Alice"` | `"Alice"` |
| `getUserName(3)` | `user` = `undefined`, `user?.name` = `undefined` | `"Неизвестный пользователь"` |
| `getCity(Bob)` | `address` отсутствует → `undefined` | `"Город не указан"` |
| `getDisplayName(Alice)` | `nickname` = `null` → `undefined` | `"Alice"` |
| `getDisplayName(Bob)` | `"bobby".toUpperCase()` | `"BOBBY"` |

## 6. ?? против ||

`||` подставляет значение по умолчанию для любого ложного значения: `0`, `""`, `false`, `NaN`. Если бы у пользователя был ник `""` или в счётчике было `0`, `||` заменил бы их. `??` реагирует только на `null` и `undefined` — обычно это именно то, что нужно.

## 7. null или undefined

Обычно `undefined` означает «значение не задано» (отсутствующее поле, не найденный элемент), а `null` — «значение явно пустое» (пользователь не указал ник). Многие команды выбирают одно из двух для своих моделей. TypeScript различает их как разные типы.

## 8. Частые ошибки

- Использовать `!` или `as User`: ошибка компиляции исчезает, а ошибка выполнения остаётся.
- Писать `if (user.address)` в выражении без возврата значения по умолчанию: функция с типом `string` должна вернуть строку во всех ветках.
- Путать `address?: Address` и `address: Address | undefined`: во втором случае ключ обязан присутствовать.

## 9. Что запомнить

В strict-режиме `null` и `undefined` — отдельные типы, и TypeScript заставляет их обработать. Используйте `?.` для безопасного доступа и `??` для значения по умолчанию, а `!` оставьте для случаев, когда гарантия существует, но компилятор её не видит.
