# Разбор задачи: «Сигнатуры функций»

## 1. Что дано

Четыре функции без типов. В strict-режиме у каждого параметра неявный тип `any`, и TypeScript сообщает об ошибке `Parameter implicitly has an 'any' type`. Нужно описать контракт каждой функции: что она принимает и что возвращает.

## 2. Что нужно получить

| Функция | Параметры | Результат |
| --- | --- | --- |
| `greet` | `name: string`, необязательный `greeting` со значением по умолчанию | `string` |
| `sum` | любое количество чисел | `number` |
| `applyToAll` | массив чисел и функция `number → number` | `number[]` |
| `logMessage` | `message: string`, необязательный `level` | `void` |

## 3. Четыре вида параметров

- **Обычный** параметр обязателен: `name: string`.
- **Со значением по умолчанию** автоматически становится необязательным. Тип выводится из значения: `greeting = "Привет"` даёт `string`. Аннотацию `greeting: string = "Привет"` писать можно, но она избыточна.
- **Необязательный** помечается знаком `?`: `level?: string`. Внутри функции его тип — `string | undefined`, поэтому перед использованием нужно обработать `undefined`, здесь это делает `??`.
- **Остаточный** (rest) собирает оставшиеся аргументы в массив, поэтому его тип — всегда массив или кортеж: `...numbers: number[]`.

## 4. Решение по шагам

### Шаг 1. Описать тип колбэка

Тип функции записывается как стрелка: `(value: number) => number`. Имя параметра в типе нужно только для читаемости. Выносим тип в псевдоним `NumberTransform`, чтобы сигнатура `applyToAll` читалась проще.

### Шаг 2. Указать возвращаемые типы

TypeScript умеет выводить результат, но явный тип у публичной функции — это контракт. Если реализация случайно начнёт возвращать другое, ошибка появится в самой функции, а не в местах вызова.

### Шаг 3. void для функции без результата

`logMessage` ничего не возвращает, поэтому её тип результата — `void`.

### Полный код

```ts
type NumberTransform = (value: number) => number;

const greet = (name: string, greeting = "Привет"): string => {
  return `${greeting}, ${name}!`;
};

const sum = (...numbers: number[]): number => {
  return numbers.reduce((total, n) => total + n, 0);
};

const applyToAll = (items: number[], transform: NumberTransform): number[] => {
  return items.map(transform);
};

const logMessage = (message: string, level?: string): void => {
  console.log(`[${level ?? "info"}] ${message}`);
};
```

## 5. Тонкости, о которых спрашивают

**Колбэк с меньшим числом параметров.** `items.map(transform)` вызывает `transform(value, index, array)`, а наш тип принимает только `value`. Это безопасно: функция, игнорирующая лишние аргументы, ничего не сломает. Обратное — колбэк, требующий больше параметров, чем передаётся, — будет ошибкой.

**void в типе колбэка.** Если параметр имеет тип `() => void`, туда можно передать функцию, возвращающую число. `void` в позиции колбэка означает «результат проигнорируют». Именно поэтому работает `list.forEach((x) => result.push(x))`, хотя `push` возвращает длину массива.

**void и undefined.** `void` означает «полезного результата нет». Тип `undefined` — обещание вернуть именно `undefined`: такой результат можно использовать как значение, а колбэк типа `() => undefined` не примет функцию, возвращающую число. С TypeScript 5.1 функция с результатом `undefined` может обойтись без `return`, раньше он был обязателен.

## 6. Частые ошибки

- Писать `greeting?: string = "Привет"`. Одновременно `?` и значение по умолчанию указать нельзя: значение по умолчанию уже делает параметр необязательным.
- Ставить необязательный параметр перед обязательным: `(level?: string, message: string)`. Необязательные параметры должны идти в конце.
- Типизировать rest-параметр как `number` вместо `number[]`.
- Использовать тип `Function`. Он разрешает вызов с любыми аргументами и возвращает `any`, поэтому ничего не проверяет.

## 7. Что запомнить

Сигнатура функции — это контракт: типы параметров, их обязательность и тип результата. Значение по умолчанию и `?` делают параметр необязательным, rest-параметр всегда массив, а `void` в колбэке означает «результат не важен».
