# Разбор задачи: «Первые аннотации»

## 1. Что дано

В исходном коде четыре переменные: имя `userName`, возраст `userAge`, признак активности `isActive` и массив результатов `scores`. Значения уже подсказывают их назначение: `"Alice"`, `30`, `true` и `[10, 20, 30]`.

В конце есть намеренная ошибка: `userName = 42`. После такого присваивания имя стало бы числом, и последующий вызов строкового метода, например `userName.toUpperCase()`, оказался бы опасным.

## 2. Что нужно получить

Нужно явно описать допустимые значения каждой переменной. При этом разрешено менять имя на другую строку, возраст — на другое число, а в `scores` добавлять числа. Присваивание числа в имя должно отвергаться системой типов.

| Переменная | Тип | Допустимый пример | Недопустимый пример |
| --- | --- | --- | --- |
| `userName` | `string` | `"Bob"` | `42` |
| `userAge` | `number` | `31` | `"31"` |
| `isActive` | `boolean` | `false` | `"false"` |
| `scores` | `number[]` | `[5, 15]` | `[5, "15"]` |

## 3. Первая идея: оставить всё без аннотаций

TypeScript умеет **выводить тип** из начального значения. Уже у `let userName = "Alice"` будет тип `string`, поэтому исходное присваивание `42` ошибочно и без нашей доработки. Отсутствие двоеточия не означает отсутствие типизации.

Но цель упражнения — освоить явные аннотации. Мы записываем те же ограничения самостоятельно, чтобы научиться читать и объявлять контракт переменной. Расширять имя до `string | number` ради исчезновения ошибки нельзя: это разрешило бы именно то поведение, которое условие запрещает.

## 4. Решение по шагам

### Шаг 1. Поставить тип после имени

В объявлении `let userName: string = "Alice"` часть после двоеточия отвечает на вопрос «какие значения здесь разрешены», а часть после `=` задаёт текущее значение. Тип и значение выполняют разные роли.

### Шаг 2. Описать элементы массива

Запись `number[]` читается как «массив чисел». Она ограничивает каждый элемент, но не фиксирует длину: пустой массив и массив из ста чисел тоже подходят. Равнозначная запись — `Array<number>`.

### Полный код

```ts
let userName: string = "Alice";
let userAge: number = 30;
let isActive: boolean = true;
let scores: number[] = [10, 20, 30];

// userName = 42; // Ошибка: число несовместимо со string.
```

Ошибочная строка оставлена комментарием, чтобы показать запрещённую операцию, а не подавить диагностику.

## 5. Разбор на конкретных действиях

```ts
userName = "Bob";
userAge = 31;
isActive = false;
scores.push(40);
```

После этих действий имя равно `"Bob"`, возраст — `31`, активность — `false`, а результаты — `[10, 20, 30, 40]`. Все новые значения соответствуют контрактам.

А `scores.push("40")` было бы ошибкой: строка с цифрами остаётся строкой. Аннотация сама не вызывает `Number()` и не преобразует входные данные.

## 6. Важные детали и частые ошибки

- Используйте примитивные типы `string`, `number`, `boolean` со строчной буквы. Типы `String`, `Number`, `Boolean` связаны с объектами-обёртками и для этих переменных не нужны.
- `number` допускает и целые, и дробные числа. Он сам по себе не гарантирует положительный возраст или конечное значение: такие правила задаются отдельной логикой.
- Не заключайте название типа в кавычки: `string` означает любую строку, а `"string"` — только одно конкретное строковое значение.
- Аннотации исчезают при преобразовании в JavaScript. Они помогают находить ошибки в коде, но не проверяют автоматически данные, пришедшие из сети или текстового поля.

## 7. Что запомнить

Аннотация описывает допустимые значения, инициализатор задаёт начальное значение, а вывод типов позволяет TypeScript получить многие аннотации самостоятельно. В этой задаче достаточно четырёх простых типов; дополнительная логика не требуется.
