# Разбор задачи: «Подписка на события»

## 1. Что дано

Класс `EventEmitter` хранит обработчики, метод `on` добавляет подписчика, а `emit` вызывает подписчиков с данными события. В примере создаётся пользователь `{ id: 1, name: "Alice" }` и обработчик печатает его имя.

Без типов можно ошибиться в названии события или передать ему неподходящие данные. Нужно сохранить связь между каждым событием и его собственной полезной нагрузкой — `payload`.

## 2. Что нужно получить

Карта событий описывает два случая:

| Событие | Данные обработчика |
| --- | --- |
| `userCreated` | `{ id: number; name: string }` |
| `userDeleted` | `{ id: number }` |

Подписчик `userCreated` должен видеть `name`, а подписчик `userDeleted` не должен рассчитывать на это поле. Неизвестное имя события и неверная структура отправляемых данных должны обнаруживаться при типизации вызова.

## 3. Почему недостаточно двух независимых объединений

Можно ограничить имя через `keyof Events`, а данные — через `Events[keyof Events]`. Но это даст два независимых набора: любое имя и любые данные из карты. Связь конкретной пары потеряется.

Нужен общий параметр типа `K` внутри каждого вызова. Тогда имя имеет тип `K`, а данные и параметр обработчика — именно `Events[K]`.

Для хранилища тоже недостаточно одного массива обработчиков с общим аргументом. У каждого ключа должен быть свой массив функций с подходящей сигнатурой.

## 4. Решение по шагам

### Шаг 1. Описать карту событий

`EventMap` — обычный интерфейс, где ключи являются именами событий, а значения описывают соответствующие данные. Класс получает эту карту как параметр типа `Events`.

### Шаг 2. Построить хранилище через mapped type

```ts
private listeners: {
  [K in keyof Events]?: Array<(payload: Events[K]) => void>;
} = {};
```

Разберём запись изнутри наружу. `Events[K]` — данные конкретного события. `(payload: Events[K]) => void` — функция, принимающая эти данные. `Array<...>` хранит несколько подписчиков. `[K in keyof Events]` создаёт такое поле для каждого имени. Знак `?` разрешает отсутствие массива до первой подписки.

### Шаг 3. Добавить типизированные on и emit

Каждый метод объявляет собственный `K extends keyof Events`. В `on` он связывает имя с аргументом callback, а в `emit` — имя с передаваемым payload.

### Полный код

```ts
interface EventMap {
  userCreated: { id: number; name: string };
  userDeleted: { id: number };
}

class EventEmitter<Events extends object> {
  private listeners: {
    [K in keyof Events]?: Array<(payload: Events[K]) => void>;
  } = {};

  on<K extends keyof Events>(
    event: K,
    callback: (payload: Events[K]) => void
  ): void {
    const listeners = (this.listeners[event] ??= []);
    listeners.push(callback);
  }

  emit<K extends keyof Events>(event: K, payload: Events[K]): void {
    (this.listeners[event] || []).forEach((cb) => cb(payload));
  }
}

const emitter = new EventEmitter<EventMap>();

emitter.on("userCreated", (user) => console.log(user.name));
emitter.emit("userCreated", { id: 1, name: "Alice" });
```

## 5. Разбор подписки и отправки «вживую»

При `on("userCreated", callback)` параметр типа `K` становится `"userCreated"`. Поэтому `user` внутри callback выводится как `{ id: number; name: string }` без ручной аннотации.

Дальше выполняется обычный JavaScript:

1. Вначале `listeners` — пустой объект.
2. `this.listeners[event] ??= []` создаёт массив, если по ключу ещё нет значения.
3. Локальная переменная `listeners` получает ссылку на этот массив.
4. `push(callback)` сохраняет функцию для будущего вызова. При подписке она ещё не выполняется.
5. `emit` находит сохранённый массив и передаёт каждому callback объект пользователя.
6. Обработчик читает `name` и выводит `Alice`.

Повторная подписка добавит ещё одну функцию в тот же массив. Если отправить `userDeleted`, на который никто не подписался, выражение `|| []` даст пустой массив и вызовов не будет.

## 6. Какие ошибки замечает контракт

```ts
emitter.on("userDeleted", (user) => console.log(user.id));
emitter.emit("userDeleted", { id: 1 });

// emitter.on("userUpdated", () => {}); // Нет такого ключа.
// emitter.emit("userCreated", { id: 1 }); // Не хватает name.
// emitter.on("userDeleted", (user) => console.log(user.name));
// У данных удаления нет гарантированного name.
```

Ограничение `Events extends object` позволяет передать интерфейс `EventMap`, не требуя от него строковой индексной сигнатуры. Нам нужны конкретные известные поля карты, а не словарь всех возможных строк.

## 7. Границы этого решения и частые ошибки

- Не заменяйте `Events[K]` на `unknown` в аргументе пользовательского callback: тогда подписчик потеряет информацию о своих данных. `unknown` уместен на границе недоверенного ввода, но здесь карта уже задаёт контракт.
- Сопоставление наиболее точно для конкретных имён событий. Если вызывающий код заранее расширил имя до объединения ключей, `Events[K]` тоже станет объединением; строгие гарантии для таких динамических пар требуют дополнительного моделирования.
- Обработчики вызываются синхронно в порядке подписки. Класс не создаёт очередь микрозадач и не ждёт асинхронные callback.
- Исключение внутри callback прервёт текущий `forEach` и выйдет из `emit`. Отдельная политика обработки ошибок в условии не задана.
- В этом минимальном классе нет отписки, одноразовых подписок и устранения дубликатов. В долгоживущем приложении это отдельные требования к жизненному циклу слушателей.
- Типизация не валидирует данные, которые обошли типизированный контракт, например пришли из внешнего JavaScript.

## 8. Что запомнить

Карта событий служит источником истины, `K` сохраняет выбранное имя, а `Events[K]` связывает с ним данные. Тот же принцип используется и для публичных методов, и для внутреннего хранилища подписчиков.
