# Разбор задачи: «Перегрузка обработчика»

## 1. Что дано

Функция `createElement` создаёт обычные объекты по строке тега. Для `"img"` она добавляет `src`, для `"a"` — `href`, для любого другого значения возвращает только `tag`.

Это учебная функция. Несмотря на имя, она не вызывает `document.createElement` и не создаёт настоящие DOM-узлы.

## 2. Что нужно получить

| Вызов | Значение | Тип результата |
| --- | --- | --- |
| `createElement("img")` | `{ tag: "img", src: "" }` | `ImgElement` |
| `createElement("a")` | `{ tag: "a", href: "" }` | `AnchorElement` |
| `createElement("div")` | `{ tag: "div" }` | `GenericElement` |

У результата первого вызова должно быть сразу доступно `src`, у второго — `href`. Повторно выяснять тип после вызова не должно требоваться, если конкретный тег уже известен.

## 3. Почему общего union-результата недостаточно

Сигнатура с параметром `string` и результатом `ImgElement | AnchorElement | GenericElement` описывает все возможные выходы. Но она не связывает конкретный вход с одним выходом.

Даже после вызова с литералом `"img"` вызывающий код получал бы общий набор вариантов. Поле `src` есть не у каждого из них, поэтому пользоваться им без уточнения нельзя.

Перегрузки позволяют описать несколько зависимостей «аргумент → результат» для одной реализации.

## 4. Решение по шагам

### Шаг 1. Описать три формы результата

У специальных форм `tag` получает литеральный тип. Общая форма хранит `tag: string` и не обещает дополнительных свойств.

### Шаг 2. Объявить внешние сигнатуры

Сначала перечисляем точные случаи `"img"` и `"a"`, затем общий случай `string`. Эти объявления заканчиваются точкой с запятой и не содержат тела.

### Шаг 3. Написать одну реализацию

Последняя функция содержит реальный код и охватывает все объявленные варианты. Она по-прежнему обязана проверять тег: перегрузки не создают ветвление за нас.

### Полный код

```ts
interface ImgElement {
  tag: "img";
  src: string;
}

interface AnchorElement {
  tag: "a";
  href: string;
}

interface GenericElement {
  tag: string;
}

function createElement(tag: "img"): ImgElement;
function createElement(tag: "a"): AnchorElement;
function createElement(tag: string): GenericElement;
function createElement(
  tag: string
): ImgElement | AnchorElement | GenericElement {
  if (tag === "img") {
    return { tag, src: "" };
  }
  if (tag === "a") {
    return { tag, href: "" };
  }
  return { tag };
}

const img = createElement("img");
const link = createElement("a");
```

## 5. Как выбирается тип вызова

Для литерала `"img"` подходит специальная сигнатура, поэтому `img` получает `ImgElement`. У него можно написать `img.src = "photo.png"`. Аналогично `link.href = "/profile"` использует контракт для `"a"`.

Строка `"div"` не соответствует специальным литералам, но подходит общему строковому варианту. Результат имеет только гарантированное поле `tag`.

Сигнатура реализации не является дополнительной внешней перегрузкой. Вызывающий код опирается на три объявления над ней. Именно поэтому общий вариант с `tag: string` объявлен отдельно.

## 6. Что меняется для неизвестного заранее тега

```ts
const buildElement = (tag: string): GenericElement => {
  return createElement(tag);
};
```

Здесь аргумент известен только как `string`, поэтому выбирается общий контракт. Во время выполнения строка может оказаться `"img"`, и объект действительно получит `src`, но система типов не обещает этого заранее.

То же ограничение важно для аргумента-объединения: наличие отдельных перегрузок не означает автоматического объединения их результатов для любого union-входа. В текущей функции широкий строковый вариант даёт общий результат.

## 7. Важные детали и частые ошибки

- Не пишите отдельное тело под каждую сигнатуру. В TypeScript у этой функции одна JavaScript-реализация.
- Размещайте специальные варианты перед широкими: так набор перегрузок проще читать и корректно подбирать при пересекающихся сигнатурах.
- Не ограничивайтесь проверкой совместимости типов реализации. Она не доказывает полностью, что каждому входу возвращён именно обещанный объект: ветки должны соблюдать описанное соответствие.
- `GenericElement` не означает «объект физически не может иметь никаких других полей». Он означает, что внешний контракт гарантирует только `tag`.
- Здесь перегрузки полезны именно из-за зависимости результата от аргумента. Если бы результат был одинаковым, обычное объединение входных типов было бы проще.

## 8. Что запомнить

Перегрузки уточняют контракт вызова, а одна реализация выполняет работу. Чем точнее известен аргумент, тем точнее может быть выбранная сигнатура и тип результата.
