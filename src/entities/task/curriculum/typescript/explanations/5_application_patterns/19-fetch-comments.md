# Разбор задачи: «Получение данных»

## 1. Что дано

Есть адрес `https://jsonplaceholder.typicode.com/comments` и заготовка функции `getData(url)`. После получения комментариев нужно вывести каждый в формате `ID: id, Email: email`.

От комментария в этом упражнении нужны два поля: числовой `id` и строковый `email`. Другие поля ответа не участвуют в обработке.

## 2. Что нужно получить

Функция должна вернуть промис с массивом комментариев — `Promise<Comment[]>`. Получение ответа асинхронно: массив нельзя вернуть синхронно сразу после запуска запроса.

Если HTTP-ответ неуспешный, функция должна завершиться ошибкой. При успехе вызывающий код обходит массив и печатает отдельную строку для каждого элемента.

## 3. Почему одного fetch недостаточно

`fetch(url)` возвращает промис с объектом `Response`. Это ещё не массив комментариев. У ответа есть статус и методы для чтения тела.

Кроме того, ответы с HTTP-кодами `404` или `500` сами по себе не означают отклонение промиса `fetch`. Сервер ответил, но результат неуспешный — эту ситуацию нужно обработать через `response.ok`.

Таким образом, у решения две асинхронные стадии: дождаться ответа, затем прочитать его JSON-тело.

## 4. Решение по шагам

### Шаг 1. Описать используемые поля

Интерфейс `Comment` задаёт форму элемента массива. Мы не перечисляем поля, которые код не использует. Это описание ожидаемых данных, а не операция удаления остальных полей ответа.

### Шаг 2. Дождаться ответа и обработать статус

`async` делает результат функции промисом, `await fetch(url)` получает `Response`. Если `response.ok` ложно, бросаем ошибку: промис `getData` будет отклонён, а успешная ветка `.then` не выполнится.

### Шаг 3. Вернуть прочитанный JSON

`response.json()` тоже возвращает промис. Возврат этого промиса из `async`-функции не создаёт вложенный `Promise<Promise<...>>`: внешний промис принимает его итоговое состояние.

### Полный код учебного решения

```ts
interface Comment {
  id: number;
  email: string;
}

const COMMENTS_URL = "https://jsonplaceholder.typicode.com/comments";

const getData = async (url: string): Promise<Comment[]> => {
  const response = await fetch(url);

  if (!response.ok) {
    throw new Error("Failed to fetch data");
  }

  return response.json();
};

getData(COMMENTS_URL).then((data) => {
  data.forEach(({ id, email }) => {
    console.log(`ID: ${id}, Email: ${email}`);
  });
});
```

## 5. Разбор успешного выполнения

Пусть сервер вернул такой фрагмент данных:

```json
[
  { "id": 1, "email": "alice@example.com" },
  { "id": 2, "email": "bob@example.com" }
]
```

Сначала разрешается промис запроса. Успешный статус позволяет перейти к `response.json()`. После чтения JSON разрешается промис `getData`, и обработчик `.then` получает уже массив.

`forEach` вызывает функцию для каждого элемента. Деструктуризация `({ id, email })` извлекает два поля, а шаблонная строка формирует:

```text
ID: 1, Email: alice@example.com
ID: 2, Email: bob@example.com
```

Для пустого массива ничего не выводится: элементов для обхода нет.

## 6. Где заканчивается гарантия аннотации

Учебное решение предполагает, что API соблюдает ожидаемую структуру. Тип `Promise<Comment[]>` даёт удобный контракт вызывающему коду, но **не проверяет JSON во время выполнения**. `response.json()` разбирает JSON-синтаксис и может вернуть массив, объект, строку или другое значение.

Если нужно работать с недоверенным ответом, данные сначала принимают как `unknown`, а затем проверяют поля. Например, отдельный защитник для одного элемента:

```ts
const isComment = (value: unknown): value is Comment => {
  return (
    typeof value === "object" &&
    value !== null &&
    "id" in value &&
    typeof value.id === "number" &&
    "email" in value &&
    typeof value.email === "string"
  );
};
```

Тогда вместо прямого `return response.json()` внутри `getData` можно использовать:

```ts
const data: unknown = await response.json();

if (!Array.isArray(data) || !data.every(isComment)) {
  throw new Error("Некорректный формат комментариев");
}

return data;
```

Здесь массив проверяется отдельно, затем каждый его элемент. После успешных проверок тип результата подкреплён реальной логикой. Проверка строкового `email` ещё не доказывает корректность почтового адреса — это уже другое правило.

## 7. Ошибки и важные детали

- Возможны разные причины отклонения: ошибка сети, неуспешный HTTP-статус, некорректный JSON. При реальном использовании их нужно обрабатывать через `.catch` или `try/catch` с `await`.
- Не забывайте возвращать данные из `getData`: без `return` асинхронная функция завершится значением `undefined`.
- Не вызывайте `forEach` у результата `fetch` или у самого промиса. Перебирать нужно массив после чтения тела и ожидания результата.
- Метод `response.json()` следует вызывать один раз для этого тела ответа: оно читается как поток.
- Имя `Comment` в браузерных проектах также занято DOM-типом. Здесь подразумевается локальная модель комментария; при переносе кода в глобальный скрипт разумнее назвать её `ApiComment` или изолировать объявления модулем.

## 8. Что запомнить

Асинхронный контракт, проверка HTTP-статуса, чтение JSON и проверка структуры данных — отдельные шаги. Важно понимать, какую часть выполняет каждый из них, а не считать аннотацию заменой всей обработки ответа.
