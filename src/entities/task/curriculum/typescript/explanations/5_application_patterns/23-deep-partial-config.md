# Разбор задачи: «Глубокая настройка»

## 1. Что дано

Конфигурация `AppConfig` содержит две ветки: `theme` с цветом и размером шрифта, а также `features` с флагом тёмного режима и вложенной настройкой `beta.enabled`.

Функция `updateConfig` должна принимать частичное обновление. Например, пользователь хочет изменить только цвет, сохранив размер шрифта и все флаги.

## 2. Что нужно получить

Для текущей конфигурации:

```ts
const current: AppConfig = {
  theme: { color: "blue", fontSize: 16 },
  features: { darkMode: false, beta: { enabled: false } },
};
```

обновление `{ theme: { color: "red" } }` должно дать:

```ts
// {
//   theme: { color: "red", fontSize: 16 },
//   features: { darkMode: false, beta: { enabled: false } }
// }
```

Нужно решить две разные задачи: разрешить такую частичную форму **в типах** и действительно сохранить остальные поля **во время выполнения**.

## 3. Почему Partial и один spread не справляются

`Partial<AppConfig>` делает необязательными только `theme` и `features`. Если передать `theme`, внутри всё ещё потребуются и `color`, и `fontSize`. Для частичности на каждом уровне нужна рекурсия в типе.

У выражения `{ ...current, ...updates }` другая проблема. Spread объединяет верхний уровень: значение `updates.theme` целиком заменит `current.theme`. В примере выше размер шрифта исчезнет.

Даже идеальный тип `DeepPartial` сам не изменяет работу spread. Преобразование типов и алгоритм слияния нужно реализовать отдельно.

## 4. Решение по шагам

### Шаг 1. Рекурсивно сделать поля необязательными

```ts
type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K];
};
```

`[K in keyof T]` проходит по полям текущего типа, `?` разрешает пропуск поля. Если значение поля — объект, применяется тот же `DeepPartial` к его внутренней структуре. Для строки, числа или логического значения сохраняется исходный тип.

Для этой конфигурации результат можно прочитать как:

```ts
// {
//   theme?: { color?: string; fontSize?: number };
//   features?: {
//     darkMode?: boolean;
//     beta?: { enabled?: boolean };
//   };
// }
```

### Шаг 2. Объединить каждую известную ветку

Структура `AppConfig` небольшая и заранее известна. Поэтому достаточно явно собрать `theme`, `features` и `features.beta`, каждый раз сначала копируя текущие поля, а затем обновления.

### Полный код

```ts
interface AppConfig {
  theme: {
    color: string;
    fontSize: number;
  };
  features: {
    darkMode: boolean;
    beta: {
      enabled: boolean;
    };
  };
}

type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K];
};

const updateConfig = (
  current: AppConfig,
  updates: DeepPartial<AppConfig>
): AppConfig => {
  return {
    ...current,
    ...updates,
    theme: { ...current.theme, ...updates.theme },
    features: {
      ...current.features,
      ...updates.features,
      beta: { ...current.features.beta, ...updates.features?.beta },
    },
  };
};
```

## 5. Разбор вложенного обновления «вживую»

Рассмотрим вызов:

```ts
const next = updateConfig(current, {
  theme: { color: "red" },
  features: { beta: { enabled: true } },
});
```

1. Верхний уровень получает поля `current`, затем `updates`.
2. После spread явно формируется новый `theme`. Из текущего объекта берутся `color` и `fontSize`, затем только `color` перезаписывается на `"red"`.
3. В `features` сохраняется текущий `darkMode`. Обновление не содержит этот ключ, поэтому его значение остаётся `false`.
4. Вложенный `beta` собирается отдельно: текущий `enabled` заменяется на `true`.
5. Возвращается полная конфигурация, где все обязательные поля присутствуют.

```ts
// next.theme → { color: "red", fontSize: 16 }
// next.features → { darkMode: false, beta: { enabled: true } }
// current по-прежнему хранит исходные значения.
```

Явно собранные ветки стоят после `...updates`. Если поставить общий spread в конце, он снова затрёт результат аккуратного вложенного объединения.

## 6. Почему нужны ?. и правильный порядок

`updates.features` может отсутствовать. Выражение `updates.features?.beta` безопасно вернёт `undefined` вместо обращения к полю отсутствующего объекта. Spread объекта из `undefined` не добавляет свойств, поэтому в таком случае сохраняется текущий `beta`.

У `theme` отдельная опциональная цепочка не нужна: чтение `updates.theme` уже допустимо, а доступа к его внутреннему полю в этом выражении нет.

Каждое объединение идёт в порядке «текущее → обновление». Обратный порядок восстановил бы старые значения поверх новых.

## 7. Границы решения и частые ошибки

- Обновление `{}` сохраняет значения всех настроек. Пустой объект во вложенной ветке также не должен стирать её текущие поля.
- Частичность здесь означает **пропустить** поле, которое не нужно менять. Явное значение `undefined` может перезаписать примитивное поле через spread, если настройки типизации или внешний ввод позволяют его передать. Если API трактует `undefined` как «не менять», потребуется отдельная нормализация; полезна и настройка `exactOptionalPropertyTypes`.
- Данный `DeepPartial` рассчитан на показанную структуру из обязательных вложенных объектов и примитивов. Для массивов, функций, `Date` и сложных объединений нужно заранее определить правила преобразования.
- Алгоритм слияния написан для конкретного `AppConfig`. Если добавить новую вложенную ветку, её слияние тоже нужно описать: рекурсивный тип не обновит JavaScript-алгоритм автоматически.
- Функция создаёт новые объекты и не присваивает значения в `current`. Для этой структуры все вложенные ветки результата также пересоздаются.
- Обновление не удаляет свойства. Если требуется удаление, его нужно выразить отдельным соглашением, а не смешивать с отсутствующим ключом.

## 8. Что запомнить

`DeepPartial` разрешает неполный вход на вложенных уровнях, а явное слияние сохраняет полную конфигурацию в результате. Корректная форма аргумента и корректное изменение данных — две части одного решения.
