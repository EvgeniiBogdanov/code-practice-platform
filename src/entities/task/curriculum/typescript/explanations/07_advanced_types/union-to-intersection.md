# Разбор задачи: «Объединение в пересечение»

## 1. Что дано

`combine` сливает плагины в один объект. Параметр `...plugins` — кортеж, и `P[number]` даёт **объединение** типов плагинов: `{ log } | { now } | { random }`. Но результат слияния содержит методы **всех** плагинов, то есть это **пересечение** `{ log } & { now } & { random }`. Нужно превратить одно в другое.

## 2. Что нужно получить

```ts
UnionToIntersection<A | B | C> // A & B & C
```

и функцию `combine`, у результата которой доступны все методы с точными сигнатурами.

## 3. Ключевая идея: вывод из контравариантной позиции

Когда TypeScript выводит `infer I` из нескольких кандидатов:

- в **ковариантной** позиции (результат функции, поле объекта) кандидаты объединяются через `|`;
- в **контравариантной** позиции (параметр функции) — через `&`.

Почему пересечение? Если одна функция должна подходить сразу под `(arg: A) => void` и `(arg: B) => void`, её параметр обязан принимать и `A`, и `B`, то есть `A & B`.

## 4. Решение по шагам

```ts
type UnionToIntersection<U> = (U extends unknown ? (arg: U) => void : never) extends (
  arg: infer I
) => void
  ? I
  : never;
```

### Шаг 1. Распределить U по функциям

`U extends unknown ? (arg: U) => void : never` — распределяющий условный тип. Для `A | B | C` получается объединение функций:

```ts
((arg: A) => void) | ((arg: B) => void) | ((arg: C) => void)
```

### Шаг 2. Вывести тип параметра

Это объединение сопоставляется с `(arg: infer I) => void`. У `I` три кандидата — `A`, `B`, `C`, — и все в позиции параметра. TypeScript объединяет их пересечением: `I = A & B & C`.

Внешний условный тип не распределяется, потому что слева стоит не голый параметр, а вычисленное выражение.

## 5. combine

```ts
type Combined<P extends object[]> = UnionToIntersection<P[number]>;

const combine = <P extends object[]>(...plugins: P): Combined<P> =>
  plugins.reduce<object>((result, plugin) => ({ ...result, ...plugin }), {}) as Combined<P>;
```

- rest-параметр `...plugins: P` выводит кортеж типов плагинов;
- `P[number]` — объединение всех плагинов;
- `UnionToIntersection` превращает его в пересечение.

`reduce` не умеет накапливать типы шаг за шагом: на каждом шаге результат имеет тип `object`. Поэтому связь с вычисленным пересечением фиксируется одним утверждением на выходе. Публичная сигнатура при этом точная: `api.random("10")` — ошибка.

## 6. Тонкости

- **Примитивы.** `UnionToIntersection<string | number>` — `never`: `string & number` пуст. Приём имеет смысл для объектов и функций.
- **boolean.** `UnionToIntersection<boolean>` — `true & false`, то есть `never`.
- **Конфликты.** Если два плагина объявят `log` с разными сигнатурами, пересечение создаст перегрузку, а при несовместимых полях-значениях — `never` для поля.
- **Порядок спреда.** Во время выполнения при совпадении ключей побеждает последний плагин, а тип описывает пересечение. Для конфликтующих плагинов тип и поведение расходятся.

## 7. Где применяется

- объединение плагинов и middleware (контекст, накопленный разными слоями);
- слияние слайсов стора в один тип состояния;
- построение перегрузок из объединения функций;
- как шаг в более сложных типах вроде `UnionToTuple`.

## 8. Частые ошибки

- Пытаться построить пересечение через отображаемый тип по ключам объединения: `keyof (A | B)` — только общие ключи.
- Забыть распределение на первом шаге и получить одну функцию `(arg: A | B | C) => void`, из которой выводится объединение.
- Ожидать, что тип поможет с конфликтующими ключами во время выполнения.

## 9. Что запомнить

`infer` в позиции параметра функции объединяет кандидатов пересечением. Распределив объединение по функциям и выведя тип параметра, получаем `A & B & C`. Этот приём опирается на контравариантность из задачи о вариантности.
