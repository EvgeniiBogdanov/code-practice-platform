# Разбор задачи: «Операции с кортежами»

## 1. Что дано

Кортеж знает тип и порядок каждой позиции, а также точную длину. На этом построены вычисления на уровне типов: типизация аргументов функций, `Promise.all`, `pipe`, `curry`. Нужно освоить базовые операции.

## 2. Что нужно получить

| Тип | Результат |
| --- | --- |
| `First<[1, 2, 3]>` | `1` |
| `Last<[1, 2, 3]>` | `3` |
| `Length<[1, 2, 3]>` | `3` |
| `Concat<[1], [2, 3]>` | `[1, 2, 3]` |
| `Reverse<[1, "a", true]>` | `[true, "a", 1]` |
| `concat([1, "a"], [true])` | `[1, "a", true]` |

## 3. Инструменты

**Шаблон кортежа с infer.** В `extends` можно описать форму кортежа и извлечь части:

```ts
T extends [infer F, ...infer Rest] // первый элемент и остаток
T extends [...infer Init, infer L] // начало и последний элемент
```

**Вариативные кортежи** (TypeScript 4.0). Кортеж-параметр можно раскрыть в любой позиции: `[...A, ...B]`.

**length кортежа** — числовой литерал, а не `number`.

## 4. Решение по шагам

### First и Last

```ts
type First<T extends readonly unknown[]> = T extends readonly [infer F, ...unknown[]] ? F : never;
type Last<T extends readonly unknown[]> = T extends readonly [...unknown[], infer L] ? L : never;
```

Пустой кортеж не совпадает с шаблоном «хотя бы один элемент», поэтому результат — `never`. `readonly` в ограничении и шаблоне позволяет принимать и `readonly`-кортежи, например результат `as const`.

Почему не `T[0]`? Для пустого кортежа `[][0]` — ошибка, а для массива `T[0]` вернёт тип элемента, хотя массив может быть пустым.

### Length

```ts
type Length<T extends readonly unknown[]> = T["length"];
```

Для кортежа `[1, 2, 3]` поле `length` имеет тип `3`.

### Concat

```ts
type Concat<A extends readonly unknown[], B extends readonly unknown[]> = [...A, ...B];
```

### Reverse — рекурсия

```ts
type Reverse<T extends readonly unknown[]> = T extends readonly [infer F, ...infer Rest]
  ? [...Reverse<Rest>, F]
  : [];
```

| Шаг | `T` | Результат |
| --- | --- | --- |
| 1 | `[1, "a", true]` | `[...Reverse<["a", true]>, 1]` |
| 2 | `["a", true]` | `[...Reverse<[true]>, "a"]` |
| 3 | `[true]` | `[...Reverse<[]>, true]` |
| 4 | `[]` | `[]` |
| итог | | `[true, "a", 1]` |

### concat — функция

```ts
const concat = <const A extends readonly unknown[], const B extends readonly unknown[]>(
  a: A,
  b: B
): [...A, ...B] => [...a, ...b];
```

- Модификатор `const` выводит литерал `[1, "a"]` как кортеж `readonly [1, "a"]`, а не как `(string | number)[]`.
- Ограничение `readonly unknown[]` обязательно: с `const` выводится `readonly`-кортеж, и изменяемое ограничение `unknown[]` его бы не приняло.
- Спред двух обобщённых кортежей TypeScript типизирует как `[...A, ...B]`, поэтому утверждение не нужно.

## 5. Где это применяется

- типизация аргументов функций: параметры функции — это кортеж (`Parameters<F>`);
- `Promise.all` возвращает кортеж результатов;
- `curry`, `pipe`, `bind` — преобразования кортежей аргументов;
- счётчики на уровне типов: «прибавить единицу» — значит добавить элемент в кортеж и прочитать `length`.

## 6. Частые ошибки

- Использовать `T[0]` для первого элемента и не учитывать пустой кортеж.
- Забыть `readonly` в шаблоне и не поддержать кортежи из `as const`.
- Писать `const A extends unknown[]` — `const`-вывод откатится к обычному, и позиции потеряются.

## 7. Что запомнить

Шаблоны `[infer F, ...infer Rest]` и `[...infer Init, infer L]` разбирают кортеж, `[...A, ...B]` собирает его обратно, а рекурсия позволяет обработать кортеж любой длины.
