# Разбор задачи: «Optimistic-отправка сообщений»

## 1. Идея optimistic update

Пользователь нажимает «Отправить» и ждёт, пока сообщение появится в чате после ответа сервера: на медленной сети это секунды. **Optimistic update** обновляет интерфейс сразу, исходя из того, что запрос удастся, и исправляет картину, если это не так.

У подхода три обязательных части:

1. мгновенное отображение (`status: "sending"`);
2. подтверждение (`"sent"`);
3. **обработка неудачи**: откат или пометка с возможностью повторить.

## 2. Откат или повтор

| Действие | Что делать при ошибке |
| --- | --- |
| Лайк, переключатель | Вернуть прежнее состояние и показать уведомление |
| Сообщение, комментарий | Оставить с пометкой «не отправлено» и дать повторить: пользователь не должен потерять текст |

## 3. Решение по шагам

### Шаг 1. Иммутабельный список

Каждое изменение создаёт новый массив (`map`, `[...messages, message]`) и передаётся в `onChange`. React и `useSyncExternalStore` замечают изменение по ссылке; мутация на месте осталась бы незамеченной.

### Шаг 2. Очередь как цепочка промисов

```ts
queue = queue.then(async () => {
  try { await send(...); setStatus(id, "sent"); }
  catch { setStatus(id, "failed"); }
});
```

Следующая отправка стартует только после предыдущей. Порядок сообщений в чате сохраняется даже при разном времени ответа сервера. `try/catch` внутри цепочки важен: иначе отклонённый промис оборвал бы всю очередь.

### Шаг 3. `retry` только для `failed`

Повтор возвращает статус `sending` и ставит сообщение **в конец** очереди. Для остальных статусов он ничего не делает: нельзя отправить дважды то, что ещё отправляется или уже отправлено.

## 4. Идемпотентность

Клиентский `id` нужен не только для списка. Если ответ потерялся, а сообщение на сервер дошло, повтор создаст дубль. Сервер защищается идемпотентностью: сообщение с уже известным `id` повторно не создаётся.

## 5. Как это выглядит с TanStack Query

В `useMutation` для этого есть `onMutate` (показать сразу), `onError` (откатить) и `onSettled` (сверить с сервером). Но очередь по порядку для чата остаётся за вами: мутации по умолчанию выполняются параллельно.

## 6. Что обсудить на интервью

- Как сохранять черновики при перезагрузке страницы (`localStorage` или IndexedDB).
- Что делать при долгом офлайне и как показать статус каждому сообщению.
- Как сочетать с WebSocket: отправка по сокету, подтверждение приходит событием (см. предыдущее упражнение).
