# Разбор задачи: «Поиск с debounce и защитой от гонок»

## 1. Что здесь проектируется

Автокомплит кажется простым: «слушаем ввод, шлём запрос». На деле в нём три независимые проблемы, и каждая решается своим приёмом.

| Проблема | Симптом | Приём |
| --- | --- | --- |
| Слишком много запросов | На каждую букву уходит запрос, сервер перегружен | **debounce**: запрос уходит после паузы в наборе |
| Запросы остаются в полёте | Ответ на «re» приходит, когда пользователь уже набрал «react» | **отмена** через `AbortController` |
| Ответы приходят в другом порядке | Подсказки к старому запросу затирают свежие | **проверка актуальности** ответа |

## 2. Решение по шагам

### Шаг 1. Единая «эпоха»

Любое новое действие пользователя (`search` или `cancel`) делает все прошлые ожидания неактуальными. Это удобно выразить одним счётчиком:

```ts
let epoch = 0;

const cancel = (): void => {
  clearTimeout(timer);
  controller?.abort();
  epoch += 1;
};
```

`cancel` снимает ожидающую паузу, прерывает запрос в полёте и «сжигает» эпоху.

### Шаг 2. Запрос запоминает свою эпоху

```ts
const current = epoch;
// ...
if (current === epoch) onResults(items);
```

Если за время запроса эпоха сменилась, ответ устарел. Он молча выбрасывается, и пользователь не видит подсказок к тексту, которого в поле уже нет.

### Шаг 3. Ошибка отмены — не ошибка

Прерванный `fetch` отклоняется с `AbortError`. Проверка `current === epoch` в `catch` отсекает его: отмена всегда означает, что эпоха уже сменилась.

### Шаг 4. Пустой запрос

Строка из пробелов не должна уходить на сервер. `search("")` сразу вызывает `onResults([])`, а прежние ожидания уже сняты вызовом `cancel()` в начале.

## 3. Почему отмена и проверка актуальности нужны вместе

- **Только проверка актуальности.** UI защищён, но браузер продолжает качать лишние ответы, а сервер считает их до конца.
- **Только `AbortController`.** Отмена не гарантирована: ответ мог прийти до вызова `abort()`, но обработчик выполнится позже. Без проверки он перезапишет новый список.

Поэтому в продакшене используют оба приёма. Библиотеки вроде TanStack Query делают это за вас: у запроса есть ключ, смена ключа отменяет прежний запрос, а устаревший результат не попадает в компонент.

## 4. Как это выглядит в React

```tsx
const [query, setQuery] = useState("");
const debouncedQuery = useDebouncedValue(query, 300);
const { data } = useQuery({
  queryKey: ["search", debouncedQuery],
  queryFn: ({ signal }) => searchApi(debouncedQuery, signal),
  enabled: debouncedQuery.trim() !== "",
});
```

Debounce живёт на значении, отмену по `signal` даёт библиотека. Но принципы те же, что и в этом упражнении.

## 5. Что обсудить на интервью

- Почему 300 мс, а не 100 или 1000? Это компромисс между задержкой ответа и нагрузкой; значение подбирают по данным.
- Нужен ли запрос на один символ? Часто нет: `minLength` экономит запросы, которые возвращают слишком общий список.
- Что делать с клавиатурой и доступностью? Это паттерн combobox: `aria-activedescendant`, стрелки, `Esc` (см. кейс «Автокомплит»).
