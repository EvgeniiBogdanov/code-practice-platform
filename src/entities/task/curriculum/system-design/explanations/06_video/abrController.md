# Разбор задачи: «Выбор качества видео (ABR)»

## 1. Зачем это плееру

Видео нарезано на сегменты по 2–6 секунд, каждый есть в нескольких качествах: лесенка битрейтов от 360p до 1080p. Перед каждым сегментом плеер решает, какое качество качать. Это **адаптивный битрейт** (ABR).

Две противоположные ошибки:

- **слишком высокое качество** — сегмент качается дольше, чем играет, буфер кончается, видео встаёт на паузу;
- **слишком частые переключения** — картинка то резкая, то мыльная, и это заметно глазу.

Пауза раздражает сильнее, чем мыло, поэтому вниз переключаемся быстро, а вверх — осторожно.

## 2. Решение по шагам

### Шаг 1. Сглаженная оценка сети

Скорость одного сегмента шумная: в метро соседние замеры отличаются в разы. Экспоненциальное сглаживание (EWMA) учитывает новый замер с весом `alpha`:

```ts
estimate = estimate === null ? sample : alpha * sample + (1 - alpha) * estimate;
```

Маленький `alpha` — оценка устойчива к выбросам, но медленнее реагирует на реальное падение сети. Большой — наоборот.

### Шаг 2. Запас

Оценка — среднее, а сеть колеблется вокруг него. Поэтому выбираем качество, которое влезает не в оценку, а в `estimate * safety` (например, 80% от оценки). Запас поглощает колебания без пауз.

### Шаг 3. Асимметричные переключения

```ts
if (target < current) current = target;
else if (target > current && bufferSec >= minBufferForUpSec) current += 1;
```

- **Вниз — сразу до цели.** Если сеть упала, каждый лишний тяжёлый сегмент приближает паузу.
- **Вверх — по одной ступени и только с запасом буфера.** Если повышение окажется ошибкой, полный буфер даст время вернуться вниз без паузы.

### Шаг 4. Старт

Без замеров оценки нет. Начинаем с низкого качества: первый сегмент маленький, первый кадр появляется быстро, а по нему уже есть первый замер.

## 3. Подводные камни

- **Замер маленького сегмента.** На коротком запросе время установления соединения больше времени передачи, и скорость занижается. Плееры отбрасывают замеры слишком маленьких сегментов.
- **Только пропускная способность.** Реальные плееры учитывают и уровень буфера: алгоритмы на основе буфера (BOLA) выбирают качество по тому, сколько видео уже скачано. hls.js и dash.js комбинируют оба подхода.
- **Разрешение выше экрана.** Нет смысла качать 4K в окно на 640 пикселей: верхнюю ступень ограничивает размер плеера.
- **Ручной выбор.** Если зритель выбрал качество сам, автоматика отключается до сброса выбора.

## 4. Связь с реальными плеерами

hls.js хранит две EWMA-оценки, быструю и медленную, и берёт меньшую из них. Shaka Player и dash.js устроены похоже и дают настроить запас и пороги буфера.

## 5. Что обсудить на интервью
