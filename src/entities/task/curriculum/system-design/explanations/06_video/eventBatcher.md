# Разбор задачи: «Пакетная отправка метрик»

## 1. Зачем это видеосервису

Качество просмотра нельзя улучшить, не измеряя его на реальных зрителях: время до первого кадра, буферизация, смены качества, ошибки. Плеер генерирует десятки событий за просмотр.

- **Запрос на каждое событие** конкурирует с видео за сеть и батарею.
- **Один отчёт в конце** теряется: большинство просмотров обрываются закрытием вкладки.

Решение — очередь событий, которая отправляется пачками: по размеру, по таймеру и принудительно при уходе со страницы.

## 2. Решение по шагам

### Шаг 1. Три повода отправить

- Набралось `maxBatch` событий — отправляем сразу.
- Прошло `flushMs` с первого события в очереди — отправляем, что есть: метрики не должны лежать минутами.
- Страница уходит (`flush`) — отправляем всё.

### Шаг 2. Одна отправка за раз

```ts
while (queue.length >= maxBatch || (sendAll && queue.length > 0)) {
  const batch = queue.splice(0, maxBatch);
  await send(batch);
}
```

Цикл забирает пачку, ждёт отправки и проверяет очередь снова. События, пришедшие во время отправки, уйдут следующей пачкой: параллельных запросов нет, порядок сохраняется.

### Шаг 3. Ошибка не теряет события

Отклонённая пачка возвращается **в начало** очереди. Следующая отправка (по таймеру, размеру или `flush`) повторит её первой, и сервер получит события в исходном порядке.

### Шаг 4. Предел очереди

Без сети очередь растёт бесконечно и съедает память. При переполнении выбрасываем самые старые события: свежие важнее для диагностики текущего просмотра.

## 3. Подводные камни

- **Закрытие вкладки.** Обычный `fetch` при закрытии страницы может не дойти. На событие `visibilitychange` (вкладка скрыта) последнюю пачку отправляют через `navigator.sendBeacon` или `fetch` с `keepalive: true`.
- **Дубли при повторе.** Если сервер принял пачку, а ответ потерялся, повтор пришлёт её второй раз. Помогает id события: сервер отбрасывает уже виденные.
- **Повторы без паузы.** При сбое сервера метрик клиенты не должны долбить его: пауза между повторами растёт.
- **Персональные данные.** В метрики не кладём ничего, что идентифицирует зрителя сверх нужного; IP и user agent сервер видит и так.

## 4. Связь с реальными инструментами

Так устроены SDK аналитики и RUM: Sentry, Amplitude, библиотека `web-vitals` в связке с `sendBeacon`. Плееры отдают события QoE (Quality of Experience) в похожем формате.
