# Разбор задачи: «Пересчёт формул по графу зависимостей»

## 1. Зачем это таблице

Формулы ссылаются друг на друга: `D1 = B1 + C1`, `B1 = A1 + 1`, `C1 = A1 * 10`. Пользователь меняет `A1`, и нужно обновить всё, что от неё зависит.

- **Пересчитать весь лист** — просто, но на тысячах формул каждый ввод становится медленным.
- **Пересчитать зависимые в произвольном порядке** — `D1` может посчитаться раньше `B1` и взять старое значение.
- **Пересчитывать рекурсивно от каждой ячейки** — в ромбе `D1` посчитается дважды, а в длинной цепочке ромбов — экспоненциальное число раз.

Нужно: только зависимые формулы, каждая один раз, после всех своих зависимостей. Это топологическая сортировка.

## 2. Решение по шагам

### Шаг 1. Обратные ссылки

Формула знает, какие ячейки читает (`deps`). Для пересчёта нужен обратный вопрос: кто читает эту ячейку. Храним `dependents: ячейка → формулы` и обновляем при каждой записи формулы. Старую формулу ячейки сначала отвязываем, иначе её прежние зависимости продолжат вызывать пересчёт.

### Шаг 2. Что затронуто

Обходом от изменённой ячейки по обратным ссылкам собираем все достижимые формулы. Обход — стеком, а не рекурсией: цепочка из десятков тысяч формул переполнит стек вызовов.

### Шаг 3. Порядок (алгоритм Кана)

Для каждой затронутой формулы считаем, сколько её зависимостей тоже затронуто и ещё не посчитано. Формулы с нулём готовы. Посчитали формулу — уменьшаем счётчик у тех, кто её читает; дошёл до нуля — формула готова.

```ts
const id = ready.shift()!;
evaluate(id);
for (const reader of dependents.get(id) ?? []) {
  const left = waiting.get(reader)! - 1;
  waiting.set(reader, left);
  if (left === 0) ready.push(reader);
}
```

Каждая формула попадает в очередь ровно один раз — когда посчитаны все её зависимости.

### Шаг 4. Циклы

В цикле каждая формула ждёт другую, и счётчики никогда не доходят до нуля. Поэтому всё, что осталось непосчитанным после алгоритма Кана, — это цикл или то, что от него зависит. Им ставим `#CYCLE`. Вкладка не зависает, а пользователь видит ошибку в ячейке.

## 3. Подводные камни

- **Ссылка на саму себя.** `A1 = A1 + 1` — цикл длины один, его ловит то же правило.
- **Повторная зависимость.** `A1 + A1` читает ячейку дважды, но ждать её нужно один раз: считаем различные зависимости.
- **Распространение ошибки.** Формула, которая читает `#CYCLE` или `#DIV/0!`, тоже даёт ошибку, а не `NaN`.
- **Диапазоны.** `SUM(A1:A100000)` даёт сто тысяч рёбер. Движки хранят ссылку на диапазон как один узел и проверяют попадание ячейки в него.
- **Летучие функции.** `NOW()` и `RAND()` пересчитываются при каждом изменении, их помечают отдельно.

## 4. Связь с реальными движками

Excel и Google Sheets строят граф зависимостей и пересчитывают только «грязные» ячейки. Тот же принцип у реактивных библиотек: MobX, сигналы в Solid и Preact пересчитывают производные значения по графу и в топологическом порядке.
