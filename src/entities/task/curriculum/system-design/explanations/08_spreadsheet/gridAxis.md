# Разбор задачи: «Ось виртуализированной сетки»

## 1. Зачем это таблице

Лист на миллион строк нельзя отрисовать целиком: ни DOM, ни canvas не справятся. Рисуется только окно — строки и колонки, которые сейчас видны, плюс небольшой запас. Чтобы найти окно, нужно ответить на два вопроса:

- где начинается строка `i` (`offsetOf`);
- какая строка лежит на смещении прокрутки (`indexAt`).

Если все строки одной высоты, это деление. Но пользователь растягивает строки, и тогда смещение — сумма высот всех строк до нужной. Сетка двумерная, но строки и колонки независимы: одна такая ось для строк, вторая — для колонок.

## 2. Решение по шагам

### Шаг 1. Хранить только исключения

Из миллиона строк изменённых обычно единицы или сотни. Храним размеры только для них:

```ts
const offsetOf = (index: number): number => {
  let offset = index * defaultSize;
  for (const [row, size] of sizes) if (row < index) offset += size - defaultSize;
  return offset;
};
```

Смещение — это «все строки одинаковые» плюс поправки от изменённых строк выше. Время зависит от числа изменённых строк, а не от номера строки.

### Шаг 2. Двоичный поиск строки

Смещения растут вместе с индексом, поэтому строку по смещению можно искать двоичным поиском: последняя строка, которая начинается не позже нужного смещения.

```ts
while (low < high) {
  const mid = Math.ceil((low + high) / 2);
  if (offsetOf(mid) <= offset) low = mid;
  else high = mid - 1;
}
```

Двадцать шагов на миллион строк. Смещения за пределами оси сами превращаются в первую или последнюю строку.

### Шаг 3. Окно

Первая видимая строка — строка на `scroll`. Последняя — строка на нижней границе окна, если она начинается выше границы. Строка, которая начинается ровно на границе, ещё не видна. К окну добавляется запас `overscan`, чтобы при быстрой прокрутке не мелькали пустые полосы.

## 3. Подводные камни

- **Массив префиксных сумм.** Его легко построить, но после изменения строки 0 пересчитывается весь миллион элементов.
- **Много изменённых строк.** Если пользователь растянул десятки тысяч строк, перебор поправок становится медленным. Тогда используют дерево Фенвика или дерево отрезков: и смещение, и изменение размера за O(log n).
- **Граница окна.** Ошибка на единицу даёт лишнюю или потерянную строку внизу, и её видно при прокрутке.
- **Огромные смещения.** Браузеры ограничивают высоту элемента (порядка десятков миллионов пикселей). Для очень длинных осей прокрутку масштабируют, а не задают реальной высотой.

## 4. Связь с реальными библиотеками

TanStack Virtual и react-window решают ту же задачу для списков и сеток: измеряют размеры, хранят смещения и ищут окно двоичным поиском. Google Sheets рисует сетку на canvas по тому же принципу.
