# Разбор задачи: «Кэш stale-while-revalidate»

## 1. Зачем это в карточке товара

Карточка открывается часто, а цены и остатки меняются. Два плохих варианта:

- **всегда ждать сеть** — карточка медленная на мобильной;
- **показывать кэш без обновления** — цена может устареть навсегда.

Stale-while-revalidate (SWR) берёт лучшее из двух: отдаёт устаревшее значение **сразу** и обновляет его в фоне. Следующее открытие уже покажет свежее.

Решение о покупке при этом принимается по серверной проверке, а не по кэшу: кэш только для показа.

## 2. Решение по шагам

### Шаг 1. Запись с временем

```ts
interface Entry<V> {
  value: V;
  storedAt: number;
}
```

Запись помнит, когда её сохранили. По разнице с `Date.now()` видно, свежа она или устарела.

### Шаг 2. Три случая в `get`

- Записи нет: ждём `fetcher`, сохраняем результат и возвращаем его.
- Запись свежая (моложе `staleMs`): отдаём без запроса.
- Запись устарела: отдаём сразу и запускаем обновление в фоне.

### Шаг 3. Одно обновление на ключ

Пока обновление идёт, новые `get` не должны запускать второй запрос. Для этого хранится `inflight`: если запрос уже есть, возвращаем его же.

```ts
const pending = inflight.get(key);
if (pending) return pending;
```

Запрос удаляется из `inflight` в `finally`, поэтому следующее устаревание снова запустит обновление.

### Шаг 4. Ошибка фонового обновления

Фоновое обновление никто не ждёт, поэтому его ошибка не должна стать необработанной. Поймайте её и оставьте запись как была:

```ts
revalidate(key).catch(() => {});
```

Запись не меняется при ошибке, пользователь продолжает видеть последнее известное значение.

## 3. Подводные камни

- **Пустой catch скрывает проблемы.** В реальном приложении ошибку фонового обновления стоит отправлять в мониторинг, но не показывать пользователю.
- **`invalidate` во время обновления.** Запрос в полёте может записать значение уже после инвалидации. Для строгой гарантии нужна версия записи.
- **Свежесть и устаревание — разные сроки.** `staleMs` задаёт, когда запись перестаёт считаться свежей, а не когда её удаляют.

## 4. Связь с реальными библиотеками

TanStack Query и SWR работают по тому же принципу: `staleTime` определяет свежесть, а фоновая перепроверка запускается при устаревании. Здесь мы строим то же самое вручную, чтобы понимать механику.

## 5. Что обсудить на интервью
