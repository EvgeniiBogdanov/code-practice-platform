# Разбор задачи: «Троттлинг с ведущим и завершающим вызовом»

## 1. Зачем троттлинг в маркетплейсе

Обработчик скролла каталога и изменение размера окна срабатывают десятки раз в секунду. Загрузка следующей порции или пересчёт видимых карточек на каждый кадр — лишняя работа. Троттлинг ограничивает частоту: функция выполняется не чаще одного раза за интервал.

Но просто **пропускать** вызовы внутри интервала опасно: если пользователь остановился на середине окна, последнее положение скролла так и не обработается. Поэтому троттлинг с **ведущим** и **завершающим** вызовом: первый вызов сразу, последний — в конце окна.

## 2. Решение по шагам

### Шаг 1. Окно — это таймер

Пока таймер активен, мы внутри окна. Вызов сразу выполняется только тогда, когда таймера нет:

```ts
if (timer === null) {
  fn(...args);
  openWindow();
  return;
}
pendingArgs = args;
```

### Шаг 2. Конец окна

По окончании окна берём запомненные аргументы, сбрасываем их и выполняем функцию. Затем окно открывается снова: иначе следующий вызов прошёл бы без паузы.

Если вызовов внутри окна не было, `pendingArgs` пуст, окно просто закрывается и следующий вызов снова будет ведущим.

### Шаг 3. Отмена

`cancel` отменяет таймер и очищает запомненный вызов. Важно сбросить `timer` в `null`: иначе следующий вызов будет считаться внутри окна и не выполнится.

## 3. Подводные камни

- **Потеря финального состояния.** Пропуск вызовов без завершающего даёт устаревший результат: последний скролл не обработан.
- **Окно не продлевается.** Завершающий вызов открывает новое окно, иначе два вызова подряд, попавшие на границу, выполнятся без паузы.
- **Отмена не сбрасывает состояние.** Если забыть `timer = null`, следующий вызов «застрянет» внутри окна.

## 4. Троттлинг, debounce и лимит на сервере

| Механизм | Что делает | Где нужен |
| --- | --- | --- |
| **Debounce** | Ждёт паузы в вызовах и выполняется один раз | Поиск, автосохранение черновика |
| **Троттлинг** | Выполняется не чаще раза в интервал | Скролл, resize, движение мыши |
| **Rate limit на сервере** | Ограничивает число запросов от клиента, отвечает `429` | Защита сервера, скрапинг цен |

Троттлинг на клиенте защищает интерфейс, но не сервер: клиент можно обойти. Серверу нужен собственный лимит, а клиент обязан уважать `Retry-After`.

## 5. Что обсудить на интервью

- Почему для скролла троттлинг, а для поиска debounce.
- Что случится, если завершающий вызов отбросить.
- Почему клиентский троттлинг не заменяет rate limit на сервере.
