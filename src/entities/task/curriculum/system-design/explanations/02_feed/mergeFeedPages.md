# Разбор задачи: «Слияние страниц ленты»

## 1. Контекст

Бесконечная лента грузится порциями. API возвращает страницу и курсор следующей:

```ts
{ items: Post[], nextCursor: string | null }
```

Курсор указывает на конкретный элемент, а не на номер страницы, поэтому новые посты в начале ленты не сдвигают границы. Но запросы идут в разное время, и данные меняются между ними: пост может прийти дважды, во второй раз со свежим счётчиком лайков.

## 2. Что должна делать функция

- склеить страницы по порядку;
- убрать дубликаты по `id`;
- оставить пост там, где он встретился впервые (чтобы список не «прыгал»), но показать **самые свежие данные**;
- взять `nextCursor` у последней страницы;
- ничего не мутировать (React-состояние и кэш запросов нельзя менять на месте).

## 3. Решение

```ts
const byId = new Map<string, T>();
for (const page of pages) {
  for (const item of page.items) byId.set(item.id, item);
}
return { items: [...byId.values()], nextCursor: pages.at(-1)?.nextCursor ?? null };
```

Ключ в том, как работает `Map.set` для существующего ключа: значение заменяется, а **позиция сохраняется**. Один проход даёт и дедупликацию, и нужный порядок.

## 4. Альтернативы и их цена

| Подход | Проблема |
| --- | --- |
| `items.filter((x, i) => items.findIndex(...) === i)` | O(n²), оставляет **старую** версию поста |
| Дедупликация по `Set` из `id` | Теряет свежие данные |
| Хранить страницы в `useState` вручную | Нужно самому решать гонки, повторные загрузки и инвалидацию |

## 5. Как это выглядит в React

```tsx
const { data, fetchNextPage, hasNextPage } = useInfiniteQuery({
  queryKey: ["feed"],
  queryFn: ({ pageParam }) => fetchFeed(pageParam),
  initialPageParam: null,
  getNextPageParam: (page) => page.nextCursor,
});
const items = useMemo(() => mergeFeedPages(data?.pages ?? []).items, [data]);
```

Загрузкой страниц занимается библиотека, а слияние остаётся чистой функцией: её легко тестировать и переиспользовать.

## 6. Что обсудить на интервью

- Почему курсор, а не `offset`? Лента меняется, `offset` даёт дубли и пропуски.
- Как вставлять новые посты сверху: баннер «Показать новые» вместо автоматической вставки (чтобы не сдвигать то, что читает пользователь).
- Как быть с очень длинной лентой: виртуализация списка (см. тему «Производительность»).
