# Разбор задачи: «Нормализованное хранилище сущностей»

## 1. Проблема вложенных данных

API часто отдаёт данные вложенными: лента содержит посты, посты содержат авторов. Один и тот же пост может одновременно быть в ленте, в профиле автора и в закладках. Если хранить копию в каждом списке:

- лайк надо обновить в трёх местах;
- копии рано или поздно расходятся;
- любое обновление пересоздаёт большие вложенные структуры.

## 2. Нормализация

Каждую сущность хранят **один раз**, а списки держат только id:

```ts
entities: { "p1": { id: "p1", text: "…", likes: 3 } }
feed: ["p1", "p2"]
bookmarks: ["p1"]
```

Обновили пост один раз — он обновился везде. За это платят селекторами, которые собирают данные обратно (`getAll(ids)`).

## 3. Решение по шагам

### Шаг 1. Объединение полей

Сервер может прислать только часть полей (например, `{ id, likes }`). Поэтому `upsert` объединяет: `{ ...старая, ...новая }`, а не заменяет сущность целиком.

### Шаг 2. Определить, изменилось ли что-то

Сущность не изменилась, если каждое пришедшее поле равно хранимому (`Object.is`). Это дешёвая неглубокая проверка: по краям API данные приходят плоскими, а вложенное лучше нормализовать отдельно.

### Шаг 3. Сохранять ссылки

Если ничего не изменилось, объект остаётся **тем же самым**. Это нужно не ради красоты:

```tsx
const PostCard = React.memo(({ post }: { post: Post }) => ...);
```

`React.memo` сравнивает пропсы по ссылке. Когда обновился один пост, остальные карточки получают прежние объекты и не перерисовываются.

### Шаг 4. Уведомлять только о реальных изменениях

Подписчики вызываются после изменения, а не после каждого `upsertMany`. Иначе `useSyncExternalStore` будет лишний раз перерисовывать компоненты.

## 4. Подключение к React

```tsx
const post = useSyncExternalStore(
  store.subscribe,
  () => store.getById(id)
);
```

Селектор должен возвращать **стабильное значение**: пока сущность не менялась, это тот же объект. Поэтому так важен шаг 3.

## 5. Что обсудить на интервью

- Нормализовать всё или только общие сущности? Общие (посты, пользователи): да. Списки, которые встречаются в одном месте, нормализовать необязательно.
- Как связать с TanStack Query: он хранит ответы по ключам запросов; нормализованный слой нужен, когда одна сущность живёт в нескольких запросах и должна обновляться везде.
- Что делать с удалением: убрать из хранилища и из всех списков или пометить как удалённую.
