## Что такое DFS

**DFS (Depth-First Search, обход/поиск в глубину)** — это алгоритм обхода деревьев и графов, при котором мы идём по одной ветке **максимально глубоко**, прежде чем возвращаемся назад (это называется **backtracking**, откат) и пробуем следующую ветку.

Аналогия: представьте, что вы исследуете лабиринт. Стратегия DFS — это идти по одному коридору до самого конца (пока не упрётесь в тупик), и только тогда возвращаться к последней развилке и пробовать другой путь. Это противоположность стратегии "заглянуть во все соседние комнаты, прежде чем идти дальше" — так работает BFS (обход в ширину).

```
        1
       / \
      2   3
     / \   \
    4   5   6
```

Обход DFS (в порядке "сверху вниз, сначала влево") для этого дерева: `1 → 2 → 4 → 5 → 3 → 6`. Обратите внимание: мы полностью "закрываем" левое поддерево (2, 4, 5), прежде чем перейти к правому (3, 6).

## DFS vs BFS

| Критерий | DFS (в глубину) | BFS (в ширину) |
|---|---|---|
| Стратегия | Идти вглубь до конца, потом возвращаться | Обходить уровень за уровнем |
| Структура данных | Стек (или рекурсия, использующая стек вызовов) | Очередь (Queue) |
| Память в худшем случае | O(h), где h — высота дерева | O(w), где w — максимальная ширина уровня |
| Находит кратчайший путь? | Не гарантированно | Да, для невзвешенных графов |
| Типичные задачи | Обход всех узлов, поиск пути, топологическая сортировка, компоненты связности | Кратчайший путь, обход по уровням |

Важно понимать: DFS и BFS — это не взаимоисключающие "конкуренты", а инструменты для разных задач. Иногда правильный выбор алгоритма экономит вам порядок величины по времени или памяти.

## Дерево как структура данных

Дерево — это связная структура данных без циклов, где есть один корневой узел (`root`), а у каждого узла может быть несколько дочерних узлов (`children`).

Разберём на примере **бинарного дерева** — самого распространённого случая, где у каждого узла не больше двух детей: `left` и `right`.

```js
const createTreeNode = (value, left = null, right = null) => ({
  value,
  left,
  right,
});

// Дерево из примера выше:
const tree = createTreeNode(1,
  createTreeNode(2,
    createTreeNode(4),
    createTreeNode(5)
  ),
  createTreeNode(3,
    null,
    createTreeNode(6)
  )
);
```

Такая фабричная функция — это самый простой способ описать узел дерева в функциональном стиле, без `class`. Каждый узел "не знает" о существовании всего дерева целиком — он знает только о своих прямых детях, и это ключевая идея, которая делает рекурсию таким естественным инструментом для работы с деревьями: **дерево — это рекурсивная структура**, потому что каждое поддерево само по себе тоже является деревом.

## Три вида обхода дерева: preorder, inorder, postorder

Для бинарных деревьев существует три классических порядка обхода в глубину — они отличаются только тем, **когда именно** мы "обрабатываем" (например, печатаем) текущий узел относительно его детей.

### Preorder (прямой обход): узел → левое поддерево → правое поддерево

```js
const preorder = (node, result = []) => {
  if (!node) return result;

  result.push(node.value);   // сначала сам узел
  preorder(node.left, result);
  preorder(node.right, result);

  return result;
};

console.log(preorder(tree)); // [1, 2, 4, 5, 3, 6]
```

### Inorder (симметричный обход): левое поддерево → узел → правое поддерево

```js
const inorder = (node, result = []) => {
  if (!node) return result;

  inorder(node.left, result);
  result.push(node.value);   // узел — в середине
  inorder(node.right, result);

  return result;
};

console.log(inorder(tree)); // [4, 2, 5, 1, 3, 6]
```

Особенность: для **бинарного дерева поиска** (BST — Binary Search Tree, где слева всегда меньшие значения, справа — большие) inorder-обход всегда выдаёт значения **в отсортированном порядке**. Это одно из самых полезных свойств такого обхода.

### Postorder (обратный обход): левое поддерево → правое поддерево → узел

```js
const postorder = (node, result = []) => {
  if (!node) return result;

  postorder(node.left, result);
  postorder(node.right, result);
  result.push(node.value);   // узел — последним

  return result;
};

console.log(postorder(tree)); // [4, 5, 2, 6, 3, 1]
```

Postorder часто используется, когда нужно сначала обработать "детей", а потом уже "родителя" — например, при подсчёте размера поддерева, удалении узлов дерева (сначала освобождаем детей, потом сам узел) или вычислении выражений в виде дерева (сначала вычисляем операнды, потом применяем операцию).

**Мнемоника, чтобы не путать порядки**: буква "in" в inorder намекает, что узел обрабатывается "внутри" — между левым и правым поддеревом. "Pre" — "перед" детьми. "Post" — "после" детей.

## Рекурсивный DFS — реализация

Общий шаблон рекурсивного DFS для дерева (не обязательно бинарного, с произвольным числом детей) выглядит так:

```js
const createNode = (value, children = []) => ({ value, children });

const dfs = (node, visit) => {
  if (!node) return;

  visit(node); // делаем что-то с узлом (preorder-стиль)

  for (const child of node.children) {
    dfs(child, visit);
  }
};

// Пример использования
const root = createNode(1, [
  createNode(2, [createNode(4), createNode(5)]),
  createNode(3, [createNode(6)]),
]);

const visited = [];
dfs(root, (node) => visited.push(node.value));

console.log(visited); // [1, 2, 4, 5, 3, 6]
```

Функция `visit` здесь — это **колбэк**, который мы передаём в `dfs`, чтобы решить, что именно делать с каждым узлом (печатать, суммировать значения, искать конкретное значение и т.д.), не переписывая сам алгоритм обхода. Это очень частый и удобный паттерн.

## Как работает рекурсия «под капотом» (стек вызовов)

Чтобы по-настоящему понять DFS, важно понимать, как JavaScript исполняет рекурсивные вызовы — через **стек вызовов (call stack)**.

Когда функция вызывает сама себя, движок JavaScript не "заменяет" текущий вызов новым — он **кладёт новый вызов поверх старого**, как тарелку на стопку тарелок. Только когда самый верхний вызов завершается (`return`), управление возвращается к вызову под ним.

Для дерева `1 → (2 → (4, 5)), (3 → (6))` и функции `preorder`, стек вызовов в момент, когда мы обрабатываем узел `4`, выглядит так (сверху — самый недавний вызов):

```
preorder(4)   ← мы здесь прямо сейчас
preorder(2)   ← ждёт, пока preorder(4) и preorder(5) завершатся
preorder(1)   ← ждёт, пока preorder(2) и preorder(3) завершатся
```

Именно поэтому DFS **естественно** реализуется через рекурсию: сам стек вызовов ведёт себя точно так же, как стек, который вы бы завели вручную для итеративной версии алгоритма (см. следующий раздел). Понимание этой аналогии — ключ к тому, чтобы перестать бояться рекурсии.

## Итеративный DFS через явный стек

Если рекурсия вам неудобна (например, дерево очень глубокое и есть риск переполнения стека вызовов — подробнее в разделе "Подводные камни"), DFS можно реализовать и без рекурсии, используя **свой собственный стек** — обычный массив, где мы работаем только с его концом через `push`/`pop`.

```js
const dfsIterative = (root) => {
  if (!root) return [];

  const stack = [root];
  const result = [];

  while (stack.length > 0) {
    const node = stack.pop(); // берём последний добавленный узел
    result.push(node.value);

    // Кладём детей в обратном порядке, чтобы левый ребёнок
    // обрабатывался раньше правого (как в рекурсивном preorder)
    for (let i = node.children.length - 1; i >= 0; i--) {
      stack.push(node.children[i]);
    }
  }

  return result;
};

console.log(dfsIterative(root)); // [1, 2, 4, 5, 3, 6]
```

Важный нюанс: детей нужно класть в стек **в обратном порядке**, потому что стек работает по принципу LIFO (Last In, First Out — последний пришёл, первый вышел). Если положить детей в обычном порядке (сначала левого, потом правого), то `pop()` сначала вытащит правого ребёнка — и порядок обхода перепутается с ожидаемым preorder.

## DFS на графах

Деревья — это частный случай графов (граф без циклов, где у каждого узла ровно один родитель). У обычных графов могут быть циклы, поэтому при обходе графа критически важно **запоминать уже посещённые узлы** — иначе алгоритм зациклится навсегда.

```js
const dfsGraph = (graph, start) => {
  const visited = new Set();
  const result = [];

  const traverse = (node) => {
    if (visited.has(node)) return;

    visited.add(node);
    result.push(node);

    for (const neighbor of graph[node] ?? []) {
      traverse(neighbor);
    }
  };

  traverse(start);
  return result;
};

// Граф в виде списка смежности
const graph = {
  A: ["B", "C"],
  B: ["A", "D"],
  C: ["A", "D"],
  D: ["B", "C", "E"],
  E: ["D"],
};

console.log(dfsGraph(graph, "A")); // ["A", "B", "D", "C", "E"]
```

Без множества `visited` этот код зациклился бы: `A → B → A → B → A → ...` до переполнения стека — граф ведь содержит цикл `A  B`.

## Классические задачи с собеседований

### 1. Максимальная глубина (высота) дерева

```js
const maxDepth = (node) => {
  if (!node) return 0;

  const leftDepth = maxDepth(node.left);
  const rightDepth = maxDepth(node.right);

  return Math.max(leftDepth, rightDepth) + 1;
};
```

Это классический postorder-стиль: сначала узнаём глубину поддеревьев, потом на основе этого вычисляем глубину текущего узла.

### 2. Поиск значения в дереве

```js
const contains = (node, target) => {
  if (!node) return false;
  if (node.value === target) return true;

  return contains(node.left, target) || contains(node.right, target);
};
```

Оператор `||` здесь работает как "короткое замыкание": если значение найдено в левом поддереве, `contains(node.right, target)` даже не будет вызвана — незачем искать дальше.

### 3. Сумма всех путей от корня до листьев, равных заданному числу (Path Sum)

```js
const hasPathSum = (node, targetSum) => {
  if (!node) return false;

  // Лист: проверяем, равна ли оставшаяся сумма значению узла
  if (!node.left && !node.right) {
    return node.value === targetSum;
  }

  const remaining = targetSum - node.value;

  return hasPathSum(node.left, remaining) || hasPathSum(node.right, remaining);
};
```

### 4. Проверка, является ли дерево бинарным деревом поиска (BST)

```js
const isValidBST = (node, min = -Infinity, max = Infinity) => {
  if (!node) return true;

  if (node.value <= min || node.value >= max) return false;

  return (
    isValidBST(node.left, min, node.value) &&
    isValidBST(node.right, node.value, max)
  );
};
```

Частая ошибка новичков — проверять только "родитель больше/меньше прямых детей", но не всего поддерева. Здесь `min`/`max` — это "коридор" допустимых значений, который сужается по мере спуска вглубь дерева.

### 5. Количество островов (DFS на графах/матрицах — очень частая задача)

```js
const numIslands = (grid) => {
  const rows = grid.length;
  const cols = grid[0].length;
  let count = 0;

  const sink = (r, c) => {
    const outOfBounds = r < 0 || c < 0 || r >= rows || c >= cols;
    if (outOfBounds || grid[r][c] === "0") return;

    grid[r][c] = "0"; // помечаем клетку как посещённую ("топим" остров)

    sink(r + 1, c);
    sink(r - 1, c);
    sink(r, c + 1);
    sink(r, c - 1);
  };

  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (grid[r][c] === "1") {
        count++;
        sink(r, c);
      }
    }
  }

  return count;
};
```

Эта задача показывает: DFS применим не только к явным структурам "узел-дети", но и к **сеточным** структурам (матрицам), где "соседями" считаются клетки сверху/снизу/слева/справа.

## Сложность DFS (Big O)

| Показатель | Значение |
|---|---|
| Время (дерево из n узлов) | O(n) — каждый узел посещается ровно один раз |
| Время (граф с V вершинами и E рёбрами) | O(V + E) — посещаем каждую вершину и каждое ребро |
| Память (рекурсивная версия) | O(h), где h — высота дерева (глубина рекурсии); в худшем случае (вырожденное дерево-цепочка) — O(n) |
| Память (итеративная версия) | O(h) в среднем, до O(n) в худшем случае — размер стека зависит от формы дерева |

## Подводные камни

### 1. Забыли базовый случай рекурсии (base case)

```js
//  Бесконечная рекурсия — нет проверки на null
const preorderBroken = (node, result = []) => {
  result.push(node.value); // упадёт с ошибкой, когда node === null
  preorderBroken(node.left, result);
  preorderBroken(node.right, result);
  return result;
};

//  Правильно — base case проверяется первым
const preorderCorrect = (node, result = []) => {
  if (!node) return result;
  result.push(node.value);
  preorderCorrect(node.left, result);
  preorderCorrect(node.right, result);
  return result;
};
```

Каждая рекурсивная функция обязана иметь условие остановки. Без него вы получите либо `TypeError` (обращение к свойству `null`), либо `RangeError: Maximum call stack size exceeded` — переполнение стека вызовов.

### 2. Переполнение стека вызовов (Stack Overflow) на глубоких деревьях

Рекурсия ограничена размером стека вызовов движка JavaScript — обычно это несколько тысяч вложенных вызовов (точное число зависит от движка и доступной памяти). Если дерево **вырождено** — то есть фактически представляет собой длинную цепочку (например, отсортированные данные, вставленные одно за другим в несбалансированное BST), — глубина рекурсии будет равна количеству элементов, и на списке из 50 000+ узлов рекурсивный DFS может упасть с ошибкой `Maximum call stack size exceeded`.

**Решение**: для потенциально очень глубоких структур используйте итеративный DFS через явный стек (см. раздел выше) — он ограничен только объёмом кучи (heap), а не стека вызовов.

### 3. Забыли отметить узел посещённым при обходе графа

```js
//  Нет проверки visited — зациклится на графе с циклами
const dfsGraphBroken = (graph, node, result = []) => {
  result.push(node);
  for (const neighbor of graph[node]) {
    dfsGraphBroken(graph, neighbor, result); // бесконечный цикл при циклах в графе!
  }
  return result;
};
```

Для деревьев эта проблема не актуальна (в дереве по определению нет циклов), но при малейшем расширении задачи до графов — забытая проверка `visited` мгновенно превращает рабочий код в бесконечный цикл.

### 4. Мутация общего результата между несколькими вызовами (проблема с параметрами по умолчанию)

```js
const collectValues = (node, result = []) => {
  if (!node) return result;
  result.push(node.value);
  collectValues(node.left, result);
  collectValues(node.right, result);
  return result;
};

// Осторожно!
console.log(collectValues(tree1)); // [1, 2, 3]
console.log(collectValues(tree2)); // ожидаем [4, 5], но если result передан
                                    // случайно из предыдущего вызова — получим мусор
```

Параметр `result = []` в JS **создаётся заново при каждом вызове функции**, если аргумент не передан явно — это не то же самое, что "заведённый один раз объект по умолчанию", как в некоторых других языках (например, в Python значения по умолчанию — мутируемая ловушка, в JS такой проблемы нет). Но если вы **сами по ошибке передаёте** один и тот же массив в несколько независимых вызовов — вы получите смешение результатов. Возьмите за правило: если функция не должна ничего "копить" между вызовами, не передавайте `result` явно снаружи.

### 5. Путаница между porядками обхода (preorder / inorder / postorder)

Самая частая ошибка новичков — не глядя копировать шаблон одного вида обхода, когда задача требует другого. Например, если вам нужно удалить узлы дерева и освободить память, начиная с листьев, **обязательно** нужен postorder (сначала дети, потом сам узел) — иначе вы удалите родителя раньше, чем обработаете детей, и потеряете к ним доступ.

### 6. Забыли, что `||` и `&&` — это не просто булевы операторы, а операторы с "коротким замыканием"

В примере с `contains` (см. выше) многие новички переписывают код так:

```js
//  Менее эффективно — оба вызова происходят всегда,
// даже если левое поддерево уже дало true
const containsInefficient = (node, target) => {
  if (!node) return false;
  const foundLeft = contains(node.left, target);
  const foundRight = contains(node.right, target);
  return node.value === target || foundLeft || foundRight;
};
```

Такой вариант работает **правильно**, но менее эффективно — правое поддерево обходится, даже если ответ уже найден слева. Использование `||` напрямую в `return` выражении (без промежуточных переменных) даёт бесплатную оптимизацию за счёт короткого замыкания.

### 7. Мутация исходной структуры при обходе (как в задаче про острова)

В решении `numIslands` мы напрямую меняем `grid[r][c] = "0"` — это удобно и экономит память (не нужен отдельный `Set` посещённых клеток), но **мутирует входные данные**. Если вызывающий код рассчитывает, что исходная матрица останется неизменной после вызова функции — это баг. В таких случаях либо документируйте побочный эффект явно, либо работайте с копией данных, либо используйте отдельную структуру `visited`.

## Когда использовать DFS, а когда BFS

**Используйте DFS, если:**
- нужно посетить **все** узлы дерева или графа (порядок не так важен);
- решаете задачи на бэктрекинг (перебор всех путей, комбинаторика, генерация перестановок);
- ищете **любой** путь между двумя узлами, а не обязательно кратчайший;
- работаете с деревом, где глубина заведомо небольшая (сбалансированное дерево) — тогда риск переполнения стека минимален.

**Используйте BFS, если:**
- нужен **кратчайший путь** в невзвешенном графе;
- нужен обход **по уровням** (например, "напечатать дерево по слоям");
- дерево/граф может быть очень широким, но неглубоким — тогда у BFS будет меньше памяти в худшем случае, чем у DFS в противоположной ситуации (очень глубокое дерево).
