## 1. Паттерн и шаблон алгоритма

**Паттерн:** Stack (стек)  
**Разновидность:** `Stack: Nested Context` (стек контекстов для вложенных конструкций)

### В чём суть паттерна и разновидности
Когда в строке есть **вложенные** скобки, внутренний блок нужно полностью обработать, прежде чем вернуться к внешнему. Для этого при входе в `[` мы **откладываем в стек** состояние внешнего уровня (то, что уже собрано, и множитель), а внутри работаем с чистым листом. При `]` достаём контекст, применяем множитель к внутренней строке и приклеиваем её к внешней. Так же работает вызов функций: стек хранит «куда вернуться».

### Шаблон кода для запоминания синтаксиса
```javascript
// Шаблон: Stack: Nested Context (вложенные скобки с множителем)
const nestedTemplate = (s) => {
  const stack = [];
  let current = "";
  let count = 0;

  for (const char of s) {
    if (char >= "0" && char <= "9") {
      count = count * 10 + Number(char);     // многозначное число
    } else if (char === "[") {
      stack.push([current, count]);          // сохраняем внешний контекст
      current = "";
      count = 0;
    } else if (char === "]") {
      const [previous, times] = stack.pop(); // возвращаемся на уровень выше
      current = previous + current.repeat(times);
    } else {
      current += char;
    }
  }

  return current;
};
```

## 2. Суть задачи

Раскодировать строку по правилу `k[encoded]`: подстрока `encoded` повторяется `k` раз.
Скобки могут быть вложенными, а `k` многозначным.

```
"2[ab]3[c]" -> "ababccc"
"2[x3[y]]"  -> "xyyyxyyy"
"a2[bc]d"   -> "abcbcd"
```

## 3. Наивное решение (для понимания)

Повторять замену самых внутренних скобок через регулярное выражение, пока в строке
есть `[`:

```js
const decodeString = (s) => {
  const innermost = /(\d+)\[([a-z]*)\]/;
  while (innermost.test(s)) {
    s = s.replace(innermost, (_, k, str) => str.repeat(Number(k)));
  }
  return s;
};
```

Это короткое и рабочее решение, но каждый `replace` заново сканирует всю строку:
в худшем случае **O(n²)**. К тому же оно скрывает идею, которую от вас ждут:
стек и разбор за один проход.

## 4. Пошаговый разбор кода

```js
const decodeString = (s) => {
  const stack = [];
  let current = "";
  let count = 0;

  for (const char of s) {
    if (char >= "0" && char <= "9") {
      count = count * 10 + Number(char);
    } else if (char === "[") {
      stack.push([current, count]);
      current = "";
      count = 0;
    } else if (char === "]") {
      const [previous, times] = stack.pop();
      current = previous + current.repeat(times);
    } else {
      current += char;
    }
  }

  return current;
};
```

- **Цифра.** Накапливаем множитель: `12` читается как `1`, затем `1 * 10 + 2`.
- **`[`.** Начинается вложенный блок. Кладём в стек пару `[current, count]` (что уже
  собрано снаружи и сколько раз повторять блок), обнуляем `current` и `count`.
- **`]`.** Блок закончился. Достаём из стека внешнюю строку `previous` и множитель
  `times`, повторяем накопленный `current` и приклеиваем к `previous`.
- **Буква.** Просто дописываем в `current`.

### Трассировка на примере `s = "2[x3[y]]"`

| char | Действие | current | count | stack |
|---|---|---|---|---|
| `2` | множитель | `""` | 2 | `[]` |
| `[` | push `["", 2]` | `""` | 0 | `[["", 2]]` |
| `x` | дописываем | `"x"` | 0 | `[["", 2]]` |
| `3` | множитель | `"x"` | 3 | `[["", 2]]` |
| `[` | push `["x", 3]` | `""` | 0 | `[["", 2], ["x", 3]]` |
| `y` | дописываем | `"y"` | 0 | `[["", 2], ["x", 3]]` |
| `]` | pop → `"x" + "y".repeat(3)` | `"xyyy"` | 0 | `[["", 2]]` |
| `]` | pop → `"" + "xyyy".repeat(2)` | `"xyyyxyyy"` | 0 | `[]` |

Результат: `"xyyyxyyy"`.

---

## 5. Сложность и сравнение альтернатив

- **Время: O(L)**, где `L` — длина **раскодированной** строки (каждый символ ответа
  строится ограниченное число раз). Сам разбор входа линеен по длине `s`.
- **Память: O(n)** — глубина стека не больше числа вложенных скобок.

## Альтернативный подход

**Рекурсия.** Вызов `decode(i)` разбирает всё до соответствующей `]`, а внутри
вложенной `[` вызывает себя же. Это тот же стек, только неявный (стек вызовов).
Код выходит короче и читается как грамматика, но при очень глубокой вложенности
есть риск переполнения стека вызовов. Явный стек из решения выше от этого защищён.
