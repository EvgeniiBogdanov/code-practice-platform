## 1. Паттерн и шаблон алгоритма

**Паттерн:** Stack (стек)  
**Разновидность:** `Stack: Path Stack` (стек сегментов с откатом назад)

### В чём суть паттерна и разновидности
Путь в файловой системе — это цепочка директорий, а `..` отменяет **последний** вошедший сегмент. «Отменить последнее» — это ровно `pop()` стека (LIFO). Поэтому сегменты пути кладём в стек, а `..` снимает верхний, остальные служебные сегменты игнорируем.

### Шаблон кода для запоминания синтаксиса
```javascript
// Шаблон: Stack: Path Stack (обработка сегментов со «шагом назад»)
const pathTemplate = (path) => {
  const stack = [];

  for (const part of path.split("/")) {
    if (part === "" || part === ".") continue; // ничего не меняют
    if (part === "..") stack.pop();            // шаг назад (в корне — безопасно)
    else stack.push(part);                     // обычная директория
  }

  return "/" + stack.join("/");
};
```

---

## 2. Суть задачи

Привести абсолютный Unix-путь к каноническому виду:
- `.` игнорируется, `..` поднимает на уровень выше (выше корня подняться нельзя);
- повторяющиеся слэши считаются одним;
- `...` (и длиннее) — обычное имя директории;
- результат начинается с `/`, не заканчивается `/` (кроме самого корня).

## 3. Наивное решение (для понимания)

Многократно заменять шаблоны через `replace`: `//` → `/`, `/./` → `/`,
`/dir/../` → `/`, пока строка меняется.

- Работает только для частных случаев и сложно получить правильно: `/..`, `/.../`
  и концевые слэши ломают простые регулярки.
- Время в худшем случае **O(n²)** из-за повторных проходов по строке.

Стек решает это за один проход.

## 4. Пошаговый разбор кода

```js
const simplifyPath = (path) => {
  const stack = [];

  for (const part of path.split("/")) {
    if (part === "" || part === ".") {
      continue;
    }

    if (part === "..") {
      stack.pop();
    } else {
      stack.push(part);
    }
  }

  return "/" + stack.join("/");
};
```

1. `path.split("/")` разбивает путь на сегменты. Двойные слэши и ведущий `/` дают
   **пустые строки**, их пропускаем.
2. `.` — текущая директория, пропускаем.
3. `..` — шаг назад: `stack.pop()`. Если стек пуст (мы в корне), `pop()` ничего не
   делает и ошибки нет, как раз как требует задача.
4. Всё остальное (включая `...`) — имя директории, кладём в стек.
5. В конце собираем путь: `"/" + stack.join("/")`. Для пустого стека получится `"/"`.

### Трассировка на примере `path = "/a/./b/../../c/"`

| part | Действие | stack |
|---|---|---|
| `""` | пропуск | `[]` |
| `a` | push | `["a"]` |
| `.` | пропуск | `["a"]` |
| `b` | push | `["a", "b"]` |
| `..` | pop | `["a"]` |
| `..` | pop | `[]` |
| `c` | push | `["c"]` |
| `""` | пропуск | `["c"]` |

Результат: `"/c"`.

---

## 5. Сложность и сравнение альтернатив

- **Время: O(n)** — один проход по сегментам.
- **Память: O(n)** — стек и массив сегментов от `split`.

### Частые ошибки
- Забыть, что `...` — обычное имя, а не специальный сегмент.
- Вызвать `pop()` на пустом стеке в языке, где это ошибка (в JS возвращает `undefined`).
- Оставить завершающий `/` или вернуть пустую строку вместо `"/"` для корня.

## Альтернативный подход

Можно обойтись без `split`, разбирая строку вручную посимвольно: так память под
массив сегментов не нужна, но код заметно длиннее и подвержен ошибкам. Для
собеседования вариант со `split` и стеком предпочтительнее.
