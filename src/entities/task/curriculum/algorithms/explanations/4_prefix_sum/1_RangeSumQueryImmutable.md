## 1. Паттерн и шаблон алгоритма

**Паттерн:** Prefix Sum (префиксные суммы)  
**Разновидность:** `Prefix Sum: Array` (массив накопленных сумм с нулевым сдвигом)

### В чём суть паттерна и разновидности
Паттерн **Prefix Sum: Array** — мощный инструмент предподсчёта, позволяющий отвечать на запросы суммы любого диапазона `[L, R]` за $O(1)$ без единого цикла. Мы строим массив `prefix` длины $n + 1$, где `prefix[i]` хранит сумму первых $i$ элементов. Тогда сумма отрезка от $L$ до $R$ вычисляется как разность двух точек: `prefix[R + 1] - prefix[L]`. Начальный ноль `prefix[0] = 0` избавляет от необходимости писать проверки для $L = 0$.

### Шаблон кода для запоминания синтаксиса
```javascript
// Шаблон: Prefix Sum: Array (построение префиксного массива и вычисление суммы за O(1))
const buildPrefixSum = (arr) => {
  const prefix = new Array(arr.length + 1).fill(0);

  for (let i = 0; i < arr.length; i++) {
    prefix[i + 1] = prefix[i] + arr[i];
  }

  // Функция запроса суммы диапазона [left, right] включительно
  const rangeSum = (left, right) => prefix[right + 1] - prefix[left];

  return { prefix, rangeSum };
};
```

## 2. Суть задачи

В массиве `nums` — изменения баланса счёта по дням (бывают и отрицательные). Аналитикам
нужно много раз узнавать, на сколько изменился баланс за период — то есть сумму элементов
с индекса `left` по `right` включительно.

```
const balance = createNumArray([4, -1, 3, 0, 5, -2]);
balance.sumRange(1, 3)  ->  2   (-1 + 3 + 0)
```

Ключевая подсказка — массив `nums` **не меняется** после подготовки. Это именно тот случай,
когда префиксные суммы раскрывают свою силу: один раз подготовили массив накопленных сумм,
а дальше каждый запрос суммы отвечаем мгновенно, без цикла.

Такую структуру часто оформляют как класс с конструктором и методом `sumRange`.
Здесь мы делаем то же самое через **функцию-фабрику**, которая возвращает объект
с методом, — идиоматичный подход для стрелочных функций и замыканий (closures).

## 3. Разбор решения

1. В момент создания структуры (`createNumArray(nums)`) один раз строим массив
   префиксных сумм `prefix`, где `prefix[i]` — это сумма первых `i` элементов
   `nums` (сумма элементов `nums[0..i-1]`). В начале массива стоит "лишний" 0 —
   он означает сумму нуля элементов и убирает необходимость отдельно
   обрабатывать случай `left === 0`.

2. Дальше на любой запрос `sumRange(left, right)` мы просто вычисляем:

   ```
   sumRange(left, right) = prefix[right + 1] - prefix[left]
   ```

   Идея: `prefix[right + 1]` — это сумма всего "до `right` включительно",
   `prefix[left]` — это сумма всего "до `left`, не включая `left`". Вычитая
   одно из другого, получаем ровно сумму отрезка `[left, right]`.

3. Построение `prefix` выполняется один раз за `O(n)`, а каждый запрос
   `sumRange` после этого выполняется за `O(1)` — без единого цикла.

## 4. Пошаговый разбор кода

```js
const createNumArray = (nums) => {
  // 1. Готовим массив префиксных сумм длиной nums.length + 1,
  //    сразу заполняем нулями
  const prefix = new Array(nums.length + 1).fill(0);

  // 2. Один проход по nums: каждый следующий элемент prefix —
  //    это предыдущий элемент prefix + текущий элемент nums
  for (let i = 0; i < nums.length; i++) {
    prefix[i + 1] = prefix[i] + nums[i];
  }

  // 3. Возвращаем объект с методом sumRange.
  //    Благодаря замыканию (closure) метод "помнит" про prefix,
  //    хотя сама переменная prefix уже не видна снаружи функции.
  return {
    sumRange: (left, right) => prefix[right + 1] - prefix[left],
  };
};
```

### Трассировка построения `prefix` для `nums = [4, -1, 3, 0, 5, -2]`

| i | nums[i] | prefix[i] (было) | prefix[i+1] = prefix[i] + nums[i] |
|---|---|---|---|
| старт | — | — | prefix[0] = 0 |
| 0 | 4 | 0 | prefix[1] = 0 + 4 = 4 |
| 1 | -1 | 4 | prefix[2] = 4 + (-1) = 3 |
| 2 | 3 | 3 | prefix[3] = 3 + 3 = 6 |
| 3 | 0 | 6 | prefix[4] = 6 + 0 = 6 |
| 4 | 5 | 6 | prefix[5] = 6 + 5 = 11 |
| 5 | -2 | 11 | prefix[6] = 11 + (-2) = 9 |

Итог: `prefix = [0, 4, 3, 6, 6, 11, 9]`.

### Проверка запросов

- `sumRange(1, 3)` → `prefix[4] - prefix[1]` = `6 - 4` = **2**
  (проверка вручную: `-1 + 3 + 0 = 2`)
- `sumRange(0, 5)` → `prefix[6] - prefix[0]` = `9 - 0` = **9**
  (это сумма всего массива)
- `sumRange(4, 4)` → `prefix[5] - prefix[4]` = `11 - 6` = **5**
  (отрезок из одного дня: `nums[4] = 5`)

## 5. Сложность и сравнение со Sliding Window

- **Построение (конструктор):** O(n) по времени, O(n) по дополнительной памяти (массив `prefix`).
- **Каждый запрос `sumRange`:** O(1) — всего одно вычитание.
- **Итого для `q` запросов:** O(n + q) — значительно быстрее наивного подхода, где каждый запрос суммировал бы отрезок заново за O(n), и итоговая сложность была бы O(n · q).

### Почему тут не подходит Sliding Window
В отличие от задачи *Minimum Size Subarray Sum*, здесь:
- Числа могут быть **отрицательными** — окно не может предсказуемо расти или сжиматься, потому что добавление элемента не всегда увеличивает сумму.
- Нам нужно отвечать на запросы суммы **на произвольных, заранее неизвестных отрезках** `[left, right]`, а не искать какой-то один подмассив по условию.
Именно поэтому здесь используется Prefix Sum, а не Two Pointers / Sliding Window.
