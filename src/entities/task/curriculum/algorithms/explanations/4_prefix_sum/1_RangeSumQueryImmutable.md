## Какой алгоритм используется

**Prefix Sum (Префиксные суммы)**

## Суть задачи

Дан массив чисел `nums` (в том числе могут быть отрицательные). Нужно
подготовить структуру данных, которая много раз будет отвечать на запросы вида:
"какая сумма элементов на отрезке от `left` до `right` (включительно)?".

Слово **Immutable** ("неизменяемый") в названии — ключевая подсказка: массив
`nums` **не меняется** после создания структуры. Это именно тот случай, когда
префиксные суммы раскрывают свою силу — один раз подготовили массив
накопленных сумм, а дальше каждый запрос суммы отвечаем мгновенно, без цикла.

В оригинале на LeetCode задача оформлена как класс `NumArray` с конструктором и
методом `sumRange`. В JavaScript-варианте мы делаем то же самое, но через
**функцию-фабрику**, которая возвращает объект с методом — идиоматичный подход
для стрелочных функций и замыканий (closures).

## Разбор решения

1. В момент создания структуры (`createNumArray(nums)`) один раз строим массив
   префиксных сумм `prefix`, где `prefix[i]` — это сумма первых `i` элементов
   `nums` (сумма элементов `nums[0..i-1]`). В начале массива стоит "лишний" 0 —
   он означает сумму нуля элементов и убирает необходимость отдельно
   обрабатывать случай `left === 0`.

2. Дальше на любой запрос `sumRange(left, right)` мы просто вычисляем:

   ```
   sumRange(left, right) = prefix[right + 1] - prefix[left]
   ```

   Идея: `prefix[right + 1]` — это сумма всего "до `right` включительно",
   `prefix[left]` — это сумма всего "до `left`, не включая `left`". Вычитая
   одно из другого, получаем ровно сумму отрезка `[left, right]`.

3. Построение `prefix` выполняется один раз за `O(n)`, а каждый запрос
   `sumRange` после этого выполняется за `O(1)` — без единого цикла.

## Пошаговый разбор кода

```js
const createNumArray = (nums) => {
  // 1. Готовим массив префиксных сумм длиной nums.length + 1,
  //    сразу заполняем нулями
  const prefix = new Array(nums.length + 1).fill(0);

  // 2. Один проход по nums: каждый следующий элемент prefix —
  //    это предыдущий элемент prefix + текущий элемент nums
  for (let i = 0; i < nums.length; i++) {
    prefix[i + 1] = prefix[i] + nums[i];
  }

  // 3. Возвращаем объект с методом sumRange.
  //    Благодаря замыканию (closure) метод "помнит" про prefix,
  //    хотя сама переменная prefix уже не видна снаружи функции.
  return {
    sumRange: (left, right) => prefix[right + 1] - prefix[left],
  };
};
```

### Трассировка построения `prefix` для `nums = [-2, 0, 3, -5, 2, -1]`

| i | nums[i] | prefix[i] (было) | prefix[i+1] = prefix[i] + nums[i] |
|---|---|---|---|
| старт | — | — | prefix[0] = 0 |
| 0 | -2 | 0 | prefix[1] = 0 + (-2) = -2 |
| 1 | 0 | -2 | prefix[2] = -2 + 0 = -2 |
| 2 | 3 | -2 | prefix[3] = -2 + 3 = 1 |
| 3 | -5 | 1 | prefix[4] = 1 + (-5) = -4 |
| 4 | 2 | -4 | prefix[5] = -4 + 2 = -2 |
| 5 | -1 | -2 | prefix[6] = -2 + (-1) = -3 |

Итог: `prefix = [0, -2, -2, 1, -4, -2, -3]`.

### Проверка запросов

- `sumRange(0, 2)` → `prefix[3] - prefix[0]` = `1 - 0` = **1** 
  (проверка вручную: `-2 + 0 + 3 = 1`)
- `sumRange(2, 5)` → `prefix[6] - prefix[2]` = `-3 - (-2)` = **-1** 
  (проверка вручную: `3 + (-5) + 2 + (-1) = -1`)
- `sumRange(0, 5)` → `prefix[6] - prefix[0]` = `-3 - 0` = **-3** 
  (это сумма всего массива)

## Сложность

- **Построение (конструктор):** O(n) по времени, O(n) по дополнительной памяти
  (массив `prefix`).
- **Каждый запрос `sumRange`:** O(1) — всего одно вычитание.
- **Итого для `q` запросов:** O(n + q) — значительно быстрее наивного подхода,
  где каждый запрос суммировал бы отрезок заново за O(n), и итоговая
  сложность была бы O(n · q).

## Почему тут не подходит Sliding Window

В отличие от задачи *Minimum Size Subarray Sum*, здесь:
- Числа могут быть **отрицательными** — окно не может предсказуемо расти или
  сжиматься, потому что добавление элемента не всегда увеличивает сумму.
- Нам нужно отвечать на запросы суммы **на произвольных, заранее неизвестных
  отрезках** `[left, right]`, а не искать какой-то один подмассив по условию.

Именно поэтому здесь используется Prefix Sum, а не Two Pointers / Sliding Window.
