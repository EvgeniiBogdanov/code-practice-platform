## Какой алгоритм используется

**Prefix Sum + Hash Map (префиксные суммы + хеш-таблица)**

## Суть задачи

Дан массив целых чисел `nums` (числа могут быть и отрицательными) и число `k`.
Нужно посчитать, **сколько всего** существует подмассивов (непрерывных
участков массива), сумма элементов которых равна ровно `k`.

Подмассив — это непустой кусок массива из **идущих подряд** элементов.
Нужно посчитать **все** такие подмассивы, включая пересекающиеся между собой
(один и тот же элемент массива может входить в несколько разных подходящих
подмассивов).

## Почему тут НЕ подходит Sliding Window

В задаче *Minimum Size Subarray Sum* мы использовали Sliding Window именно
потому, что там **все числа положительные** — сумма окна предсказуемо растёт
при расширении и уменьшается при сжатии.

Здесь числа **могут быть отрицательными**. Это ломает саму идею скользящего
окна: расширяя окно вправо, сумма может как вырасти, так и упасть — окно не
может "разумно" решить, стоит ли его сжимать слева. Поэтому нужен другой
подход — **Prefix Sum в связке с хеш-таблицей (`Map`)**.

## Разбор решения

Ключевая идея строится на свойстве префиксных сумм:

> Если `prefix[j]` — сумма всех элементов от начала массива до индекса `j`
> (включительно), то сумма подмассива между индексами `i+1` и `j` равна
> `prefix[j] - prefix[i]`.

Нам нужно найти все пары `(i, j)`, где `prefix[j] - prefix[i] = k`. Если
переписать это как `prefix[i] = prefix[j] - k`, то задача сводится к
следующему: **на каждом шаге `j` проверяем, сколько раз раньше уже
встречалась префиксная сумма, равная `currentSum - k`.**

Чтобы не хранить весь массив префиксных сумм и не делать вложенный цикл
поиска, мы используем структуру данных `Map` (и называем переменную с ней
`map`), где:
- **ключ** — значение префиксной суммы;
- **значение** — сколько раз эта сумма уже встречалась.

Это позволяет проходить массив **всего один раз** (за `O(n)`), вместо
`O(n²)` при переборе всех пар `(i, j)` в лоб.

Отдельно стоит объяснить строчку `map.set(0, 1)` в начале: это означает, что
"пустой префикс" (сумма нуля элементов, то есть до начала массива) уже
встретился один раз. Это нужно, чтобы правильно засчитывались подмассивы,
которые начинаются **с самого первого элемента** массива.

## Пошаговый разбор кода

```js
const subarraySum = (nums, k) => {
  const map = new Map(); // какая префиксная сумма сколько раз уже встречалась
  map.set(0, 1);           // "пустой" префикс (сумма 0) заранее встретился 1 раз

  let count = 0;       // сколько подходящих подмассивов уже нашли
  let currentSum = 0;  // текущая накопленная (префиксная) сумма

  for (const num of nums) {
    currentSum += num; // расширяем префикс на очередной элемент

    // currentSum - k — это та префиксная сумма, которую нужно было
    // встретить раньше, чтобы между ней и текущим элементом получить сумму k
    if (map.has(currentSum - k)) {
      count += map.get(currentSum - k); // прибавляем, сколько раз такая сумма встречалась
    }

    // запоминаем текущую сумму (увеличиваем счётчик для неё в Map)
    map.set(currentSum, (map.get(currentSum) || 0) + 1);
  }

  return count;
};
```

### Пошаговая трассировка на примере `nums = [1,1,1], k = 2`

| num | currentSum (после сложения) | currentSum - k | map содержит currentSum - k? | Прибавили к count | count | map после шага |
|---|---|---|---|---|---|---|
| — | — | — | — | — | 0 | `{0: 1}` |
| 1 | 1 | -1 | нет | +0 | 0 | `{0:1, 1:1}` |
| 1 | 2 | 0 | да (`map.get(0) = 1`) | +1 | 1 | `{0:1, 1:1, 2:1}` |
| 1 | 3 | 1 | да (`map.get(1) = 1`) | +1 | 2 | `{0:1, 1:1, 2:1, 3:1}` |

Итог: `count = 2` ✅. Это подмассивы `nums[0..1] = [1,1]` (сумма 2) и
`nums[1..2] = [1,1]` (сумма 2).

### Проверка на массиве с отрицательными числами

```js
console.log(subarraySum([1, -1, 0], 0)); // 3
```

Здесь как раз видно, зачем нужен именно Prefix Sum + Map, а не Sliding
Window: подходят подмассивы `[1,-1]`, `[0]` и `[1,-1,0]` — и всё это благодаря
тому, что подход одинаково хорошо работает с отрицательными числами.

## Сложность

- **Время:** O(n) — один проход по массиву, каждая операция с `Map`
  (`get`/`set`/`has`) в среднем занимает O(1).
- **Память:** O(n) — в худшем случае в `Map` попадут до `n + 1` разных
  значений префиксных сумм.

Это значительно быстрее наивного перебора всех пар `(i, j)`, который работал
бы за O(n²) (для каждого начала подмассива считать сумму заново) или даже
O(n³) без предварительного накопления суммы.

## Подводные камни

1. **Забыть про `map.set(0, 1)`.**
   Без этой строчки не будут засчитываться подмассивы, которые начинаются с
   самого первого элемента массива (`nums[0..j]`), потому что для них
   значение `currentSum - k` было бы равно `0`, а такой суммы ещё не было
   бы в `Map`.

2. **Перепутать знак в формуле.**
   Правильно: `currentSum - k` (мы ищем "что было раньше", а не "что будет
   потом"). Частая ошибка новичков — написать `k - currentSum`, что даёт
   неправильный результат.

3. **Считать, что задача про Sliding Window.**
   Из-за похожести на *Minimum Size Subarray Sum* легко попытаться применить
   Two Pointers — но из-за отрицательных чисел это не сработает.
