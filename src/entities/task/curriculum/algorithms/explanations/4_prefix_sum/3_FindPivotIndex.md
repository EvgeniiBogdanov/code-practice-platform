## Какой алгоритм используется

**Prefix Sum (Префиксные суммы)**

## Суть задачи

Дан массив целых чисел `nums`. Нужно найти **опорный индекс** (pivot index) —
это такой индекс, у которого сумма всех чисел **строго слева** от него равна
сумме всех чисел **строго справа** от него. Сам элемент на этом индексе в
подсчёт левой и правой суммы не входит.

Если индекс находится у самого края массива (в начале или в конце), то сумма
с той стороны, где элементов нет, считается равной `0`.

Нужно вернуть **самый левый** подходящий индекс. Если такого индекса нет —
вернуть `-1`.

## Разбор решения

Наивный способ — для каждого индекса `i` заново пробегать циклом по всему
массиву слева и справа, чтобы посчитать суммы. Это работало бы за `O(n²)` —
медленно при больших массивах.

Более быстрый способ строится на простом наблюдении: если мы знаем **общую
сумму всего массива** (`totalSum`) и знаем **сумму слева** от текущего
индекса (`leftSum`), то сумму справа можно получить без единого
дополнительного цикла:

```
rightSum = totalSum - leftSum - nums[i]
```

То есть от общей суммы отнимаем всё, что уже слева, и сам текущий элемент —
остаётся ровно сумма всего, что справа. Это и есть идея префиксных сумм:
мы **один раз** проходим по массиву и на каждом шаге поддерживаем
накопленную (префиксную) сумму слева, вместо того чтобы пересчитывать её
заново для каждого индекса.

Дальше всё просто: идём по массиву слева направо, на каждом шаге сравниваем
`leftSum` и вычисленную `rightSum`. Если они равны — нашли ответ (и, так как
идём с самого начала, это автоматически будет **самый левый** подходящий
индекс). Если дошли до конца массива и совпадения не нашли — возвращаем `-1`.

## Пошаговый разбор кода

```js
const pivotIndex = (nums) => {
  // 1. Считаем сумму всего массива один раз — она нам понадобится,
  //    чтобы быстро получать сумму "справа" на каждом шаге
  const totalSum = nums.reduce((a, b) => a + b, 0);

  // 2. leftSum — сумма элементов строго слева от текущего индекса.
  //    В самом начале слева ничего нет, поэтому leftSum = 0
  let leftSum = 0;

  for (let i = 0; i < nums.length; i++) {
    // 3. Сумма справа = вся сумма минус всё слева минус сам текущий элемент
    const rightSum = totalSum - leftSum - nums[i];

    // 4. Если суммы слева и справа совпали — это наш ответ.
    //    Поскольку идём с индекса 0, это гарантированно самый левый вариант
    if (leftSum === rightSum) return i;

    // 5. Переходим к следующему индексу: текущий элемент
    //    добавляется в "накопленную сумму слева"
    leftSum += nums[i];
  }

  // 6. Ни один индекс не подошёл
  return -1;
};
```

### Пошаговая трассировка на примере `nums = [1,7,3,6,5,6]`

Сначала считаем `totalSum = 1+7+3+6+5+6 = 28`.

| i | nums[i] | leftSum (до шага) | rightSum = totalSum - leftSum - nums[i] | leftSum === rightSum? |
|---|---|---|---|---|
| 0 | 1 | 0 | 28 - 0 - 1 = 27 | нет |
| 1 | 7 | 1 | 28 - 1 - 7 = 20 | нет |
| 2 | 3 | 8 | 28 - 8 - 3 = 17 | нет |
| 3 | 6 | 11 | 28 - 11 - 6 = 11 | **да**  |

Как только на шаге `i = 3` суммы совпали (`11 === 11`), функция сразу
возвращает `3` — это и есть ответ, без необходимости досматривать оставшуюся
часть массива.

### Проверка граничного случая (пример 3)

```js
console.log(pivotIndex([2, 1, -1])); // 0
```

Здесь `totalSum = 2`. На первом же шаге (`i = 0`) `leftSum = 0` (слева ничего
нет), а `rightSum = 2 - 0 - 2 = 0` — суммы совпадают сразу, и функция
возвращает `0`. Это хороший пример, почему в условии отдельно оговорено, что
сумма с "пустой" стороны считается равной `0`.

## Сложность

- **Время:** O(n) — один проход, чтобы посчитать `totalSum` (метод `reduce`),
  и ещё один проход, чтобы найти опорный индекс. Итого два линейных прохода,
  что всё равно даёт O(n), а не O(n²), как при наивном подходе.
- **Память:** O(1) — используем только несколько переменных
  (`totalSum`, `leftSum`, `rightSum`), без дополнительных массивов.

## Подводные камни

1. **Перепутать "строго слева/справа" с "включительно".**
   Сумма слева и сумма справа **не включают** сам элемент на индексе `i`.
   Именно поэтому в формуле `rightSum = totalSum - leftSum - nums[i]` мы
   отдельно вычитаем `nums[i]` — если этого не сделать, элемент на пивоте
   ошибочно попадёт в правую сумму.

2. **Забыть про то, что нужен именно самый левый индекс.**
   Так как мы идём строго слева направо и возвращаем результат сразу при
   первом совпадении (`return i`), самый левый подходящий индекс находится
   автоматически — не нужно досматривать весь массив и потом выбирать
   минимальный индекс отдельно.

3. **Пытаться считать `rightSum` заново циклом на каждом шаге.**
   Это самая частая ошибка новичков при первой попытке решить задачу —
   она даёт корректный результат, но с квадратичной сложностью O(n²).
   Использование `totalSum` и постепенного накопления `leftSum` — это и есть
   ключевая оптимизация с помощью префиксных сумм.
