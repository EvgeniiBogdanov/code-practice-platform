## 1. Паттерн и шаблон алгоритма

**Паттерн:** Two Pointers (два указателя)  
**Разновидность:** `Two Pointers: Merge` (слияние двух отсортированных массивов, по указателю на каждый)

### В чём суть паттерна и разновидности
Когда есть **два отсортированных массива**, у каждого заводится свой указатель. На каждом шаге сравниваются `a[i]` и `b[j]`: меньший элемент точно не может встретиться во втором массиве (он весь «справа» от `j` и больше), поэтому его судьба решается сразу, а указатель двигается. Так два массива обходятся за один проход $O(n + m)$ без `Set` и сортировки.

### Шаблон кода для запоминания синтаксиса
```javascript
// Шаблон: Two Pointers: Merge (параллельный обход двух отсортированных массивов)
const mergeTemplate = (a, b) => {
  const result = [];
  let i = 0;
  let j = 0;

  while (i < a.length && j < b.length) {
    if (a[i] === b[j]) {
      i++; j++;               // элемент есть в обоих
    } else if (a[i] < b[j]) {
      result.push(a[i++]);    // элемент только в a
    } else {
      result.push(b[j++]);    // элемент только в b
    }
  }

  while (i < a.length) result.push(a[i++]); // хвост a
  while (j < b.length) result.push(b[j++]); // хвост b
  return result;
};
```

## 2. Суть задачи

Даны два отсортированных массива (с повторами). Нужно вернуть отсортированный
массив значений, которые есть **ровно в одном** из двух массивов, причём каждое
значение не больше одного раза.

```
a = [1, 1, 2]    b = [2, 3, 3]    ->  [1, 3]
```

Значение `2` есть в обоих массивах, поэтому исключается. Повторы `1` и `3`
схлопываются в одно значение.

## 3. Наивное решение (для понимания)

Собрать два `Set`, отфильтровать значения друг по другу и отсортировать результат.

```js
const symmetricDifference = (a, b) => {
  const setA = new Set(a);
  const setB = new Set(b);
  const result = [
    ...[...setA].filter((x) => !setB.has(x)),
    ...[...setB].filter((x) => !setA.has(x)),
  ];
  return result.sort((x, y) => x - y);
};
```

- Время: **O((n + m) log(n + m))** из-за финальной сортировки.
- Память: **O(n + m)**.

Это упускает главное условие: массивы **уже отсортированы**, и этим можно воспользоваться.

## 4. Пошаговый разбор кода

```js
const symmetricDifference = (a, b) => {
  const result = [];
  const pushUnique = (value) => {
    if (result.length === 0 || result[result.length - 1] !== value) {
      result.push(value);
    }
  };

  let i = 0;
  let j = 0;

  while (i < a.length && j < b.length) {
    if (a[i] === b[j]) {
      const common = a[i];
      while (i < a.length && a[i] === common) i++;
      while (j < b.length && b[j] === common) j++;
    } else if (a[i] < b[j]) {
      pushUnique(a[i++]);
    } else {
      pushUnique(b[j++]);
    }
  }

  while (i < a.length) pushUnique(a[i++]);
  while (j < b.length) pushUnique(b[j++]);

  return result;
};
```

- **Значения равны.** Значение есть в обоих массивах, поэтому в ответ оно не
  попадает. Пропускаем **все** его повторы сразу в обоих массивах. Без этого `1, 1`
  в одном массиве и `1` в другом дали бы ошибку.
- **`a[i] < b[j]`.** Значение `a[i]` меньше всего оставшегося в `b`, значит, его там
  нет. Оно «своё» и идёт в ответ.
- **`a[i] > b[j]`.** Симметрично для `b[j]`.
- **Хвосты.** Когда один массив закончился, всё оставшееся в другом заведомо
  отсутствует в первом.
- **`pushUnique`.** Результат строится по возрастанию, поэтому дубликат всегда
  совпадает с последним элементом `result`, и `Set` не нужен.

### Трассировка на примере `a = [1, 2, 3, 5]`, `b = [2, 3, 4, 6]`

| i | j | a[i] | b[j] | Действие | result |
|---|---|---|---|---|---|
| 0 | 0 | 1 | 2 | `1 < 2` → в ответ `1` | `[1]` |
| 1 | 0 | 2 | 2 | равны → пропуск `2` в обоих | `[1]` |
| 2 | 1 | 3 | 3 | равны → пропуск `3` в обоих | `[1]` |
| 3 | 2 | 5 | 4 | `5 > 4` → в ответ `4` | `[1, 4]` |
| 3 | 3 | 5 | 6 | `5 < 6` → в ответ `5` | `[1, 4, 5]` |
| 4 | 3 | — | 6 | `a` закончился → хвост `b` | `[1, 4, 5, 6]` |

## 5. Сложность и сравнение альтернатив

- **Время: O(n + m)** — каждый указатель только движется вперёд.
- **Память: O(1)** дополнительной (не считая массива-ответа).

### Почему не `Set` + сортировка
Вариант с `Set` проще в написании, но медленнее (O(k log k)) и тратит O(n + m)
памяти. Если данные отсортированы, на собеседовании от вас ждут именно два
указателя.

## Альтернативный подход

**Бинарный поиск каждого элемента** одного массива в другом: O(n log m), без
дополнительной памяти, но медленнее слияния и требует отдельной обработки повторов.
