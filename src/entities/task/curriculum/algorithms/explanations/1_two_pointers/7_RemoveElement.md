## 1. Паттерн

**Two Pointers: Read / Write** — два сонаправленных указателя выполняют разные роли:

- `read` просматривает каждый элемент исходного массива;
- `write` указывает позицию для следующего подходящего элемента.

Это базовая версия паттерна без обменов элементов и без дополнительных структур данных.

## 2. Алгоритм

1. Установить `write = 0`.
2. Пройти массив указателем `read`.
3. Если `nums[read] !== val`, записать элемент в `nums[write]` и увеличить `write`.
4. Вернуть `write`: это и длина результата, и граница полезного префикса.

```javascript
const removeElement = (nums, val) => {
  let write = 0;

  for (let read = 0; read < nums.length; read++) {
    if (nums[read] !== val) {
      nums[write] = nums[read];
      write++;
    }
  }

  return write;
};
```

Трассировка для `nums = [5, 1, 5, 5, 2]`, `val = 5`:

| `read` | `nums[read]` | Действие | `nums` после шага | `write` |
|:---:|:---:|:---|:---|:---:|
| 0 | 5 | равно `val`, пропускаем | `[5, 1, 5, 5, 2]` | 0 |
| 1 | 1 | `nums[0] = 1` | `[1, 1, 5, 5, 2]` | 1 |
| 2 | 5 | пропускаем | `[1, 1, 5, 5, 2]` | 1 |
| 3 | 5 | пропускаем | `[1, 1, 5, 5, 2]` | 1 |
| 4 | 2 | `nums[1] = 2` | `[1, 2, 5, 5, 2]` | 2 |

Функция возвращает `2`, значимый префикс — `[1, 2]`. Хвост `[5, 5, 2]` остался от исходного массива, и его значения не важны.

## 3. Сложность

- Время: `O(n)` — каждый элемент читается один раз.
- Дополнительная память: `O(1)` — используется только два индекса.

## 4. Частые ошибки

- Возвращать сам массив вместо длины `k`.
- Увеличивать `write`, даже когда найдено удаляемое значение.
- Использовать `splice` в цикле и получить `O(n²)` из-за повторных сдвигов.
- Считать элементы после индекса `k - 1` частью ответа: их значения не важны.
