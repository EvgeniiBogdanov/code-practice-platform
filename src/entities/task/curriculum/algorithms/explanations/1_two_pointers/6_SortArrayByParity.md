## 1. Паттерн и шаблон алгоритма

**Паттерн:** Two Pointers (два указателя)  
**Разновидность:** `Two Pointers: In-Place Partitioning (Hoare)` (встречные указатели для разделения на месте)

### В чём суть паттерна и разновидности
Паттерн **Two Pointers: In-Place Partitioning** по схеме Хоара — фундаментальный приём для разделения элементов массива на две категории по предикату без выделения дополнительной памяти ($O(1)$ Space).
- `left` стартует с начала массива и ищет элемент, нарушающий условие левой части (в данном случае — нечётное число).
- `right` стартует с конца массива и ищет элемент, нарушающий условие правой части (чётное число).
- Как только оба элемента найдены и `left < right`, мы меняем их местами (`swap`), после чего оба указателя шагают навстречу друг другу.

В отличие от схемы Ломуто (медленный и быстрый указатели), встречная схема Хоара выполняет **минимальное количество операций обмена (swaps)**, так как каждый обмен ставит сразу два элемента в их правильные половины.

### Шаблон кода для запоминания синтаксиса
```javascript
// Шаблон: Two Pointers: In-Place Partitioning (схема Хоара)
const partitionTemplate = (arr) => {
  let left = 0;
  let right = arr.length - 1;

  while (left < right) {
    while (left < right && /* элемент arr[left] уже на своём месте */) {
      left++;
    }
    while (left < right && /* элемент arr[right] уже на своём месте */) {
      right--;
    }
    if (left < right) {
      [arr[left], arr[right]] = [arr[right], arr[left]];
      left++;
      right--;
    }
  }

  return arr;
};
```

## 2. Суть задачи
Дан массив целых чисел `nums`. Необходимо переставить элементы **на месте (in-place)** так, чтобы все **чётные** числа оказались в начале массива, а все **нечётные** — в конце.

Функция возвращает изменённый массив `nums`. Дополнительные требования:
- Нельзя создавать копию массива, сложность по памяти должна быть $O(1)$.
- Временная сложность должна быть линейной $O(n)$.
- Относительный порядок элементов внутри групп чётных и нечётных чисел не имеет значения (любой валидный порядок принимается).

---

## 3. Разбор решения

1. Заводим два указателя: `left = 0` (начало массива) и `right = nums.length - 1` (конец массива).
2. Запускаем внешний цикл, пока `left < right`:
   - Сдвигаем `left++` до тех пор, пока текущее число чётное (`nums[left] % 2 === 0`).
   - Сдвигаем `right--` до тех пор, пока текущее число нечётное (`nums[right] % 2 !== 0`).
   - Если после смещений `left < right`, значит, `nums[left]` — нечётное, а `nums[right]` — чётное. Они стоят не в своих половинах! Меняем их местами: `[nums[left], nums[right]] = [nums[right], nums[left]]`.
   - После обмена сдвигаем оба указателя: `left++`, `right--`.
3. Когда `left >= right`, все чётные числа гарантированно находятся левее границы, а все нечётные — правее. Возвращаем исходный мутированный массив `nums`.

## 4. Пошаговый разбор кода

```js
const sortArrayByParity = (nums) => {
  let left = 0;
  let right = nums.length - 1;

  while (left < right) {
    // Ищем нечётное число слева
    while (left < right && nums[left] % 2 === 0) {
      left++;
    }

    // Ищем чётное число справа
    while (left < right && nums[right] % 2 !== 0) {
      right--;
    }

    // Если указатели не пересеклись, меняем элементы местами
    if (left < right) {
      [nums[left], nums[right]] = [nums[right], nums[left]];
      left++;
      right--;
    }
  }

  return nums;
};
```

### Трассировка для `nums = [3, 1, 2, 4]`

| Шаг | `left` (знач.) | `right` (знач.) | Условие обмена | Действие | Массив после шага |
|:---:|:---:|:---:|:---:|:---|:---|
| Старт | 0 (`3`, нечёт) | 3 (`4`, чёт) | `left < right` | `swap(3, 4)`, `left++`, `right--` | `[4, 1, 2, 3]` |
| 2 | 1 (`1`, нечёт) | 2 (`2`, чёт) | `left < right` | `swap(1, 2)`, `left++`, `right--` | `[4, 2, 1, 3]` |
| Конец | 2 (`1`) | 1 (`2`) | `left >= right` | Цикл завершён | `[4, 2, 1, 3]` |

## 5. Сложность и типичные ошибки на собеседовании

- **По времени**: $O(n)$, так как суммарно указатели `left` и `right` совершают не более $n$ шагов.
- **По памяти**: $O(1)$, все операции производятся на месте без выделения вспомогательных массивов.

### Частые ошибки
1. **Проверка нечётности через `num % 2 === 1`**:
   В JavaScript остаток от деления для отрицательных чисел отрицателен (`-5 % 2 === -1`). Проверка `=== 1` вернёт `false` для отрицательных нечётных чисел! Правильно писать: `num % 2 !== 0` или `(num & 1) === 1`.
2. **Забытая проверка `left < right` во внутренних циклах `while`**:
   Если массив состоит только из чётных или только из нечётных чисел, внутренний `while` без проверки `left < right` выйдет за границы массива (`undefined`).
3. **Создание нового массива через `filter().concat()`**:
   `return [...nums.filter(x => x % 2 === 0), ...nums.filter(x => x % 2 !== 0)]` требует $O(n)$ дополнительной памяти и $2n$ проходов, нарушая требование in-place $O(1)$.
