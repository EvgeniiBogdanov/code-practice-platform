## 1. Паттерн и шаблон алгоритма

**Паттерн:** Sliding Window (скользящее окно)  
**Разновидность:** `Sliding Window: Dynamic` (динамический размер окна / Flexible Window)

### В чём суть паттерна и разновидности
Паттерн **Sliding Window: Dynamic** применяется в задачах на подмассивы или подстроки («найти максимальную/минимальную длину, удовлетворяющую условию»). Мы поддерживаем непрерывный диапазон `[left, right]`:
1. Указатель `right` расширяет окно в цикле `for`.
2. Когда условие окна нарушается (появился дубликат, сумма превысила порог), внутренний цикл `while` сжимает окно слева сдвигом `left++`, пока окно снова не станет валидным.
Оба указателя движутся **только вперёд**, что гарантирует амортизированную сложность $O(n)$ вместо $O(n^2)$.

### Шаблон кода для запоминания синтаксиса
```javascript
// Шаблон: Sliding Window: Dynamic (динамическое окно с сужением при нарушении условия)
const flexibleSlidingWindowTemplate = (sequence) => {
  let left = 0;
  let maxLen = 0;
  const windowState = new Set(); // или Map / счётчик

  for (let right = 0; right < sequence.length; right++) {
    // 1. Если добавление sequence[right] нарушает инвариант — сжимаем окно слева
    while (windowState.has(sequence[right])) {
      windowState.delete(sequence[left]);
      left++;
    }

    // 2. Добавляем элемент в состояние окна
    windowState.add(sequence[right]);

    // 3. Фиксируем валидный результат
    maxLen = Math.max(maxLen, right - left + 1);
  }

  return maxLen;
};
```

## 2. Суть задачи

Дана строка `s`. Нужно найти **длину** самой длинной **подстроки**
(символы должны идти подряд, без "перескакиваний"), в которой все символы
уникальны — то есть нет ни одного повторяющегося символа.

- `"pizzaparty"` → ответ `5` (фрагмент `"party"`)
- `"aaaa"` → ответ `1` (фрагмент `"a"`)
- `"abba"` → ответ `2` (`"ab"` или `"ba"`; `"aba"` не подходит — `a` повторяется)

## 3. Наивное решение (для понимания)

Самый простой способ — перебрать **все возможные подстроки** строки `s`
(два вложенных цикла — начало и конец подстроки) и для каждой проверить,
все ли символы в ней уникальны.

```js
const lengthOfLongestSubstringBruteForce = (s) => {
  let maxLength = 0;

  for (let i = 0; i < s.length; i++) {
    const seen = new Set();
    for (let j = i; j < s.length; j++) {
      if (seen.has(s[j])) break;
      seen.add(s[j]);
      maxLength = Math.max(maxLength, j - i + 1);
    }
  }

  return maxLength;
};
```

- Время: **O(n²)** — для каждой стартовой позиции `i` заново проверяем
  символы вплоть до конца строки.
- Память: **O(min(n, m))**, где `m` — размер алфавита.

Работает, но медленно для длинных строк (до 10^5 символов по условию).
Здесь и приходит на помощь Sliding Window.

## 4. Оптимальное решение — разбор пошагово

Идея: заводим окно `[left, right]`, которое **всегда** содержит только
уникальные символы, и множество `Set`, где хранятся все символы,
находящиеся сейчас внутри окна.

1. Двигаем указатель `right` вперёд по строке, шаг за шагом расширяя окно.
2. На каждом шаге проверяем: символ `s[right]`, который мы хотим добавить
   в окно, **уже есть** в `Set`?
   - Если да — значит, окно сейчас "сломано" (есть повтор). Сжимаем окно
     **слева**: удаляем символы из `Set` и двигаем `left` вперёд, пока
     повторяющийся символ не "выпадет" из окна.
   - Если нет — окно всё ещё валидно, можно просто добавить символ.
3. Добавляем `s[right]` в `Set` (теперь он точно уникален внутри окна).
4. Сравниваем текущую длину окна (`right - left + 1`) с максимальной
   найденной длиной и обновляем ответ при необходимости.
5. Повторяем, пока `right` не дойдёт до конца строки.

```js
const lengthOfLongestSubstring = (s) => {
  // set хранит все символы, которые сейчас находятся внутри окна [left, right]
  const set = new Set();
  let left = 0;
  let maxLength = 0;

  for (let right = 0; right < s.length; right++) {
    // Пока символ s[right] уже есть в окне — сжимаем окно слева,
    // удаляя символы, пока повтор не исчезнет
    while (set.has(s[right])) {
      set.delete(s[left]);
      left++;
    }

    // Теперь символ s[right] точно уникален внутри окна — добавляем его
    set.add(s[right]);

    // Сравниваем длину текущего окна с максимальной найденной длиной
    maxLength = Math.max(maxLength, right - left + 1);
  }

  return maxLength;
};
```

### Трассировка на примере `s = "pizzaparty"`

| right | s[right] | Есть в set? | Действие | Окно [left, right] | maxLength |
|---|---|---|---|---|---|
| 0 | p | нет | добавляем "p" | "p" | 1 |
| 1 | i | нет | добавляем "i" | "pi" | 2 |
| 2 | z | нет | добавляем "z" | "piz" | 3 |
| 3 | z | да | удаляем "p" (left: 0→1), удаляем "i" (left: 1→2), удаляем "z" (left: 2→3), добавляем "z" | "z" | 3 |
| 4 | a | нет | добавляем "a" | "za" | 3 |
| 5 | p | нет | добавляем "p" | "zap" | 3 |
| 6 | a | да | удаляем "z" (left: 3→4), удаляем "a" (left: 4→5), добавляем "a" | "pa" | 3 |
| 7 | r | нет | добавляем "r" | "par" | 3 |
| 8 | t | нет | добавляем "t" | "part" | 4 |
| 9 | y | нет | добавляем "y" | "party" | 5 |

Итоговый ответ: `5` — подстрока `"party"`. Обратите внимание на шаг `right = 5`: вторая `p`
не считается повтором, потому что первая `p` уже выпала из окна на шаге 3.

### Трассировка на примере `s = "abba"`

| right | s[right] | Есть в set? | Действие | Окно [left, right] | maxLength |
|---|---|---|---|---|---|
| 0 | a | нет | добавляем "a" | "a" | 1 |
| 1 | b | нет | добавляем "b" | "ab" | 2 |
| 2 | b | да | удаляем "a" (left: 0→1), удаляем "b" (left: 1→2), добавляем "b" | "b" | 2 |
| 3 | a | нет | добавляем "a" | "ba" | 2 |

Итоговый ответ: `2`. На шаге 3 буква `a` уже не в окне: `Set` хранит только текущее окно,
поэтому ложного повтора нет.

## 5. Оценка сложности и инвариант указателей

- **Время: O(n)** — суммарно `left` и `right` проходят по строке не больше
  `2n` шагов вместе, что даёт строгую линейную сложность.
- **Память: O(min(n, m))**, где `m` — размер алфавита допустимых символов.
  В худшем случае `Set` хранит все уникальные символы строки одновременно.

### Почему `right` никогда не двигается назад
Важный момент: указатель `right` в цикле `for` **всегда** идёт только
вперёд. А указатель `left` внутри `while` тоже двигается **только вперёд**,
никогда не возвращаясь назад. Из-за этого каждый символ строки
обрабатывается не больше двух раз за весь алгоритм: один раз, когда
`right` "впускает" его в окно, и один раз, когда `left` "выпускает" его
из окна. Именно поэтому, несмотря на вложенный `while` внутри `for`,
итоговая сложность остаётся линейной — `O(n)`, а не `O(n²)`.
