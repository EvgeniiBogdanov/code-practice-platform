## Идея алгоритма на пальцах

Представьте, что вы смотрите на длинный ряд домов через окно поезда, а окно
вашего вагона показывает только несколько домов зараз. Поезд едет вперёд —
и в поле зрения появляются новые дома, а старые уходят назад и пропадают
из виду. В любой момент времени вы видите только **непрерывный кусок**
(последовательный "срез") всего ряда домов.

Именно так работает и алгоритм **Sliding Window**: это "окно" — непрерывный
отрезок массива или строки — которое мы двигаем ("сдвигаем") слева направо,
шаг за шагом, и на каждом шаге анализируем то, что находится внутри окна
**прямо сейчас**.

Технически окно задаётся двумя указателями (индексами):

- **`left`** — левая граница окна (начало);
- **`right`** — правая граница окна (конец).

Всё, что находится между `left` и `right` (включительно) — это и есть
текущее "окно". Мы двигаем эти два указателя по массиву/строке так, чтобы
не пересчитывать всё заново на каждом шаге, а **переиспользовать** уже
посчитанный результат от предыдущего окна.

```
nums = [1, 3, -1, -3, 5, 3, 6, 7]
         ^        ^
       left      right
       окно: [1, 3, -1, -3]
```

## Зачем это нужно: от наивного решения к Sliding Window

Возьмём классическую задачу: **найти максимальную сумму подмассива длины `k`**.

```
nums = [2, 1, 5, 1, 3, 2], k = 3
```

### Наивное решение (Brute Force)

Самая простая идея — перебрать **все возможные** подмассивы длины `k`
и для каждого посчитать сумму заново:

```js
const maxSumBruteForce = (nums, k) => {
  let maxSum = -Infinity;

  for (let i = 0; i <= nums.length - k; i++) {
    let currentSum = 0;
    for (let j = i; j < i + k; j++) {
      currentSum += nums[j];
    }
    maxSum = Math.max(maxSum, currentSum);
  }

  return maxSum;
};

console.log(maxSumBruteForce([2, 1, 5, 1, 3, 2], 3)); // 9
```

Проблема — здесь **два вложенных цикла**. Внешний цикл перебирает все
стартовые позиции окна, а внутренний — заново суммирует все `k` элементов
этого окна. Даже если два соседних окна отличаются всего на 1 элемент,
мы всё равно пересчитываем сумму "с нуля".

- Время: **O(n · k)** — для каждого из `n` окон тратим `O(k)` на подсчёт суммы.

### Решение через Sliding Window

Ключевое наблюдение: соседние окна **почти полностью совпадают** —
отличается только один элемент слева (уходит из окна) и один элемент справа
(входит в окно). Значит, не нужно пересчитывать сумму окна с нуля —
достаточно:

1. **Вычесть** из текущей суммы элемент, который "выпал" из окна слева.
2. **Прибавить** к текущей сумме новый элемент, который "вошёл" в окно справа.

```js
const maxSumSlidingWindow = (nums, k) => {
  let windowSum = 0;

  // Считаем сумму первого окна (первые k элементов)
  for (let i = 0; i < k; i++) {
    windowSum += nums[i];
  }

  let maxSum = windowSum;

  // Двигаем окно вправо на один элемент за раз
  for (let right = k; right < nums.length; right++) {
    windowSum += nums[right];         // добавляем новый элемент справа
    windowSum -= nums[right - k];     // убираем элемент, который "выпал" слева
    maxSum = Math.max(maxSum, windowSum);
  }

  return maxSum;
};

console.log(maxSumSlidingWindow([2, 1, 5, 1, 3, 2], 3)); // 9
```

- Время: **O(n)** — каждый элемент массива обрабатывается ровно **дважды**:
  один раз когда "входит" в окно, и один раз когда "выходит" из окна.

Это и есть суть Sliding Window: **избежать повторной работы**, переиспользуя
результат предыдущего шага вместо пересчёта всего окна заново.

## Два вида скользящего окна

Есть два основных варианта этой техники:

| Вид | Размер окна | Когда используется |
|---|---|---|
| **Fixed Size Window** (фиксированный размер) | Заранее известен и не меняется (например, `k`) | "Найти максимальную сумму подмассива длины `k`" |
| **Dynamic Size Window** (переменный размер) | Растёт и сжимается по ходу работы алгоритма | "Найти самую длинную подстроку без повторяющихся символов" |

Разница в реализации минимальная, но важно понимать, к какому виду
относится задача, чтобы выбрать правильный шаблон решения.

## Fixed Size Window (окно фиксированного размера)

Используется, когда размер окна `k` **дан заранее** и не меняется в процессе
решения.

### Общий алгоритм

1. Посчитать результат (сумму/среднее/максимум и т.д.) для **первого окна**
   размера `k` — то есть для первых `k` элементов.
2. Двигать окно вправо на 1 элемент за раз:
   - добавить в результат новый элемент, который вошёл в окно справа;
   - убрать из результата элемент, который вышел из окна слева;
   - обновить финальный ответ, если нужно.
3. Повторять шаг 2 до конца массива.

### Пример: средняя сумма всех подмассивов размера k

```js
const findMaxAverage = (nums, k) => {
  let windowSum = 0;

  for (let i = 0; i < k; i++) {
    windowSum += nums[i];
  }

  let maxSum = windowSum;

  for (let right = k; right < nums.length; right++) {
    windowSum += nums[right] - nums[right - k];
    maxSum = Math.max(maxSum, windowSum);
  }

  return maxSum / k;
};

console.log(findMaxAverage([1, 12, -5, -6, 50, 3], 4)); // 12.75
```

Здесь `windowSum` — это "состояние" окна, которое мы поддерживаем
инкрементально, не пересчитывая с нуля.

## Dynamic Size Window (окно переменного размера)

Используется, когда размер окна **заранее не известен** — он растёт и
сжимается в зависимости от условия задачи. Обычно формулировка задачи
звучит как "найти **самый длинный/короткий** подмассив/подстроку,
удовлетворяющий условию X".

### Общий алгоритм

1. Оба указателя, `left` и `right`, стартуют с индекса `0`.
2. Двигаем `right` вперёд на каждой итерации, **расширяя** окно и
   обновляя его "состояние" (например, добавляя новый символ в `Set`
   или увеличивая сумму).
3. Пока окно **нарушает условие задачи** (например, сумма стала больше
   допустимой, или в окне появился повторяющийся символ) — **сжимаем**
   окно, двигая `left` вперёд, пока условие снова не станет верным.
4. На каждом шаге (или когда условие выполнено) обновляем финальный ответ.

### Пример: длина наименьшего подмассива с суммой ≥ target

```js
const minSubArrayLen = (target, nums) => {
  let left = 0;
  let windowSum = 0;
  let minLength = Infinity;

  for (let right = 0; right < nums.length; right++) {
    windowSum += nums[right]; // расширяем окно вправо

    // Пока сумма окна достаточна — пытаемся сжать окно слева,
    // чтобы найти окно поменьше
    while (windowSum >= target) {
      minLength = Math.min(minLength, right - left + 1);
      windowSum -= nums[left];
      left++;
    }
  }

  return minLength === Infinity ? 0 : minLength;
};

console.log(minSubArrayLen(7, [2, 3, 1, 2, 4, 3])); // 2 (подмассив [4,3])
```

Обратите внимание: `right` **никогда не двигается назад** — окно всегда
расширяется вправо, а сжимается только слева. Именно поэтому такой подход
даёт линейную сложность, а не квадратичную: суммарно `left` и `right`
пройдут по массиву не больше `2n` шагов, а не `n²`.

## Универсальный шаблон кода

Вот общий "скелет", под который подходит большинство задач на Sliding
Window с динамическим размером окна:

```js
const slidingWindowTemplate = (arr) => {
  let left = 0;
  let windowState = /* начальное состояние окна: сумма, Map, Set и т.д. */ 0;
  let answer = 0;

  for (let right = 0; right < arr.length; right++) {
    // 1. Добавляем arr[right] в состояние окна (окно расширяется)
    // windowState = ...

    // 2. Пока окно нарушает условие задачи — сжимаем его слева
    while (/* условие нарушено */ false) {
      // Убираем arr[left] из состояния окна
      left++;
    }

    // 3. Обновляем финальный ответ, используя текущее окно [left, right]
    // answer = ...
  }

  return answer;
};
```

Такой шаблон подходит для задач "найти самое длинное/короткое окно,
удовлетворяющее условию" — меняется только то, что мы храним в
`windowState` (сумма, счётчик символов в `Map`, набор уникальных символов
в `Set`, и т.д.) и какое условие проверяем в `while`.

## Разбор реальной задачи с LeetCode

**Задача:** [3. Longest Substring Without Repeating Characters](https://leetcode.com/problems/longest-substring-without-repeating-characters/)
— найти длину самой длинной подстроки без повторяющихся символов.

```
Вход: s = "abcabcbb"
Выход: 3
Объяснение: самая длинная подстрока без повторов — "abc", её длина 3.
```

### Пошаговое решение

Используем `Set`, чтобы хранить все символы, которые сейчас находятся
внутри окна. Идея:

- Двигаем `right` вправо, добавляя символы в `Set`.
- Если символ `s[right]` **уже есть** в `Set` — значит, окно содержит
  повтор. Сжимаем окно слева (удаляя символы из `Set` и продвигая `left`),
  пока повторяющийся символ не "выпадет" из окна.
- На каждом шаге сравниваем текущую длину окна (`right - left + 1`)
  с максимальной найденной длиной.

```js
const lengthOfLongestSubstring = (s) => {
  const set = new Set();
  let left = 0;
  let maxLength = 0;

  for (let right = 0; right < s.length; right++) {
    // Пока символ s[right] уже есть в окне — сжимаем окно слева
    while (set.has(s[right])) {
      set.delete(s[left]);
      left++;
    }

    // Добавляем новый символ в окно
    set.add(s[right]);

    // Обновляем максимальную длину окна без повторов
    maxLength = Math.max(maxLength, right - left + 1);
  }

  return maxLength;
};

console.log(lengthOfLongestSubstring("abcabcbb")); // 3
console.log(lengthOfLongestSubstring("bbbbb"));    // 1
console.log(lengthOfLongestSubstring("pwwkew"));   // 3
```

### Трассировка на примере `s = "abcabcbb"`

| right | s[right] | Действие | Окно [left, right] | maxLength |
|---|---|---|---|---|
| 0 | a | добавляем "a" | "a" | 1 |
| 1 | b | добавляем "b" | "ab" | 2 |
| 2 | c | добавляем "c" | "abc" | 3 |
| 3 | a | "a" уже в окне → удаляем "a", left=1; добавляем "a" | "bca" | 3 |
| 4 | b | "b" уже в окне → удаляем "b", left=2; добавляем "b" | "cab" | 3 |
| 5 | c | "c" уже в окне → удаляем "c", left=3; добавляем "c" | "abc" | 3 |
| 6 | b | "b" уже в окне → удаляем "a" (left=3→4), "b" всё ещё в окне → удаляем "b" (left=4→5); добавляем "b" | "cb" | 3 |
| 7 | b | "b" уже в окне → удаляем "c" (left=5→6), "b" всё ещё в окне → удаляем "b" (left=6→7); добавляем "b" | "b" | 3 |

Итоговый ответ: `3`.

## Подводные камни и типичные ошибки

Это самая важная часть для новичка — на этих граблях спотыкаются почти все.

### 1. Забыть сжать окно (`while` вместо `if`)

При динамическом окне сжатие часто нужно делать **в цикле `while`**,
а не через `if`. Одно добавление элемента справа иногда требует
**нескольких** шагов сжатия слева, а не одного.

```js
// ❌ Неправильно — может остаться нарушенное условие после одного сдвига
if (windowSum > target) {
  windowSum -= nums[left];
  left++;
}

// ✅ Правильно — сжимаем, пока условие не станет верным
while (windowSum > target) {
  windowSum -= nums[left];
  left++;
}
```

### 2. Off-by-one ошибки при подсчёте длины окна

Длина окна `[left, right]` (включительно с обеих сторон) равна
`right - left + 1`, а не `right - left`. Забыть `+1` — самая частая
ошибка при работе со Sliding Window.

```js
// ❌ Неправильно — длина окна занижена на 1
const windowLength = right - left;

// ✅ Правильно
const windowLength = right - left + 1;
```

### 3. Пересчитывать окно с нуля вместо инкрементального обновления

Если внутри цикла вы заново считаете сумму или заново перебираете все
элементы текущего окна — вы теряете весь смысл Sliding Window и
возвращаетесь к сложности `O(n · k)` или `O(n²)`.

```js
// ❌ Неправильно — теряем преимущество Sliding Window
for (let right = k; right < nums.length; right++) {
  let windowSum = 0;
  for (let j = right - k + 1; j <= right; j++) {
    windowSum += nums[j]; // пересчитываем всё окно заново на каждом шаге
  }
}

// ✅ Правильно — переиспользуем сумму предыдущего окна
windowSum += nums[right] - nums[right - k];
```

### 4. Забыть обновить состояние окна при сжатии

Если окно хранит что-то сложнее суммы (например, `Map` со счётчиком
символов), при сдвиге `left` **обязательно** нужно обновить это состояние
(уменьшить счётчик или удалить ключ), а не просто увеличить `left`.

```js
// ❌ Неправильно — left двигается, но map не обновляется,
// из-за этого условие в while никогда не станет false
while (/* условие */) {
  left++;
}

// ✅ Правильно — сначала обновляем состояние, потом двигаем left
while (/* условие */) {
  map.set(s[left], map.get(s[left]) - 1);
  if (map.get(s[left]) === 0) {
    map.delete(s[left]);
  }
  left++;
}
```

### 5. Путать условие "окно должно вместиться" и "окно уже не влезает"

Легко перепутать, когда сжимать окно: **до** добавления нового элемента
или **после**. Обычно правильный порядок такой: сначала расширяем окно
(добавляем `arr[right]`), **потом** проверяем условие и, если нужно,
сжимаем. Если проверить условие до добавления элемента — можно получить
неверный (за)ниженный ответ.

### 6. Неправильные границы для Fixed Size Window

Когда размер окна фиксирован (`k`), важно не выйти за границы массива
при вычислении "элемента, который выпал из окна" — это `nums[right - k]`,
а не `nums[right - k - 1]` или `nums[left]` (потому что `left` в
классической реализации fixed window может вообще не использоваться,
достаточно одного указателя `right` и формулы `right - k`).

### 7. Забыть обработать случай, когда массив короче окна

Если `k > nums.length`, наивная реализация может обратиться к
несуществующему индексу массива. Стоит добавить проверку в начале
функции:

```js
if (nums.length < k) {
  return null; // или другое значение по смыслу задачи
}
```

## Как понять, что перед вами задача на Sliding Window

Обратите внимание на такие сигналы в условии задачи:

- Речь идёт о **непрерывном** (contiguous) подмассиве или подстроке —
  то есть элементы должны идти подряд, без "перескакиваний".
- В условии есть слова: "подмассив", "подстрока", "самый длинный",
  "самый короткий", "максимальная сумма окна размера k", "без повторов".
- Наивное решение требует **вложенных циклов** для перебора всех
  подмассивов/подстрок — обычно это сигнал, что можно оптимизировать
  до одного прохода.
- Задача касается **массивов и строк**, а не деревьев или графов.

Если условие задачи говорит про **непоследовательные** элементы (можно
пропускать элементы, выбирать любые, не обязательно подряд идущие) —
это, скорее всего, **не** Sliding Window, а другой паттерн (например,
динамическое программирование).

## Сложность алгоритма

Для большинства задач на Sliding Window:

- **Время: O(n)** — несмотря на то, что внутри есть цикл `while`,
  указатель `left` **суммарно** двигается вперёд не больше `n` раз за
  весь алгоритм (он никогда не двигается назад). Поэтому итоговая работа
  обоих указателей вместе — `O(n) + O(n) = O(n)`, а не `O(n²)`, даже
  если на первый взгляд вложенный `while` внутри `for` выглядит подозрительно.
- **Память:** зависит от того, что хранится в "состоянии окна":
  - `O(1)`, если храним только число (сумму, счётчик);
  - `O(k)`, если храним `Set`/`Map` с ограниченным алфавитом
    (например, 26 латинских букв);
  - `O(n)` в общем случае, если состояние окна может расти вместе с длиной
    входных данных.

## Sliding Window vs Two Pointers — в чём разница

Эти два паттерна часто путают, потому что оба используют указатели
`left` и `right`, и Sliding Window иногда даже называют "частным случаем"
Two Pointers. Но есть смысловое отличие:

| | Sliding Window | Two Pointers |
|---|---|---|
| Что представляют указатели | Границы **непрерывного окна** данных | Просто две **независимые позиции**, необязательно образующие сплошной отрезок |
| Типичная задача | "Найти подмассив/подстроку, удовлетворяющую условию" | "Найти пару элементов с нужной суммой в отсортированном массиве", "развернуть строку" |
| Движение указателей | `right` всегда двигается вперёд, `left` "догоняет" его | Указатели могут двигаться навстречу друг другу или независимо |

На практике границы между этими паттернами размыты, и не стоит слишком
зацикливаться на терминологии — важнее понимать саму идею: избегать
повторных вычислений, переиспользуя уже посчитанный результат.
