# Contains Duplicate — разбор задачи

## Какой алгоритм используется

**Hash Set (хеш-множество)**

Задача решается с помощью структуры данных `Set` — она умеет хранить только
**уникальные** значения и очень быстро проверять, есть ли элемент в наборе
(метод `.has()` работает в среднем за O(1)). Идея в том, чтобы пройти по
массиву один раз и на каждом шаге проверять: не встречалось ли уже такое
число раньше. Если встречалось — это дубликат.

## Суть задачи

Дан массив чисел `nums`. Нужно определить, есть ли в нём **повторяющиеся**
числа (хотя бы одно число встречается 2 раза и больше).

- Если повтор есть — вернуть `true`.
- Если все числа уникальны — вернуть `false`.

## Наивное решение (для понимания)

Самый простой способ — сравнить каждое число с каждым другим (два вложенных
цикла) и проверить, не совпадают ли они.

```js
const containsDuplicate = (nums) => {
  for (let i = 0; i < nums.length; i++) {
    for (let j = i + 1; j < nums.length; j++) {
      if (nums[i] === nums[j]) {
        return true;
      }
    }
  }
  return false;
};
```

- Время: **O(n²)** — для каждого элемента перебираем все остальные.
- Память: **O(1)**.

Работает, но медленно на больших массивах (в задаче размер массива может
достигать 10^5 элементов). Есть способ решить эту же задачу быстрее.

## Оптимальное решение — разбор пошагово

Идея: заводим пустой `Set` и идём по массиву слева направо. Для каждого
числа проверяем — **видели ли мы его раньше**:

- Если число **уже есть** в `Set` — значит, мы нашли повтор, можно сразу
  вернуть `true` и не тратить время на оставшуюся часть массива.
- Если числа в `Set` ещё нет — добавляем его туда и идём дальше.
- Если дошли до конца массива и ни разу не нашли повтор — возвращаем `false`.

```js
const containsDuplicate = (nums) => {
  // set хранит все числа, которые мы уже "прошли" по массиву
  const set = new Set();

  for (const num of nums) {
    // Если такое число уже встречалось раньше — это дубликат
    if (set.has(num)) {
      return true;
    }
    // Иначе запоминаем число, чтобы сравнивать с ним в будущем
    set.add(num);
  }

  // Прошли весь массив и не нашли повторов
  return false;
};
```

### Трассировка на примере `nums = [1, 2, 3, 1]`

| Шаг | num | set.has(num)? | Действие | set после шага |
|---|---|---|---|---|
| 1 | 1 | нет | добавляем 1 | `{1}` |
| 2 | 2 | нет | добавляем 2 | `{1, 2}` |
| 3 | 3 | нет | добавляем 3 | `{1, 2, 3}` |
| 4 | 1 | **да** | возвращаем `true` | — |

Как только на четвёртом шаге встретилась уже виденная `1`, цикл сразу
прерывается — не нужно проверять весь массив до конца.

### Трассировка на примере `nums = [1, 2, 3, 4]`

Все четыре числа разные, поэтому `set.has(num)` ни разу не сработает.
После прохода всего массива `Set` будет содержать `{1, 2, 3, 4}`,
и функция вернёт `false`.

## Сложность

- **Время: O(n)** — в худшем случае (когда дубликатов нет вообще) проходим
  по массиву один раз, а проверка `.has()` и вставка `.add()` в среднем
  занимают O(1).
- **Память: O(n)** — в худшем случае `Set` хранит столько же элементов,
  сколько было в исходном массиве.

## Почему это быстрее, чем `new Set(nums).size !== nums.length`

Есть ещё один похожий по идее вариант решения:

```js
const containsDuplicate = (nums) => {
  const set = new Set(nums);
  return set.size !== nums.length;
};
```

Он тоже работает за O(n) по Big O, но **всегда** строит `Set` из всего
массива целиком, даже если дубликат встретился в самом начале. Вариант с
циклом и ранним `return true` при первом же найденном повторе завершает
работу раньше и на практике эффективнее — особенно если дубликат
расположен близко к началу массива. По асимптотической сложности оба
решения равны (O(n)), но у решения с ранним выходом лучше *реальная*
скорость работы (constant factor) в среднем и лучшем случаях.

## Альтернативный подход

Ещё один вариант — **отсортировать** массив (`O(n log n)`), а затем пройти
по нему один раз и проверить, есть ли два соседних одинаковых элемента.
Это работает медленнее решения через `Set` (O(n log n) против O(n)),
но зато не требует дополнительной памяти под структуру данных (если сортировать
на месте).
