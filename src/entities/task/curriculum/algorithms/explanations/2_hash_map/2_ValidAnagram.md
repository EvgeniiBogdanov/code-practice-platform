## 1. Паттерн и шаблон алгоритма

**Паттерн:** Hash Map (хеш-таблица)  
**Разновидность:** `Hash Map: Frequency` (подсчёт частоты элементов / Frequency Counter)

### В чём суть паттерна и разновидности
Паттерн **Hash Map: Frequency** применяется всякий раз, когда нужно сопоставить распределение элементов (символов, чисел, токенов) между двумя коллекциями, либо определить мажоритарный элемент. Вместо дорогой сортировки за $O(n \log n)$, мы за один проход строим частотный словарь (`map.set(key, (map.get(key) || 0) + 1)`), а затем за второй проход декрементируем счётчики или сравниваем их, достигая идеальной линейной сложности $O(n)$.

### Шаблон кода для запоминания синтаксиса
```javascript
// Шаблон: Hash Map: Frequency (построение и валидация частотного словаря)
const frequencyCounterTemplate = (seqA, seqB) => {
  if (seqA.length !== seqB.length) return false;

  const freqMap = new Map();

  // 1. Накопление частот
  for (const item of seqA) {
    freqMap.set(item, (freqMap.get(item) || 0) + 1);
  }

  // 2. Погашение частот
  for (const item of seqB) {
    const count = freqMap.get(item);
    if (!count) return false; // элемента нет или его лимит исчерпан
    freqMap.set(item, count - 1);
  }

  return true;
};
```

## 2. Суть задачи

Даны две строки `s` и `t`. Нужно определить, является ли `t` анаграммой `s` —
то есть состоит ли `t` из **точно тех же букв** в **том же количестве**,
что и `s`, просто в другом порядке.

Условия:
- Строки состоят только из строчных латинских букв.
- Если длины строк разные, они точно не могут быть анаграммами.

## 3. Наивное решение (через сортировку)

Самый простой способ — отсортировать буквы в обеих строках по алфавиту и
сравнить получившиеся строки. Если результаты совпадают — это анаграммы.

```js
const isAnagram = (s, t) => {
  if (s.length !== t.length) return false;
  return s.split("").sort().join("") === t.split("").sort().join("");
};
```

- Время: **O(n log n)** — из-за сортировки.
- Память: **O(n)** — на создание новых отсортированных строк.

Это рабочее решение, но его можно ускорить, если не сортировать строки,
а просто посчитать количество каждой буквы.

## 4. Пошаговый разбор кода

Идея: если строки — анаграммы, то количество каждой буквы в `s` должно
полностью совпадать с количеством этой же буквы в `t`.

Шаги:
1. Если длины строк разные — сразу возвращаем `false` (это не анаграммы).
2. Проходим по строке `s` и с помощью `Map` считаем, сколько раз встречается
   каждая буква. Ключ — буква, значение — счётчик.
3. Проходим по строке `t` и для каждой буквы **уменьшаем** её счётчик в `map`.
   - Если такой буквы нет в `map` или её счётчик уже равен `0` — значит,
     в `t` этой буквы больше, чем в `s`, и строки точно не анаграммы.
4. Если прошли всю строку `t` без несостыковок — строки являются анаграммами.

```js
const isAnagram = (s, t) => {
  // Если длины разные — анаграммой быть не может
  if (s.length !== t.length) {
    return false;
  }

  // map хранит пары "буква -> сколько раз она встретилась в s"
  const map = new Map();

  // Считаем количество каждой буквы в строке s
  for (const char of s) {
    map.set(char, (map.get(char) || 0) + 1);
  }

  // Проходим по строке t и "вычитаем" буквы из счётчика
  for (const char of t) {
    // Если буквы нет в map или она уже "закончилась" — не анаграмма
    if (!map.has(char) || map.get(char) === 0) {
      return false;
    }
    map.set(char, map.get(char) - 1);
  }

  // Все буквы совпали по количеству — это анаграммы
  return true;
};
```

### Трассировка на примере `s = "rat", t = "car"`

**Шаг 1.** Длины строк совпадают (по 3 символа) — продолжаем.

**Шаг 2.** Считаем буквы в `s = "rat"`:

| Буква | Счётчик в map |
|-------|---------------|
| r     | 1             |
| a     | 1             |
| t     | 1             |

**Шаг 3.** Проходим по `t = "car"`:

| Буква | Есть в map? | Счётчик > 0? | Действие |
|-------|-------------|--------------|----------|
| c     | нет         | —            | возвращаем `false` |

Буквы "c" нет в исходной строке `s`, значит строки — не анаграммы. Ответ: `false`.

## 5. Сложность и Follow-up (Unicode-символы)

- **Время: O(n)** — два линейных прохода по строкам (сначала по `s`, потом по `t`).
- **Память: O(1)** в контексте задачи, так как алфавит фиксирован (26 строчных
  латинских букв), поэтому `Map` не может занять больше константного объёма
  независимо от длины строк. Если бы допускались любые Unicode-символы
  (см. Follow-up на LeetCode), память формально считалась бы **O(k)**, где
  `k` — количество уникальных символов.

### Про Follow-up (Unicode-символы)

LeetCode спрашивает: как решение изменится, если строки могут содержать
любые Unicode-символы, а не только строчные латинские буквы?

Хорошая новость — решение через `Map` **уже работает** для любых символов,
в отличие от подхода с массивом фиксированного размера `new Array(26)`,
который годится только для 26 латинских букв. `Map` в JavaScript использует
сами символы как ключи, поэтому Unicode-символы (эмодзи, кириллица,
иероглифы и т.д.) обрабатываются без изменений в коде.
