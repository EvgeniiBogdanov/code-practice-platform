## 1. Паттерн и шаблон алгоритма

**Паттерн:** Binary Search (бинарный поиск)  
**Разновидность:** `Binary Search: Boundary` (поиск первого элемента, удовлетворяющего предикату / границы монотонной функции)

### В чём суть паттерна и разновидности
Паттерн **Binary Search: Boundary** применяется, когда пространство поиска разбивается условием на две зоны: `[false, false, ..., true, true]` (или наоборот), и требуется найти первую точку смены состояния (границу).
Особенности реализации:
1. Цикл продолжается, пока `left < right` (без равенства, чтобы избежать зацикливания при `right = mid`).
2. Если предикат истинен (`isBad(mid) === true`), кандидат найден, но левее может быть более ранний $\to$ `right = mid` (сохраняем `mid`).
3. Если предикат ложен $\to$ `left = mid + 1` (отбрасываем `mid`).
4. При выходе из цикла гарантированно `left === right` — точная граница.

### Шаблон кода для запоминания синтаксиса
```javascript
// Шаблон: Binary Search: Boundary (поиск первой границы истинности)
const binarySearchBoundaryTemplate = (n, isConditionMet) => {
  let left = 1;
  let right = n;

  while (left < right) {
    const mid = left + Math.floor((right - left) / 2);

    if (isConditionMet(mid)) {
      // mid подходит, но искомая первая граница может быть левее
      right = mid;
    } else {
      // mid не подходит, первая граница строго правее
      left = mid + 1;
    }
  }

  // left === right — индекс первой границы
  return left;
};
```

## 2. Суть задачи

Сборки проекта пронумерованы от `1` до `n`. С какой-то сборки в код попала ошибка,
и все сборки начиная с неё падают. Нужно найти **номер первой падающей сборки**.

Проверить сборку можно функцией `isBadVersion(version)`, но проверка дорогая, поэтому
вызывать её нужно как можно реже. Перебирать сборки подряд (1, 2, 3, 4...) не годится:
в третьем примере `n = 2 000 000 000`.

Ключевое наблюдение: если выстроить версии в ряд, то они выглядят так:

```
проходит, проходит, проходит, ПАДАЕТ, падает, падает, падает...
```

Это отсортированная последовательность из двух "зон" — как массив,
где сначала идут `false`, а потом только `true`. А значит, мы можем
искать границу между ними бинарным поиском, а не проверять всё подряд.

## 3. Разбор решения

Функция `solution` устроена как **каррированная функция** (curried function) —
то есть функция, которая вместо всех аргументов сразу принимает их по одному,
возвращая на каждом шаге новую функцию:

```javascript
solution(isBadVersion) // возвращает функцию, принимающую n
solution(isBadVersion)(n) // сразу вызывает обе и получает результат
```

Это удобно, когда `isBadVersion` — что-то вроде "настройки" или "окружения"
(в реальном проекте это был бы вызов CI или внешний API), а `n` — конкретные входные
данные для конкретного вызова. Настроил `isBadVersion` один раз — и дальше
можно переиспользовать готовую функцию для разных `n`.

Внутри — классический бинарный поиск, но ищем не конкретное значение,
а **границу**, где `false` заканчивается и начинается `true`.

Держим два указателя:
- `left` — левая граница диапазона поиска (изначально версия `1`)
- `right` — правая граница диапазона поиска (изначально версия `n`)

На каждом шаге берём середину диапазона `mid` и спрашиваем у `isBadVersion(mid)`:

- если `mid` — **плохая версия** (`isBad === true`), значит первая плохая
  версия либо это `mid`, либо она находится левее. Сужаем диапазон поиска,
  сдвигая `right` до `mid` (саму `mid` не отбрасываем, она всё ещё может
  быть ответом).
- если `mid` — **хорошая версия** (`isBad === false`), значит первая плохая
  версия точно правее. Сдвигаем `left` до `mid + 1` (саму `mid` можно смело
  отбросить, она хорошая).

Цикл продолжается, пока `left` не станет равным `right` — в этот момент
`left` (он же `right`) и есть номер первой плохой версии.

## 4. Пошаговый разбор кода

```javascript
const solution = (isBadVersion) => {
  // Возвращаем функцию, которая принимает n и ищет первую плохую версию.
  // isBadVersion "запоминается" через замыкание (closure)
  return (n) => {
    // left и right — границы диапазона, в котором ищем первую плохую версию
    let left = 1;
    let right = n;

    // Сужаем диапазон, пока не останется одна версия — это и есть ответ
    while (left < right) {
      // Берём середину диапазона.
      // left + (right - left) / 2 используется вместо (left + right) / 2,
      // чтобы избежать переполнения числа при очень больших n
      const mid = Math.floor(left + (right - left) / 2);

      // Проверяем середину один раз и сохраняем результат,
      // чтобы не дёргать isBadVersion дважды
      const isBad = isBadVersion(mid);

      if (isBad) {
        // mid — плохая версия, первая плохая версия — mid или левее.
        // Не отбрасываем mid, поэтому right = mid (а не mid - 1)
        right = mid;
      }
      if (!isBad) {
        // mid — хорошая версия, первая плохая версия точно правее.
        // mid можно отбросить, поэтому left = mid + 1
        left = mid + 1;
      }
    }

    // left === right — это и есть номер первой плохой версии
    return left;
  };
};
```

### Трассировка на примере `n = 10`, первая падающая сборка — `6`

| шаг | left | right | mid | isBadVersion(mid) | действие |
|---|---|---|---|---|---|
| 1 | 1 | 10 | 5 | false | ответ правее → left = 6 |
| 2 | 6 | 10 | 8 | true | ответ — 8 или левее → right = 8 |
| 3 | 6 | 8 | 7 | true | right = 7 |
| 4 | 6 | 7 | 6 | true | right = 6 |

`left === right === 6` — цикл завершён, ответ `6`. Понадобилось 4 проверки вместо 6 при переборе подряд.

### Почему это работает быстро

Перебор по одному занял бы до `n` вызовов `isBadVersion` (в худшем случае —
миллиарды). Бинарный поиск на каждом шаге отбрасывает половину диапазона,
поэтому число вызовов растёт как `log2(n)` — для `n = 2 000 000 000` это
всего около **31 вызова**.

## 5. Сложность

- **Время:** O(log n) — на каждом шаге диапазон уменьшается вдвое
- **Память:** O(1) — используем только пару переменных
