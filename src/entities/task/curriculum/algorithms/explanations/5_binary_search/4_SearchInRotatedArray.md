## 1. Паттерн и шаблон алгоритма

**Паттерн:** Binary Search (бинарный поиск)  
**Разновидность:** `Binary Search: Rotated` (бинарный поиск в циклически сдвинутом / повёрнутом отсортированном массиве)

### В чём суть паттерна и разновидности
В повёрнутом отсортированном массиве точка излома делит его на две части, но в любой точке разреза хотя бы одна из половин (`left...mid` или `mid...right`) всегда остаётся строго монотонной (отсортированной).
Алгоритм выявляет отсортированную половину условием `nums[left] <= nums[mid]`:
- Если левая половина упорядочена: проверяем `nums[left] <= target < nums[mid]`. Если верно — сужаем поиск влево, иначе вправо.
- Если правая половина упорядочена: проверяем `nums[mid] < target <= nums[right]`. Если верно — сужаем вправо, иначе влево.
Это сохраняет логарифмическую сложность $O(\log n)$.

### Шаблон кода для запоминания синтаксиса
```javascript
// Шаблон: Binary Search: Rotated (поиск в повёрнутом массиве)
const binarySearchRotatedTemplate = (nums, target) => {
  let left = 0;
  let right = nums.length - 1;

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);

    if (nums[mid] === target) return mid;

    // Выясняем, какая половина гарантированно отсортирована
    if (nums[left] <= nums[mid]) {
      // Левая половина отсортирована
      if (nums[left] <= target && target < nums[mid]) {
        right = mid - 1; // ищем в отсортированной левой части
      } else {
        left = mid + 1;  // ищем в правой части
      }
    } else {
      // Правая половина отсортирована
      if (nums[mid] < target && target <= nums[right]) {
        left = mid + 1;  // ищем в отсортированной правой части
      } else {
        right = mid - 1; // ищем в левой части
      }
    }
  }

  return -1;
};
```

## 2. Суть задачи

Есть отсортированный по возрастанию массив, но его "повернули" — то есть
кусок с начала переставили в конец. Например:

```
было:  [0, 1, 2, 4, 5, 6, 7]
стало: [4, 5, 6, 7, 0, 1, 2]   (повернули на 3 позиции влево)
```

Нужно найти индекс числа `target` в таком массиве. Если числа нет — вернуть `-1`.

Условие требует сложность `O(log n)`, а это значит, что простой перебор
циклом (`for`) не подходит — нужен **бинарный поиск**. Но обычный бинарный
поиск работает только на полностью отсортированном массиве, а наш массив
отсортирован "с изломом". Значит, алгоритм нужно немного доработать.

## 3. Разбор решения

Ключевая идея: даже если весь массив не отсортирован целиком,
**одна из двух половин** (левая от `mid` до `left`, либо правая от `mid`
до `right`) **всегда отсортирована по-настоящему**. Достаточно на каждом
шаге определить, какая половина отсортирована, и проверить — не лежит ли
`target` внутри неё.

Пошагово:

1. Заводим два указателя: `left` (начало массива) и `right` (конец массива).
2. Пока `left <= right`, ищем середину `mid`.
3. Если `nums[mid]` — это и есть `target`, возвращаем `mid`.
4. Сравниваем `nums[left]` и `nums[mid]`, чтобы понять, какая половина
   отсортирована, и сохраняем результат в `leftHalfSorted`:
   - если `nums[left] <= nums[mid]` — отсортирована **левая** половина
     (`left ... mid`);
   - иначе — отсортирована **правая** половина (`mid ... right`).
5. В отсортированной половине можно точно сказать, попадает в неё `target`
   или нет — обычным сравнением с границами (как в обычном бинарном поиске).
   - Если `target` попадает в отсортированную половину — сужаем поиск до неё.
   - Если нет — значит `target` (если он вообще есть в массиве) лежит
     в другой половине, сужаем поиск туда.
6. Повторяем, пока не найдём `target` или пока диапазон поиска не закончится
   (`left > right`) — тогда возвращаем `-1`.

## 4. Пошаговый разбор кода

```javascript
const search = (nums, target) => {
  let left = 0;
  let right = nums.length - 1;

  while (left <= right) {
    // Середина текущего диапазона поиска.
    // left + (right - left) / 2 используется вместо (left + right) / 2,
    // чтобы избежать переполнения при очень больших индексах
    const mid = Math.floor(left + (right - left) / 2);

    // Нашли нужный элемент — сразу возвращаем его индекс
    if (nums[mid] === target) return mid;

    // Определяем, какая половина диапазона отсортирована "по-настоящему".
    // Если элемент слева не больше элемента в середине — левая половина
    // отсортирована без "излома"
    const leftHalfSorted = nums[left] <= nums[mid];

    if (leftHalfSorted) {
      // Левая половина отсортирована — можно проверить обычным сравнением,
      // попадает ли target в диапазон [nums[left], nums[mid])
      const targetInLeftHalf = nums[left] <= target && target < nums[mid];

      // Если target внутри отсортированной левой половины — ищем там,
      // иначе — искать нужно в правой половине
      targetInLeftHalf ? (right = mid - 1) : (left = mid + 1);
    }

    if (!leftHalfSorted) {
      // Отсортирована правая половина — проверяем,
      // попадает ли target в диапазон (nums[mid], nums[right]]
      const targetInRightHalf = nums[mid] < target && target <= nums[right];

      // Если target внутри отсортированной правой половины — ищем там,
      // иначе — искать нужно в левой половине
      targetInRightHalf ? (left = mid + 1) : (right = mid - 1);
    }
  }

  // Диапазон поиска закончился, а target так и не нашли
  return -1;
};
```

### Почему это O(log n)

На каждом шаге мы отбрасываем ровно половину оставшегося диапазона
поиска — не важно, в какой из половин "излом", проверка всегда
позволяет понять, куда сужать поиск. Поэтому число шагов растёт
как `log2(n)`, а не как `n`.

## 5. Сложность

- **Время:** O(log n) — классическая скорость бинарного поиска
- **Память:** O(1) — используем только несколько переменных
