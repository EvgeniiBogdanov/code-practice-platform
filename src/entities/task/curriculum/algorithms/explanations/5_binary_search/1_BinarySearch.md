## Какой алгоритм используется

**Binary Search (Бинарный поиск)**

## Суть задачи

Дан массив целых чисел `nums`, **отсортированный по возрастанию**, и число
`target`. Все числа в массиве уникальны (повторов нет).

Нужно найти индекс числа `target` в массиве и вернуть его. Если такого числа
в массиве нет — вернуть `-1`.

Отдельное условие задачи: решение должно работать за **O(log n)**. Это прямая
подсказка — простой перебор циклом (`O(n)`) технически даст правильный
ответ, но не пройдёт по требованиям задачи. Здесь ожидается именно бинарный
поиск.

## Разбор решения

Раз массив отсортирован, можно не проверять элементы по порядку один за
другим, а каждый раз смотреть на **средний элемент** оставшегося диапазона
поиска и сравнивать его с `target`:

- Если средний элемент равен `target` — ответ найден.
- Если средний элемент **меньше** `target` — значит, искомое число (если оно
  есть) точно находится **правее** середины. Всю левую половину, включая
  сам средний элемент, можно смело отбросить.
- Если средний элемент **больше** `target` — искомое число точно **левее**
  середины. Отбрасываем правую половину.

Так на каждом шаге диапазон поиска уменьшается вдвое. Если в какой-то момент
диапазон становится пустым (границы "пересеклись") — значит, числа `target`
в массиве нет вообще, возвращаем `-1`.

## Пошаговый разбор кода

```js
const search = (nums, target) => {
  // left и right — границы диапазона, где мы ещё можем найти target.
  // В самом начале это весь массив: от первого до последнего индекса
  let left = 0;
  let right = nums.length - 1;

  // Пока диапазон поиска не пуст (границы не "пересеклись")
  while (left <= right) {
    // Индекс среднего элемента текущего диапазона.
    // left + (right - left) / 2 — то же самое, что (left + right) / 2,
    // но более безопасная запись (подробнее — в разделе "Подводные камни")
    const mid = Math.floor(left + (right - left) / 2);

    if (nums[mid] === target) {
      return mid; // нашли — сразу возвращаем индекс
    }

    // Заранее считаем результат сравнения в отдельную переменную —
    // это делает следующий код чуть более читаемым
    const isSmaller = nums[mid] < target;

    if (isSmaller) {
      // средний элемент слишком маленький — искомое число правее
      left = mid + 1;
    }

    if (!isSmaller) {
      // средний элемент слишком большой — искомое число левее
      right = mid - 1;
    }
  }

  // Диапазон поиска опустел, а target так и не нашли
  return -1;
};
```

### Пошаговая трассировка на примере `nums = [-1,0,3,5,9,12], target = 9`

Индексы массива: `0..5`.

| шаг | left | right | mid | nums[mid] | сравнение | действие |
|---|---|---|---|---|---|---|
| 1 | 0 | 5 | 2 | 3 | 3 < 9 | искомое правее → left = 3 |
| 2 | 3 | 5 | 4 | 9 | 9 === 9 | **найдено!** возвращаем 4 |

Всего понадобилось **2 сравнения**, чтобы найти число `9` в массиве из 6
элементов — вместо потенциальных 5 сравнений при обычном переборе по порядку.

### Проверка примера с отсутствующим числом

```js
console.log(search([-1, 0, 3, 5, 9, 12], 2)); // -1
```

Здесь на каком-то шаге границы `left` и `right` "пересекутся"
(`left > right`), цикл `while` завершится, и функция вернёт `-1` — число `2`
в массиве действительно отсутствует.

### Проверка граничного случая (массив из одного элемента)

```js
console.log(search([5], 5)); // 0
```

Это хороший пример, чтобы проверить, что цикл вообще стартует и корректно
работает на самом маленьком возможном входе. При `left = 0` и `right = 0`
условие `left <= right` выполняется (`0 <= 0`), `mid` вычисляется как `0`,
`nums[0] === 5` — совпадение найдено сразу на первой итерации.

## Сложность

- **Время:** O(log n) — на каждом шаге диапазон поиска уменьшается вдвое, что
  соответствует требованию задачи.
- **Память:** O(1) — используем только несколько переменных
  (`left`, `right`, `mid`), без дополнительных структур данных.

Для сравнения: наивный перебор циклом дал бы O(n), что для массива из
10 000 элементов (максимум по условию задачи) означает до 10 000 сравнений в
худшем случае — против всего около 14 сравнений у бинарного поиска
(`log₂(10000) ≈ 13.3`).

## Почему тут именно Binary Search, а не другой подход

- Массив **отсортирован** по возрастанию — это ключевое условие, без которого
  бинарный поиск неприменим.
- Все числа **уникальны** — не нужно думать о том, какое из повторяющихся
  вхождений возвращать (это упрощённый случай по сравнению с задачами, где
  требуется искать первое или последнее вхождение при дубликатах).
- Требование сложности **O(log n)** прямо указывает на бинарный поиск —
  линейный перебор эту границу превысит уже на больших входных данных.

## Особенности этой реализации

1. **`left + (right - left) / 2` вместо `(left + right) / 2`.**
   Математически это одно и то же значение. Но `(left + right) / 2` в языках
   со строгой типизацией (Java, C++) может привести к переполнению
   целочисленного типа при очень больших `left` и `right` (их сумма может
   выйти за пределы допустимого диапазона `int`, даже если сама середина —
   вполне нормальное число). Запись `left + (right - left) / 2` устраняет
   эту опасность, потому что `right - left` всегда меньше, чем `right` само
   по себе. В JavaScript все числа — `double`, и реального переполнения
   `int` тут не случится, но такая запись — хорошая, безопасная привычка,
   которая пригодится и в других языках программирования.

2. **`isSmaller` + два независимых `if` вместо `if / else if`.**
   Результат сравнения `nums[mid] < target` сохраняется в отдельную
   переменную `isSmaller`, а дальше идут два самостоятельных условия:
   `if (isSmaller)` и `if (!isSmaller)`. Это работает так же, как
   `if / else`, но делает каждое условие более явным и читаемым по
   отдельности — особенно полезно, если позже понадобится добавить
   дополнительную логику в одну из веток, не трогая другую.
