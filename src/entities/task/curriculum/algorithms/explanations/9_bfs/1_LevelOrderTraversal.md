## 1. Паттерн и шаблон алгоритма

**Паттерн:** BFS (Breadth-First Search, поиск в ширину)  
**Разновидность:** `BFS: Level Order` (поуровневый обход с фиксацией размера очереди)

### В чём суть паттерна и разновидности
В отличие от обхода в глубину (DFS), поиск в ширину (BFS) использует очередь (FIFO) и обрабатывает граф или дерево концентрическими слоями («уровнями»).
Чтобы разделить узлы по уровням, применяется ключевой приём: в начале каждого слоя фиксируется текущая длина очереди `const levelSize = queue.length`. Внутренний цикл обрабатывает ровно `levelSize` узлов, складывая их значения в массив текущего уровня, а вновь добавляемые дети автоматически попадают на следующий уровень очереди.

### Шаблон кода для запоминания синтаксиса
```javascript
// Шаблон: BFS: Level Order (поуровневый обход графа/дерева)
const bfsLevelOrderTemplate = (root) => {
  if (!root) return [];

  const result = [];
  const queue = [root];

  while (queue.length > 0) {
    const levelSize = queue.length; // Фиксируем количество узлов на уровне
    const currentLevel = [];

    for (let i = 0; i < levelSize; i++) {
      const node = queue.shift();
      currentLevel.push(node.val);

      // Добавляем детей в очередь для следующего уровня
      if (node.left) queue.push(node.left);
      if (node.right) queue.push(node.right);
    }

    result.push(currentLevel);
  }

  return result;
};
```

## 2. Суть задачи

Оргструктура компании хранится как бинарное дерево. Нужно вернуть значения всех узлов,
сгруппированные по уровням: сначала уровень с корнем, затем уровень
с его детьми, затем уровень с внуками, и так далее. Внутри каждого
уровня узлы идут слева направо.

Пример:

```
        10
       /  \
      6    15
     / \     \
    3   8     20
```

Результат: `[[10], [6, 15], [3, 8, 20]]` — три вложенных массива, по
одному на каждый уровень дерева.

## 3. Разбор решения

### Почему это BFS, а не DFS

Задача явно просит группировать узлы **по уровням** — а BFS как раз
устроен так, что "текущий фронт" обхода — это всегда ровно один
уровень дерева. Если использовать DFS (рекурсивный обход "вглубь"),
пришлось бы отдельно передавать номер глубины и вручную
группировать результаты — это тоже рабочий вариант, но BFS для этой
задачи выглядит естественнее, потому что порядок обработки узлов в
очереди сам по себе совпадает с порядком уровней.

### Ключевая идея: как понять, где заканчивается уровень

Если просто обходить дерево через очередь, доставая по одному узлу
и добавляя его детей, то в очереди со временем **перемешаются** узлы
разных уровней — непонятно, где заканчивается один уровень и
начинается следующий.

Решение: перед тем как начать обрабатывать очередной уровень, мы
**запоминаем текущий размер очереди** — `levelSize`. Это ровно
столько узлов, сколько относится к текущему уровню (потому что все
дети предыдущего уровня к этому моменту уже добавлены, а дети
текущего уровня — ещё нет). Затем обрабатываем именно `levelSize`
узлов, попутно добавляя в очередь их детей — они попадут уже в
*следующий* проход `while`, то есть в следующий уровень.

## 4. Пошаговый разбор кода

```js
const levelOrder = (root) => {
  const levels = [];
  // Сюда будем складывать результат — массив уровней.

  if (root === null) {
    return levels;
  }
  // Пустое дерево — сразу возвращаем пустой массив, обходить нечего.

  const queue = [root];
  // Очередь для BFS. push() добавляет в конец, shift() достаёт из
  // начала — вместе это даёт поведение FIFO (кто раньше зашёл,
  // тот раньше выходит), то есть настоящую очередь.

  while (queue.length > 0) {
    const levelSize = queue.length;
    // Замораживаем размер очереди ДО того, как начнём добавлять
    // в неё детей текущего уровня. Это и есть количество узлов
    // на текущем уровне — не больше и не меньше.

    const currentLevel = [];
    // Сюда сложим значения узлов именно этого уровня.

    for (let i = 0; i < levelSize; i += 1) {
      const node = queue.shift();
      // Достаём узел текущего уровня из начала очереди.

      currentLevel.push(node.val);
      // Запоминаем его значение.

      if (node.left !== null) {
        queue.push(node.left);
      }
      if (node.right !== null) {
        queue.push(node.right);
      }
      // Кладём его детей в КОНЕЦ очереди — они относятся уже
      // к следующему уровню и будут обработаны только на
      // следующей итерации внешнего while.
    }

    levels.push(currentLevel);
    // Уровень полностью собран — добавляем его в общий результат.
  }

  return levels;
};
```

### Разбор на примере
Дерево `[10, 6, 15, 3, 8, null, 20]` (рисунок — в разделе 2):

1. `queue = [10]`. `levelSize = 1`. Обрабатываем `10`, добавляем его
   детей `6` и `15`. `currentLevel = [10]`. `queue = [6, 15]`.
   `levels = [[10]]`.
2. `queue = [6, 15]`. `levelSize = 2`. Обрабатываем `6` (добавляем его
   детей `3` и `8`), затем `15` (у него только правый ребёнок `20`).
   `currentLevel = [6, 15]`. `queue = [3, 8, 20]`.
   `levels = [[10], [6, 15]]`.
3. `queue = [3, 8, 20]`. `levelSize = 3`. Обрабатываем `3`, `8` и `20`
   (у всех нет детей). `currentLevel = [3, 8, 20]`. `queue = []`.
   `levels = [[10], [6, 15], [3, 8, 20]]`.
4. `queue` пуста — цикл заканчивается, возвращаем `levels`.

## 5. Сложность и особенности
- **Время:** O(n), где n — количество узлов дерева, потому что
  каждый узел кладётся в очередь и достаётся из неё ровно один раз.
- **Память:** O(n) — в худшем случае (например, у полного дерева
  последний уровень может содержать почти половину всех узлов)
  очередь одновременно хранит вплоть до O(n) элементов; плюс сам
  результирующий массив тоже хранит все n значений.

### Про вспомогательные функции
`createNode` и `buildTree` — не часть самой задачи, а просто удобный
способ задавать деревья в примерах через плоский массив, а не собирать
узлы вручную объект за объектом.
