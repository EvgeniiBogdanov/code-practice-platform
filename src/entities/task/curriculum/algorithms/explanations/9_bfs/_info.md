## 1. Что такое BFS и в чём его суть

**BFS (Breadth-First Search, обход/поиск в ширину)** — это алгоритм
обхода графа или дерева, при котором мы посещаем вершины "слоями":
сначала стартовую вершину, потом всех её соседей, потом соседей
соседей, и так далее.

Представьте, что вы бросили камень в воду — круги расходятся от
центра равномерно, слой за слоем. Это и есть BFS: мы никогда не
"убегаем" далеко вглубь, пока не обойдём всё, что ближе.

Более формально: если `d[v]` — это расстояние (в рёбрах) от
стартовой вершины до вершины `v`, то BFS посещает вершины строго в
порядке возрастания `d[v]` — сначала самые близкие, потом более
далёкие.

## 2. BFS vs DFS — в чём разница

|                     | BFS (в ширину)                       | DFS (в глубину)                    |
|---------------------|---------------------------------------|-------------------------------------|
| Структура данных    | Очередь (Queue, FIFO)                 | Стек (Stack, LIFO) или рекурсия     |
| Порядок обхода      | По слоям, "вширь"                     | "Вглубь" до конца одной ветки       |
| Что находит         | Кратчайший путь в невзвешенном графе  | Любой путь (не обязательно кратчайший) |
| Память               | Может хранить много вершин "на фронте"| Обычно требует меньше памяти        |

Ключевая интуиция: DFS — это когда вы идёте по лабиринту, держась
одной рукой за стену, и уходите максимально далеко, прежде чем
вернуться назад. BFS — это когда вы одновременно (как бы) отправляете
"гонцов" во все стороны и продвигаетесь равномерно.

## 3. Как устроен алгоритм пошагово

1. Берём стартовую вершину, кладём её в **очередь** и помечаем как
   "посещённую".
2. Пока очередь не пуста:
   - достаём вершину из **начала** очереди;
   - обрабатываем её (например, выводим на экран или проверяем
     условие);
   - находим всех её соседей, которые ещё не посещены;
   - помечаем их как посещённые и кладём в **конец** очереди.
3. Когда очередь опустела — обход закончен.

Важный момент: вершина помечается посещённой **в момент добавления в
очередь**, а не в момент извлечения из неё. Если пометить её позже,
одна и та же вершина может попасть в очередь несколько раз (подробнее
в разделе "Подводные камни").

## 4. Реализация на JavaScript (стрелочные функции)

Самый простой случай — BFS по дереву, где циклов быть не может по
определению, поэтому не нужно ничего помечать как "посещённое".

```js
const createNode = (val, left = null, right = null) => ({ val, left, right });

const tree = createNode(1,
  createNode(2,
    createNode(4),
    createNode(5)
  ),
  createNode(3)
);

const bfs = (root) => {
  const result = [];

  if (root === null) {
    return result;
  }

  const queue = [root];

  while (queue.length > 0) {
    const node = queue.shift();
    result.push(node.val);

    if (node.left !== null) {
      queue.push(node.left);
    }
    if (node.right !== null) {
      queue.push(node.right);
    }
  }

  return result;
};

console.log(bfs(tree)); // [1, 2, 3, 4, 5]
```

Дерево из примера выглядит так:

```
        1
       / \
      2   3
     / \
    4   5
```

BFS обходит его по уровням: сначала `1`, потом весь второй уровень
(`2, 3`), потом весь третий (`4, 5`) — результат `[1, 2, 3, 4, 5]`.

## 5. Разбор кода построчно

```js
const bfs = (root) => {
  const result = [];
  // Сюда будем складывать порядок посещения узлов.

  if (root === null) {
    return result;
  }
  // Если дерево пустое — сразу возвращаем пустой результат,
  // обходить нечего.

  const queue = [root];
  // Очередь — это обычный массив. В начале в ней лежит только корень.
  // push() добавляет элемент в КОНЕЦ, shift() достаёт из НАЧАЛА —
  // вместе они дают нам поведение FIFO (First In, First Out),
  // то есть именно очередь, а не стек.

  while (queue.length > 0) {
    const node = queue.shift();
    // Достаём САМЫЙ ПЕРВЫЙ элемент очереди — то есть того, кто ждёт
    // дольше всех. Именно это и создаёт обход "по слоям".

    result.push(node.val);
    // Обрабатываем узел — в данном случае просто запоминаем значение.

    if (node.left !== null) {
      queue.push(node.left);
    }
    if (node.right !== null) {
      queue.push(node.right);
    }
    // Кладём в КОНЕЦ очереди детей текущего узла. Они будут обработаны
    // только после того, как обработаются ВСЕ узлы текущего уровня —
    // потому что они лежат в конце, а очередь работает по принципу
    // "кто раньше пришёл, тот раньше уйдёт".
  };

  return result;
};
```

## 6. BFS на дереве

На дереве BFS особенно нагляден, потому что в дереве **нет циклов** —
значит, не нужно ничего помечать "посещённым": каждый узел
физически достижим только одним путём от корня.

Частая практическая задача — обойти дерево **по уровням**, сохраняя
каждый уровень отдельным массивом (а не одним плоским списком).
Для этого на каждой итерации внешнего цикла "замораживаем" текущий
размер очереди — это и есть размер текущего уровня:

```js
const levelOrder = (root) => {
  const levels = [];

  if (root === null) {
    return levels;
  }

  const queue = [root];

  while (queue.length > 0) {
    const levelSize = queue.length;
    const currentLevel = [];

    for (let i = 0; i < levelSize; i += 1) {
      const node = queue.shift();
      currentLevel.push(node.val);

      if (node.left !== null) {
        queue.push(node.left);
      }
      if (node.right !== null) {
        queue.push(node.right);
      }
    }

    levels.push(currentLevel);
  }

  return levels;
};

console.log(levelOrder(tree)); // [[1], [2, 3], [4, 5]]
```

Хитрость тут в строке `const levelSize = queue.length;` — мы
запоминаем, сколько узлов было в очереди **до того**, как начали
добавлять туда детей. Именно столько узлов относится к текущему
уровню — ни больше, ни меньше.

## 7. BFS на графе (с циклами)

В отличие от дерева, в графе можно вернуться в уже посещённую
вершину — поэтому необходим **набор посещённых вершин** (`visited`),
иначе алгоритм зациклится и никогда не завершится (или будет
многократно обрабатывать одни и те же вершины).

```js
const bfsGraph = (graph, start) => {
  const visited = new Set([start]);
  const order = [];
  const queue = [start];

  while (queue.length > 0) {
    const vertex = queue.shift();
    order.push(vertex);

    const neighbours = graph.get(vertex);

    for (const neighbour of neighbours) {
      if (visited.has(neighbour) === false) {
        visited.add(neighbour);
        queue.push(neighbour);
      }
    }
  }

  return order;
};

const graph = new Map([
  ['A', ['B', 'C']],
  ['B', ['A', 'D']],
  ['C', ['A', 'D']],
  ['D', ['B', 'C', 'E']],
  ['E', ['D']],
]);

console.log(bfsGraph(graph, 'A')); // ['A', 'B', 'C', 'D', 'E']
```

Здесь `graph` — это **список смежности** (adjacency list): для
каждой вершины хранится массив её соседей. `visited` — это `Set`
(множество), в котором мы отмечаем вершину **сразу при добавлении
в очередь**, а не при извлечении (почему это важно — см. раздел
"Подводные камни").

## 8. Практический пример: кратчайший путь

Самое частое практическое применение BFS — поиск **кратчайшего пути**
в невзвешенном графе (то есть там, где все рёбра "стоят" одинаково).
Идея простая: раз BFS обходит вершины строго по возрастанию
расстояния от старта, то первый же раз, когда мы дойдём до целевой
вершины, — путь до неё гарантированно кратчайший.

```js
const shortestPath = (graph, start, target) => {
  const visited = new Set([start]);
  const queue = [[start]];
  // В очереди храним не просто вершины, а целые ПУТИ (массивы вершин),
  // которые привели нас в эту точку — так удобно восстановить маршрут.

  while (queue.length > 0) {
    const path = queue.shift();
    const vertex = path[path.length - 1];

    if (vertex === target) {
      return path;
    }

    const neighbours = graph.get(vertex);

    for (const neighbour of neighbours) {
      if (visited.has(neighbour) === false) {
        visited.add(neighbour);
        queue.push([...path, neighbour]);
      }
    }
  }

  return null;
};

console.log(shortestPath(graph, 'A', 'E')); // ['A', 'B', 'D', 'E'] или ['A', 'C', 'D', 'E']
```

## 9. Подводные камни

### 9.1. Помечать вершину нужно ПРИ добавлении в очередь, а не при извлечении
Частая ошибка новичков:

```js
// ТАК ДЕЛАТЬ НЕ НАДО
while (queue.length > 0) {
  const vertex = queue.shift();
  if (visited.has(vertex)) continue;
  visited.add(vertex); // помечаем СЛИШКОМ ПОЗДНО

  for (const neighbour of graph.get(vertex)) {
    queue.push(neighbour);
  }
}
```

Проблема: пока вершина ждёт своей очереди, её могут **несколько раз**
добавить в очередь другие соседи — ведь она ещё не помечена как
посещённая. В плотном графе это может привести к экспоненциальному
раздуванию очереди. Правильно — помечать вершину `visited` сразу в
момент `queue.push(...)`, как в примерах выше.

### 9.2. `Array.prototype.shift()` — это операция O(n), а не O(1)
Многие новички используют обычный массив и `shift()` как очередь —
и это абсолютно нормально для учебных задач и задач с LeetCode
(данные там небольшие). Но нужно понимать: `shift()` физически
сдвигает **все оставшиеся элементы** массива на одну позицию влево,
поэтому вызов `shift()` стоит O(n), а не O(1), как у настоящей
очереди. Если очередь может вырасти до десятков и сотен тысяч
элементов (например, обход огромного графа), лучше использовать:
- два указателя-индекса вместо `shift()` (не удалять элементы, а
  просто двигать "указатель начала" по массиву);
- либо связный список;
- либо специализированную структуру данных "Deque".

### 9.3. Забыть проверить на `null`/`undefined` перед обращением к полям узла
Если у узла дерева нет левого потомка (`node.left === null`), а
код всё равно попытается сделать `queue.push(node.left.val)` без
проверки — вылетит ошибка. Всегда проверяйте на `null` **перед**
тем, как класть узел в очередь, а не после.

### 9.4. Перепутать BFS с "уровневым" DFS
Иногда кажется, что если делать DFS и одновременно передавать номер
глубины (`depth`), результат будет "как будто по уровням" — и это
почти правда для сбора данных по уровням, но **порядок обработки**
всё равно останется "вглубь", а не "вширь". Если критичен именно
порядок посещения (а не просто группировка по уровням), нужен именно
BFS с очередью, а не DFS с параметром глубины.

### 9.5. Забыть проверить дерево/граф на пустоту
`root === null` или пустой граф — важный edge case, который легко
забыть. Без такой проверки `queue.shift()` на первой же итерации
вернёт `undefined`, и следующая строка (`node.val`) упадёт с ошибкой.

## 10. Сложность алгоритма

- **Время:** O(V + E), где V — количество вершин, E — количество
  рёбер. Каждая вершина посещается один раз, каждое ребро
  просматривается один или два раза (в зависимости от того,
  ориентированный граф или нет).
- **Память:** O(V) — в худшем случае в очереди и в множестве
  `visited` может оказаться сразу весь граф (например, если граф —
  это "звезда", где одна вершина соединена со всеми остальными).

Для дерева из n узлов это упрощается до **O(n)** по времени и памяти.

## 11. Где применяется BFS

- Поиск кратчайшего пути в невзвешенном графе (например, в лабиринте
  или сетке).
- Обход дерева "по уровням" (level order traversal) — частая задача
  на собеседованиях.
- Поиск компонент связности в графе.
- Алгоритмы вроде "число рукопожатий" (расстояние между двумя людьми
  в социальном графе).
- Веб-краулеры (поисковые пауки) — обходят страницы "слоями" от
  стартовой.
- Сборщики мусора (garbage collection) в некоторых языках
  программирования используют BFS-подобные алгоритмы для обхода
  графа ссылок между объектами.
