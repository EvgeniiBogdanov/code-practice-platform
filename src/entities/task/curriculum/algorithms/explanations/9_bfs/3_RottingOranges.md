# Rotting Oranges (LeetCode 994) — разбор задачи

## Какой алгоритм используется
**Multi-source BFS (обход в ширину сразу от нескольких стартовых
точек)**. Это тот же принцип, что и в обычном BFS, но в очередь
изначально кладутся **все** гнилые апельсины сразу, а не один узел —
потому что заражение распространяется от них одновременно и
параллельно, а не по очереди.

## Суть задачи
Дана сетка (grid), где `0` — пустая клетка, `1` — свежий апельсин,
`2` — гнилой апельсин. Каждую минуту любой свежий апельсин, стоящий
рядом (сверху/снизу/слева/справа, НЕ по диагонали) с гнилым,
портится сам. Нужно найти минимальное количество минут, за которое
сгниют все апельсины, или вернуть `-1`, если какой-то свежий
апельсин никогда не "дотянется" до заражения.

Пример:

```
2 1 1
1 1 0
0 1 1
```

Ответ — `4` минуты, потому что заражение расходится от угла `(0,0)`
"волнами" во все стороны, и самый дальний апельсин `(2,2)` заражается
только на 4-й минуте.

## Почему это именно BFS, а не DFS
Ключевая фраза в условии — **"каждую минуту"**. Все свежие апельсины,
соседствующие с гнилыми, портятся **одновременно**, за один и тот же
"тик" времени. Именно так и работает BFS: он обрабатывает узлы
"слоями" — сначала всех "соседей на расстоянии 1", потом всех
"соседей на расстоянии 2", и так далее. Каждый такой слой в этой
задаче — это ровно одна минута.

DFS для этой задачи не подходит: он "ныряет" по одному конкретному
пути вглубь дерева заражения, будто апельсины портятся один за
другим по очереди, а не пачками одновременно — это не соответствует
логике задачи "минута — это волна заражения", и посчитать корректное
количество минут через DFS сложно и ненадёжно.

## Почему BFS запускается сразу из нескольких точек (multi-source)
Если в сетке несколько гнилых апельсинов с самого начала, заражение
идёт от **каждого** из них одновременно, и они могут "встретиться"
где-то посередине. Поэтому в самую первую очередь (до начала обхода)
в очередь BFS кладутся **все** изначально гнилые апельсины разом —
это и называется multi-source BFS. Дальше алгоритм ничем не
отличается от обычного BFS: просто у него сразу несколько "стартовых
узлов" вместо одного.

## Общая идея решения
1. Проходим по всей сетке один раз: находим все изначально гнилые
   апельсины и кладём их координаты в очередь; заодно считаем общее
   количество свежих апельсинов (`freshCount`).
2. Пока в очереди что-то есть и остались свежие апельсины — делаем
   один "проход BFS по уровню" (это и есть одна минута):
   - запоминаем, сколько узлов сейчас в очереди (`levelSize`) — это
     все гнилые апельсины текущего "поколения";
   - для каждого из них проверяем всех 4 соседей; если сосед —
     свежий апельсин, заражаем его (`grid[r][c] = 2`), уменьшаем
     `freshCount` и добавляем его в очередь — он будет заражать
     дальше уже на следующей минуте;
   - после обработки всего уровня увеличиваем счётчик минут на 1.
3. Если после окончания BFS остались незаражённые свежие апельсины
   (`freshCount > 0`) — значит, до них было физически не добраться,
   возвращаем `-1`. Иначе возвращаем накопленное количество минут.

## Пошаговый разбор кода

```js
const orangesRotting = (grid) => {
  const rows = grid.length;
  const cols = grid[0].length;
  const queue = [];
  let freshCount = 0;

  for (let r = 0; r < rows; r += 1) {
    for (let c = 0; c < cols; c += 1) {
      if (grid[r][c] === 2) {
        queue.push([r, c]);
      }
      if (grid[r][c] === 1) {
        freshCount += 1;
      }
    }
  }
  // Готовим multi-source BFS: сразу кладём в очередь координаты
  // ВСЕХ изначально гнилых апельсинов и попутно считаем, сколько
  // всего свежих апельсинов есть в сетке.

  let minutes = 0;
  // Счётчик минут — будет увеличиваться на 1 за каждый обработанный
  // "слой" BFS (то есть за каждую волну заражения).

  while (queue.length > 0 && freshCount > 0) {
    // Продолжаем, пока в очереди есть гнилые апельсины, готовые
    // заражать соседей, И пока остались незаражённые свежие апельсины.
    // Если свежих апельсинов больше нет — заражать уже нечего,
    // можно останавливаться, даже если в очереди что-то осталось.

    const levelSize = queue.length;
    // Замораживаем размер очереди ДО начала обработки этого слоя —
    // это все апельсины, заразившиеся в предыдущую минуту (или
    // изначально гнилые, если это первый проход).

    for (let i = 0; i < levelSize; i += 1) {
      const [row, col] = queue.shift();
      const neighbors = [
        [row - 1, col],
        [row + 1, col],
        [row, col - 1],
        [row, col + 1],
      ];

      for (const [r, c] of neighbors) {
        const inBounds = r >= 0 && r < rows && c >= 0 && c < cols;
        if (inBounds && grid[r][c] === 1) {
          grid[r][c] = 2;
          freshCount -= 1;
          queue.push([r, c]);
        }
      }
      // Заражаем всех свежих соседей текущего гнилого апельсина —
      // они попадут в очередь и будут заражать дальше уже на
      // СЛЕДУЮЩЕЙ минуте, а не прямо сейчас.
    }

    minutes += 1;
    // Весь этот слой (эта "волна" заражения) обработан — засчитываем
    // одну прошедшую минуту.
  }

  if (freshCount > 0) {
    return -1;
  }
  // Если после того, как BFS закончился (очередь опустела), остались
  // незаражённые свежие апельсины — значит, до них было физически
  // не добраться (они отрезаны пустыми клетками или краем сетки).

  return minutes;
};
```

## Разбор на примере
Сетка `[[2,1,1],[1,1,0],[0,1,1]]`:

- **Старт:** гнилой апельсин один — `(0,0)`. `queue = [[0,0]]`,
  `freshCount = 5`, `minutes = 0`.
- **Минута 1:** обрабатываем `(0,0)`. Заражаем соседей `(0,1)` и
  `(1,0)` (оба были свежими). `freshCount = 3`. `minutes = 1`.
- **Минута 2:** обрабатываем `(0,1)` и `(1,0)`. Заражаем `(0,2)` и
  `(1,1)`. `freshCount = 1`. `minutes = 2`.
- **Минута 3:** обрабатываем `(0,2)` и `(1,1)`. Заражаем `(2,1)`
  (единственный оставшийся сосед-апельсин). `freshCount = 0`.
  `minutes = 3`.
- **Минута 4:** обрабатываем `(2,1)`. Заражаем `(2,2)`.
  `freshCount = 0` уже был, но именно сейчас последний апельсин
  реально заразился. `minutes = 4`.
- Дальше `freshCount === 0`, цикл `while` останавливается.
  Возвращаем `4`.

## Подводный камень: когда увеличивать счётчик минут
Легко ошибиться и увеличивать `minutes` на каждой итерации `while`
без учёта того, действительно ли что-то заразилось. В этом решении
проблема решена условием `queue.length > 0 && freshCount > 0` —
цикл просто не запускается лишний раз, если заражать больше некого,
поэтому "пустых" минут не начисляется. Это особенно важно для
примера 3 (`[[0,2]]`) — там свежих апельсинов нет вообще, и
`minutes` должен остаться `0`, а не увеличиться просто потому, что
гнилой апельсин лежит в очереди.

## Сложность
- **Время:** O(m × n), где m и n — размеры сетки, потому что каждая
  клетка добавляется в очередь и обрабатывается не более одного
  раза.
- **Память:** O(m × n) в худшем случае — например, если почти все
  клетки гнилые с самого начала, очередь в первый момент содержит
  почти всю сетку.
