## 1. Паттерн и шаблон алгоритма

**Паттерн:** Linked List (связный список)  
**Разновидность:** `Linked List: Reversal` (разворот указателей связного списка in-place)

### В чём суть паттерна и разновидности
В односвязном списке каждый узел ссылается только на следующий элемент. Чтобы развернуть направление списка без выделения дополнительной памяти ($O(1)$ space), используется приём с тремя указателями:
1. `prev` (предыдущий узел, изначально `null`);
2. `curr` (текущий узел, изначально `head`);
3. `nextTemp` (временное сохранение ссылки на следующий узел).

Ключевое правило: **сначала сохранить `curr.next`**, затем перенаправить `curr.next = prev`, после чего переместить `prev` и `curr` на один шаг вперёд. При выходе из цикла `prev` становится новой головой списка.

### Шаблон кода для запоминания синтаксиса
```javascript
// Шаблон: Linked List: Reversal (разворот списка in-place)
const reverseListTemplate = (head) => {
  let prev = null;
  let curr = head;

  while (curr !== null) {
    const nextTemp = curr.next; // 1. Запоминаем следующий узел
    curr.next = prev;           // 2. Разворачиваем связь назад
    prev = curr;                // 3. Сдвигаем prev на текущий узел
    curr = nextTemp;            // 4. Переходим к следующему узлу
  }

  return prev; // prev указывает на новую голову развёрнутого списка
};
```

## 2. Суть задачи простыми словами

Представьте цепочку вагончиков поезда, где у каждого вагона есть крюк, цепляющий его к **следующему** вагону:

```
1 → 2 → 3 → 4 → 5 → null
```

Нужно перецепить все крюки так, чтобы они смотрели в обратную сторону — на **предыдущий** вагон:

```
null ← 1 ← 2 ← 3 ← 4 ← 5
```

При этом последний вагон (5) станет первым, а первый (1) — последним. Физически элементы никуда не перемещаются в памяти — меняются только ссылки `next` у каждого узла.

## 3. Разбор решения

### Устройство узла в этом решении

Вместо класса узел здесь создаётся простой фабричной функцией, которая возвращает обычный объект:

```js
const createNode = (val = 0, next = null) => ({ val, next });
```

Это более "функциональный" стиль: никакого `new`, никакого `this` — просто объект с двумя полями. Значения по умолчанию (`val = 0`, `next = null`) избавляют от необходимости отдельно обрабатывать пустые аргументы.

### Построение списка из массива: `createLinkedList`

```js
const createLinkedList = (arr) => arr.reduceRight((acc, val) => createNode(val, acc), null);
```

Здесь используется `reduceRight` — то есть массив обходится **с конца**. Это сделано намеренно и довольно элегантно: раз узел создаётся сразу со ссылкой `next` на уже готовый "хвост", список удобнее собирать с последнего элемента к первому.

Разберём на примере `[1, 2, 3]`:

| Шаг | val | acc (накопитель, он же будущий `next`) | Результат `createNode(val, acc)` |
|---|---|---|---|
| старт | — | `null` | — |
| 1 | `3` | `null` | `{ val: 3, next: null }` |
| 2 | `2` | `{ val: 3, next: null }` | `{ val: 2, next: {val: 3, ...} }` |
| 3 | `1` | `{ val: 2, next: {...} }` | `{ val: 1, next: {val: 2, ...} }` |

В итоге `reduceRight` возвращает узел `1`, у которого `next` указывает на `2`, а у того — на `3`. Получился полноценный связный список `1 → 2 → 3 → null`, собранный всего одной строкой без циклов.

## 4. Пошаговый разбор кода

```js
const reverseList = (head) => {
  let prev = null;          // 1. "Хвост" уже развёрнутой части списка
  let current = head;       // 2. Узел, который разворачиваем прямо сейчас

  while (current) {                    // 3. Пока не дошли до конца списка
    const nextTemp = current.next;     // 4. Запоминаем следующий узел — иначе потеряем к нему доступ
    current.next = prev;               // 5. Перецепляем крюк current на prev (сам разворот!)
    prev = current;                    // 6. prev "передвигается" на current
    current = nextTemp;                // 7. current "передвигается" на nextTemp
  }

  return prev;               // 8. Когда current стал null, prev — это новая голова списка
};
```

### Визуализация по шагам для `[1, 2, 3]`

| Шаг | prev | current | nextTemp | Список (реально существующие связи) |
|---|---|---|---|---|
| старт | `null` | `1` | — | `1 → 2 → 3 → null` |
| после 1-й итерации | `1` | `2` | `2` | `null ← 1`   `2 → 3 → null` |
| после 2-й итерации | `2 → 1` | `3` | `3` | `null ← 1 ← 2`   `3 → null` |
| после 3-й итерации | `3 → 2 → 1` | `null` | `null` | `null ← 1 ← 2 ← 3` |

Цикл заканчивается, когда `current` становится `null` — значит, мы прошли весь список. `prev` в этот момент указывает на последний обработанный узел, то есть на **новую голову**.

### Почему важен порядок строк 4-5-6-7

Если поменять местами шаги 4 и 5 — то есть сначала переписать `current.next = prev`, а потом попытаться прочитать `current.next` — вы получите `prev` вместо настоящего "следующего" узла и потеряете весь оставшийся хвост списка. Именно поэтому **сначала сохраняем `next` в `nextTemp`**, и только потом разрываем/меняем ссылку.

## Рекурсивное решение (для сравнения, follow-up из условия)

```js
const reverseListRecursive = (head) =>
  head?.next
    ? (() => {
        const newHead = reverseListRecursive(head.next);
        head.next.next = head;
        head.next = null;
        return newHead;
      })()
    : head ?? null;
```

Идея рекурсии: "поверь, что весь список **после** текущего узла уже развёрнут, а тебе осталось только пристроить текущий узел в конец этого развёрнутого хвоста". Разворот идёт "снизу вверх" — сначала рекурсия доходит до последнего узла (он и станет новой головой), а затем на обратном пути каждый узел перецепляет ссылку `next` у своего соседа.

Итеративная версия из `solution.js` — предпочтительный вариант для реальной работы и собеседований: она читаемее и не рискует упереться в переполнение стека вызовов (stack overflow) на списке из 5000 узлов (максимум по условию задачи), в отличие от рекурсии.

## 5. Сложность и особенности

| Показатель | Итеративное решение | Рекурсивное решение |
|---|---|---|
| Время | O(n) — один проход по списку | O(n) — один проход, но с накладными расходами на вызовы функций |
| Память | O(1) — используем только несколько переменных-указателей | O(n) — из-за стека вызовов рекурсии |

Итеративное решение — оптимальное по обоим показателям, поэтому именно оно приведено в `solution.js`.

### Частые ошибки при решении этой задачи

- Забыть сохранить `current.next` в `nextTemp` перед тем, как его перезаписать — теряется доступ к оставшейся части списка.
- Вернуть `head` вместо `prev` в конце функции — `head` к этому моменту уже указывает на **старый первый**, а теперь **последний** элемент, а не на новую голову.
- Не обработать пустой список (`head === null`) — в текущем решении это работает автоматически: `while (current)` просто ни разу не выполнится, и функция сразу вернёт `prev`, равный `null`.
- Перепутать `nextTemp` (временная переменная) с `current.next` (реальная связь в списке) — из-за похожих ролей легко создать путаницу при отладке.
- При использовании `createNode` забыть, что это обычный объект, а не экземпляр класса — методы вроде `instanceof ListNode` здесь работать не будут, так как никакого класса `ListNode` не существует.
