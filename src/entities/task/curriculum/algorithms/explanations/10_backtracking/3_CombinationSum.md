## 1. Паттерн и шаблон алгоритма

**Паттерн:** Backtracking (перебор с возвратом)  
**Разновидность:** `Backtracking: Combinations` (комбинации с возможностью повторения элементов и отсечением по сумме)

### В чём суть паттерна и разновидности
В задаче поиска комбинаций, дающих в сумме `target`:
1. **Повторное использование элементов:** текущее число можно брать сколько угодно раз, поэтому в рекурсивный вызов передаётся **тот же индекс** `i`, а не `i + 1`: `backtrack(i, remaining - candidates[i])`.
2. **Исключение перестановок:** цикл начинает перебор с `start`, запрещая возврат к элементам левее текущего (что предотвращает генерацию дубликатов `[2, 3, 2]` и `[3, 2, 2]`).
3. **Отсечение (Pruning):** ветка немедленно обрывается, если `remaining < 0` (поскольку числа положительны, дальнейшее добавление чисел только увеличит сумму).

### Шаблон кода для запоминания синтаксиса
```javascript
// Шаблон: Backtracking: Combinations (комбинации чисел с повторением)
const combinationSumTemplate = (candidates, target) => {
  const result = [];
  const path = [];

  const backtrack = (start, remaining) => {
    // 1. Целевая сумма достигнута
    if (remaining === 0) {
      result.push([...path]);
      return;
    }

    // 2. Отсечение невалидной ветки
    if (remaining < 0) {
      return;
    }

    // 3. Перебираем кандидатов от индекса start
    for (let i = start; i < candidates.length; i++) {
      path.push(candidates[i]); // Делаем выбор

      // Передаем индекс i (тот же элемент можно использовать повторно)
      backtrack(i, remaining - candidates[i]);

      path.pop(); // Откатываем выбор (backtrack)
    }
  };

  backtrack(0, target);
  return result;
};
```

## 2. Суть задачи

На весах нужно набрать ровно `target` граммов гирями из набора `candidates` (все веса разные).
Нужно найти все различные наборы гирь, которые в сумме дают `target`.

```
combinationSum([3, 4, 5], 8)  ->  [[3, 5], [4, 4]]
```

Особенности:
- Одну и ту же гирю можно брать сколько угодно раз (в примере `[4, 4]` — две гири по 4).
- Наборы `[2,2,5]` и `[2,5]` — разные, потому что в них разное количество двоек.
- Наборы, отличающиеся только порядком (`[3, 5]` и `[5, 3]`), считаются одинаковыми.
  Порядок наборов в ответе не важен.

## 3. Разбор решения

Представим это как дерево решений: на каждом шаге мы выбираем — берём мы очередное
число из `candidates` ещё раз или переходим к следующему числу в массиве.

Чтобы не получать дубликаты вроде `[2,3]` и `[3,2]`, мы всегда двигаемся по массиву
"только вперёд" — то есть если взяли число с индексом `i`, то на следующем шаге можем
снова взять число с индексом `i` (оно же ещё раз) или любое число с индексом больше `i`,
но не с индексом меньше.

Условия остановки (базовые случаи рекурсии):
1. Если оставшаяся сумма (`remaining`) стала равна `0` — набор найден, сохраняем его.
2. Если оставшаяся сумма стала меньше `0` — этот путь не подходит, прекращаем его
   исследовать (числа только положительные, дальше сумма будет ещё больше).

## 4. Пошаговый разбор кода

```js
const combinationSum = (candidates, target) => {
  const result = [];   // сюда складываем все найденные наборы
  const current = [];  // текущий набор чисел, который мы сейчас собираем

  const backtrack = (start, remaining) => {
    // remaining — сколько ещё нужно "набрать" до target

    if (remaining === 0) {
      // сумма сошлась — нашли рабочий набор,
      // копируем current (через спред), чтобы дальнейшие изменения
      // current не повлияли на уже сохранённый результат
      result.push([...current]);
      return;
    }

    if (remaining < 0) {
      // "перебрали" сумму — этот путь никуда не ведёт, откатываемся
      return;
    }

    // перебираем числа начиная с индекса start (а не с 0!),
    // чтобы не получать перестановки одного и того же набора
    for (let i = start; i < candidates.length; i++) {
      current.push(candidates[i]);           // пробуем взять число
      backtrack(i, remaining - candidates[i]); // идём глубже; i (не i+1),
                                                 // т.к. число можно повторять
      current.pop();                          // откат: убираем число,
                                                 // чтобы попробовать следующий вариант
    }
  };

  backtrack(0, target);
  return result;
};
```

### Разбор на примере `candidates = [3, 4, 5], target = 8`

1. Начинаем с `current = []`, `remaining = 8`.
2. Берём `3` → `current = [3]`, `remaining = 5`.
3. Берём `3` ещё раз → `current = [3,3]`, `remaining = 2`. Любая следующая гиря (3, 4 или 5)
   уводит `remaining` в минус — эти ветки отсекаются, откатываемся.
4. Берём `4` → `current = [3,4]`, `remaining = 1`. Снова тупик, откатываемся.
5. Берём `5` → `current = [3,5]`, `remaining = 0` → набор `[3,5]` сохранён.
6. Ветка, начинающаяся с `4`: `[4,4]` даёт `remaining = 0` → набор сохранён; `[4,5]` — перебор.
   Гирю `3` в этой ветке уже не берём (цикл идёт от `start`), иначе получили бы `[4,3]` —
   тот же набор, что `[3,4]`.
7. Ветка с `5`: `[5,5]` уже даёт `remaining = -2`, отсекаем.
8. В итоге получаем `[[3,5],[4,4]]`.

## 5. Сложность и особенности

- Точную сложность по времени сложно выразить простой формулой (зависит от количества
  найденных комбинаций), но грубо она экспоненциальная: `O(candidates.length ^ (target / min(candidates)))`.
- Память: `O(target / min(candidates))` на глубину рекурсии + место под сам результат.

Для ограничений задачи (`target <= 40`, `candidates[i] >= 2`) это вполне приемлемо.
