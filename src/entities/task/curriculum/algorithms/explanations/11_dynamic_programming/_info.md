## 1. Что такое динамическое программирование

**Динамическое программирование (DP)** — способ решать задачу, разбивая её на **подзадачи**, решая каждую
подзадачу **один раз** и запоминая результат. Если подзадачи повторяются, переиспользование результата превращает
экспоненциальный перебор в полиномиальное решение.

Простая аналогия: вы считаете сумму `1 + 1 + 1 + 1 + 1 + 1 + 1 + 1`. Вам говорят «а если добавить ещё `+ 1`?». Вы не
пересчитываете всё заново, а просто прибавляете единицу к уже готовому ответу `8`. DP — это системное применение этой идеи.

## 2. Когда применять DP

Две приметы, по которым узнают задачу на DP:

1. **Оптимальная подструктура.** Ответ для большой задачи собирается из ответов для меньших
   (`ways(n) = ways(n - 1) + ways(n - 2)`).
2. **Перекрывающиеся подзадачи.** При простом рекурсивном решении одни и те же подзадачи вычисляются много раз.

Типичные формулировки: «сколько существует способов», «минимальное / максимальное значение», «можно ли набрать»,
«самая длинная подпоследовательность».

Если подзадачи **не** перекрываются (как в слиянии в Merge Sort), это уже «разделяй и властвуй», а не DP.

## 3. Два способа: top-down и bottom-up

| | Top-down (мемоизация) | Bottom-up (табуляция) |
|---|---|---|
| Идея | Рекурсия + кеш уже вычисленных значений | Цикл, который заполняет таблицу от меньших подзадач к большим |
| Плюсы | Проще написать из рекурренты; считает только нужные состояния | Нет рекурсии, нет риска переполнения стека; проще оптимизировать память |
| Минусы | Глубокая рекурсия, накладные расходы на вызовы | Нужно продумать порядок заполнения |

На платформе основные решения написаны **bottom-up**: они короче и позволяют сжать память.

## 4. Как придумать решение: пять шагов

1. **Состояние.** Что означает `dp[i]` (или `dp[i][j]`)? Сформулируйте словами: «минимальное число монет для суммы `i`».
2. **Переход.** Как `dp[i]` выражается через меньшие состояния? Это рекуррентная формула.
3. **База.** Какие значения известны сразу (`dp[0] = 0`)?
4. **Порядок.** В каком порядке заполнять таблицу, чтобы нужные значения уже были готовы?
5. **Ответ.** В какой ячейке лежит итог (`dp[n]`, максимум по всей таблице)?

Если состояние выбрано правильно, остальные шаги получаются почти механически.

## 5. Пример: числа Фибоначчи тремя способами

```js
// 1. Наивная рекурсия: O(2ⁿ)
const fibNaive = (n) => (n < 2 ? n : fibNaive(n - 1) + fibNaive(n - 2));

// 2. Top-down с мемоизацией: O(n) времени, O(n) памяти
const fibMemo = (n, memo = new Map()) => {
  if (n < 2) return n;
  if (memo.has(n)) return memo.get(n);
  const value = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
  memo.set(n, value);
  return value;
};

// 3. Bottom-up со сжатием памяти: O(n) времени, O(1) памяти
const fibIterative = (n) => {
  let previous = 0;
  let current = 1;
  for (let i = 2; i <= n; i++) {
    [previous, current] = [current, previous + current];
  }
  return n === 0 ? 0 : current;
};
```

Три решения дают один результат, но первое непригодно уже для `n = 45`, а третье работает мгновенно.

## 6. Основные виды задач

| Вид | Состояние | Пример |
|---|---|---|
| **1D, предыдущие 1–2 значения** | `dp[i]` зависит от `dp[i-1]`, `dp[i-2]` | Climbing Stairs, House Robber |
| **Рюкзак (knapsack)** | `dp[sum]` — лучший результат для суммы | Coin Change |
| **2D по сетке** | `dp[row][col]` — результат для клетки | Unique Paths |
| **Подпоследовательности** | `dp[i]` — лучший ответ, заканчивающийся в `i` | Longest Increasing Subsequence |
| **Строки (две строки)** | `dp[i][j]` — ответ для префиксов длины `i` и `j` | Edit Distance, LCS |

## 7. Оптимизация памяти

Если `dp[i]` зависит только от нескольких предыдущих значений, массив не нужен: достаточно переменных.
Для 2D-таблицы, где строка зависит только от предыдущей строки, хранят две строки (или одну, если порядок обхода это позволяет).
Оптимизировать стоит **после** того, как решение с полной таблицей написано и проверено.

## 8. Подводные камни

- **Неверное определение состояния.** Если `dp[i]` описан размыто, рекуррента не выводится. Сначала сформулируйте словами.
- **Забытая база.** Без `dp[0]` все остальные значения останутся `Infinity` или `0`.
- **Жадность вместо DP.** `coins = [1, 3, 4]`, сумма `6`: жадный выбор даёт `4 + 1 + 1`, а лучший ответ — `3 + 3`.
- **Порядок циклов.** В задачах на число способов порядок «монеты снаружи, суммы внутри» считает комбинации, а обратный порядок — перестановки.
- **`Infinity` и `-1`.** Недостижимые состояния помечают `Infinity`, а в ответ превращают в `-1` только в самом конце.
- **Рекурсия на больших входах.** Top-down на длинных цепочках может переполнить стек вызовов.

## 9. Сложность

- **Время:** обычно (число состояний) × (стоимость перехода). Для `dp[sum]` и `n` монет: `O(amount · n)`.
- **Память:** число состояний, а с оптимизацией «скользящего окна» часто `O(1)` или `O(n)` вместо `O(n²)`.
