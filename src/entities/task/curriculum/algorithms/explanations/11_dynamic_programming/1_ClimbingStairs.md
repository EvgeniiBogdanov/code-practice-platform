## 1. Паттерн и шаблон алгоритма

**Паттерн:** Dynamic Programming (динамическое программирование)  
**Разновидность:** `DP: 1D Rolling Variables` (одномерная рекуррента, в памяти только последние значения)

### В чём суть паттерна и разновидности
Ответ для `n` выражается через ответы для меньших `n`. Здесь `ways(n) = ways(n - 1) + ways(n - 2)`: на ступеньку `n` можно прийти с `n - 1` (шагом в 1) или с `n - 2` (шагом в 2). Когда рекуррента зависит только от нескольких предыдущих значений, весь массив `dp` не нужен: достаточно двух переменных. Это превращает память из $O(n)$ в $O(1)$.

### Шаблон кода для запоминания синтаксиса
```javascript
// Шаблон: DP: 1D Rolling Variables (ответ зависит от двух предыдущих)
const rollingTemplate = (n) => {
  let previous = 1; // база для 0
  let current = 1;  // база для 1

  for (let i = 2; i <= n; i++) {
    [previous, current] = [current, previous + current];
  }

  return current;
};
```

## 2. Суть задачи

Нужно подняться на лестницу из `n` ступенек. За раз можно сделать шаг на 1 или на 2 ступеньки.
Сколько существует различных способов добраться до вершины?

```
n = 3  ->  3  (1+1+1, 1+2, 2+1)
```

## 3. Наивное решение (для понимания)

Рекурсия прямо по формуле:

```js
const climbStairs = (n) => (n <= 1 ? 1 : climbStairs(n - 1) + climbStairs(n - 2));
```

- Время: **O(2ⁿ)** — одни и те же значения пересчитываются снова и снова
  (`climbStairs(3)` вычисляется внутри и `climbStairs(5)`, и `climbStairs(4)`).
- Память: O(n) на стек вызовов.

Уже `n = 45` делает такое решение непригодным. Это классический пример, ради которого вводят
**перекрывающиеся подзадачи**.

## 4. Пошаговый разбор кода

```js
const climbStairs = (n) => {
  let previous = 1;
  let current = 1;

  for (let step = 2; step <= n; step++) {
    [previous, current] = [current, previous + current];
  }

  return current;
};
```

1. **База.** До ступеньки `0` добраться можно одним способом («ничего не делать»), до ступеньки `1` тоже одним.
2. **Переход.** Для каждой следующей ступеньки число способов равно сумме двух предыдущих.
3. **Сдвиг окна.** Деструктуризация `[previous, current] = [current, previous + current]` одновременно
   сдвигает пару значений вперёд без временной переменной.
4. Ответ лежит в `current`. Для `n = 1` цикл не выполняется и возвращается `1`.

### Трассировка на примере `n = 5`

| step | previous | current |
|---|---|---|
| старт | 1 | 1 |
| 2 | 1 | 2 |
| 3 | 2 | 3 |
| 4 | 3 | 5 |
| 5 | 5 | 8 |

Ответ: `8` (это числа Фибоначчи).

## 5. Сложность и сравнение альтернатив

- **Время: O(n)**.
- **Память: O(1)**.

## Альтернативные подходы

- **Top-down с мемоизацией:** та же рекурсия, но результаты кладутся в `Map`/массив. Время O(n), память O(n).
  Удобно, когда не все подзадачи нужны.
- **Массив `dp` (bottom-up):** `dp[i] = dp[i - 1] + dp[i - 2]`. Понятнее, но память O(n).
- **Формула Бине или возведение матрицы в степень:** O(log n), на практике для этой задачи не требуется.
