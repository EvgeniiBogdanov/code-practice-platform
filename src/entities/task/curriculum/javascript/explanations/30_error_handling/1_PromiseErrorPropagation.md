### Что делает решение
Код проверяет, как ошибка «путешествует» по цепочке промисов. Главное правило: **цепочка промисов работает как `try/catch`, растянутый во времени.**

| Действие в обработчике | Следующий промис в цепочке |
|---|---|
| `return value` | fulfilled со значением `value` |
| `throw error` | rejected с ошибкой `error` |
| ничего не вернул | fulfilled с `undefined` |
| вернул промис | принимает его состояние |

### Пошаговый разбор
1. После `throw` цепочка становится rejected. Все `then` без второго аргумента **пропускаются**, пока ошибка не дойдёт до `catch`. `catch` вернул строку — цепочка восстановлена, и следующий `then` получает `"восстановлено"`.
2. `then(onFulfilled, onRejected)` — обработчики одного уровня. `onRejected` ловит ошибки **предыдущего** промиса, но не ошибку, брошенную в `onFulfilled` рядом с ним. Её ловит следующий `catch`. Поэтому `then(a).catch(b)` надёжнее, чем `then(a, b)`.
3. `finally` не получает аргументов и не меняет значение: его `return` игнорируется. Исключение: если `finally` бросит ошибку или вернёт отклонённый промис, она заменит исходный результат.
4. `throw` внутри `async`-функции возвращает отклонённый промис. `await` «разворачивает» его обратно в исключение, поэтому работает обычный `try/catch`.
5. Синхронное исключение в executor `new Promise` автоматически превращается в `reject`.
6. Пустой `catch(() => {})` гасит ошибку: цепочка продолжается с `undefined`. Это частая причина «тихих» багов, когда ошибка нигде не видна.

### Граничные случаи и ошибки
- **Асинхронный throw в executor не ловится.** `new Promise(() => setTimeout(() => { throw err }))` — ошибка случится позже, вне executor. Промис останется в состоянии `pending`, а ошибка станет глобальной. Внутри таймеров нужно явно вызывать `reject`.
- **Необработанное отклонение** (`unhandledrejection`) — если у отклонённого промиса нет `catch`. В Node.js по умолчанию это завершает процесс.
- Забытый `return` перед вложенным промисом разрывает цепочку: внешний `catch` не увидит ошибку вложенного промиса.
- `await` без `try/catch` в async-функции не теряет ошибку: она переходит в возвращаемый промис, и её нужно обработать у вызывающего.

### Сложность
Задача на понимание: `O(1)`.

### Что запомнить для собеседования
- `throw` в обработчике = rejected, `return` = fulfilled.
- Ошибка пропускает все `then` до ближайшего `catch`, после `catch` цепочка восстанавливается.
- `then(a, b)` не ловит ошибку из `a` — используйте `then(a).catch(b)`.
- `finally` прозрачен для значения, но может заменить его своей ошибкой.
