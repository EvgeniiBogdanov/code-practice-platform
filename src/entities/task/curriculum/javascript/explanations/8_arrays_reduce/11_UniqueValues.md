### Что делает решение
`[...new Set(arr)]` — идиоматичный способ удалить дубликаты:
1. `new Set(arr)` проходит по массиву и добавляет значения в множество. Повторное значение просто не добавляется.
2. Set сохраняет **порядок первой вставки**, поэтому результат идёт в порядке первого появления.
3. Spread `[...set]` превращает множество обратно в массив (то же делает `Array.from(set)`).

### Два подхода
| Подход | Время | Память | Комментарий |
|---|---|---|---|
| `[...new Set(arr)]` | `O(n)` | `O(n)` | проверка `has` в Set — в среднем `O(1)` |
| `reduce` + `includes` | `O(n²)` | `O(n)` | `includes` каждый раз проходит по аккумулятору |
| `filter((x, i) => arr.indexOf(x) === i)` | `O(n²)` | `O(n)` | частый ответ, но `indexOf` не находит `NaN` и удаляет все `NaN` |

На собеседовании вариант с `Set` ожидают первым, а квадратичный вариант полезно назвать и объяснить, почему он хуже.

### Граничные случаи и ошибки
- **`NaN`.** `Set` и `includes` используют сравнение SameValueZero, в котором `NaN` равен `NaN`, поэтому остаётся один `NaN`. Вариант с `indexOf` использует `===` и потеряет **все** `NaN`, потому что `indexOf(NaN)` всегда `-1`.
- **`0` и `-0`** при SameValueZero считаются одинаковыми — останется первый встретившийся.
- **Объекты** сравниваются по ссылке: `[{ id: 1 }, { id: 1 }]` останутся двумя элементами. Для дедупликации по ключу нужен `Map` (`new Map(arr.map((x) => [x.id, x]))`) — это отдельная задача в разделе «Коллекции».

### Сложность
- Через `Set`: `O(n)` по времени и памяти.
- Через `reduce` + `includes`: `O(n²)` по времени, `O(n)` по памяти.

### Что запомнить для собеседования
- `[...new Set(arr)]` — стандартный ответ, порядок сохраняется.
- Set сравнивает по SameValueZero: `NaN` равен `NaN`, объекты сравниваются по ссылке.
- Вариант с `indexOf` теряет `NaN` и работает за `O(n²)`.
