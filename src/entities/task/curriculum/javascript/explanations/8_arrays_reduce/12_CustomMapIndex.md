## Что делает решение

Функция превращает массив пользователей в индекс по `id`. Вместо повторного поиска:

```js
users.find((user) => user.id === 'u2');
```

можно заранее построить объект и затем обращаться напрямую: `usersById.u2` или `usersById['u2']`.

Такой индекс часто называют нормализованной структурой данных. Несмотря на слово «Map» в названии задачи, результат здесь — обычный объект, а не экземпляр `Map`.

## Пошаговый разбор

```js
const mapUsersById = (users) => {
  return users.reduce((acc, user) => {
    acc[user.id] = user;
    return acc;
  }, {});
};
```

Начальный аккумулятор — пустой объект. На каждой итерации `user.id` становится вычисляемым ключом, а значением остаётся весь объект пользователя.

Для первых двух элементов состояние меняется так:

```js
{}

// после Alice
{ u1: { id: 'u1', name: 'Alice', age: 25 } }

// после Bob
{
  u1: { id: 'u1', name: 'Alice', age: 25 },
  u2: { id: 'u2', name: 'Bob', age: 30 }
}
```

После построения индекса получение пользователя по известному ключу в среднем занимает `O(1)`, тогда как каждый вызов `find` может просматривать до `n` элементов.

## Вариант с `Object.fromEntries`

Структуру «массив пар → объект» стандартная библиотека умеет собирать напрямую:

```js
const usersById = Object.fromEntries(
  users.map((user) => [user.id, user])
);
```

Сначала `map` создаёт пары `[ключ, значение]`, затем `Object.fromEntries` строит объект. Это декларативно, но создаёт промежуточный массив пар. В показанном альтернативном решении деструктурируются только `id` и `name`, поэтому поле `price` или `age` намеренно теряется — это уже не полностью эквивалентное преобразование.

## Граничные случаи и ошибки

- Повторяющийся `id` перезапишет предыдущего пользователя: победит последний элемент массива.
- Отсутствующий `id` создаст ключ `'undefined'`. Обычно контракт данных нужно проверить заранее.
- Числовой `1` и строковый `'1'` становятся одним ключом объекта. Если тип ключа принципиален, используйте настоящий `Map`.
- В индекс кладутся ссылки на исходные объекты, а не копии. Изменение пользователя будет видно в обеих структурах.

## Сложность

Построение индекса занимает `O(n)` времени и `O(n)` памяти. Последующий доступ по `id` в среднем — `O(1)`.

## Что запомнить

Индекс имеет смысл, когда элементы многократно ищут по одному уникальному полю. Ключ должен быть стабильным и уникальным, а поведение при дубликатах следует определить явно.
