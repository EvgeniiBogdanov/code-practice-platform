## Что делает решение

Функция строит двухуровневый индекс:

```text
страна → id пользователя → данные пользователя
```

Первый уровень позволяет получить всех пользователей страны, второй — конкретного пользователя по `id` без дополнительного поиска по массиву.

```js
{
  Russia: {
    1: { age: 24, name: 'Иван', country: 'Russia' }
  },
  Belarus: {
    2: { age: 23, name: 'Дмитрий', country: 'Belarus' }
  }
}
```

## Пошаговый разбор

```js
const groupCountries = (data) => {
  return data.reduce((acc, { id, age, name, country }) => {
    acc[country] ??= {};
    acc[country][id] = { age, name, country };
    return acc;
  }, {});
};
```

Начальный аккумулятор — пустой объект верхнего уровня. На каждой итерации текущий пользователь сразу деструктурируется.

Строка `acc[country] ??= {}` гарантирует существование объекта страны. Важно использовать `??=`: уже созданная группа не должна заменяться новым пустым объектом, иначе ранее добавленные пользователи исчезнут.

Затем `acc[country][id]` обращается сразу к двум динамическим ключам. В значение записываются `age`, `name` и `country`. Сам `id` внутри значения не дублируется, потому что он уже хранится как ключ второго уровня.

Для первых трёх пользователей процесс выглядит так:

1. Иван создаёт `Russia`, затем ключ `1` внутри неё.
2. Дмитрий создаёт отдельную группу `Belarus` и ключ `2`.
3. Алексей использует уже существующую `Russia` и добавляется под ключом `3`.

Это не вложенный цикл: для каждого входного объекта выполняется постоянное число операций.

## Зачем нужна такая структура

Если данные часто читаются по паре `country + id`, доступ `result[country]?.[id]` в среднем занимает `O(1)`. В исходном массиве пришлось бы каждый раз запускать `find`, то есть до `O(n)`. Цена ускорения чтения — дополнительная память и предварительное построение индекса.

## Граничные случаи и ошибки

- Пустой массив возвращает `{}`.
- Одинаковый `id` внутри одной страны перезапишет предыдущую запись; одинаковые `id` в разных странах не конфликтуют.
- Числовые `id` в объекте фактически становятся строковыми ключами.
- Отсутствующий `country` создаст группу `'undefined'`, а отсутствующий `id` — запись `'undefined'` внутри группы.
- Если страна пользователя может измениться, индекс нужно перестроить или аккуратно перенести запись между группами.
- Для ключей из недоверенного внешнего ввода надёжнее использовать вложенные `Map` либо объекты без прототипа.

## Сложность

Построение занимает `O(n)` времени и `O(n + k)` памяти, где `k` — количество стран. Доступ по известным `country` и `id` в среднем — `O(1)`.

## Что запомнить

Для многоуровневой группировки создавайте уровни снаружи внутрь: сначала контейнер страны, затем запись пользователя. На каждом уровне заранее определите ключ, форму значения и поведение при дубликатах.
