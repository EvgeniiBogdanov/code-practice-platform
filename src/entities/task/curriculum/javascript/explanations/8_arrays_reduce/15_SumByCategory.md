## Что делает решение

Функция одновременно выполняет группировку и числовую агрегацию. Расходы объединяются по полю `category`, и для каждой категории в объекте накапливается общая сумма `amount`.

```js
const expenses = [
  { category: "Еда", amount: 500 },
  { category: "Транспорт", amount: 150 },
  { category: "Еда", amount: 300 },
  { category: "Развлечения", amount: 1000 },
  { category: "Транспорт", amount: 200 },
];

// результат
{
  "Еда": 800,
  "Транспорт": 350,
  "Развлечения": 1000
}
```

Все повторяющиеся категории сливаются в единые свойства результирующего объекта, суммируя затраты за один проход по массиву.

## Пошаговый разбор рекомендуемого варианта

```js
const sumByCategory = (expenses) => {
  return expenses.reduce((acc, { category, amount }) => {
    acc[category] ??= 0;
    acc[category] += amount;
    return acc;
  }, {});
};
```

1. **Инициализация аккумулятора**: вторым аргументом в `reduce()` передается пустой объект `{}`.
2. **Деструктуризация параметров**: на каждой итерации из текущего объекта расхода сразу извлекаются поля `{ category, amount }`.
3. **Оператор нулевого присваивания (`??=`)**: выражение `acc[category] ??= 0` создает числовой баланс `0` только в том случае, если категория встречается впервые (значение свойства равно `null` или `undefined`). Если категория уже инициализирована, значение не сбрасывается.
4. **Суммирование**: оператор `acc[category] += amount` прибавляет текущую сумму расхода к балансу категории.
5. **Возврат аккумулятора**: обновленный объект `acc` возвращается для следующего шага свертки.

Трассировка элементов:

| Шаг | Расход | Состояние аккумулятора `acc` |
| :--- | :--- | :--- |
| Старт | — | `{}` |
| 1 | `{ category: "Еда", amount: 500 }` | `{ "Еда": 500 }` |
| 2 | `{ category: "Транспорт", amount: 150 }` | `{ "Еда": 500, "Транспорт": 150 }` |
| 3 | `{ category: "Еда", amount: 300 }` | `{ "Еда": 800, "Транспорт": 150 }` |
| 4 | `{ category: "Развлечения", amount: 1000 }` | `{ "Еда": 800, "Транспорт": 150, "Развлечения": 1000 }` |
| 5 | `{ category: "Транспорт", amount: 200 }` | `{ "Еда": 800, "Транспорт": 350, "Развлечения": 1000 }` |

## Почему `??=` предпочтительнее `||`

Классический подход до появления ES2020 часто записывали через логическое ИЛИ:

```js
acc[category] = (acc[category] || 0) + amount;
```

Хотя для строго положительных расходов результат совпадает, между ними есть концептуальная разница:
- Оператор `||` считает ложными (falsy) любые значения `0`, `""`, `false`, `NaN`. Если баланс категории уже равен `0` (например, бесплатная услуга или компенсация), оператор `||` расценит его как отсутствующий.
- Оператор `??=` (Nullish Coalescing Assignment) проверяет строго `null` и `undefined`. Он семантически безупречно выражает намерение: «инициализировать поле, если оно еще не было создано».

## Граничные случаи и ошибки

- **Пустой массив расходов**: `sumByCategory([])` корректно возвращает `{}`.
- **Строковые суммы**: если поле `amount` передано как строка (`"500"`), оператор `+=` выполнит строковую конкатенацию вместо сложения (`0 + "500"` -> `"0500"`). Перед суммированием убедитесь в числовом типе данных или используйте `Number(amount)`.
- **Отрицательные расходы**: отрицательные числа (например, кэшбэк или возврат) корректно вычитаются из суммы соответствующей категории.
- **Регистр названий**: категории `"еда"` и `"Еда"` считаются разными ключами объекта. При необходимости данные следует предварительно нормализовать через `.toLowerCase()`.

## Сложность

- **Время**: $O(n)$, где $n$ — количество записей в массиве `expenses`. Каждый элемент массива обрабатывается ровно один раз.
- **Память**: $O(k)$, где $k$ — количество уникальных категорий. Память расходуется только на хранение ключей и чисел в результирующем объекте.

## Что запомнить

Группировка с суммированием строится по паттерну: получить ключ группы, лениво инициализировать аккумулятор нулем через `acc[key] ??= 0` и прибавить числовое значение `acc[key] += value`. Это чистый, однопроходный алгоритм сложности $O(n)$, работающий без промежуточных массивов и лишних копирований.
