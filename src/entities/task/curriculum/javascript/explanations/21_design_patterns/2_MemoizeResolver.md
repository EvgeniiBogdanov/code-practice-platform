# Мемоизация функции с resolver

## 1. Что делает memoize

Мемоизация сохраняет результат вычисления для набора аргументов. При повторном вызове с тем же ключом исходная функция не запускается — значение берётся из кэша. Это полезно для дорогих чистых вычислений.

`resolver` позволяет вызывающему коду самому определить, как аргументы превращаются в ключ.

## 2. Почему используется Map

```js
const cache = new Map();
```

Map хранит ключи без неявного преобразования в строки и умеет различать отсутствие ключа и сохранённое значение `undefined`.

## 3. Пошаговый разбор

```js
const key = resolver ? resolver(...args) : JSON.stringify(args);
```

Если resolver передан, он отвечает за стабильный уникальный ключ. Иначе аргументы сериализуются. Такой fallback удобен для простых JSON-совместимых значений, но имеет ограничения.

```js
if (cache.has(key)) {
  return cache.get(key);
}
```

Сначала обязательно вызывается `has`, а не только `get`: закэшированный результат может быть `undefined`, и по одному `get` его нельзя отличить от промаха.

```js
const result = fn(...args);
cache.set(key, result);
return result;
```

При промахе выполняется исходная функция, результат записывается и сразу возвращается. В примере счётчик увеличивается только при первом вызове одинаковой пары аргументов.

## 4. Требование чистоты

Мемоизация корректна, когда результат зависит только от аргументов. Если `fn` читает текущее время, случайное число, глобальное состояние или меняющийся объект, старый кэш может вернуть неверное значение.

## 5. Ловушки ключа

- `JSON.stringify` падает на циклических ссылках и `BigInt`.
- Функции, `undefined` и Symbol сериализуются неполно.
- Объекты с одинаковыми данными, но разным порядком добавления ключей, могут дать разные строки.
- Плохой resolver может создать коллизию: разные аргументы получат один ключ.
- Кэш растёт без ограничений. Для долгоживущего кода нужны `maxSize`, TTL или LRU.
- Для async-функции кэшируется сам Promise. Это объединяет параллельные вызовы, но отклонённый Promise тоже останется в кэше, если его явно не удалить.

## 6. Сложность

Попадание в Map в среднем близко к `O(1)`, но вычисление ключа может стоить `O(s)` от размера аргументов. Память растёт как `O(m)` для числа уникальных ключей.

## 7. Что запомнить

Мемоизация состоит из генерации ключа, проверки `cache.has`, вычисления при промахе и сохранения. Качество решения почти полностью зависит от корректного resolver и политики очистки кэша.
