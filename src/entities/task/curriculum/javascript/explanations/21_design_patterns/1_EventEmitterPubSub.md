# Шина событий EventEmitter

## 1. Зачем нужен EventEmitter

EventEmitter отделяет отправителя события от получателей. Отправитель знает только имя события и данные, но не знает, какие части программы отреагируют. Подписчики, в свою очередь, не вызывают отправителя напрямую.

В решении поддержаны четыре операции: постоянная подписка `on`, отписка `off`, публикация `emit` и одноразовая подписка `once`.

## 2. Структура хранения

```js
this.events = new Map();
```

Ключ Map — имя события, значение — массив функций-слушателей. Разные события получают независимые списки.

## 3. Подписка и отписка

`on` при необходимости создаёт массив, добавляет listener и возвращает функцию очистки:

```js
return () => this.off(event, listener);
```

Так вызывающему коду не нужно снова хранить имя события. Достаточно вызвать `unsubscribe()` при уничтожении компонента или завершении операции.

`off` создаёт новый массив без переданной функции. Сравнение идёт по ссылке: другая функция с таким же кодом не считается тем же listener.

## 4. Публикация события

```js
this.events.get(event).forEach((listener) => listener(...args));
```

Все слушатели выбранного события вызываются в порядке подписки и получают одинаковые аргументы. Если события нет, `emit` просто завершается.

## 5. Как устроен once

`once` подписывает функцию-обёртку. При первом событии обёртка сначала удаляет себя, затем вызывает пользовательский listener. Порядок важен: если listener синхронно вызовет `emit` ещё раз, одноразовая подписка уже удалена и второй раз не сработает.

## 6. Граничные случаи

- Повторный `on` одной и той же функции создаёт повторные вызовы.
- После удаления последнего listener в Map остаётся пустой массив; его можно удалять для экономии памяти.
- Если один listener бросит ошибку, текущий `forEach` прервётся и следующие слушатели не выполнятся. Контракт обработки ошибок нужно определить отдельно.
- Всегда нужна отписка от долгоживущего emitter, иначе он удерживает ссылки на слушателей и связанные объекты.
- Если слушатели меняют подписки во время `emit`, полезно итерировать копию массива для предсказуемого поведения.

## 7. Сложность

`on` обычно `O(1)`, `emit` — `O(k)` для `k` слушателей события, `off` с `filter` — `O(k)`. Память пропорциональна общему числу подписок.

## 8. Что запомнить

EventEmitter — это таблица `event -> listeners`. Главные инженерные детали находятся не в `emit`, а в корректной отписке, одноразовых слушателях и правилах изменения списка во время публикации.
