### Что делает решение

Это расширенная версия EventEmitter: все методы подписки возвращают `this`, поэтому подписки объединяются в цепочку, а `emit` возвращает `boolean`. Такой вариант чаще встречается на собеседованиях (по публичным отчётам, в том числе Т-Банка) и ближе к `EventEmitter` из Node.js.

```js
emitter
  .on("message", log)
  .once("message", handler)
  .on("close", onClose);
```

Решение хранит слушатели в `Map`: ключ — имя события, значение — массив функций.

- **`on`** добавляет слушатель в массив события и возвращает `this`.
- **`once`** оборачивает слушатель в функцию `wrapper`. Обёртка сначала отписывает саму себя, затем вызывает исходную функцию. Так одноразовость работает даже тогда, когда слушатель сам вызывает `emit` того же события.
- **`off`** создаёт новый массив без нужных слушателей. Он сравнивает не только `item !== listener`, но и `item.listener !== listener`: благодаря свойству `wrapper.listener` подписку из `once` можно снять по исходной функции.
- **`emit`** возвращает `false`, если подписчиков нет, иначе вызывает копию списка слушателей по порядку подписки и возвращает `true`.

### Почему обход идёт по копии

Слушатель может изменить список во время `emit`: подписаться ещё раз или отписаться. Если идти по живому массиву, порядок вызовов станет непредсказуемым. Копия `[...listeners]` фиксирует набор слушателей на момент вызова `emit`:

- слушатель, добавленный внутри обхода, начнёт работать только со следующего `emit`;
- слушатель, удалённый внутри обхода, всё равно будет вызван в текущем обходе (так же ведёт себя Node.js).

### Граничные случаи и ошибки

- Типичная ошибка: `once` реализован через `on` с флагом, а `off(event, listener)` не находит обёртку и ничего не удаляет. Исправление: сохранять исходную функцию в `wrapper.listener`.
- Если `once` не отписывается **до** вызова слушателя, повторный `emit` изнутри слушателя вызовет его снова.
- Если забыть удалять пустые массивы, `emit` вернёт `true` для события без подписчиков. В решении пустой список удаляется из `Map`.
- Один и тот же слушатель можно подписать несколько раз, он будет вызван столько раз. `off` в этой версии удаляет все такие подписки (в Node.js удаляется только последняя).
- `emit` для события без подписчиков не выбрасывает ошибку: возвращается `false`.
- В `off` и `emit` нельзя полагаться на `this` внутри слушателя: слушатели вызываются как обычные функции, без привязки контекста.

### Сложность

- `on`, `once` — `O(1)`.
- `off` — `O(k)`, где `k` — число слушателей события.
- `emit` — `O(k)` по времени и `O(k)` по памяти из-за копии списка.

### Что запомнить для собеседования

- Chaining означает «каждый метод возвращает `this`»; исключение — `emit`, который возвращает `boolean`, как в Node.js.
- `once` нужно делать через обёртку, которая отписывается **до** вызова слушателя, и хранить в ней исходную функцию для `off`.
- Обход `emit` ведётся по копии списка слушателей.
- Подписки без отписки приводят к утечкам памяти: слушатели удерживают замыкания и объекты.
- Вопросы-продолжения: `prependListener`, максимальное число слушателей, асинхронные слушатели, `emit` с ошибкой в слушателе, привязка `this`.
