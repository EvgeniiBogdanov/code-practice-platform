### Что делает решение
**Singleton** гарантирует, что у класса есть только один экземпляр, и даёт к нему глобальную точку доступа. Типичные примеры — конфигурация приложения, логгер, соединение с базой данных, кэш.

Реализация на классе:
1. Экземпляр хранится в **приватном статическом поле** `static #instance`. Снаружи его нельзя подменить или сбросить.
2. В конструкторе: если экземпляр уже есть — **возвращаем его**. Это использует правило оператора `new`: если конструктор вернул объект, `new` возвращает этот объект вместо только что созданного. Поэтому `new AppConfig()` тоже отдаёт одиночку.
3. `getInstance()` — привычный по другим языкам способ получить экземпляр.

### Идиоматичный вариант для JS
В JavaScript синглтон обычно не нужно реализовывать классом. **ES-модуль выполняется один раз**, и все `import` получают одну и ту же ссылку на экспортированный объект:
```js
// app-config.js
const settings = new Map();
export const appConfig = { get: (k) => settings.get(k), set: (k, v) => settings.set(k, v) };
```
Второе решение показывает тот же принцип через IIFE (в песочнице нет модулей). На собеседовании хороший ответ — реализовать классический вариант и сказать, что в JS модуль уже является синглтоном.

### Критика паттерна
Singleton часто называют антипаттерном:
- это скрытое глобальное состояние, и зависимости класса не видны в его сигнатуре;
- тесты влияют друг на друга, потому что состояние сохраняется между ними (нужен метод сброса или моки модулей);
- жёсткая связанность: подменить реализацию сложно.

Во фронтенде вместо самописных синглтонов используют модули, DI-контейнеры (Angular) или контекст и сторы (React Context, Zustand, Redux), где «одиночка» создаётся явно в одном месте.

### Граничные случаи и ошибки
- `return AppConfig.#instance` из конструктора работает только для объектов. Примитив, возвращённый из конструктора, `new` проигнорирует.
- Поля класса (`#settings = new Map()`) инициализируются **до** тела конструктора, поэтому при повторном `new` создаётся и сразу выбрасывается лишняя `Map`. Для конфигурации это несущественно, для тяжёлых ресурсов используйте только `getInstance()` с ленивым созданием.
- В многооконных средах (iframe, воркеры) у каждого контекста свой модуль и свой «одиночка».

### Сложность
`getInstance`, `get` и `set` работают за `O(1)`.

### Что запомнить для собеседования
- Singleton = один экземпляр + глобальная точка доступа.
- В JS модуль уже является синглтоном: модульный код выполняется один раз.
- Знайте критику: скрытое глобальное состояние, проблемы с тестами и связанностью.
