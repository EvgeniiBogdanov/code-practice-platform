### Что делает решение
Run-Length Encoding (RLE) заменяет серию одинаковых символов парой «символ + длина серии»:
1. Идём по строке и сравниваем текущий символ со **следующим** (`str[i + 1]`).
2. Пока они совпадают, увеличиваем счётчик серии.
3. Когда следующий символ другой (или строка закончилась и `str[i + 1] === undefined`), серия завершена: записываем символ и, если серия длиннее 1, её длину. Затем сбрасываем счётчик.

Части результата собираются в массив и склеиваются через `join("")` один раз в конце.

### Пошаговый пример для `"aaabbc"`
| i | символ | следующий | count | действие |
|---|---|---|---|---|
| 0 | a | a | 2 | продолжаем |
| 1 | a | a | 3 | продолжаем |
| 2 | a | b | 3 | записываем `a3` |
| 3 | b | b | 2 | продолжаем |
| 4 | b | c | 2 | записываем `b2` |
| 5 | c | undefined | 1 | записываем `c` |

### Граничные случаи и ошибки
- **Последняя серия.** Самая частая ошибка — сравнивать с предыдущим символом и забыть дописать последнюю серию после цикла. Сравнение со следующим символом решает это автоматически: за концом строки стоит `undefined`.
- Серии, которые повторяются не подряд (`"aabbaa"`), кодируются отдельно: `a2b2a2`, а не `a4b2`. Это не подсчёт частот.
- Многозначные счётчики (`a12`) должны работать — счётчик хранится числом, а не одним символом.
- Если в исходной строке есть цифры (`"a11"`), закодированный результат нельзя однозначно раскодировать. На собеседовании это хороший вопрос для обсуждения.
- Вариант с LeetCode (443 String Compression) требует сжатия на месте в массиве символов — уточняйте формат.

### Сложность
- По времени: `O(n)` — один проход.
- По памяти: `O(n)` для результата.

### Что запомнить для собеседования
- Сравнение с **следующим** символом закрывает последнюю серию без дополнительного кода.
- Собирайте результат в массив и вызывайте `join` один раз.
- Типичное продолжение — написать `decompress`, обратную функцию.
