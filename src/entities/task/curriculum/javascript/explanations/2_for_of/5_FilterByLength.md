## Что делает решение

```js
const filterByLength = (arr, n) => {
  const result = [];
  for (const str of arr) {
    if (str.length > n) result.push(str);
  }
  return result;
};
```

Функция создаёт новый массив со строками, длина которых **строго больше** `n`. Исходный порядок сохраняется, а входной массив не изменяется.

## Как работает фильтр

`result` начинается пустым. Каждый элемент проверяется независимо: прошедший предикат добавляется через `push`, остальные пропускаются. Для `['кофе', 'сок', 'газировка']` и `n = 4` попадёт только `'газировка'`; строка длиной ровно четыре не проходит.

Вариант `arr.filter((str) => str.length > n)` выражает ту же операцию короче. Явный цикл полезен для нескольких условий, логирования или досрочного выхода, хотя обычная фильтрация всегда проходит весь массив.

## Граничные случаи и ошибки

- Условие задачи требует `> n`; замена на `>= n` изменит результат на границе.
- Пустой массив возвращает новый пустой массив.
- Нестрочный элемент без подходящего свойства `length`, например `null`, вызовет ошибку. Массив внутри входа тоже имеет `length` и может случайно пройти проверку.
- JavaScript считает длину строки в UTF-16-кодовых единицах. Некоторые emoji занимают две единицы, а пользовательский «символ» может состоять из нескольких code points. Для визуальных символов нужен иной способ сегментации.
- Отрицательный `n` пропустит почти все строки, включая пустую при `n < 0`.
- Возвращаются те же строковые значения; для объектов аналогичный фильтр не создавал бы глубоких копий.

## Сложность

Проверяются все `m` строк: `O(m)` операций обхода. Результат занимает до `O(m)` памяти. Само чтение `.length` строки — `O(1)`.

## Что запомнить

Фильтрация состоит из нового контейнера, предиката и добавления прошедших элементов. Самая частая логическая ошибка — неверная строгость границы. Отдельно уточняйте, что считается длиной для Unicode-текста.
