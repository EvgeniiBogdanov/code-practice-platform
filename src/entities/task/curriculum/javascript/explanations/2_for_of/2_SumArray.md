## Что делает решение

```js
const sumNumbers = (arr) => {
  let sum = 0;
  for (const num of arr) sum += num;
  return sum;
};
```

`for...of` выдаёт очередное значение массива прямо в `num`, а аккумулятор `sum` собирает общий результат. Индекс здесь не участвует в логике, поэтому форма проще индексного `for`.

## Как работает накопление

Для `[43, 32, 33]` сумма меняется `0 → 43 → 75 → 108`. Перед каждой итерацией `sum` содержит сумму уже просмотренного префикса. Ноль корректно обрабатывает и пустой массив.

Альтернативный `reduce((acc, curr) => acc + curr, 0)` делает ту же работу. `for...of` удобен, если понадобится ранний выход, несколько аккумуляторов или отладка; `reduce` подчёркивает простую свёртку.

## Граничные случаи и ошибки

- Контракт предполагает числа. При встрече строки оператор `+` начнёт конкатенацию.
- `NaN` заражает сумму, а `Infinity` может дать бесконечный результат.
- Дроби складываются с обычной погрешностью IEEE 754.
- `for...of` прочитает пустой слот разреженного массива как `undefined`; прибавление даст `NaN`. `reduce` пустые слоты пропускает — альтернативы здесь не полностью эквивалентны.
- Нейтерируемый вход (`null`, обычный объект) вызовет `TypeError`.
- Функция только читает элементы и не мутирует массив.
- Сумма больших целых может выйти за `Number.MAX_SAFE_INTEGER`; смешивать `Number` и `BigInt` нельзя.

## Сложность

Каждый элемент посещается один раз: `O(n)` времени и `O(1)` дополнительной памяти. `reduce` имеет ту же асимптотику.

## Что запомнить

Когда индекс не нужен, `for...of` напрямую выражает «для каждого значения». Но синтаксис не валидирует данные: тип элементов, пропуски и числовая точность остаются частью контракта функции.
