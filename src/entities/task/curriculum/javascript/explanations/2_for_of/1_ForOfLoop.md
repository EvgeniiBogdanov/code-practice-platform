## Что делает решение

```js
for (const el of arr) {
  // работа с el
}
```

`for...of` последовательно получает **значения** из итерируемого объекта. Для массива `el` будет первым элементом, затем вторым и так далее. Индекс вручную не нужен.

## Как устроен обход

Цикл использует протокол итерации — метод `Symbol.iterator`. Его поддерживают массивы, строки, `Map`, `Set`, типизированные массивы и многие DOM-коллекции. У строки итерации возвращают Unicode code points, поэтому такой обход обычно безопаснее индексирования для emoji.

`const` не делает элемент неизменяемым. На каждой итерации создаётся новая привязка `el`, которую нельзя переназначить, но объект в ней всё ещё можно мутировать. `break`, `continue` и `return` работают как в обычном цикле.

## Граничные случаи и ошибки

- В шаблоне `arr` должен существовать; иначе будет `ReferenceError`.
- Обычный объект `{ a: 1 }` не итерируем по умолчанию. Для него используют `Object.entries(obj)` или `for...in` с проверкой собственных свойств.
- `for...of` возвращает значения, а `for...in` — перечислимые ключи. Путаница особенно заметна на массивах: `for...in` даст строковые индексы.
- Пустая коллекция даёт ноль итераций.
- Для получения индекса используйте `for (const [index, value] of arr.entries())`.
- Нельзя применять обычный `for...of` к асинхронному итератору; для него существует `for await...of` внутри `async`-контекста.
- Изменение коллекции во время обхода зависит от её типа и усложняет рассуждение.

## Сложность

Полный обход `n` значений занимает `O(n)` времени и `O(1)` дополнительной памяти, если тело и сам итератор не создают дополнительные структуры.

## Что запомнить

Используйте `for...of`, когда нужны сами значения и коллекция реализует протокол итерации. Для индексов, ключей объекта и асинхронных источников выбираются другие формы обхода.
