## Что делает решение

```js
const includesElement = (arr, target) => {
  for (const item of arr) {
    if (item === target) return true;
  }
  return false;
};
```

Функция выполняет линейный поиск. При первом строгом совпадении она немедленно возвращает `true`; если цикл завершился, совпадений нет и возвращается `false`.

## Почему важен ранний return

После найденного элемента продолжать обход бессмысленно. `return` завершает и цикл, и функцию. Для цели в начале массива это одна проверка; для отсутствующей цели — `n` проверок. `return false` должен находиться после цикла: если поставить его внутри после первого несовпадения, функция проверит только первый элемент.

Встроенный вариант `arr.includes(target)` короче и обычно предпочтителен, если не нужна собственная логика сравнения.

## Граничные случаи и ошибки

- Сравнение `===` не приводит типы: число `1` и строка `"1"` различны.
- Объекты сравниваются по ссылке. Новый `{ id: 1 }` не равен объекту с теми же полями, уже лежащему в массиве.
- Важное отличие альтернатив: `includes` использует сравнение SameValueZero и умеет находить `NaN`, а текущий цикл с `===` — нет.
- Пустой массив возвращает `false`.
- Разреженный массив при `for...of` выдаёт `undefined` для пустого слота; поиск `undefined` может вернуть `true`.
- Для поиска объекта по полю используйте предикат (`some(item => item.id === id)`), а не сравнение нового литерала.
- Нейтерируемый вход вызовет `TypeError`.

## Сложность

Лучший случай — `O(1)`, когда совпадает первый элемент. Средний и худший — `O(n)`. Дополнительная память — `O(1)`. `includes` имеет ту же асимптотику.

## Что запомнить

Линейный поиск должен завершаться сразу после успеха и возвращать неуспех только после полного обхода. Уточняйте семантику равенства: `===`, SameValueZero и сравнение объектов по полям дают разные результаты.
