### Что делает решение
`for...of`, spread `[...x]`, `Array.from`, деструктуризация массивов, `new Map(x)` и `Promise.all(x)` работают не только с массивами, а с любым **итерируемым** объектом. Протокол состоит из двух частей:
1. **Iterable** — объект с методом `[Symbol.iterator]()`, который возвращает итератор.
2. **Iterator** — объект с методом `next()`, который возвращает `{ value, done }`. Когда `done: true`, перебор заканчивается.

В решении `createRange` возвращает объект только с методом `[Symbol.iterator]`. Числа **не хранятся** — каждое вычисляется по запросу в `next()`. Поэтому диапазон `createRange(1, 1e9)` не займёт память, пока его не перебирают.

### Почему перебор можно повторить
Каждый вызов `[Symbol.iterator]()` создаёт **новый** итератор со своей переменной `current` в замыкании. Если хранить `current` в самом объекте range, второй `[...range]` вернул бы пустой массив: состояние осталось бы «в конце» после первого перебора.

### Вариант с генератором
Функция-генератор `*[Symbol.iterator]()` автоматически возвращает объект, который одновременно является итератором и итерируемым. `yield` заменяет ручное `return { value, done }`. В реальном коде используют именно этот вариант, но ручная реализация протокола показывает понимание механизма.

### Граничные случаи и ошибки
- `from > to` — первый же вызов `next()` возвращает `done: true`, результат пустой.
- `step <= 0` приведёт к бесконечному перебору. В продакшен-версии нужна проверка с `RangeError`.
- Деструктуризация `const [first, second] = range` берёт только два значения и останавливает итератор. Если у итератора есть метод `return()`, он будет вызван — так освобождают ресурсы.
- Обычный объект `{}` не итерируемый: `for (const x of {})` бросает `TypeError: {} is not iterable`. Для объектов используют `Object.entries(obj)`.

### Сложность
- Каждый `next()` — `O(1)`.
- Память — `O(1)` независимо от размера диапазона: значения вычисляются лениво.

### Что запомнить для собеседования
- Iterable — объект с `[Symbol.iterator]()`, iterator — объект с `next()` → `{ value, done }`.
- Состояние перебора храните в итераторе, а не в самом iterable, чтобы перебор был повторяемым.
- Генераторы — самый короткий способ реализовать протокол.
