### Что делает решение
**Асинхронный генератор** (`async function*`) объединяет два механизма: внутри можно использовать `await`, и он отдаёт значения через `yield`. Каждый вызов `next()` возвращает **Promise** с `{ value, done }`. Перебирать такой генератор нужно через `for await...of`.

`fetchAllItems` прячет пагинацию API за простым потоком элементов:
1. Начинаем с первой страницы.
2. `await fetchPage(page)` ждёт ответа.
3. `yield* items` отдаёт элементы страницы по одному. Потребитель не знает, что данные приходят пачками.
4. Переходим на `nextPage`, пока он не станет `null`.

### Ленивость и ранняя остановка
Генератор не загружает следующую страницу, пока потребитель не попросил следующий элемент. Поэтому `collectFirst(3)`:
- получает `a` и `b` из первой страницы;
- запрашивает вторую страницу, получает `c` — набрано 3 элемента;
- `break` закрывает генератор (вызывает его `return()`), и третья страница **не запрашивается**.

Это главное преимущество перед подходом «сначала загрузить всё в массив, потом обработать»: экономятся запросы и память, а первые результаты доступны сразу.

### Где применяется
- Бесконечная лента и постраничные API (GitHub, Stripe и многие SDK отдают async-итераторы).
- Чтение потоков: `ReadableStream` и потоки Node.js итерируются через `for await`.
- Обработка событий как последовательности.

### Граничные случаи и ошибки
- `for...of` (без `await`) по асинхронному генератору бросает `TypeError`: у объекта нет `Symbol.iterator`, только `Symbol.asyncIterator`.
- `for await` работает только внутри `async`-функции или на верхнем уровне модуля.
- Ошибка внутри `fetchPage` пробрасывается в `for await` и ловится обычным `try/catch` вокруг цикла.
- Страницы загружаются **последовательно**. Если нужна параллельная загрузка, используют `Promise.all` с ограничением параллельности — но тогда теряется ленивость.
- `yield items` вместо `yield* items` отдаст массивы целиком, а не элементы.

### Сложность
- По времени: `O(p)` запросов, где `p` — количество страниц, нужных для набора `n` элементов.
- По памяти: `O(размер страницы)` внутри генератора плюс `O(n)` на результат.

### Что запомнить для собеседования
- `async function*` + `for await...of` — стандартный способ лениво обрабатывать постраничные и потоковые данные.
- `break` в `for await` закрывает генератор, и лишние запросы не выполняются.
- `yield*` делегирует перебор другому итерируемому объекту.
