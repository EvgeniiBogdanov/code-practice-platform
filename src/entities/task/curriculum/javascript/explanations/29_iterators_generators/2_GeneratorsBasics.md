### Что делает решение
**Генератор** (`function*`) — функция, выполнение которой можно приостанавливать:
- вызов `idGenerator("user")` **не выполняет** тело, а возвращает объект-генератор;
- каждый `gen.next()` выполняет тело до ближайшего `yield`, возвращает `{ value, done: false }` и замораживает выполнение, сохраняя локальные переменные;
- когда функция завершается (`return` или конец тела), `next()` возвращает `{ value: undefined, done: true }`.

Поэтому `while (true)` внутри генератора не вешает вкладку: цикл выполняет ровно один шаг на каждый запрос значения. Это **ленивые вычисления**: значения появляются только тогда, когда их просят.

### Разбор функций
- `idGenerator` — бесконечная последовательность. Счётчик `id` сохраняется между вызовами `next()` без внешнего состояния и замыканий.
- `fibonacci` хранит два последних числа и сдвигает их деструктуризацией `[a, b] = [b, a + b]`.
- `take` — «ограничитель» для любого iterable. `for...of` внутри генератора запрашивает значения у источника по одному. Как только набрано `n`, `return` завершает и `take`, и исходный итератор. Без `take` выражение `[...fibonacci()]` никогда не закончится.

Проверка `n <= 0` в начале важна: без неё `take` запросил бы у источника одно лишнее значение. Для генератора с побочными эффектами (например, запросами в сеть) это ошибка.

### Где генераторы встречаются на практике
- Ленивые последовательности и пагинация.
- Redux-Saga: побочные эффекты описываются генераторами.
- `async/await` исторически вырос из генераторов: библиотека `co` превращала `yield promise` в последовательный асинхронный код.

### Граничные случаи и ошибки
- `[...gen]` и `Array.from(gen)` для бесконечного генератора зависнут — всегда ограничивайте их через `take` или `break`.
- Генератор одноразовый: после `done: true` повторный перебор того же объекта ничего не вернёт. Нужен новый вызов `fibonacci()`.
- Стрелочных генераторов не существует: `*() => {}` — синтаксическая ошибка.
- `yield` нельзя использовать во вложенной обычной функции (например, в колбэке `forEach`) — только непосредственно в теле генератора. Для делегирования есть `yield* iterable`.

### Сложность
- Каждый шаг `next()` — `O(1)` для всех трёх генераторов.
- Память — `O(1)`: последовательность не хранится целиком.

### Что запомнить для собеседования
- Генератор приостанавливается на `yield` и возобновляется при `next()`.
- Ленивость позволяет описывать бесконечные последовательности.
- `return` или `break` в `for...of` закрывает исходный итератор.
