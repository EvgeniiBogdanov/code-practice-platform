## Что делает решение

Мемоизация сохраняет результат функции для набора аргументов. Повторный вызов с теми же аргументами берёт значение из кэша, пока не истёк TTL — время жизни записи.

```js
const memoize = (fn, ms) => {
  const cache = new Map();

  return (...args) => {
    const key = JSON.stringify(args);
    const now = Date.now();

    if (cache.has(key)) {
      const { value, expiry } = cache.get(key);
      if (now < expiry) {
        return value;
      }
    }

    const result = fn(...args);
    cache.set(key, { value: result, expiry: now + ms });
    return result;
  };
};
```

## Где хранится кэш

`cache` создаётся один раз внутри `memoize`. Возвращённая функция сохраняет к нему доступ благодаря замыканию. Снаружи коллекцию нельзя случайно изменить, но она продолжает жить, пока доступна мемоизированная функция.

В `Map` хранится не только результат, но и момент истечения:

```js
key → { value, expiry }
```

`expiry = now + ms`. Запись считается актуальной только при строгом условии `now < expiry`. Ровно в момент `expiry` нужно вычислить новое значение.

## Сценарий по времени

Пусть TTL равен 1000 мс:

1. В `0 мс` вызывается `memoized(2, 3)`. Кэша нет, выполняется `fn`, результат сохраняется до `1000 мс`.
2. В `400 мс` те же аргументы находят запись, `400 < 1000`, поэтому `fn` не запускается.
3. В `1200 мс` запись уже просрочена, функция вычисляется повторно и `set` заменяет старое значение новым.

Другой порядок или другие значения аргументов создают отдельный ключ.

## Как формируется ключ

`JSON.stringify(args)` превращает массив аргументов в строку: `(1, 2)` становится `"[1,2]"`, а `(2, 1)` — `"[2,1]"`. Для простых JSON-совместимых аргументов это удобно, но не универсально.

## Граничные случаи и ошибки

- `undefined`, функции, символы, `NaN` и `Infinity` могут сериализоваться одинаково или потеряться, создавая коллизии.
- `BigInt` и циклические объекты приводят к ошибке `JSON.stringify`.
- Объекты с теми же полями, добавленными в разном порядке, могут получить разные строки.
- Просроченные ключи не удаляются по таймеру. Они заменяются при следующем обращении, а никогда больше не используемые записи остаются в памяти.
- Стрелочная обёртка вызывает `fn(...args)` и не сохраняет динамический `this` исходной функции.
- Если `fn` возвращает промис, кэшируется сам промис; отклонённый промис тоже останется до истечения TTL.
- Отрицательный или нулевой `ms` делает запись сразу неактуальной.

## Сложность

Проверка кэша в среднем близка к `O(1)`, но создание ключа занимает `O(s)`, где `s` — размер сериализованных аргументов. Промах дополнительно стоит столько же, сколько вызов `fn`. Память — `O(k)` записей плюс сохранённые результаты.

## Что запомнить

TTL-кэш хранит результат вместе со временем истечения и проверяет срок при обращении. `JSON.stringify` — допустимое учебное упрощение для ограниченных аргументов, но контракт ключа и стратегия очистки должны быть явно определены в продакшене.
