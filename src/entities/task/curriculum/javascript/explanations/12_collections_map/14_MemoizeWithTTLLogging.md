## Что делает решение

Это TTL-мемоизация с наблюдаемыми состояниями. Функция сообщает в консоль, откуда получен результат:

- `from cache` — найдена актуальная запись;
- `key delete` — запись найдена, но просрочена и удалена;
- `calculated` — исходная функция была выполнена.

```js
function memoize(fn, ttl) {
  const cache = new Map();

  return function (...args) {
    const key = JSON.stringify(args);
    const now = Date.now();

    if (cache.has(key)) {
      const cached = cache.get(key);

      if (now - cached.timestamp < ttl) {
        console.log("from cache");
        return cached.value;
      }

      cache.delete(key);
      console.log("key delete");
    }

    const result = fn(...args);
    console.log("calculated");
    cache.set(key, { value: result, timestamp: Date.now() });
    return result;
  };
}
```

## Три ветки выполнения

При первом вызове ключа нет: код пропускает проверку, выполняет `fn`, пишет `calculated` и сохраняет результат со временем.

При повторном вызове вычисляется возраст записи: `now - cached.timestamp`. Если он меньше `ttl`, возвращается `cached.value`, а исходная функция не запускается.

Если возраст равен или превышает TTL, выполняются две последовательные операции: старая запись удаляется с логом `key delete`, затем результат пересчитывается с логом `calculated`. Поэтому один просроченный вызов выводит две строки.

## Почему timestamp записывается после вычисления

В решении используется новый `Date.now()` при `cache.set`. Значит, срок жизни начинается после синхронного вычисления `fn`, а не до него. Для медленной функции это разумнее: пользователь получает почти полный TTL уже готового результата.

## Что на самом деле означает очистка

Удаление является ленивым: просроченный ключ очищается только при следующем обращении именно к нему. Фонового таймера нет. Если к старому ключу больше никогда не обратиться, его запись останется в `Map`. Для ограниченного упражнения это нормально, но производственный кэш обычно дополняют лимитом размера, периодической очисткой или LRU-политикой.

## Граничные случаи и ошибки

- Ключ через `JSON.stringify` имеет коллизии для `undefined`, функций, символов, `NaN` и `Infinity`; циклы и `BigInt` приводят к ошибке.
- Вызов `fn(...args)` не передаёт динамический `this`, хотя обёртка объявлена обычной функцией. Для методов нужен `fn.apply(this, args)`.
- Нулевой или отрицательный TTL приводит к пересчёту на каждом вызове после удаления прежней записи.
- Если `fn` бросает ошибку, `calculated` не выводится и запись не создаётся.
- Если `fn` возвращает промис, кэшируется промис, а время ставится сразу; код не ждёт его выполнения.
- Логирование является частью наблюдаемого поведения и может замедлять горячий код.

## Сложность

Операции с `Map` в среднем близки к `O(1)`, сериализация ключа — `O(s)`. Попадание в кэш не вызывает `fn`; промах или истечение TTL добавляет стоимость вычисления. Память зависит от числа сохранённых ключей: `O(k)`.

## Что запомнить

TTL проверяется как возраст записи, а очистка в этом решении происходит лениво при чтении. Логи помогают увидеть переходы состояния, но не заменяют продуманную стратегию ключей, ограничения памяти и поддержку `this`.
