## Что делает решение

Функция безопасно получает значение по ключу. Если ключ существует, возвращается связанное значение; если нет — строка `"not found"`.

```js
const getValue = (map, key) => {
  return map.has(key) ? map.get(key) : "not found";
};
```

Для `new Map([["x", 10], ["y", 20]])` вызов `getValue(map, "x")` вернёт `10`, а `getValue(map, "z")` — `"not found"`.

## Зачем нужны два метода

`map.get(key)` возвращает значение или `undefined`, когда записи нет. Проблема в том, что `undefined` разрешено хранить как обычное значение:

```js
const map = new Map([["answer", undefined]]);

map.get("answer");  // undefined
map.get("missing"); // undefined
```

По одному результату `get` эти случаи не различить. `map.has(key)` отвечает именно на вопрос о существовании записи:

```js
map.has("answer");  // true
map.has("missing"); // false
```

Поэтому сначала выполняется `has`, а `get` вызывается только для существующего ключа.

## Как читается тернарный оператор

Выражение:

```js
map.has(key) ? map.get(key) : "not found"
```

читается так: «если ключ есть — вернуть значение, иначе вернуть текст ошибки». Это компактная форма обычного `if`:

```js
if (map.has(key)) {
  return map.get(key);
}

return "not found";
```

Обе записи эквивалентны. Тернарный оператор уместен здесь, потому что условие короткое и выбирает одно из двух возвращаемых значений.

## Граничные случаи и ошибки

- Проверка `if (map.get(key))` неверна: существующие значения `0`, `false`, `""`, `null` и `undefined` являются falsy.
- Строка `"not found"` может сама быть допустимым значением коллекции. В реальном API однозначнее вернуть `undefined`, `null` или объект вроде `{ found: false }`.
- Объектный ключ должен быть той же ссылкой, которая использовалась при `set`.
- `Map` различает число `1` и строку `"1"`.
- Функция не изменяет переданную коллекцию.

## Сложность

`has` и `get` в типичных реализациях работают в среднем за время, близкое к `O(1)`. Функция использует `O(1)` дополнительной памяти.

## Что запомнить

`get` отвечает «какое значение?», а `has` — «существует ли ключ?». Когда `undefined` может быть сохранённым значением, эти вопросы нельзя объединять в одну проверку результата `get`.
