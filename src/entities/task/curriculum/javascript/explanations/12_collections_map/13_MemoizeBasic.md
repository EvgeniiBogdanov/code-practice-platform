## Что делает решение

`memoize(fn)` возвращает обёртку, которая вычисляет результат только для нового набора аргументов. Повторный вызов получает сохранённое значение из `Map`.

```js
function memoize(fn) {
  const cache = new Map();

  return function (...args) {
    const key = JSON.stringify(args);

    if (cache.has(key)) {
      return cache.get(key);
    }

    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}
```

## Как работает замыкание

`cache` — локальная переменная вызова `memoize`. После завершения `memoize` она не исчезает, потому что возвращённая функция продолжает её использовать. У каждой отдельно созданной мемоизированной функции будет собственная независимая `Map`.

```js
const cachedSum = memoize((a, b) => a + b);

cachedSum(1, 2); // вычисление, сохраняется ключ "[1,2]"
cachedSum(1, 2); // чтение из Map
cachedSum(2, 1); // другой ключ, новое вычисление
```

Порядок аргументов является частью ключа, поэтому `[1, 2]` и `[2, 1]` не смешиваются.

## Почему проверяется has, а не значение get

Исходная функция может корректно вернуть `0`, `false`, пустую строку, `null` или `undefined`. Проверка `if (cache.get(key))` посчитала бы такие результаты отсутствующими и запускала функцию снова. `has` проверяет именно наличие записи независимо от сохранённого значения.

## Зачем используется apply

Возвращается обычная `function`, а не стрелка, поэтому она получает `this` от места вызова. `fn.apply(this, args)` передаёт исходной функции тот же контекст и разворачивает массив аргументов.

```js
const calculator = {
  factor: 10,
  multiply: memoize(function (value) {
    return this.factor * value;
  }),
};
```

Без передачи `this` метод мог бы работать неправильно.

## Граничные случаи и ошибки

- `JSON.stringify` не является универсальным ключом. `undefined`, функции и символы в массиве превращаются в `null`; `NaN` и `Infinity` тоже дают `null`.
- `BigInt` и циклические структуры не сериализуются.
- Содержимое объекта используется как ключ, а не его ссылка. После мутации объекта строка изменится и появится другая запись.
- Кэш растёт без ограничений и очистки. Для долгоживущей функции могут понадобиться LRU, TTL или ручной `clear`.
- Побочные эффекты исходной функции при попадании в кэш повторно не выполняются. Мемоизировать стоит детерминированные функции.
- Для промиса кэшируется объект промиса, включая отклонение.

## Сложность

Чтение `Map` в среднем близко к `O(1)`, сериализация аргументов — `O(s)`. При попадании в кэш исходная функция не вызывается; при промахе добавляется её стоимость. Память — `O(k)` для `k` уникальных ключей и результатов.

## Что запомнить

Мемоизация корректна, когда одинаковый набор аргументов должен давать одинаковый результат. Отдельно продумайте ключ, передачу `this`, допустимые типы аргументов и способ ограничить рост кэша.
