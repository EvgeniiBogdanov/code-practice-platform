## Что делает решение

Метод `forEach` вызывает переданный колбэк для каждой записи `Map`:

```js
map.forEach((value, key) => {
  console.log(`${key}: ${value}`);
});
```

При коллекции `fruit → apple`, `veg → carrot` колбэк выполнится два раза в порядке вставки записей.

## Порядок аргументов колбэка

Самая частая ошибка в этой задаче — перепутать ключ и значение. Сигнатура выглядит так:

```js
map.forEach((value, key, map) => {
  // value — значение текущей записи
  // key — её ключ
  // map — исходная коллекция
});
```

Сначала передаётся значение, затем ключ. Такой порядок выбран по аналогии с `Array.prototype.forEach((value, index, array) => ...)`: у массива на втором месте индекс, у `Map` — ключ.

## Чем forEach отличается от map

Несмотря на имя переменной `map`, вызов `map.forEach(...)` не является методом преобразования `Array.prototype.map`. `forEach` предназначен для побочных эффектов — например, вывода, логирования или обновления внешнего состояния — и всегда возвращает `undefined`.

```js
const result = map.forEach(() => 123);
console.log(result); // undefined
```

Возвращаемое значение колбэка игнорируется. Если нужен новый массив, используйте итератор и `Array.from`:

```js
const labels = Array.from(map, ([key, value]) => `${key}: ${value}`);
```

## forEach или for...of

`forEach` удобен для простого действия над всеми записями. Но из него нельзя выйти через `break` или `continue`. `return` завершает только текущий вызов колбэка и работает примерно как переход к следующей записи.

Для досрочной остановки, последовательного `await` или более сложного управления потоком выбирайте `for...of`.

## Граничные случаи и ошибки

- Пустая коллекция не вызовет колбэк.
- Порядок обхода совпадает с порядком вставки.
- Удалённая до посещения запись не будет обработана. Новая запись, добавленная до завершения обхода, может быть обработана.
- Передача `async`-колбэка не заставляет `forEach` ждать промисы; для последовательного ожидания нужен `for...of`, для параллельного — явный набор промисов.
- Перестановка `(key, value)` выведет данные наоборот и часто остаётся незамеченной, если имена переменных неочевидны.

## Сложность

Обход всех `n` записей занимает `O(n)` времени. Сам `forEach` требует `O(1)` дополнительной памяти, не считая работы колбэка.

## Что запомнить

У `Map.prototype.forEach` порядок параметров — `(value, key, map)`. Используйте его для простого действия над каждой записью; когда нужен контроль цикла или корректный `await`, переходите на `for...of`.
