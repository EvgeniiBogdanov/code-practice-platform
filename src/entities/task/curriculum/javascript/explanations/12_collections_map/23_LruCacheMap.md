### Что делает решение
Решение реализует структуру данных `LRUCache` с асимптотикой `O(1)` для всех операций с использованием встроенного порядка ключей `Map`:
1. В конструкторе сохраняет `capacity` и инициализирует экземпляр `Map`.
2. В методе `get(key)`: если ключ найден, удаляет его из `Map` и тут же вставляет обратно. Это перемещает ключ в самый конец коллекции (наиболее свежее использование).
3. В методе `put(key, value)`: если ключ уже есть — обновляет его позицию через `delete` + `set`. Если ключ новый и достигнута емкость — удаляет самый первый ключ `this.cache.keys().next().value` (наименее используемый, least recently used).

### Почему Map в JS идеально подходит для LRU Cache

1. **Гарантия спецификации ECMAScript**:
   - В отличие от обычных объектов `Object`, `Map` строго сохраняет порядок добавления ключей.
   - Вызов `map.keys().next().value` возвращает самый ранний добавленный ключ за `O(1)`.
   - Перезапись через `map.delete(key); map.set(key, value);` перемещает запись в конец за `O(1)`.

2. **Сравнение с двусвязным списком (Doubly Linked List + Hash Map)**:
   - В языках вроде C++/Java для LRU пишут двусвязный список вручную.
   - В JS движок V8 оптимизирует `Map` внутри как хэш-таблицу со связным списком (Deterministic Hash Table), поэтому стандартный `Map` дает максимальную производительность без оверхеда на кастомные узлы.

### Граничные случаи и ошибки
- **Емкость 1**: при каждом новом ключе предыдущий немедленно вытесняется.
- **Обновление значения существующего ключа**: не должно увеличивать общий `size`, но обязано актуализировать свежесть ключа.
- **Некорректная емкость**: `capacity <= 0` выбрасывает `RangeError`.

### Сложность
- **По времени**: `O(1)` для `get` и `put`.
- **По памяти**: `O(capacity)` — размер ограничен емкостью кэша.

### Что запомнить для собеседования
- `Map` в JS сохраняет порядок вставки.
- Паттерн `delete(key)` + `set(key, value)` перемещает элемент в конец.
- Самый старый элемент извлекается через `map.keys().next().value`.
