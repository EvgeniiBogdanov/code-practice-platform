### Что делает решение
LRU (Least Recently Used) — политика вытеснения: когда кэш заполнен, удаляется элемент, к которому **дольше всего не обращались**. Так устроены кэши браузера, CDN, базы данных и кэш запросов во фронтенде (например, лимит записей в TanStack Query или кэше изображений).

Решение на `Map` использует её гарантию: **ключи хранятся в порядке вставки**.
- Начало `Map` — самый старый ключ, конец — самый свежий.
- `get(key)`: если ключ есть, удаляем его и вставляем заново — он переезжает в конец («освежается»).
- `put(key, value)`: удаляем ключ (если он был) и вставляем в конец. Если размер превысил `capacity`, удаляем первый ключ — его даёт `this.cache.keys().next().value`.

Все операции `Map` (`has`, `get`, `set`, `delete`) и получение первого ключа через итератор работают за `O(1)`.

### Классическая реализация: Map + двусвязный список
На собеседовании часто просят решение «как в учебнике», без опоры на порядок `Map`:
- `Map<key, node>` — поиск узла за `O(1)`;
- двусвязный список — порядок использования. Перенос узла в конец и удаление из начала занимают `O(1)`, потому что у узла есть ссылки `prev` и `next`.
- Фиктивные узлы `head` и `tail` убирают проверки на `null` при вставке и удалении.

Это решение переносится на любой язык (в Java — `LinkedHashMap`, в Python — `OrderedDict`), поэтому его важно уметь написать.

### Граничные случаи и ошибки
- **Обновление существующего ключа** не должно вытеснять другие элементы и должно делать ключ свежим. Ошибка: при `put` существующего ключа сначала проверить переполнение и удалить чужой элемент.
- **`get` тоже освежает ключ.** Если забыть перенос в `get`, получится FIFO-кэш, а не LRU.
- Массив вместо `Map` (`indexOf` + `splice`) даёт `O(n)` на операцию — интервьюер это сразу заметит.
- `capacity = 0`: каждая вставка тут же вытесняется. Решите, нужен ли такой кэш, или бросайте ошибку в конструкторе.
- Значение `-1` как признак отсутствия — соглашение LeetCode. В реальном коде лучше возвращать `undefined`.

### Сложность
- `get` и `put`: `O(1)` по времени в обоих решениях.
- По памяти: `O(capacity)`.

### Что запомнить для собеседования
- LRU = хеш-таблица для поиска + упорядоченная структура для «свежести».
- В JS порядок вставки `Map` позволяет освежать ключ через `delete` + `set`, а самый старый ключ брать через `keys().next().value`.
- Нужно уметь написать и классический вариант с двусвязным списком (LeetCode 146).
