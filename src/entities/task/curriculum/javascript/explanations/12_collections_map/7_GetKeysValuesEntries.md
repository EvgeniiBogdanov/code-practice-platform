## Что делает решение

У `Map` есть три отдельных представления содержимого:

```js
const keysArr = [...products.keys()];
const valuesArr = [...products.values()];
const entriesArr = [...products.entries()];
```

Для коллекции `bread → 50`, `milk → 80`, `eggs → 120` получатся:

```js
keysArr;    // ["bread", "milk", "eggs"]
valuesArr;  // [50, 80, 120]
entriesArr; // [["bread", 50], ["milk", 80], ["eggs", 120]]
```

## Что возвращают методы Map

`keys()`, `values()` и `entries()` возвращают не готовые массивы, а итераторы `MapIterator`. Они выдают элементы по одному и не копируют всю коллекцию заранее.

```js
const iterator = products.keys();

iterator.next(); // { value: "bread", done: false }
iterator.next(); // { value: "milk", done: false }
```

Итератор одноразовый: после полного чтения он исчерпан. Обычно вручную вызывать `next` не нужно — его потребляет `for...of`, spread или `Array.from`.

## Зачем нужен spread

Оператор `...` последовательно получает значения из iterable и складывает их в новый массив:

```js
const keysArr = [...products.keys()];
```

Альтернативная запись эквивалентна:

```js
const keysArr = Array.from(products.keys());
```

`Array.from` особенно полезен, если одновременно нужно преобразование:

```js
const doubledPrices = Array.from(products.values(), (price) => price * 2);
```

## Связь entries с самой Map

Итератор `products.entries()` совпадает с итератором по умолчанию. Поэтому `[...products]` и `[...products.entries()]` возвращают одинаковые массивы пар.

Во всех трёх случаях сохраняется порядок вставки. Если ключом или значением является объект, в новый массив попадёт ссылка на тот же объект, а не глубокая копия.

## Граничные случаи и ошибки

- Для пустой `Map` все три массива будут пустыми.
- Методы возвращают функции-итераторы: нужно писать `products.keys()`, а не `products.keys`.
- Итератор нельзя повторно использовать после исчерпания; для нового прохода вызовите метод ещё раз.
- Созданные массивы являются снимком последовательности на момент разворачивания. Последующее добавление записи в `Map` не добавит элемент в уже созданный массив.
- Изменение объекта, ссылка на который попала в массив, всё равно будет видно через `Map`.

## Сложность

Создание каждого массива занимает `O(n)` времени и `O(n)` дополнительной памяти. Если нужны только последовательный обход или поиск, материализовывать массив необязательно.

## Что запомнить

`keys`, `values` и `entries` возвращают ленивые итераторы. Превращайте их в массив только тогда, когда действительно нужны методы массива, индексный доступ или отдельный снимок данных.
