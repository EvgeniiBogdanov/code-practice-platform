### Что делает решение
Функция `set(obj, path, value)` (аналог lodash `_.set`) динамически устанавливает значение в глубоко вложенную структуру, автоматически создавая промежуточные массивы (для числовых индексов) и объекты (для строковых ключей), а также защищая приложение от атак Prototype Pollution.

### Пошаговый разбор

1. **Автоматический выбор типа контейнера (`Array` vs `Object`)**:
   - При создании недостающего промежуточного узла функция заглядывает на один шаг вперёд (`nextKey`).
   - Если `nextKey` состоит только из цифр (`/^\d+$/`), создаётся массив `[]`.
   - Если `nextKey` текстовый — создаётся обычный объект `{}`.
   - Это гарантирует, что путь `'users[0].name'` создаст `{ users: [{ name: '...' }] }`, а не `{ users: { '0': { name: '...' } } }`.

2. **Защита от Prototype Pollution (Загрязнение прототипа)**:
   - В уязвимых реализациях злоумышленник может передать путь `'__proto__.isAdmin'` со значением `true`.
   - Это приведёт к мутации `Object.prototype`, и **все** объекты в приложении внезапно получат свойство `isAdmin: true`, что является критической уязвимостью безопасности.
   - Проверка `key === '__proto__' || key === 'constructor' || key === 'prototype'` блокирует подобные атаки.

3. **Итеративное углубление**:
   - Указатель `current` перемещается по узлам до предпоследнего ключа `keys.length - 1`, создавая недостающие звенья цепи.
   - Последний ключ `lastKey` получает целевое значение `value`.

### Граничные случаи и ошибки
- **Затирание существующих примитивов**: если в объекте было `{ a: 10 }`, а вызывается `set(obj, 'a.b', 20)`, значение `10` заменяется новым объектом `{ b: 20 }`.

### Сложность
- **По времени**: `O(P)`, где `P` — количество сегментов в пути.
- **По памяти**: `O(P)` для создаваемых промежуточных объектов и массива ключей.

### Что запомнить для собеседования
- Автосоздание массивов при числовых индексах `isIntegerKey(nextKey)`.
- Обязательная валидация на Prototype Pollution (`__proto__`, `constructor`, `prototype`).
