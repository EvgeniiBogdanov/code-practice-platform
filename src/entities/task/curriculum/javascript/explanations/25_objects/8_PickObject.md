### Что делает решение
Функция реализует популярную служебную утилиту `pick(obj, keys)` (аналог lodash `_.pick`), которая отбирает только заданные свойства из исходного объекта и формирует новый чистый объект без побочных эффектов.

### Пошаговый разбор

1. **Проверка фактического существования ключа**:
   - Использование `Object.hasOwn(obj, key)` критично: если в `keys` передан ключ, которого нет в `obj`, мы не должны добавлять в результирующий объект `result[key] = undefined`.
   - Если же в `obj` явно есть `{ status: undefined }`, и мы запрашиваем `'status'`, `Object.hasOwn` вернёт `true`, и свойство попадет в результат.

2. **Иммутабельность**:
   - Исходный объект `obj` остаётся неизменным.

3. **Сравнение с функциональным подходом `reduce`**:
   - Можно написать: `keys.reduce((acc, k) => Object.hasOwn(obj, k) ? Object.assign(acc, { [k]: obj[k] }) : acc, {})`.
   - Однако прямой цикл `for...of` в 5-10 раз быстрее и не создаёт промежуточных объектов в памяти.

### Граничные случаи и ошибки
- **`null` или не-объект на входе**: возвращается `{}`.
- **Пустой массив ключей**: возвращается `{}`.
- **Ключи из прототипа**: `Object.hasOwn` игнорирует методы прототипа (например `toString`, если он передан в массиве `keys`).

### Сложность
- **По времени**: `O(K)`, где `K` — количество элементов в массиве `keys`.
- **По памяти**: `O(M)`, где `M <= K` — количество отобранных ключей.

### Что запомнить для собеседования
- `pick` отбирает белый список свойств (whitelist).
- Несуществующие ключи не должны попадать со значением `undefined` (проверяется через `Object.hasOwn`).
