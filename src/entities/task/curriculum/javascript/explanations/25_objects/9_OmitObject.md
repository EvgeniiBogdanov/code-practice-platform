### Что делает решение
Функция реализует утилиту `omit(obj, keys)` (аналог lodash `_.omit`), формируя новый объект со всеми свойствами исходного объекта, за исключением ключей из «чёрного списка» (blacklist).

### Пошаговый разбор

1. **Оптимизация поиска через `new Set(keys)`**:
   - Если проверять `keys.includes(key)` на каждой итерации, поиск займёт `O(K)` времени, а общая сложность составит `O(N * K)`.
   - Обернув `keys` в `new Set(keys)`, мы получаем проверку `omitSet.has(key)` за константное время `O(1)`, снижая общую сложность до линейной `O(N + K)`.

2. **Иммутабельность и отсутствие `delete`**:
   - Наивный подход: скопировать объект `{ ...obj }` и вызвать `delete copy[k]` в цикле.
   - Минусы наивного подхода: как мы знаем, `delete` ломает hidden class в V8 и работает медленнее. Создание объекта «с нуля» через `result[key] = obj[key]` эффективнее.

3. **Сравнение с `pick`**:
   - `pick` отбирает белый список (whitelist) и итерируется по массиву `keys`.
   - `omit` исключает чёрный список (blacklist) и итерируется по всем ключам объекта `Object.keys(obj)`.

### Граничные случаи и ошибки
- **Ключи, которых нет в объекте**: если в `keys` передать `'unknownKey'`, функция корректно скопирует все существующие ключи без ошибок.
- **Пустой список ключей**: возвращается полная неглубокая копия объекта `obj`.

### Сложность
- **По времени**: `O(N + K)`, где `N` — число ключей в `obj`, `K` — длина массива `keys`.
- **По памяти**: `O(N)` для создания структуры `Set` и результирующего объекта.

### Что запомнить для собеседования
- `omit` реализует чёрный список (blacklist).
- Преобразование массива ключей в `Set` перед фильтрацией — маркер Senior-оптимизации (`O(N + K)` вместо `O(N * K)`).
