### Что делает решение
Решение реализует функциональный паттерн вычисления дельты (`diffObjects`) и иммутабельного применения патча (`patchObject`):
1. `diffObjects` за один проход по ключам вычисляет три непересекающихся набора: добавленные свойства (`added`), обновленные значения (`updated`) и удаленные ключи (`deleted`).
2. `patchObject` создает поверхностную копию исходного объекта (`{ ...base }`), удаляет исключенные ключи через оператор `delete` и применяет новые значения через `Object.assign`.
3. Исходный объект полностью сохраняет свою неизменяемость (`immutability`).

### Применение в реальных архитектурах

1. **Оптимизация сетевого трафика (WebSocket delta-updates)**:
   - Вместо отправки гигантского объекта состояния целиком сервер передает только компактный `diff`.
   - Клиент применяет `patchObject(state, diff)`, обновляя только изменившиеся ветки.

2. **Time-travel и Redux history**:
   - Хранение последовательности `diff` позволяет легко откатывать (`undo`) и накатывать (`redo`) состояние с минимальным расходом оперативной памяти.

### Граничные случаи и ошибки
- **Одинаковые объекты**: возвращает `{ added: {}, updated: {}, deleted: [] }`.
- **Передача `null` или примитивов**: безопасно возвращает пустую дельту без падения скрипта.

### Сложность
- **По времени**: `O(K1 + K2)` — где $K1$ и $K2$ — количество собственных ключей объектов.
- **По памяти**: `O(D)` — размер объекта дельты (только изменившиеся поля).

### Что запомнить для собеседования
- Разделение на `added`, `updated`, `deleted` — стандартный протокол JSON Patch / State Sync.
- Патч всегда должен возвращать новый объект, никогда не мутируя входной аргумент.
