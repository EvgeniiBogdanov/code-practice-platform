### Что делает решение
Решение устраняет частый баг скрытой мутации стейта, демонстрируя правильный паттерн иммутабельного обновления вложенных структур данных со **структурным разделением (structural sharing)**.

### Пошаговый разбор ошибки Code Review

1. **Почему `[...order.items]` не спас от мутации**:
   - Оператор `[...order.items]` создает новый внешний массив.
   - Однако элементы внутри массива (`{ id: 'item_1', ... }`) — это **те же самые ссылки в памяти**, что и в `originalOrder.items`.
   - Присваивание `targetItem.quantity = newQuantity` мутирует объект по ссылке, что приводит к необратимому изменению исходного объекта `originalOrder`.

2. **Правильный паттерн через `.map()`**:
   - Метод `.map()` возвращает новый массив.
   - Для целевого элемента создается новый объект с обновленным полем: `{ ...item, quantity: newQuantity }`.
   - Для всех остальных элементов возвращается **исходная ссылка `item`**.

3. **Преимущества Structural Sharing**:
   - Неизмененные объекты не дублируются в памяти.
   - Хуки и компоненты React (`React.memo`, `useMemo`, селекторы Zustand/Redux) корректно определяют, какие компоненты нужно перерендерить, а какие пропустить по ссылочному равенству `===`.

### Граничные случаи и ошибки
- **Товар не найден или количество не изменилось**: возвращается исходный объект `order` без создания лишних копий.
- **Пустой список товаров**: корректная обработка `items: []`.

### Сложность
- **По времени**: `O(N)` — один проход по массиву `items`.
- **По памяти**: `O(N)` — создание нового массива `items` и одного обновленного объекта.

### Что запомнить для собеседования
- Spread `...` выполняет только **поверхностное** копирование (1 уровень глубины).
- Для иммутабельного обновления массивов объектов используйте `items.map(item => item.id === id ? { ...item, ...patch } : item)`.
- Неизмененные ссылки должны сохраняться для оптимизации ререндеров React.
