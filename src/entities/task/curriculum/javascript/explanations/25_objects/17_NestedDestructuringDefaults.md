### Что делает решение
Решение выполняет глубокую вложенную деструктуризацию объекта с одновременным использованием:
1. Переименования ключей (алиасы: `id: accountId`).
2. Значений по умолчанию на каждом уровне вложенности (`{ user = {} } = {}`), предотвращая ошибки `TypeError: Cannot read properties of undefined`.
3. Деструктуризации массива (`emails: [primaryEmail = 'no-email'] = []`).
4. Сбора остаточных свойств верхнего уровня через оператор `...meta`.

### Пошаговый разбор синтаксиса деструктуризации

1. **Защита вложенных объектов**:
   - Конструкция `account: { id = 'anonymous' } = {}` означает: если свойство `account` отсутствует или равно `undefined`, для него подставляется дефолтный пустой объект `{}`, и дальнейшая деструктуризация `id` не упадет с ошибкой.

2. **Деструктуризация первого элемента массива**:
   - `emails: [primaryEmail = 'no-email'] = []` извлекает первый элемент массива. Если массив пуст (`[]`) или первый элемент равен `undefined`, `primaryEmail` получает значение `'no-email'`.

3. **Rest-оператор `...meta`**:
   - `...meta` собирает все ключи объекта `payload`, которые **не были явно перечислены** в левой части выражения деструктуризации (`account`, `contacts`, `plan`).

### Граничные случаи и ошибки
- **Передача `payload === null`**: `payload || {}` защищает от `TypeError: Cannot destructure property of 'null' as it is null`.
- **Пустые строки в именах**: использование `[firstName, lastName].filter(Boolean).join(" ")` предотвращает появление висячих пробелов, если заполнено только одно из полей.

### Сложность
- **По времени**: `O(K)` — где `K` — количество свойств в `payload` (для сбора `...meta`).
- **По памяти**: `O(K)` — создание нового объекта результата.

### Что запомнить для собеседования
- Для каждого промежуточного уровня вложенности обязательно указывать `= {}`.
- Алиас задается через двоеточие `originalKey: newName`.
- Дефолт задается через знак равенства `key = defaultValue`.
- `...rest` собирает только оставшиеся, неизвлеченные свойства.
