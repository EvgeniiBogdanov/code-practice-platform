### Что делает решение

Функция `deepFreeze(obj)` делает переданный объект и все его вложенные объекты рекурсивно **неизменяемыми (frozen)**:
1. Замораживает текущий уровень через `Object.freeze(obj)`.
2. Обходит все собственные свойства через `Object.getOwnPropertyNames(obj)`.
3. Если значение свойства является объектом или функцией и ещё не заморожено (`!Object.isFrozen(value)`), рекурсивно вызывает `deepFreeze(value)`.
4. Возвращает исходный замороженный объект.

```javascript
const deepFreeze = (obj) => {
  Object.freeze(obj);

  for (const key of Object.getOwnPropertyNames(obj)) {
    const value = obj[key];

    if (
      value !== null &&
      (typeof value === "object" || typeof value === "function") &&
      !Object.isFrozen(value)
    ) {
      deepFreeze(value);
    }
  }

  return obj;
};
```

---

### Пошаговый разбор

1. **Почему стандартного `Object.freeze` недостаточно?**
   - Нативный `Object.freeze(obj)` выполняет только **поверхностную** (shallow) заморозку. Свойства первого уровня становятся `writable: false, configurable: false`, но ссылки на вложенные объекты остаются изменяемыми (`user.profile.age = 31` сработает без ошибок).

2. **Проверка `!Object.isFrozen(value)`**:
   - Предотвращает повторную обработку уже замороженных объектов.
   - Защищает от зацикливания при циклических ссылках, так как родитель замораживается *до* рекурсивного спуска к детям.

3. **Использование `Object.getOwnPropertyNames`**:
   - В отличие от `Object.keys`, метод `Object.getOwnPropertyNames` захватывает также неперечислимые (non-enumerable) собственные свойства.

---

### Граничные случаи и ошибки

- **`null`**: `typeof null === "object"`. Без явной проверки `value !== null` вызов `Object.freeze(null)` в старых средах или попытка чтения свойств вызовет ошибку.
- **Примитивы**: При передаче примитива (строка, число) в ES2015+ `Object.freeze(primitive)` возвращает сам примитив без ошибок.
- **Функции**: Функции имеют `typeof === "function"` и также могут иметь собственные свойства.
- **Коллекции (`Map`, `Set`)**: `Object.freeze` замораживает свойства экземпляра, но не блокирует внутренние методы мутации (`.set()`, `.add()`, `.delete()`). На собеседовании полезно упомянуть, что для них требуется отдельная обертка.

---

### Сложность

- **По времени**: $\mathcal{O}(N)$, где $N$ — общее количество объектов и свойств в структуре данных (каждое свойство проверяется ровно один раз).
- **По памяти**: $\mathcal{O}(D)$, где $D$ — максимальная глубина вложенности объекта (стек вызовов рекурсии).

---

### Что запомнить для собеседования

- `Object.freeze` поверхностен (shallow). Для настоящей иммутабельности необходим рекурсивный обход.
- Заморозка родителя перед рекурсивным спуском к детям (`Object.freeze(obj)` первой строкой) в сочетании с проверкой `!Object.isFrozen(value)` защищает от циклических ссылок.
- Замороженный объект в strict mode при попытке мутации выбрасывает `TypeError`, а в non-strict mode мутация молча игнорируется.
