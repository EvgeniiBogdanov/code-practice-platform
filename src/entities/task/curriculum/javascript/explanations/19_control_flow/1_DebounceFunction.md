# Реализация debounce

## 1. Какое поведение нужно получить

Debounce объединяет частую серию вызовов в один. Пока новые вызовы приходят раньше, чем истекло `wait` миллисекунд, таймер переносится. Это типичный механизм для поиска по мере ввода, автосохранения и обработки `resize`.

В текущем решении третий параметр `immediate` выбирает один из двух режимов:

- `false` — trailing-вызов: функция срабатывает после паузы;
- `true` — leading-вызов: функция срабатывает сразу в начале серии, а остальные вызовы до паузы подавляются.

## 2. Почему нужен closure

```js
let timeout;
```

Переменная объявлена во внешней функции `debounce`, поэтому возвращённая функция сохраняет к ней доступ. Все вызовы одной debounced-функции видят один и тот же таймер. У другой debounced-функции будет своё независимое замыкание.

## 3. Пошаговый разбор вызова

```js
const callNow = immediate && !timeout;
clearTimeout(timeout);
```

`callNow` становится `true` только в начале новой серии, когда активного таймера ещё нет. Затем предыдущий таймер отменяется: старый trailing-вызов больше не должен сработать.

```js
timeout = setTimeout(() => {
  timeout = null;
  if (!immediate) fn.apply(this, args);
}, wait);
```

Новый таймер отмечает границу периода тишины. Сброс в `null` важен для режима `immediate`: после паузы следующий вызов снова считается началом серии. `apply(this, args)` сохраняет контекст и все аргументы исходного вызова.

```js
if (callNow) fn.apply(this, args);
```

В leading-режиме первый вызов происходит сразу. В trailing-режиме эта строка ничего не делает — выполнение произойдёт внутри таймера.

## 4. Как работает cancel

`debounced.cancel()` очищает таймер и сбрасывает ссылку. Отложенный вызов не произойдёт, а следующая попытка в leading-режиме снова сможет выполниться немедленно.

## 5. Важное ограничение текущей версии

Название задачи упоминает независимые флаги `leading` и `trailing`, но показанное решение принимает один boolean `immediate`. Оно не поддерживает режим, где включены оба флага. Для полного API понадобится объект options и отдельное хранение последних аргументов.

## 6. Частые ошибки

- Использовать стрелочную функцию как возвращаемую и потерять динамический `this`.
- Не сбросить `timeout` после срабатывания.
- Забыть отменить старый таймер.
- Считать debounce ограничителем «раз в N мс». Это throttle; debounce ждёт паузу.

## 7. Сложность

Каждый вызов выполняет `O(1)` служебной работы и хранит один таймер. Количество реальных вызовов `fn` зависит от числа отдельных серий событий.

## 8. Что запомнить

Debounce — это перезапускаемый таймер в замыкании. `clearTimeout` отменяет старое намерение, а новый таймер фиксирует последний актуальный вызов.
