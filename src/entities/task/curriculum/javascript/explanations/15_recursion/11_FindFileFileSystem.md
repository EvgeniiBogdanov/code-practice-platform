## Что делает решение

```js
const findFile = (node, name) => {
  if (!node) return false;
  if (node.name === name) return true;
  if (node.type === "folder" && Array.isArray(node.children)) {
    return node.children.some((child) => findFile(child, name));
  }
  return false;
};
```

Функция выполняет поиск в глубину по файловому дереву. Сначала проверяет текущий узел, затем при необходимости рекурсивно просматривает детей папки.

## Почему используется some

`some` возвращает `true`, как только один ребёнок или его поддерево нашли имя. Остальные ветви после успеха не обходятся. Логический результат автоматически поднимается через все уровни рекурсии.

Проверка `!node` — база для отсутствующего узла. Файл без детей после проверки имени сразу даёт `false`; рекурсия запускается только для корректной папки с массивом `children`.

## Граничные случаи и ошибки

- Несмотря на имя `findFile`, текущий код вернёт `true` и для папки с совпавшим `name`, потому что тип проверяется после имени. Если нужен только файл, добавьте `node.type === "file"`.
- Поиск сравнивает регистр и не нормализует пути: `App.js` и `app.js` различны.
- Возвращается только boolean, а не найденный узел или полный путь. Контракт следует выбирать заранее.
- Повторяющиеся имена не различаются; функция останавливается на первом успехе.
- Циклические ссылки между папками вызовут бесконечную рекурсию; нужен `WeakSet` посещённых узлов.
- Очень глубокая структура может переполнить стек.
- Повреждённая папка без массива `children` безопасно считается листом и даёт `false`.

## Сложность

В худшем случае посещаются все `n` узлов: `O(n)` времени. Стек — `O(h)`. Благодаря `some` лучший случай близок к `O(1)`, если совпадает корень.

## Что запомнить

Рекурсивный поиск должен проверять текущий узел, определять, можно ли спускаться, и коротко замыкать успех. Уточните, ищется имя любого узла, файл, объект или путь.
