## Что делает решение

```js
const treeDepth = (node) => {
  if (node === null) return 0;
  return 1 + Math.max(treeDepth(node.left), treeDepth(node.right));
};
```

Функция вычисляет высоту бинарного дерева в узлах. Пустая ветвь имеет глубину `0`; непустой узел добавляет один уровень к большей глубине своих поддеревьев.

## Как формируется ответ

Лист получает `1 + max(0, 0) = 1`. Его родитель сравнивает высоты ветвей и добавляет свой уровень. Для пути из трёх узлов результат равен `3`. Использование `Math.max` важно: высота определяется самым длинным путём, а не суммой или минимумом.

Рекурсивный вызов сначала достигает листьев, затем значения глубины поднимаются вверх. Это post-order вычисление: результат родителя зависит от уже вычисленных детей.

## Граничные случаи и ошибки

- Для `null` возвращается `0`. Некоторые определения считают высоту в рёбрах и дают пустому дереву `-1`; тогда ответы отличаются на единицу. Нужно зафиксировать соглашение.
- Код ожидает явные `null` в отсутствующих ветвях. `undefined` вызовет ошибку.
- Общие ссылки и циклы нарушают модель дерева; цикл приведёт к переполнению стека.
- У очень глубокого перекошенного дерева возможен `RangeError`. Итеративный обход может хранить пары `(node, depth)` в собственном стеке или очереди.
- Значение `node.value` не влияет на высоту и даже не читается.
- Вычисляются обе ветви; ранний выход обычно невозможен без известного ограничения глубины.

## Сложность

Каждый узел посещается один раз: `O(n)` времени. Стек занимает `O(h)`, от `O(log n)` для сбалансированного дерева до `O(n)` для цепочки.

## Что запомнить

Высота дерева — один плюс максимум высот детей. Самая частая ошибка — смешать определение в узлах и в рёбрах или сложить глубины вместо выбора более длинной ветви.
