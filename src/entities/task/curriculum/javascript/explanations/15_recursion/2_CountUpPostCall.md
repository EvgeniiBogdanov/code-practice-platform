## Что делает решение

```js
const countUp = (n) => {
  if (n <= 0) return;
  countUp(n - 1);
  console.log(n);
};
```

Функция получает `n`, но выводит числа от `1` до `n`. Отличие от обратного отсчёта — действие расположено **после** рекурсивного вызова.

## Углубление и возврат

При `countUp(3)` вызовы сначала уходят до базы: `3 → 2 → 1 → 0`. Пока более глубокий вызов не завершился, `console.log` ждёт в каждом кадре стека. После базы стек разворачивается: кадр с `n = 1` выводит `1`, затем `2`, затем `3`.

Это важная модель рекурсии: код до рекурсивного вызова работает на пути вниз, код после него — на пути возврата. Каждый кадр хранит собственное значение параметра `n`.

## Граничные случаи и ошибки

- `n <= 0` ничего не выводит.
- Перестановка `console.log` перед вызовом изменит порядок на убывающий.
- Без уменьшения аргумента или базы будет переполнение стека.
- Большое `n` опасно для стека, даже если алгоритм логически корректен; цикл безопаснее.
- Дробный вход создаёт последовательность дробей, а `Infinity` никогда не приблизится к базе.
- Возвращаемые значения рекурсивных вызовов здесь не используются. Функция предназначена только для вывода и возвращает `undefined`.

## Сложность

Время — `O(n)`, стек — `O(n)`. Сам вывод также выполняется `n` раз. Итеративный аналог имеет то же время и `O(1)` дополнительной памяти.

## Что запомнить

Позиция действия относительно рекурсивного вызова управляет порядком. Сначала углубиться, затем обработать — значит получить порядок от базы к исходной задаче. Всегда мысленно разделяйте фазу роста стека и фазу возврата.
