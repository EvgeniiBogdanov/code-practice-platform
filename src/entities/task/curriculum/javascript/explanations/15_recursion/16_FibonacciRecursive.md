## Что делает решение

```js
const fib = (n) => (n <= 1 ? n : fib(n - 1) + fib(n - 2));
```

Функция повторяет математическое определение: `F(0) = 0`, `F(1) = 1`, а каждое следующее число равно сумме двух предыдущих.

## Почему простая рекурсия медленная

Для `fib(5)` вычисляются `fib(4)` и `fib(3)`. Внутри `fib(4)` снова вычисляется `fib(3)`, то есть одни и те же подзадачи повторяются много раз. Дерево вызовов быстро разрастается. Наглядность формулы оплачивается экспоненциальным временем.

Рекомендуемый итеративный вариант хранит только соседние значения `a` и `b`, один раз проходит от `2` до `n` и возвращает `b`. Мемоизация рекурсивной версии также убирает повторы, но использует кеш.

## Граничные случаи и ошибки

- Текущий базовый случай возвращает отрицательное `n` как готовый результат, хотя классическая задача обычно допускает только неотрицательные целые.
- Дробный вход тоже в конце возвращает дробные базовые значения и не соответствует последовательности Фибоначчи.
- Для строгого API нужна проверка `Number.isInteger(n) && n >= 0`.
- Рекурсивная версия становится практически непригодной уже на умеренных `n` и может переполнить стек.
- Числа Фибоначчи вскоре превышают `Number.MAX_SAFE_INTEGER`; для точных больших значений используйте `BigInt`.
- Итеративное решение линейно, а fast doubling позволяет вычислять за `O(log n)` шагов.
- База `n <= 1` корректна только после валидации домена.

## Сложность

Наивная рекурсия — `O(2^n)` времени и `O(n)` глубины стека. Итеративный вариант — `O(n)` времени и `O(1)` памяти; мемоизация — `O(n)` времени и памяти.

## Что запомнить

Красивая рекурсивная формула не гарантирует хороший алгоритм. Ищите повторяющиеся подзадачи: для Fibonacci выбирайте итерацию, мемоизацию или fast doubling и обязательно валидируйте вход.
