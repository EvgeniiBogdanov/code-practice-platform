## Что делает решение

```js
const findMax = (arr) => {
  if (arr.length === 1) return arr[0];
  const maxOfRest = findMax(arr.slice(1));
  return arr[0] > maxOfRest ? arr[0] : maxOfRest;
};
```

Функция сравнивает первый элемент с максимумом оставшегося массива. База — массив из одного элемента: его единственный элемент и есть максимум.

## Пошаговая идея

Для `[3, 7, 2]` сначала ищется максимум `[7, 2]`, для этого — максимум `[2]`. База возвращает `2`; уровень выше выбирает `7`, верхний — снова `7`. Работа происходит при разворачивании стека.

Альтернатива `Math.max(...arr)` значительно короче, но spread передаёт элементы как аргументы и на очень больших массивах может превысить лимит аргументов. Итеративный проход надёжен для любого практического размера.

## Граничные случаи и ошибки

- Пустой массив не достигает базы: `slice(1)` остаётся пустым, и рекурсия переполнит стек. Контракт должен запретить пустой вход или вернуть, например, `-Infinity`.
- `NaN` делает сравнения ложными и может дать неожиданный результат.
- Строки сравниваются лексикографически; смешанные типы приводятся при `>`.
- `slice(1)` на каждом уровне создаёт новый массив. Это делает реализацию существенно дороже варианта с индексом.
- Глубина равна длине массива, поэтому большой вход переполнит стек.
- Исходный массив не мутируется.

## Сложность

Из-за повторных `slice` копируется `n - 1`, затем `n - 2` элементов: время и суммарные копии могут достигать `O(n²)`. Стек — `O(n)`. Версия с передаваемым индексом работает за `O(n)` времени без копий; обычный цикл — с `O(1)` памятью.

## Что запомнить

Рекурсивно можно свести максимум к «первый против максимума хвоста», но создание хвоста через `slice` скрывает квадратичную цену. Всегда определяйте поведение пустого массива.
