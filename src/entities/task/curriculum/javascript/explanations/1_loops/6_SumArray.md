## Что делает решение

```js
const sumNumbers = (arr) => {
  let sum = 0;
  for (let i = 0; i < arr.length; i++) {
    sum += arr[i];
  }
  return sum;
};
```

Функция проходит массив по индексам и накапливает сумму. Ноль — нейтральное значение, поэтому пустой массив корректно возвращает `0`.

## Как работает накопление

Для `[5, 10, 2]` значение `sum` меняется как `0 → 5 → 15 → 17`. Инвариант: перед итерацией с индексом `i` аккумулятор равен сумме элементов с индексами меньше `i`. После последнего элемента это сумма всего массива.

В карточке также дан вариант `reduce((acc, curr) => acc + curr, 0)`. Он выражает ту же свёртку декларативно. Явный `for` удобнее для отладки, `break` или дополнительной логики; `reduce` короче, когда операция действительно является простой агрегацией.

## Граничные случаи и ошибки

- Элементы должны быть числами. Строка переключит `+` на конкатенацию: `[1, "2", 3]` даст строковый результат.
- `NaN` делает всю последующую сумму `NaN`; `Infinity` сохраняется как бесконечность.
- Разреженный массив ведёт себя по-разному: индексный `for` прочитает пропуск как `undefined` и может получить `NaN`, а `reduce` пропускает пустые слоты.
- Числа с плавающей точкой имеют погрешность: `0.1 + 0.2 !== 0.3`.
- Для больших целых возможен выход за безопасный диапазон `Number`.
- Нельзя использовать `i <= arr.length`: лишнее `undefined` испортит результат.
- Функция не мутирует массив, потому что только читает его элементы.

## Сложность

Оба варианта посещают каждый элемент один раз: `O(n)` времени и `O(1)` дополнительной памяти. Callback `reduce` не меняет асимптотику.

## Что запомнить

Суммирование — типичный аккумуляторный паттерн. Явно задайте начальное значение и контракт элементов. Выбор между `for` и `reduce` — вопрос читаемости и требуемого контроля, а не разницы в Big O.
