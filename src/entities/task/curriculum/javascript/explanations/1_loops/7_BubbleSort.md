## Что делает решение

Пузырьковая сортировка многократно сравнивает соседей и меняет их местами, если левый больше правого:

```js
for (let i = 0; i < arr.length; i++) {
  for (let j = 0; j < arr.length - 1 - i; j++) {
    if (arr[j] > arr[j + 1]) {
      const temp = arr[j];
      arr[j] = arr[j + 1];
      arr[j + 1] = temp;
    }
  }
}
```

После каждого полного внутреннего прохода максимальный элемент необработанной части оказывается справа.

## Пошаговая идея

Для `[3, 1, 2]` первый проход меняет `3` и `1`, затем `3` и `2`: получается `[1, 2, 3]`. Последний элемент уже стоит правильно. Поэтому следующий внутренний цикл заканчивается раньше благодаря `- i`.

Граница `arr.length - 1 - i` также защищает обращение `arr[j + 1]`: у текущего `j` всегда существует правый сосед. Сравнение `>` не меняет местами равные значения, поэтому алгоритм стабилен для элементов с одинаковым ключом.

## Граничные случаи и ошибки

- Решение **мутирует входной массив** и возвращает ту же ссылку. Если это нежелательно, начните с `const result = [...arr]`.
- Пустой массив и один элемент возвращаются без полезных сравнений.
- Текущий код всегда выполняет все проходы. Несмотря на описание сложности в карточке, лучший случай здесь тоже `O(n²)`. Для `O(n)` на уже отсортированном массиве нужен флаг `swapped` и ранний `break`, если обменов не было.
- Смешанные типы, `NaN` и строки подчиняются правилам сравнения JavaScript и могут дать неожиданный порядок.
- Ошибка `j < arr.length - i` позволит прочитать несуществующий `arr[j + 1]` на границе.
- Пузырьковая сортировка учебная; для production-массивов обычно используют `toSorted` или `sort` с корректным компаратором.

## Сложность

В текущей реализации время `O(n²)` во всех случаях, память `O(1)`, потому что обмен идёт на месте. Версия с копией требует `O(n)` памяти; версия с флагом имеет лучший случай `O(n)`.

## Что запомнить

Внешний проход фиксирует один элемент справа, внутренний сравнивает только ещё не отсортированную часть. Всегда отмечайте мутацию входа и не приписывайте оптимизацию раннего выхода к коду, в котором её нет.
