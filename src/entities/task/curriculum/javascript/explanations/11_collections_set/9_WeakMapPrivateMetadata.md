### Что делает решение
Решение использует коллекцию `WeakMap` для реализации паттерна приватных метаданных. Метаданные (сессионный токен) связываются с объектом-ключом без изменения самого объекта и без риска утечек памяти (Memory Leaks).

### Пошаговый разбор механизма JS Engine

1. **Слабые ссылки (Weak References)**:
   - В обычном `Map` объект-ключ удерживается сильной ссылкой (strong reference). Пока `Map` жив, объект не будет удален сборщиком мусора, даже если в остальном коде на него нет ссылок.
   - В `WeakMap` ключи удерживаются слабыми ссылками. Когда объект `userAlice` удаляется или перезаписывается (`userAlice = null`), сборщик мусора V8 освобождает память объекта и автоматически удаляет связанную запись из `WeakMap`.

2. **Ограничения `WeakMap`**:
   - Ключами могут быть **только объекты** (и незарегистрированные символы в ES2023+). Примитивы (`string`, `number`) в качестве ключей вызывают `TypeError`.
   - `WeakMap` **не итерируем**: у него нет методов `.keys()`, `.values()`, `.entries()`, свойства `.size` и цикла `for..of`, так как состояние сборщика мусора недетерминировано.

3. **Инкапсуляция**:
   - Данные, сохраненные в `WeakMap`, не попадают в `Object.keys(userAlice)`, не видны в `JSON.stringify(userAlice)` и не могут быть случайно прочитаны сторонними модулями.

### Граничные случаи и ошибки
- **Попытка передать примитив**: `manager.setSession("user1", "tok")` выбрасывает `TypeError`.
- **Проверка отсутствующей сессии**: возвращает `null`, а не падает с ошибкой.

### Сложность
- **По времени**: `O(1)` для всех операций (`get`, `set`, `has`, `delete`).
- **По памяти**: `O(1)` дополнительной памяти на каждую активную сессию (с автоматическим GC-освобождением).

### Что запомнить для собеседования
- `WeakMap` предотвращает утечки памяти при связывании данных с DOM-элементами или объектами.
- Ключи — только объекты; коллекция неитерируема и не имеет свойства `.size`.
- Идеально подходит для кэшей, метаданных и эмуляции приватных полей.
