# Мини-шаблонизатор строк

## 1. Что делает функция

`renderTemplate(template, data)` ищет конструкции вида `{{ user.name }}`, читает значение по указанному пути и подставляет его в строку.

```js
renderTemplate("Привет, {{ user.name }}!", {
  user: { name: "Анна" },
});
// "Привет, Анна!"
```

## 2. Валидация входа

Если template не строка, решение возвращает пустую строку. Если data отсутствует или не является объектом, исходный шаблон возвращается без изменений. Эти ветки не дают коду упасть на вызове `replace` или при чтении свойств.

## 3. Как регулярное выражение находит плейсхолдер

```js
/{{\s*([\w.]+)\s*}}/g
```

- `{{` и `}}` обозначают границы вставки;
- `\s*` разрешает пробелы;
- `([\w.]+)` захватывает путь из имён и точек;
- флаг `g` заменяет все совпадения, а не только первое.

Callback `replace` получает полное совпадение и захваченный `path`.

## 4. Проход по вложенному пути

```js
const keys = path.split(".");
let value = data;

for (const key of keys) {
  if (value === null || value === undefined) return "";
  value = value[key];
}
```

Путь `user.profile.name` превращается в три ключа. На каждом шаге `value` перемещается глубже. Проверка перед чтением предотвращает ошибку вида `Cannot read properties of undefined`, если часть пути отсутствует.

Финальное значение преобразуется через `String`, поэтому числа и boolean корректно попадают в текст. `null` и `undefined` заменяются пустой строкой.

## 5. Граничные случаи и ограничения

- `0` и `false` нельзя проверять через `if (!value)`: это корректные значения. Поэтому решение сравнивает только с `null` и `undefined`.
- Регулярное выражение не поддерживает ключи с дефисом или пробелом.
- Прямой доступ `value[key]` может читать унаследованные свойства. Для данных из недоверенного источника полезно разрешать только собственные ключи через `Object.hasOwn` и блокировать опасные сегменты вроде `__proto__`.
- Решение не экранирует HTML. При вставке результата через `innerHTML` это может привести к XSS; обычный текстовый вывод безопаснее.

## 6. Сложность

Строка просматривается за `O(t)`, а каждый найденный путь — за число его сегментов. Дополнительная память нужна для массива ключей каждого совпадения.

## 7. Что запомнить

Шаблонизатор состоит из двух частей: регулярное выражение находит путь, а безопасный последовательный обход получает значение. Falsy-значение не равно отсутствующему значению.
