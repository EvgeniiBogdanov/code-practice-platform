### Что делает решение
Решение реализует классический детерминированный лексический анализатор (Лексер / Tokenizer / Scanner):
1. Итерирует по входной строке с помощью позиционного указателя `cursor`.
2. Для каждого текущего суффикса строки `input.slice(cursor)` последовательно применяет массив правил регулярных выражений, зафиксированных на начало строки якорем `^`.
3. Сохраняет токены с полной метаинформацией (`type`, строковое `value`, начальная позиция `start` и конечная позиция `end`), пропуская служебные разделители и пробелы при флаге `ignore: true`.
4. При обнаружении нераспознанного символа немедленно выбрасывает информативный `SyntaxError` с точным указанием позиции и проблемного символа.

### Пошаговый разбор механизма лексера

1. **Привязка к началу строки `^`**:
   - Все шаблоны регулярных выражений в спецификации токенов обязаны начинаться с якоря `^` (либо проверяться на `match.index === 0`). Это гарантирует, что движок сопоставляет правило строго со следующего необработанного символа, а не ищет совпадение в произвольном месте текста.

2. **Приоритет правил (Rule Ordering)**:
   - Порядок следования правил в массиве `tokenSpecs` определяет их приоритет. Например, ключевые слова (`function`, `let`, `if`) должны проверяться до общего идентификатора (`[a-zA-Z_]\w*`), а операторы из нескольких символов (`===`, `!==`, `>=`) — до односимвольных (`=`, `!`, `>`).

3. **Служебные токены**:
   - Правило для пробельных символов `/\s+/` помечается флагом `ignore: true`, что позволяет лексеру продвигать указатель вперед без засорения итогового потока токенов.

### Граничные случаи и ошибки
- **Пустая строка `""`**: возвращает пустой массив `[]` без входа в цикл.
- **Нераспознанный символ**: выбрасывает `SyntaxError` с точным индексом ошибки для удобной отладки компилятора.
- **Числа с плавающей точкой**: шаблон `^\d+(\.\d+)?` корректно захватывает точку как часть числа `45.5`, предотвращая ошибочное разбиение на `45`, `.` и `5`.
- **Жадность квантификаторов**: использование жадных квантификаторов позволяет за один шаг захватывать максимальную длину идентификатора или числа.

### Сложность
- **По времени**: `O(N \cdot K)` — где $N$ — длина исходной строки, $K$ — число правил в `tokenSpecs`.
- **По памяти**: `O(T)` — где $T$ — количество созданных токенов в результирующем потоке.

### Что запомнить для собеседования
- Лексический анализ (токенизация) — первый обязательный этап работы любого компилятора, интерпретатора, шаблонизатора и парсера абстрактного синтаксического дерева (AST).
- Каждое правило проверяется с якорем `^` на текущей позиции курсора.
- Порядок правил определяет приоритет совпадений.
