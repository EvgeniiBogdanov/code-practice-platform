## Что делает решение

Функция находит сумму цифр арифметически, не превращая число в строку:

```js
const sumOfDigits = (num) => {
  let sum = 0;
  let n = Math.abs(num);

  while (n > 0) {
    sum += n % 10;
    n = Math.floor(n / 10);
  }

  return sum;
};
```

В каждой итерации обрабатывается последняя десятичная цифра. Оператор `% 10` извлекает её, а `Math.floor(n / 10)` удаляет её из текущего числа.

## Пошаговый разбор

Для `sumOfDigits(705)` изменения выглядят так:

| `n` до итерации | `n % 10` | новая `sum` | `Math.floor(n / 10)` |
|---:|---:|---:|---:|
| `705` | `5` | `5` | `70` |
| `70` | `0` | `5` | `7` |
| `7` | `7` | `12` | `0` |

После этого условие `n > 0` ложно, и функция возвращает `12`. Ноль в середине числа не теряется: его вклад в сумму просто равен нулю.

`Math.abs(num)` создаёт неотрицательную рабочую копию. Хотя условие задачи говорит о неотрицательном числе, благодаря этой строке решение также вычислит сумму цифр для `-705`. Исходный параметр не изменяется; все преобразования происходят с локальной переменной `n`.

Начальное `sum = 0` одновременно является правильным результатом для числа `0`: цикл не запускается, и функция сразу возвращает ноль.

## Почему нужно округление

В JavaScript оператор `/` не выполняет целочисленное деление. Результат `705 / 10` равен `70.5`, поэтому без `Math.floor` следующая итерация работала бы уже не с целым числом. Округление вниз отбрасывает обработанный разряд.

Строковый вариант `String(Math.abs(num))` тоже понятен, но создаёт строку и проходит по её символам. Арифметический вариант показывает сам принцип работы с десятичными разрядами и использует константную дополнительную память.

## Граничные случаи и ошибки

- Эталонное решение корректно рассчитано на целые числа. Для `12.34` остаток и округление дадут результат, который не является суммой десятичных цифр записи.
- `Infinity` приводит к бесконечному циклу: после деления и округления значение остаётся `Infinity`. Перед вычислением можно проверить `Number.isSafeInteger(num)`.
- `NaN` не войдёт в цикл и даст `0`, что маскирует некорректный ввод.
- Целые числа больше `Number.MAX_SAFE_INTEGER` могут быть уже неточно представлены, поэтому их цифры нельзя надёжно восстановить этим способом.
- `Math.abs` не принимает `BigInt`. Для очень больших целых нужна отдельная реализация с `10n`, `%` и `/` для `BigInt`.
- Нельзя забывать присваивание `n = Math.floor(n / 10)`: без уменьшения `n` цикл не завершится.

## Сложность

Пусть `k` — количество десятичных цифр. Цикл выполняется `k` раз, поэтому время — `O(k)`, или `O(log10 n)` для положительного `n`. Дополнительная память — `O(1)`.

## Что запомнить

Паттерн обработки цифр справа налево состоит из двух операций: `n % 10` получает последнюю цифру, `Math.floor(n / 10)` удаляет её. Аккумулятор хранит ответ, а рабочее число обязано уменьшаться на каждой итерации. До запуска алгоритма полезно явно определить контракт: целое ли число, допустимы ли отрицательные значения и нужна ли поддержка `BigInt`.
