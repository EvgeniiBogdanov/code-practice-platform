## Что делает решение

Функция ищет `target` в **отсортированном по возрастанию** массиве и возвращает индекс найденного элемента либо `-1`:

```js
const binarySearch = (arr, target) => {
  let left = 0;
  let right = arr.length - 1;

  while (left <= right) {
    const mid = Math.floor((left + right) / 2);

    if (arr[mid] === target) return mid;

    if (arr[mid] < target) {
      left = mid + 1;
    } else {
      right = mid - 1;
    }
  }

  return -1;
};
```

Вместо проверки элементов по одному алгоритм каждый раз отбрасывает половину оставшегося диапазона.

## Пошаговый разбор

`left` и `right` задают включительный диапазон индексов, где цель ещё может находиться. Для массива `[1, 3, 5, 7, 9, 11]` и цели `7`:

| `left` | `right` | `mid` | `arr[mid]` | действие |
|---:|---:|---:|---:|---|
| `0` | `5` | `2` | `5` | цель больше, `left = 3` |
| `3` | `5` | `4` | `9` | цель меньше, `right = 3` |
| `3` | `3` | `3` | `7` | вернуть `3` |

Если средний элемент меньше цели, все элементы слева от него также меньше цели благодаря сортировке. Их можно безопасно исключить выражением `left = mid + 1`. Симметрично, при большем среднем элементе правая часть исключается через `right = mid - 1`.

`mid` уже проверен, поэтому `+ 1` и `- 1` обязательны. Присваивание `left = mid` или `right = mid` может оставить границы без изменений и зациклить поиск.

## Почему условие left <= right

Границы включительные. Когда `left === right`, остаётся ровно один возможный элемент, и его ещё нужно проверить. Условие `left < right` завершило бы цикл слишком рано. После неуспешного поиска границы пересекаются: `left > right`; это означает, что кандидатов больше нет.

Формула середины часто записывается как `left + Math.floor((right - left) / 2)`. В языках с ограниченными целыми она защищает сумму от переполнения. Для индексов JavaScript-массива практическая разница отсутствует, но форма хорошо переносится между языками.

## Граничные случаи и ошибки

- На пустом массиве `right` равен `-1`, цикл не запускается и возвращается `-1`.
- Главный контракт — массив уже отсортирован тем же отношением сравнения. На неотсортированных данных ответ не гарантирован.
- При дубликатах возвращается некоторый найденный индекс, не обязательно первый или последний. Для поиска границы нужен изменённый алгоритм.
- Строгое `===` не считает строку `"7"` равной числу `7` и не находит `NaN`, потому что `NaN !== NaN`.
- Массив с пропусками, `undefined` или смешанными типами нарушает понятный порядок сравнений.
- Сортировать вход внутри функции ради поиска обычно не стоит: это изменит индексы и добавит стоимость `O(n log n)`.

## Сложность

После каждой итерации диапазон примерно вдвое меньше. Время — `O(log n)`, а дополнительная память итеративной версии — `O(1)`. Для сравнения, линейный поиск занимает `O(n)`, но не требует сортировки.

## Что запомнить

Бинарный поиск держится на двух вещах: гарантированно отсортированных данных и инварианте «если цель существует, она находится между `left` и `right` включительно». Проверяйте середину, исключайте её из следующего диапазона и завершайте поиск, когда границы пересеклись.
