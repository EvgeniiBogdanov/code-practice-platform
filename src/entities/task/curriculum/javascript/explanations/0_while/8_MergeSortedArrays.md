## Что делает решение

Функция объединяет два уже отсортированных массива в один отсортированный результат за один линейный проход:

```js
const merge = (arr1, arr2) => {
  const result = [];
  let i = 0;
  let j = 0;

  while (i < arr1.length && j < arr2.length) {
    if (arr1[i] <= arr2[j]) {
      result.push(arr1[i]);
      i++;
    } else {
      result.push(arr2[j]);
      j++;
    }
  }

  while (i < arr1.length) result.push(arr1[i++]);
  while (j < arr2.length) result.push(arr2[j++]);

  return result;
};
```

`i` указывает на первый ещё не использованный элемент `arr1`, а `j` — на первый неиспользованный элемент `arr2`. Поскольку оба массива отсортированы, меньший из этих двух элементов является наименьшим среди всех оставшихся.

## Пошаговый разбор

Для `[1, 4, 7]` и `[2, 5, 8, 9]` основной цикл принимает решения так:

| Сравнение | Добавляется | Новые указатели |
|---|---:|---|
| `1 <= 2` | `1` из первого | `i = 1`, `j = 0` |
| `4 <= 2` — нет | `2` из второго | `i = 1`, `j = 1` |
| `4 <= 5` | `4` из первого | `i = 2`, `j = 1` |
| `7 <= 5` — нет | `5` из второго | `i = 2`, `j = 2` |
| `7 <= 8` | `7` из первого | `i = 3`, `j = 2` |

Первый массив закончился. Основной цикл использует `&&`, поэтому останавливается, как только закончился хотя бы один массив. Элементы `8` и `9` второго массива уже стоят в правильном порядке; третий `while` просто дописывает их.

Инвариант: перед каждой итерацией `result` отсортирован и содержит ровно все элементы перед индексами `i` и `j`. Выбор меньшего текущего элемента сохраняет этот инвариант.

## Зачем нужны три цикла

Основной цикл может сравнивать элементы только пока они есть в обоих массивах. После него остаток может быть только у одного массива. Два коротких добивающих цикла обрабатывают оба возможных случая и одновременно делают пустые массивы естественным граничным случаем.

При равенстве используется `<=`, поэтому сначала берётся элемент из `arr1`. Это сохраняет относительный порядок равных элементов между источниками — полезное свойство стабильного слияния, особенно если вместо чисел сравниваются объекты по полю.

## Граничные случаи и ошибки

- Оба входа должны быть отсортированы по тому же правилу. Функция не проверяет и не исправляет порядок.
- Пустой массив работает без отдельного `if`: соответствующий остаточный цикл копирует второй вход.
- Исходные массивы не мутируются; создаётся новый `result`.
- `NaN`, `undefined` и смешанные типы делают сравнение непредсказуемым для числовой сортировки.
- Если забыть увеличить `i` или `j` в соответствующей ветке, цикл никогда не продвинется.
- Вариант `[...arr1, ...arr2].sort((a, b) => a - b)` короче, но повторно сортирует уже упорядоченные данные за `O((n + m) log(n + m))`. Без числового компаратора `sort()` сравнивает строковые представления, и, например, `10` окажется перед `2`.

## Сложность

Каждый из `n + m` элементов добавляется ровно один раз. Время — `O(n + m)`. Новый массив результата занимает `O(n + m)` памяти; помимо него указатели используют `O(1)`.

## Что запомнить

Паттерн двух указателей использует уже существующий порядок данных. Сравнивайте текущих кандидатов, переносите меньший и двигайте только его указатель. После завершения сравнений не забудьте дописать хвост оставшегося массива. Это базовая операция сортировки слиянием и многих задач на отсортированные последовательности.
