### Что делает решение
Алгоритм Фишера — Йейтса (в варианте Дурстенфельда) перемешивает массив за один проход:
1. Копируем массив, чтобы не мутировать входные данные.
2. Идём по индексам **с конца**: `i = n - 1, ..., 1`.
3. Для каждой позиции `i` выбираем случайный индекс `j` из диапазона **`[0, i]` включительно** — отсюда `Math.random() * (i + 1)`.
4. Меняем `result[i]` и `result[j]` местами. После этого позиция `i` «зафиксирована», и дальше работаем только с левой частью.

Каждый элемент с равной вероятностью попадает на любую позицию, поэтому все `n!` перестановок равновероятны.

### Почему `sort(() => Math.random() - 0.5)` — плохо
- Алгоритмы сортировки рассчитывают на **согласованный** компаратор: если `a < b` и `b < c`, то `a < c`. Случайный компаратор нарушает это правило, и итог зависит от внутреннего алгоритма движка (в V8 — TimSort). Распределение получается заметно неравномерным: одни перестановки выпадают чаще других.
- Это `O(n log n)` вместо `O(n)`.
- Это частый вопрос-ловушка: «почему так нельзя перемешивать колоду карт в онлайн-казино».

### Граничные случаи и ошибки
- **Ошибка на единицу:** `Math.floor(Math.random() * i)` (без `+ 1`) никогда не оставляет элемент на месте. Это алгоритм Саттоло: он даёт только циклические перестановки и тоже неравномерен для задачи перемешивания.
- Выбор `j` из всего массива `[0, n)` на каждом шаге — тоже классическая ошибка: распределение становится смещённым.
- Пустой массив и массив из одного элемента цикл не трогает — возвращается копия.
- `Math.random` не криптостойкий. Для лотерей и безопасности используйте `crypto.getRandomValues`.

### Сложность
- По времени: `O(n)`.
- По памяти: `O(n)` на копию (или `O(1)`, если перемешивать на месте).

### Что запомнить для собеседования
- Фишер — Йейтс: проход с конца, `j` из `[0, i]` включительно, обмен.
- Сортировка со случайным компаратором даёт неравномерное распределение.
- Обмен без временной переменной — деструктуризацией `[a[i], a[j]] = [a[j], a[i]]`.
