### Что делает решение
Задача проверяет главное практическое знание о массивах: **какие методы меняют исходный массив, а какие возвращают новый**. В React и Redux мутация состояния — частый источник багов: компонент не перерисовывается, потому что ссылка на массив не изменилась.

| Мутируют исходный массив | Возвращают новый массив |
|---|---|
| `push`, `pop`, `shift`, `unshift` | `slice`, `concat` |
| `splice` | `map`, `filter`, `flat`, `flatMap` |
| `sort`, `reverse` | `toSorted`, `toReversed` (ES2023) |
| `fill`, `copyWithin` | `toSpliced`, `with` (ES2023) |

### Пошаговый разбор
1. `slice(1, 3)` копирует элементы с индексами 1 и 2 (конец не включается). Исходный массив не меняется.
2. `splice(1, 2)` удаляет 2 элемента начиная с индекса 1 **из самого массива** и возвращает удалённые элементы.
3. `splice(1, 0, "X", "Y")` удаляет 0 элементов и вставляет новые — так делается вставка в середину.
4. `slice(-2)` — отрицательный индекс отсчитывается с конца.
5. `sort()` сортирует **на месте** и возвращает ту же ссылку, поэтому `sorted === numbers`.
6. `[...numbers].reverse()` сначала делает копию, поэтому исходный массив не меняется.

### Граничные случаи и ошибки
- `sort()` без компаратора сравнивает **строки**: `[10, 2, 1].sort()` даёт `[1, 10, 2]`. Для чисел нужен `(a, b) => a - b`.
- Названия легко перепутать. Запоминалка: в **splice** есть лишняя буква «p» — он «портит» исходник.
- `slice()` без аргументов — быстрый способ сделать поверхностную копию массива.
- Копия через spread или `slice` поверхностная: объекты внутри остаются общими.

### Сложность
- `slice(start, end)` — `O(k)`, где `k` — размер копии.
- `splice` — `O(n)`: элементы после места вставки или удаления сдвигаются.
- `sort` — `O(n log n)`.

### Что запомнить для собеседования
- `slice` копирует, `splice` мутирует.
- `sort` и `reverse` мутируют и возвращают тот же массив.
- В иммутабельном коде используйте копию (`[...arr]`) или ES2023-методы `toSorted`, `toReversed`, `toSpliced`, `with`.
