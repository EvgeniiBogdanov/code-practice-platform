### Что делает решение
В ES2023 у массивов появились четыре метода, которые делают то же, что их мутирующие «братья», но **возвращают новый массив**:

| Мутирующий | Неизменяемый аналог | Особенность |
|---|---|---|
| `sort(fn)` | `toSorted(fn)` | тот же компаратор |
| `reverse()` | `toReversed()` | — |
| `splice(i, n, ...items)` | `toSpliced(i, n, ...items)` | возвращает **итоговый массив**, а не удалённые элементы |
| `arr[i] = v` | `with(i, v)` | поддерживает отрицательный индекс, при выходе за границы бросает `RangeError` |

Эти методы особенно полезны в React и Redux, где состояние нельзя мутировать: `setItems((items) => items.with(index, updated))` вместо ручного копирования.

### Классический вариант
Если окружение не поддерживает ES2023, используется схема «копия + мутирующий метод» (`[...arr].sort()`) или методы, которые и так возвращают новый массив (`map` для замены, `filter` для удаления). Именно этот вариант часто просят написать на собеседовании, чтобы проверить понимание иммутабельности.

### Граничные случаи и ошибки
- `toSorted` делает **поверхностную** копию: объекты в новом массиве — те же самые. Если изменить `sorted[0].price`, изменится и исходный объект.
- `arr.with(10, x)` для массива длиной 3 бросает `RangeError`, а присваивание `arr[10] = x` молча создало бы дыры.
- В варианте с `filter` для удаления по индексу отрицательный индекс не поддерживается — его нужно нормализовать, как в `replaceAt`.
- Старые браузеры (до 2023 года) этих методов не знают. Проверяйте целевые браузеры или подключайте core-js.

### Сложность
- `toSorted` — `O(n log n)` по времени, `O(n)` по памяти.
- `with`, `toSpliced`, `toReversed` — `O(n)` по времени и памяти: всегда создаётся полная копия.

### Что запомнить для собеседования
- `toSorted`, `toReversed`, `toSpliced`, `with` — неизменяемые версии `sort`, `reverse`, `splice` и присваивания по индексу.
- Копия поверхностная.
- Без ES2023: `[...arr].sort()`, `map` для замены и `filter` для удаления.
