### Что делает решение
До появления `class` наследование в JS строили вручную. Синтаксис `class` — это «сахар» над тем же механизмом, поэтому на собеседованиях просят показать, что происходит под капотом.

Наследование состоит из двух независимых частей:
1. **Наследование полей.** В конструкторе `Dog` вызывается `Animal.call(this, name)` — родительский конструктор выполняется с `this` нового объекта и записывает в него `name`. Это аналог `super(name)`.
2. **Наследование методов.** `Dog.prototype = Object.create(Animal.prototype)` создаёт объект, прототипом которого является `Animal.prototype`. Цепочка поиска свойств становится такой:

```
dog → Dog.prototype → Animal.prototype → Object.prototype → null
```

Когда вызывается `dog.speak()`, движок ищет `speak` сначала в самом объекте, затем в `Dog.prototype` (находит переопределённый метод). Метод `Animal.prototype.speak` по-прежнему доступен явным вызовом через `call`.

### Зачем восстанавливать `constructor`
У `Dog.prototype` по умолчанию есть свойство `constructor === Dog`. После замены прототипа на `Object.create(...)` это свойство пропадает, и `dog.constructor` находит `Animal` выше по цепочке. Это ломает код, который создаёт «объект того же типа» через `new obj.constructor()`.

### Граничные случаи и ошибки
- **`Dog.prototype = Animal.prototype`** — частая ошибка. Оба конструктора разделяют один объект, и переопределение `speak` для собак сломает всех животных.
- **`Dog.prototype = new Animal()`** — устаревший способ. Он вызывает конструктор родителя без аргументов и кладёт в прототип лишние поля (`name: undefined`).
- Методы, объявленные внутри конструктора (`this.speak = function () {}`), создаются заново для каждого экземпляра и не переиспользуются через прототип.
- Порядок важен: методы `Dog.prototype` нужно добавлять **после** замены прототипа, иначе они пропадут вместе со старым объектом.
- В `class` есть то, чего нет у функций-конструкторов: вызов без `new` бросает `TypeError`, методы неперечисляемые, тело класса всегда в строгом режиме.

### Сложность
Поиск свойства по цепочке — `O(d)`, где `d` — глубина цепочки прототипов (обычно 2–4 уровня). Движки кешируют такие поиски (inline caches).

### Что запомнить для собеседования
- Поля наследуются вызовом родительского конструктора (`Parent.call(this)`), методы — через `Object.create(Parent.prototype)`.
- После замены прототипа восстанавливайте `constructor`.
- `class` и `extends` строят ту же цепочку прототипов.
