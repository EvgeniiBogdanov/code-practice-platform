### Что делает решение
Решение эмулирует поведение нативного оператора `new` (`myNew` / `[[Construct]]`), демонстрируя фундаментальную модель прототипного создания объектов в JavaScript.

### Пошаговый разбор 4 этапов оператора `new`

1. **Создание объекта и привязка прототипа**:
   - `Object.create(Constructor.prototype)` создает пустой объект, внутренний скрытый слот `[[Prototype]]` которого указывает на объект `Constructor.prototype`.
   - Благодаря этому созданный объект автоматически наследует все методы из прототипа конструктора.

2. **Вызов функции с контекстом**:
   - `Constructor.apply(instance, args)` выполняет тело функции-конструктора, где `this` указывает на созданный `instance`. Здесь происходит инициализация собственных свойств (`this.name = ...`).

3. **Анализ возвращаемого значения (Return Override)**:
   - Если конструктор вернул примитивное значение (`number`, `string`, `boolean`, `null`, `undefined`) — это значение игнорируется, и возвращается `instance`.
   - Если конструктор явно вернул непримитив (объект `{ ... }`, массив `[ ... ]` или функцию `() => {}`) — возвращается этот объект, а созданный `instance` отбрасывается.

### Граничные случаи и ошибки
- **Конструктор возвращает `null`**: хотя `typeof null === 'object'`, `null` является примитивом. Проверка `result !== null` обязательна, иначе функция ошибочно вернет `null` вместо инстанса.
- **Стрелочные функции в качестве конструктора**: у стрелочных функций нет свойства `.prototype` и слота `[[Construct]]`, вызов с ними должен выбрасывать `TypeError`.

### Сложность
- **По времени**: `O(1)` (плюс время выполнения тела конструктора).
- **По памяти**: `O(1)` — создание одного объекта.

### Что запомнить для собеседования
- 4 шага `new`: создание объекта -> связка с `.prototype` -> вызов конструктора с `this` -> возврат объекта.
- Возврат объекта из конструктора перекрывает созданный инстанс. Возврат примитива игнорируется.
