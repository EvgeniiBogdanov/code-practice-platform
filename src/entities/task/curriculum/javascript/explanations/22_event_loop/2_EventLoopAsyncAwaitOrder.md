### Что делает решение
Это самая известная задача на Event Loop. Чтобы её решить, нужно знать три правила:
1. **Синхронный код** выполняется первым и целиком: сюда входят тело `async`-функции **до первого `await`** и executor `new Promise(...)`.
2. **Микрозадачи** (`then`/`catch`/`finally`, продолжение после `await`, `queueMicrotask`) выполняются сразу после текущего синхронного кода, все до одной.
3. **Макрозадачи** (`setTimeout`, `setInterval`, события) — по одной, только когда очередь микрозадач пуста.

### Пошаговый разбор
**Синхронная фаза:**
1. `script start`.
2. `setTimeout` регистрирует колбэк в очереди макрозадач.
3. Вызов `async1()`: печатает `async1 start`, синхронно вызывает `async2()`, которая печатает `async2`. Затем `await` приостанавливает `async1` — продолжение уйдёт в очередь микрозадач.
4. Executor промиса выполняется сразу: `promise1`. `resolve()` ставит `then` в очередь микрозадач — **после** продолжения `async1`.
5. `script end`.

**Микрозадачи:** `async1 end`, затем `promise2`.

**Макрозадачи:** `setTimeout`.

Итог: `script start → async1 start → async2 → promise1 → script end → async1 end → promise2 → setTimeout`.

### Граничные случаи и ошибки
- **Исторический нюанс.** В старых версиях V8 (Chrome до 73, Node.js до 12) `await` занимал три тика микрозадач, и `promise2` печатался раньше `async1 end`. Спецификацию оптимизировали в 2019 году: `await` нативного промиса занимает один тик. Если интервьюер ожидает старый ответ, стоит упомянуть эту историю.
- Если `async2` вернёт **не** промис, а обычное значение, порядок не изменится: `await` всё равно оборачивает значение в промис и отдаёт продолжение в микрозадачу.
- Если `async2` вернёт `new Promise(...)` или thenable явно (`return Promise.resolve()`), добавятся дополнительные тики, и `async1 end` может оказаться после `promise2`.
- Частая ошибка — думать, что `setTimeout(fn, 0)` выполнится «сразу». Он всегда ждёт, пока опустеет очередь микрозадач.

### Сложность
Задача на понимание модели выполнения: `O(1)`.

### Что запомнить для собеседования
- Код до первого `await` и executor промиса — синхронные.
- Продолжение после `await` — микрозадача.
- Порядок: синхронный код → все микрозадачи → одна макрозадача → снова все микрозадачи и так далее.
