# Базовый цикл for...in

## 1. Что перебирает for...in

`for...in` перебирает **имена перечислимых строковых свойств** объекта. На каждой итерации переменная `key` содержит ключ, а значение читается через квадратные скобки.

```js
for (const key in user) {
  console.log(`${key}: ${user[key]}`);
}
```

Если `key === 'name'`, выражение `user[key]` равнозначно `user.name`. Квадратные скобки обязательны, потому что имя хранится в переменной. `user.key` искало бы буквальное свойство с именем `key`.

## 2. Почему const допустим

Для каждой итерации движок создаёт новое значение `key`. Мы не переназначаем его вручную, поэтому `const` подходит и ограничивает переменную телом цикла.

## 3. Собственные и унаследованные свойства

В отличие от `Object.keys`, цикл может пройти перечислимые свойства из цепочки прототипов. Для произвольного объекта обычно нужна защита:

```js
for (const key in user) {
  if (!Object.hasOwn(user, key)) continue;
  console.log(user[key]);
}
```

В текущем примере `user` — обычный объектный литерал без добавленных перечислимых свойств прототипа, поэтому результат ожидаем.

## 4. Чем отличается от for...of

- `for...in` выдаёт ключи объекта;
- `for...of` выдаёт значения итерируемой коллекции по `Symbol.iterator`.

Обычный объект не является iterable, поэтому `for...of user` бросит ошибку. Если нужны значения собственного объекта, можно использовать `for (const value of Object.values(user))`.

## 5. Почему не стоит обходить массив

Для массива `for...in` возвращает индексы как строки и может захватить дополнительные свойства. Для значений массива понятнее `for...of`, для индексов — обычный `for` или `entries()`.

## 6. Порядок и типы ключей

Современный стандарт задаёт правила порядка, но полагаться на него как на сортировку бизнес-данных не стоит. Символьные ключи `for...in` не перечисляет.

## 7. Сложность

Обход `n` доступных перечислимых свойств занимает `O(n)` времени и `O(1)` дополнительной памяти.

## 8. Что запомнить

`for...in` — цикл по ключам, включая потенциально унаследованные. Значение читается через `obj[key]`, а собственность ключа при необходимости проверяется через `Object.hasOwn`.
