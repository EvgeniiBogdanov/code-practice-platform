# Значения только собственных свойств

## 1. В чём ловушка for...in

`for...in` обходит не только свойства самого объекта, но и перечислимые свойства его прототипов. Задача требует вернуть только собственные значения, поэтому каждый ключ нужно отфильтровать.

```js
for (const key in obj) {
  if (Object.hasOwn(obj, key)) {
    result.push(obj[key]);
  }
}
```

`Object.hasOwn(obj, key)` возвращает `true`, только если ключ записан непосредственно в `obj`.

## 2. Пример с прототипом

```js
const proto = { role: "admin" };
const user = Object.create(proto);
user.name = "Иван";
user.age = 30;
```

Цикл увидит `name`, `age` и `role`. Но `Object.hasOwn(user, 'role')` вернёт `false`, поэтому результат будет `['Иван', 30]`.

## 3. Почему Object.hasOwn безопаснее метода объекта

Запись `obj.hasOwnProperty(key)` может сломаться в двух случаях:

- объект создан через `Object.create(null)` и не наследует этот метод;
- сам объект содержит поле `hasOwnProperty`, которое перекрыло метод.

Статический `Object.hasOwn` не зависит от содержимого проверяемого объекта. Для старых окружений используют `Object.prototype.hasOwnProperty.call(obj, key)`.

## 4. Рекомендуемое решение для Production (без for...in)

```js
const getOwnValues = (obj) => Object.values(obj);
```

Этот метод сразу возвращает массив собственных перечислимых строковых значений, оптимизирован движком на C++ и полностью игнорирует цепочку прототипов.

### Как отвечать на собеседовании:
- **Идеальный ответ сеньора**: сразу сказать: «В проде я напишу `Object.values(obj)`, так как он нативно забирает только собственные свойства и оптимизирован движком».
- **Демонстрация базы**: добавить: «Но если задача проверяет понимание работы `for...in` и прототипного наследования, то `for...in` потянет за собой унаследованные перечислимые свойства из прототипов, и их нужно отсекать через `Object.hasOwn(obj, key)`».

## 5. Граничные случаи

- Символьные свойства не попадут ни в `for...in`, ни в `Object.values`.
- Неперечислимые свойства также пропускаются.
- Порядок значений следует стандартному порядку перечисления ключей, но это не сортировка по алфавиту.
- Пустой объект возвращает `[]`.
- Геттер свойства выполнится в момент чтения `obj[key]` и может иметь побочный эффект.

## 6. Сложность

Обход занимает `O(n + p)`, где `n` — собственные, а `p` — видимые унаследованные свойства. Результат занимает `O(n)` памяти.

## 7. Что запомнить

`for...in` видит прототип, `Object.hasOwn` проводит границу владения. Если нужен просто массив собственных значений, стандартный `Object.values` уже решает задачу.
