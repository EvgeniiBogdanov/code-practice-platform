## Что делает решение

Задача сравнивает несколько похожих инструментов, у которых разные контракты:

- `===` и `Object.is`;
- глобальный `isNaN` и `Number.isNaN`;
- логическое ИЛИ `||` и нулевое слияние `??`;
- `typeof`, `Array.isArray` и `Object.prototype.toString`.

Правильный выбор зависит не от краткости записи, а от того, какие значения должны считаться одинаковыми, отсутствующими или принадлежащими нужному типу.

## NaN и Object.is

```js
NaN === NaN;             // false
Object.is(NaN, NaN);     // true
+0 === -0;               // true
Object.is(+0, -0);       // false
```

Строгое равенство считает положительный и отрицательный ноль одинаковыми, но `NaN` — не равным никакому значению, включая себя. `Object.is` использует алгоритм SameValue: он специально считает два `NaN` одинаковыми и различает знаки нуля.

Знак нуля редко важен, но он наблюдаем: `1 / +0` даёт `Infinity`, а `1 / -0` — `-Infinity`.

`Object.is` не выполняет глубокого сравнения. Два разных объекта с одинаковыми полями всё равно не равны:

```js
Object.is({ id: 1 }, { id: 1 }); // false
```

Для контекста: `Array.prototype.includes` и ключи `Map` используют ещё одну семантику — SameValueZero. Она считает `NaN` равным `NaN`, но не различает `+0` и `-0`.

## isNaN и Number.isNaN

```js
isNaN("hello");        // true
Number.isNaN("hello"); // false
```

Глобальный `isNaN` сначала выполняет `Number(value)`, а затем проверяет результат. `Number("hello")` равен `NaN`, поэтому ответ `true`. Фактически вопрос звучит как «станет ли значение `NaN` после числового преобразования?».

`Number.isNaN` ничего не преобразует. Он возвращает `true` только для значения типа `number`, которое действительно является `NaN`. Для проверки результата вычисления это обычно более безопасный инструмент.

Например, `isNaN(undefined)` истинно, а `isNaN("")` ложно, потому что пустая строка превращается в ноль. Такие результаты легко неверно интерпретировать как проверку «является ли исходное значение числом».

## Разница между || и ??

Оба оператора возвращают один из операндов и используют короткое замыкание, но условие перехода к правой части различается:

```js
0 || 42;          // 42
0 ?? 42;          // 0
"" || "default"; // "default"
"" ?? "default"; // ""
```

`||` выбирает правую часть для любого falsy-значения: `false`, `0`, `-0`, `0n`, `""`, `NaN`, `null`, `undefined`.

`??` выбирает правую часть только для `null` или `undefined`. Поэтому он подходит для значений по умолчанию, когда ноль, пустая строка и `false` являются допустимыми пользовательскими данными.

Правая часть вычисляется только при необходимости:

```js
cachedValue ?? loadValue();
```

`loadValue()` не вызовется, если `cachedValue` не nullish. Нельзя смешивать `??` с `||` или `&&` без явных скобок: `a ?? b || c` является синтаксической ошибкой, а `(a ?? b) || c` — уже определённое выражение.

## Как надёжно определять тип

```js
typeof [];                           // "object"
Array.isArray([]);                   // true
Object.prototype.toString.call(null); // "[object Null]"
```

Массивы являются объектами, поэтому одного `typeof` недостаточно. `Array.isArray` — специализированная и надёжная проверка массива, работающая и с массивами из другого iframe/realm, где `instanceof Array` может вернуть `false`.

Вызов базового `toString` позволяет различать многие встроенные категории: `"[object Date]"`, `"[object RegExp]"`, `"[object Null]"`. Метод вызывают через `Object.prototype`, потому что у самого значения может быть переопределён или отсутствовать `toString`.

Однако результат может быть настроен через `Symbol.toStringTag`, поэтому это не абсолютная защита от недоверенного объекта. Для бизнес-валидации обычно проверяют не только тег, но и требуемое поведение или схему данных.

## Граничные случаи и ошибки

- `typeof null === "object"`; `typeof` годится для примитивов и функций, но не классифицирует все виды объектов.
- `Number.isNaN` не отвечает на вопрос «является ли значение конечным числом». Для этого подходит `typeof value === "number" && Number.isFinite(value)`.
- `Object.is` отличается от `===` только в случаях `NaN` и знаковых нулей.
- `||` часто ошибочно заменяет допустимые `0`, `false` и `""` значением по умолчанию.
- `??` не считает `NaN` отсутствующим. Если `NaN` должен заменяться, нужна отдельная проверка.
- `instanceof` зависит от цепочки прототипов и realm, а также может быть настроен через `Symbol.hasInstance`.
- Ни один из этих операторов сам по себе не валидирует форму вложенного объекта.


## Сложность

Все операторы проверки типов (`typeof`, `Array.isArray`, `Object.is`, `Number.isNaN`, `??`, `||`) выполняются за константное время `O(1)` и не требуют дополнительной памяти `O(1)`.

## Что запомнить

Выбирайте инструмент по семантике: `Object.is` — SameValue, `Number.isNaN` — строгая проверка `NaN`, `??` — значение по умолчанию только при отсутствии, `Array.isArray` — массив. Универсальной «проверки типа» одной строкой для всех прикладных контрактов не существует.
