### Что делает решение
Задача закрывает две базовые темы, с которых начинается любое собеседование по JS: **какие бывают типы** и **чем примитивы отличаются от объектов при копировании и передаче в функцию**.

### Типы данных
В JavaScript 8 типов: 7 примитивов (`number`, `string`, `boolean`, `undefined`, `null`, `bigint`, `symbol`) и `object`. У `typeof` есть два исключения, которые нужно знать:
- `typeof null === "object"`. Это ошибка первой реализации языка, которую сохранили ради обратной совместимости. Проверять `null` нужно строго: `value === null`.
- `typeof function () {} === "function"`, хотя функция — это объект. Массивы дают `"object"`, поэтому для них есть `Array.isArray`.

### Значение против ссылки
- **Примитивы** хранятся и копируются **по значению**. `let b = a` создаёт независимую копию, и изменение `b` не влияет на `a`.
- **Объекты** (включая массивы и функции) в переменной хранят **ссылку**. `const second = first` копирует ссылку, и обе переменные указывают на один объект.
- `===` для объектов сравнивает ссылки, а не содержимое: два одинаковых литерала `{ x: 1 }` не равны.

### Передача в функцию
JS всегда передаёт аргументы **по значению**, но для объекта это значение — ссылка (call by sharing). Отсюда три случая:
1. `changePrimitive` меняет локальную копию числа, снаружи `num` остаётся `1`.
2. `changeObject` мутирует объект по полученной ссылке — изменение видно снаружи.
3. `replaceObject` записывает в локальную переменную **новую** ссылку, оригинал не меняется — `100`.

### Почему у примитивов есть методы
Строки и числа — не объекты, но `"текст".toUpperCase()` работает. При обращении к свойству примитива движок временно создаёт **объект-обёртку** (`String`, `Number`, `Boolean`, `Symbol`, `BigInt`), вызывает метод и сразу выбрасывает обёртку. Отсюда два следствия:
- записать свойство в примитив нельзя: `str.custom = 1` либо молча потеряется, либо в строгом режиме бросит `TypeError`;
- `new String("a")` создаёт **объект**: `typeof new String("a") === "object"`, и `new String("a") === "a"` — `false`. Обёртки через `new` на практике не используют.

### Как проверять типы правильно
| Что проверяем | Надёжный способ |
|---|---|
| `null` | `value === null` |
| `undefined` | `value === undefined` (или `typeof value === "undefined"` для необъявленной переменной) |
| массив | `Array.isArray(value)` |
| «настоящий» объект | `value !== null && typeof value === "object"` |
| точный встроенный тип | `Object.prototype.toString.call(value)` → `"[object Date]"` |
| `NaN` | `Number.isNaN(value)` |

### Где это ломает реальный код
- **React и Redux** сравнивают состояние по ссылке. Мутация объекта (`state.items.push(x)`) не меняет ссылку, и компонент не перерисуется. Поэтому состояние обновляют иммутабельно: `{ ...state, items: [...state.items, x] }`.
- **Параметры функций.** Функция, которая «просто поправила» поле переданного объекта, меняет данные у вызывающего кода. Такие побочные эффекты — частая причина багов.
- **Сравнение в `useEffect` и `useMemo`.** Объект, созданный заново при каждом рендере, никогда не равен предыдущему, и эффект будет срабатывать каждый раз.

### Граничные случаи и ошибки
- Копия через spread `{ ...obj }` поверхностная: вложенные объекты остаются общими.
- Строки — примитивы, поэтому методы строк всегда возвращают новую строку и не меняют исходную.
- `const` не делает объект неизменяемым: это только запрет переприсваивания переменной.

### Сложность
Задача на понимание: `O(1)`.

### Что запомнить для собеседования
- 7 примитивов + `object`; `typeof null` — `"object"`, `typeof function` — `"function"`.
- Примитивы копируются по значению, объекты — по ссылке.
- В JS нет передачи по ссылке в смысле C++: функция может мутировать объект, но не может заменить внешнюю переменную.
