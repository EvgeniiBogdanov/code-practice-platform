## Что делает решение

Задача проверяет четыре связанные темы: результат `typeof`, строгое и нестрогое равенство, сравнение ссылочных значений и поведение арифметических операторов при разных типах.

```js
typeof null;          // "object"
typeof NaN;           // "number"
null === undefined;   // false
null == undefined;    // true
[] === [];            // false
[] == ![];            // true
"5" + 3;             // "53"
"5" - 3;             // 2
```

Здесь не нужно заучивать восемь несвязанных исключений. Большинство ответов выводятся из нескольких правил преобразования.

## typeof null и typeof NaN

`typeof null` возвращает строку `"object"`. Это историческая особенность JavaScript, сохранённая ради обратной совместимости. Она не означает, что `null` является объектом. Надёжная проверка выглядит как `value === null`.

`NaN` означает специальное числовое значение «не число как корректный результат вычисления», но принадлежит типу `Number`. Поэтому `typeof NaN === "number"`. Например, `Number("hello")` возвращает `NaN`, сообщая, что числовое преобразование не удалось.

## null, undefined и два вида равенства

Строгое равенство `===` не выполняет приведение типов. `null` и `undefined` — разные примитивные типы, поэтому результат `false`.

У абстрактного равенства `==` для этой пары есть специальное правило: `null` нестрого равен только `undefined` и самому себе, а `undefined` — только `null` и самому себе. Поэтому `null == undefined` истинно, но `null == 0`, `null == false` и `null == ""` ложны.

В прикладном коде обычно используют `===`. Осознанная проверка `value == null` иногда применяется как компактная проверка сразу `null` или `undefined`, но команда должна понимать это соглашение.

## Почему [] === [] возвращает false

Массив — объект. Два литерала `[]` создают две разные ссылки:

```js
const first = [];
const second = [];

first === second; // false
first === first;  // true
```

Операторы равенства не сравнивают содержимое объектов глубоко. Для структурного сравнения нужен отдельный алгоритм.

## Пошаговый разбор [] == ![]

Это самое неожиданное выражение задачи:

1. Массив — объект, а любой объект является truthy.
2. Поэтому `![]` превращается в `false`.
3. Получается `[] == false`.
4. При абстрактном равенстве boolean преобразуется в число: `false → 0`.
5. Массив преобразуется в примитив. Пустой массив через `toString()` даёт пустую строку `""`.
6. Пустая строка при числовом преобразовании даёт `0`.
7. Итоговое сравнение `0 == 0` возвращает `true`.

Важно: это объяснение поведения, а не рекомендация писать подобный код. Явные преобразования и `===` значительно легче читать.

## Почему плюс и минус ведут себя по-разному

Бинарный `+` перегружен: он выполняет либо числовое сложение, либо конкатенацию строк. После преобразования операндов к примитивам наличие строки выбирает конкатенацию:

```js
"5" + 3; // "5" + "3" → "53"
```

Оператор `-` строковой операции не имеет, поэтому приводит оба значения к числам:

```js
"5" - 3; // 5 - 3 → 2
```

По той же причине `"5" * "2"` даст `10`, а `"5px" - 3` — `NaN`.

## Граничные случаи и ошибки

- `typeof undeclaredVariable` безопасно возвращает `"undefined"`, но прямое чтение необъявленной переменной вызывает `ReferenceError`.
- `typeof function () {}` возвращает `"function"`, хотя функции являются вызываемыми объектами.
- Все объекты truthy, включая `[]`, `{}` и обёртку `new Boolean(false)`.
- `NaN === NaN` ложно; для проверки используется `Number.isNaN`.
- Сложение с `Symbol` обычно бросает `TypeError`, а смешивание `BigInt` и `Number` в арифметике запрещено.
- Автоматическое приведение удобно на границе пользовательского ввода, но внутри бизнес-логики явное `Number(value)` или `String(value)` делает контракт заметнее.

## Сложность

Все базовые операции сравнения, взятия `typeof` и приведения элементарных типов работают за константное время `O(1)` и не требуют дополнительной памяти `O(1)`.

## Что запомнить

`typeof` имеет исторические особенности, объекты сравниваются по ссылке, `===` не приводит типы, а `==` следует таблице абстрактного равенства. Бинарный плюс уникален своей строковой веткой; остальные арифметические операторы обычно требуют числового преобразования.
