## Что делает решение

Задача показывает, как объекты превращаются в примитивы перед сложением, как работает унарный плюс и почему операторы сравнения с `null` дают на первый взгляд противоречивые ответы.

```js
[] + [];        // ""
[] + {};        // "[object Object]"
{} + [];        // "[object Object]" внутри console.log
+true;          // 1
+null;          // 0
+undefined;     // NaN
+"   ";         // 0
null > 0;       // false
null == 0;      // false
null >= 0;      // true
```

Символ `+` в начале последних примеров — унарный плюс, а не два инкремента: запись `+true` означает явное числовое преобразование.

## Как объекты проходят ToPrimitive

Бинарный плюс сначала должен получить примитивные значения. Для обычного массива или объекта используется внутренний алгоритм `ToPrimitive`. Упрощённая практическая модель для этих примеров:

1. Вызывается `valueOf()`.
2. Если результат всё ещё объект, вызывается `toString()`.
3. Полученный примитив участвует в сложении.

У пустого массива `valueOf()` возвращает сам массив, а `toString()` — пустую строку. У обычного объекта строковое представление равно `"[object Object]"`.

Поэтому:

```js
[] + [];
// "" + "" → ""

[] + {};
// "" + "[object Object]" → "[object Object]"
```

После `ToPrimitive` хотя бы один операнд является строкой, поэтому бинарный плюс выбирает конкатенацию, а не числовое сложение.

Объект может управлять преобразованием через `Symbol.toPrimitive`, `valueOf` или `toString`. Полный порядок зависит от hint (`"number"`, `"string"` или `"default"`); `Date` — известный особый случай с предпочтением строки при default hint.

## Контекстная ловушка {} + []

В эталонном коде выражение передано аргументом:

```js
console.log({} + []); // "[object Object]"
```

Здесь `{}` однозначно парсится как объектный литерал, поэтому результат совпадает с предыдущим рассуждением. Но если написать `{} + []` отдельной строкой в некоторых консольных или старых синтаксических контекстах, начальные фигурные скобки могут интерпретироваться как пустой блок, а `+[]` — как унарный плюс. Тогда можно увидеть `0`. Скобки `({} + [])` устраняют неоднозначность.

## Унарный плюс

Унарный `+` применяет числовое преобразование:

| Выражение | Преобразование | Результат |
|---|---|---:|
| `+true` | `Number(true)` | `1` |
| `+null` | `Number(null)` | `0` |
| `+undefined` | `Number(undefined)` | `NaN` |
| `+"   "` | строка содержит только пробелы и считается пустой | `0` |

Это компактная запись, но `Number(value)` обычно яснее для junior-разработчика и при ревью.

## Почему null сравнивается с нулём по-разному

Нестрогое равенство и реляционные операторы используют разные алгоритмы.

`null == 0` возвращает `false`, потому что специальное правило `==` считает `null` равным только `undefined` и `null`. До обычного числового сравнения дело не доходит.

При `null > 0` реляционное сравнение приводит `null` к числу `0`. Получается `0 > 0`, то есть `false`.

`null >= 0` возвращает `true`. В терминах спецификации результат связан с проверкой, что `null < 0` не истинно; для этой пары числовое преобразование даёт `0` и `0`. Практическая модель — `0 >= 0`.

## Граничные случаи и ошибки

- `[] + 1` возвращает строку `"1"`, а `[1] + 1` — `"11"`, потому что массивы превращаются в строки.
- `+[1]` даёт `1`, `+[1, 2]` — `NaN`: строка `"1,2"` не является числом.
- Унарный плюс нельзя применять к `BigInt`: `+1n` бросает `TypeError`.
- Преобразование `Symbol` к числу также бросает `TypeError`.
- Переопределённый `Symbol.toPrimitive` может иметь побочные эффекты или бросить ошибку; преобразование объекта не обязательно безвредно.
- Не переносите правила `==` на `<`, `>` и `>=`: это разные алгоритмы.
- Для проверки отсутствующего значения используйте явные сравнения или осознанное `value == null`, а не числовые сравнения с нулём.

## Сложность

Все базовые операции сравнения, унарные/бинарные операции и алгоритмы приведения примитивов и объектов работают за константное время `O(1)` и не требуют дополнительной памяти `O(1)`.

## Что запомнить

Перед бинарным плюсом объекты проходят `ToPrimitive`; если после этого присутствует строка, выполняется конкатенация. Унарный плюс вызывает числовое преобразование. Равенство `==` и реляционные сравнения нельзя объяснять одной общей фразой «JavaScript приводит типы» — у них разные правила.
