### Что делает решение
`sleep` — самый маленький и самый полезный «промисификатор»: он превращает колбэчный `setTimeout` в Promise.
1. `new Promise((resolve) => ...)` создаёт промис в состоянии `pending`.
2. `setTimeout(resolve, ms)` через `ms` миллисекунд вызывает `resolve`, и промис выполняется.
3. `await sleep(100)` приостанавливает **только текущую async-функцию**. Поток не блокируется: интерфейс отвечает, другие таймеры и обработчики работают.

`countdown` показывает, как с `await` писать последовательную асинхронную логику обычным циклом `for`. Без промисов пришлось бы строить цепочку вложенных `setTimeout` («callback hell»).

### Сравнение с блокирующим ожиданием
```js
// Плохо: занятый цикл блокирует поток на 300 мс
const start = Date.now();
while (Date.now() - start < 300) {}
```
Такой код замораживает вкладку: не отрисовываются кадры, не обрабатываются клики и не срабатывают другие таймеры. `sleep` через промис ждёт асинхронно.

### Где применяется
- Задержка между повторными попытками запроса (`retry` с backoff).
- Тесты и демо: имитация медленного API.
- Ограничение частоты запросов (rate limiting) в циклах.

### Граничные случаи и ошибки
- `await sleep(100)` внутри `forEach` не работает как ожидается: `forEach` не ждёт промисов из колбэка, все итерации стартуют одновременно. Для последовательного выполнения нужен `for...of` или обычный `for`.
- `setTimeout(resolve(), ms)` — ошибка: `resolve` вызывается сразу, а в таймер передаётся `undefined`.
- Задержка не точная: таймер сработает **не раньше** `ms` и только когда освободится поток. Поэтому в проверке используется допуск (`>= 290`).
- Отменяемый `sleep` принимает `AbortSignal`: при `abort` очищает таймер и отклоняет промис. Это тема задачи про AbortController.

### Сложность
`O(1)` по времени выполнения кода и памяти. Реальная задержка — `ms` миллисекунд.

### Что запомнить для собеседования
- `const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));` — стоит знать наизусть.
- `await` приостанавливает async-функцию, но не блокирует поток.
- Для последовательных `await` в цикле используйте `for`/`for...of`, а не `forEach`.
