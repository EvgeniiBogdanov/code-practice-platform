# Повторные попытки с задержкой

## 1. Что делает retry

`retry(fn, maxRetries, delayMs)` вызывает асинхронную операцию. При успехе результат сразу возвращается. При ошибке функция ждёт `delayMs` и пробует снова, пока запас повторов не закончится. Если ни одна попытка не сработала, наружу должна уйти последняя ошибка.

Такой механизм полезен для временных сетевых сбоев, но не должен бездумно повторять ошибки валидации или авторизации.

## 2. Важная договорённость о количестве попыток

```js
for (let attempt = 0; attempt <= maxRetries; attempt += 1)
```

Условие `<=` означает: есть одна первоначальная попытка и ещё `maxRetries` повторов. Например, `maxRetries = 3` допускает максимум четыре вызова `fn`. Это легко перепутать, поэтому смысл параметра нужно проговаривать явно.

## 3. Пошаговый разбор

```js
try {
  return await fn();
} catch (error) {
  lastError = error;
}
```

`await` нужен не только для получения результата. Благодаря ему отклонение промиса попадает в этот `catch`. Синхронный `throw` внутри `fn` также будет пойман.

```js
if (attempt < maxRetries) {
  await delay(delayMs);
}
```

Задержка выполняется только тогда, когда впереди действительно есть следующая попытка. После последней ошибки ждать уже бессмысленно.

```js
throw lastError;
```

Если цикл не вернул результат, все попытки исчерпаны. Бросаем именно последнюю ошибку: обычно она лучше всего описывает актуальную причину сбоя.

## 4. Как устроена delay

```js
const delay = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
```

`setTimeout` сам не умеет работать с `await`, поэтому его оборачивают в промис, который завершится после таймера.

## 5. Частые ошибки и улучшения

- Сделать задержку перед первой попыткой — пользователь будет ждать без причины.
- Получить бесконечный цикл из-за неверного счётчика.
- Повторять любые ошибки. В production обычно есть `shouldRetry(error)`.
- Использовать постоянную задержку при большой нагрузке. Часто применяют exponential backoff: `delayMs * 2 ** attempt`, иногда с небольшой случайной добавкой.
- Не поддержать отмену. Для долгих повторов полезен `AbortSignal`.

## 6. Сложность

Служебная память — `O(1)`. Число вызовов — не более `maxRetries + 1`; общее время складывается из времени операций и пауз между ними.

## 7. Что запомнить

Retry — это контролируемый цикл: попытка, перехват ошибки, проверка лимита, пауза и только затем новый вызов.
