# Ограничение параллелизма

## 1. Зачем нужен пул

Если запустить тысячу сетевых запросов через один `Promise.all`, браузер и сервер получат резкий всплеск нагрузки. `asyncPool(limit, items, iteratorFn)` сохраняет параллельность, но не разрешает одновременно выполнять больше `limit` операций.

Функция должна вернуть результаты в порядке входных элементов, даже если сами операции завершаются в другом порядке.

## 2. Ментальная модель

`executing` — это список занятых рабочих мест. Пока мест меньше лимита, запускаем новые задачи. Как только все места заняты, ждём освобождения **любого** из них через `Promise.race`. После этого цикл может запустить следующий элемент.

## 3. Пошаговый разбор

```js
const results = [];
const executing = new Set();
```

`results` хранит итог, `executing` — только ещё не завершившиеся промисы.

```js
const promise = Promise.resolve()
  .then(() => iteratorFn(item))
  .then((result) => {
    results[index] = result;
    executing.delete(promise);
  });
```

Начальный `Promise.resolve().then(...)` превращает синхронный вызов и возвращаемый промис в одну цепочку. Запись по `index` сохраняет порядок. После успеха задача удаляет саму себя из `Set`, освобождая место.

```js
executing.add(promise);
if (executing.size >= limit) {
  await Promise.race(executing);
}
```

Когда достигнут лимит, цикл приостанавливается до первого завершения. Он ждёт не все активные задачи, а только одну — именно поэтому очередь продолжает наполняться постепенно.

После обхода элементов остаются последние активные задачи:

```js
await Promise.all(executing);
return results;
```

## 4. Пример

При `limit = 2` сначала стартуют элементы `0` и `1`. Если элемент `1` завершился раньше, стартует `2`, пока `0` ещё работает. Одновременно активны максимум две операции, а результат всё равно собирается как `[result0, result1, result2]`.

## 5. Граничные случаи и ограничения решения

- `limit` должен быть положительным целым числом; это стоит валидировать до цикла.
- Пустой `items` возвращает `[]`.
- Первая ошибка отклоняет `asyncPool`. Уже запущенные операции не отменяются автоматически.
- В текущем решении удаление из `executing` находится только в успешной ветке. Для повторного использования после ошибок очистку надёжнее выполнять в `finally`.

## 6. Сложность

Каждый элемент запускается один раз: `O(n)` служебной работы. Результаты занимают `O(n)`, а набор активных задач — не более `O(limit)`.

## 7. Что запомнить

Ограничение параллелизма строится на трёх деталях: `Set` активных задач, `Promise.race` для ожидания свободного места и индексы для стабильного порядка результата.
