## Что делает решение

```js
function createIncrement() {
  let count = 0;
  function increment() { count++; }
  function log() { console.log(`Count is ${count}`); }
  return [increment, log];
}
```

Фабрика возвращает две функции, разделяющие одно приватное окружение. `increment` изменяет `count`, а `log` читает его актуальное значение. После трёх инкрементов выводится `Count is 3`.

## Почему исправление работает

Ключевой момент — шаблонная строка создаётся **в момент вызова `log`**. Если заранее вычислить `const message = `Count is ${count}`` при создании фабрики, она навсегда сохранит текст с нулём. Сам `count` — живая привязка, поэтому чтение внутри `log` видит все изменения от `increment`.

Деструктуризация `[increment, log]` только извлекает функции. Она не разрушает их общее замыкание: обе были созданы в одном вызове `createIncrement`.

## Граничные случаи и ошибки

- Два вызова `createIncrement()` создают независимые пары и независимые счётчики.
- `increment` ничего явно не возвращает. Если нужен новый счёт, следует вернуть `count` осознанно.
- Порядок элементов массива — часть хрупкого API: случайная перестановка сломает деструктуризацию. Объект `{ increment, log }` часто читается надёжнее.
- Внешний код не может напрямую установить `count`, что обеспечивает инкапсуляцию, но reset нужно проектировать отдельным методом.
- Передача `log` как callback безопасна относительно `this`, потому что функция использует лексическую переменную, а не свойства объекта.
- Частое создание экземпляров создаёт отдельные функции на каждый счётчик — обычно это ожидаемая цена приватного состояния.

## Сложность

Создание экземпляра, инкремент и логическое чтение состояния — `O(1)` времени; каждый экземпляр занимает `O(1)` памяти.

## Что запомнить

Чтобы получить свежее значение, вычисляйте производное выражение внутри функции чтения. Замыкание удобно разделяет приватное состояние между несколькими методами, созданными одним внешним вызовом.
