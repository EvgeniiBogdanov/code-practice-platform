## Что делает решение

```js
const createCounter = () => {
  let count = 0;
  return () => ++count;
};
```

`createCounter` создаёт локальную переменную и возвращает функцию, которая продолжает иметь к ней доступ после завершения внешнего вызова. Это и есть замыкание: функция вместе с её лексическим окружением.

## Как сохраняется состояние

Вызов `createCounter()` создаёт новое окружение с `count = 0`. Возвращённая функция удерживает это окружение достижимым для сборщика мусора. Первый `counter()` выполняет префиксный `++count`: сначала увеличивает до `1`, затем возвращает `1`. Следующие вызовы возвращают `2`, `3`.

Два вызова фабрики независимы: `const a = createCounter(); const b = createCounter();` создают два разных `count`. Прямого доступа к ним снаружи нет, что даёт простую инкапсуляцию.

## Граничные случаи и ошибки

- Постфиксный `count++` вернул бы сначала `0`, хотя состояние после вызова стало бы `1`.
- Повторный вызов `createCounter()` не продолжает старый счётчик, а создаёт новый.
- Замыкание хранит не «снимок числа», а доступ к переменной, поэтому каждый вызов видит её актуальное значение.
- Пока возвращённая функция достижима, её окружение тоже нельзя освободить. Замыкание над крупными ненужными объектами способно удерживать память.
- Операция не атомарна в распределённых или worker-сценариях; это локальное синхронное состояние одного JavaScript-контекста.
- Сброс и чтение без инкремента не предусмотрены контрактом. Их следует добавить явными методами, а не раскрывать переменную.

## Сложность

Создание и каждый вызов выполняют `O(1)` работы и используют `O(1)` состояния на экземпляр счётчика.

## Что запомнить

Замыкание позволяет функции сохранять приватное состояние между вызовами. Каждый вызов внешней фабрики создаёт отдельное окружение, а форма инкремента определяет возвращаемое значение.
