## Что делает решение

Цикл планирует отдельный таймер для каждого элемента массива:

```js
for (let i = 0; i < arr.length; i++) {
  setTimeout(() => {
    console.log("Index: " + i + ", element: " + arr[i]);
  }, 1000);
}
```

Через примерно одну секунду callbacks выводят корректные пары индекса и значения: `0/10`, `1/12`, `2/15`, `3/21`.

## Почему let исправляет индекс

Каждая итерация `for (let i...)` создаёт собственную привязку `i`. Callback замыкается над привязкой своей итерации. С `var` все функции читали бы одну переменную после завершения цикла: `i === arr.length`, а `arr[i]` был бы `undefined`.

Таймеры имеют одинаковую задержку, но цикл не ждёт каждый из них. Он быстро регистрирует четыре задачи, после чего event loop выполняет callbacks, когда стек свободен и минимальная задержка прошла.

## Граничные случаи и ошибки

- Фиксируется индекс, но не значение элемента. Все callbacks читают общий `arr` в момент запуска. Если массив изменить до этого, вывод может отличаться. Для снимка используйте `const value = arr[i]` внутри итерации и замкните `value`.
- Задержка `1000` — минимум, а не точное расписание. Загруженный поток выполнит код позже.
- Пустой массив не создаёт таймеров.
- Удаление или перестановка элементов до запуска меняет `arr[i]`.
- Создание тысяч таймеров расходует память; для пакетной обработки нужен иной планировщик.
- Для отмены таймеров необходимо сохранить возвращённые идентификаторы.
- Логи появляются почти одновременно, а не с интервалом в секунду между элементами. Для последовательной задержки нужны разные задержки или цепочка ожиданий.

## Сложность

Регистрация и выполнение `n` callbacks требуют `O(n)` времени и `O(n)` памяти до их завершения.

## Что запомнить

`let` создаёт индекс на итерацию, но остальные внешние данные остаются живыми. Различайте захват привязки и снимок значения, а также минимальную задержку таймера и реальное время выполнения.
