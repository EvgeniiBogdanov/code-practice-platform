### Что делает решение

При выполнении кода функции:

```js
function testReturn() {
  try {
    return 1;
  } catch (e) {
    return 2;
  } finally {
    return 3;
  }
}

console.log(testReturn());
```

В консоль **будет выведено число 3**.

### Пошаговый разбор механизма JS Engine

1. **Гарантия выполнения блока `finally`**:
   - Блок `finally` выполняется **всегда**, независимо от того, завершился ли блок `try` успешно, выбросил ли исключение или выполнил оператор `return`.
   - При выполнении `return 1` внутри `try` движок формирует запись завершения типа `return` со значением `1` (*Completion Record: { [[Type]]: return, [[Value]]: 1 }*).
   - Однако функция не возвращает управление немедленно: перед выходом из функции спецификация ECMAScript обязывает выполнить блок `finally`.

2. **Перезапись возвращаемого значения (Unconditional Completion)**:
   - Внутри блока `finally` встречается собственный оператор `return 3`.
   - Оператор `return` внутри `finally` формирует новую запись завершения со значением `3`, которая **полностью перезаписывает и отменяет** ранее сформированное значение `1`.
   - Блок `catch` вообще не выполняется, так как в `try` не было выброшено ошибок.
   - Функция возвращает `3`.

3. **Подавление ошибок (Error Suppression)**:
   - Если бы в блоке `try` было выброшено исключение:
   ```js
   function testError() {
     try {
       throw new Error("Критический сбой");
     } finally {
       return 42; // Ошибка будет проглочена!
     }
   }
   ```
   Оператор `return` в `finally` перекроет даже неперехваченное исключение (*throw completion*), скрыв ошибку от вызывающего кода.

4. **Антипаттерн и правило ESLint `no-unsafe-finally`**:
   - Написание `return`, `throw`, `break` или `continue` внутри `finally` считается опасным антипаттерном.
   - Стандартные конфигурации линтеров (ESLint: `no-unsafe-finally`) запрещают передачу потока управления из блока `finally`.
   - В `finally` должны находиться только чистые побочные эффекты очистки ресурсов (закрытие дескрипторов файлов, очистка таймеров, отписка от событий).

### Граничные случаи и ошибки

- **Если в `finally` нет `return`**: если убрать `return 3` из `finally` (например, оставить только `console.log("очистка")`), функция вернет `1` из блока `try`.
- **Ошибка внутри `finally`**: если `finally` сам выбросит исключение (`throw new Error("finally error")`), это исключение перезапишет `return 1` и вылетит наружу.

### Сложность

- **По времени**: `O(1)` — прямое выполнение инструкций блоков `try` и `finally`.
- **По памяти**: `O(1)` — хранение промежуточного состояния завершения.

### Что запомнить для собеседования

- Блок `finally` выполняется всегда перед выходом из функции.
- Любой оператор прерывания потока (`return`, `throw`) в `finally` безусловно подавляет результаты `try` и `catch`.
- Использовать `return` внутри блока `finally` категорически запрещено (правило `no-unsafe-finally`).
