## Что делает решение

```js
for (let i = 0; i < 3; i++) {
  button.addEventListener("click", function () {
    console.log(i);
  });
}
```

Цикл добавляет одному элементу три обработчика. Благодаря `let` каждая итерация получает отдельную лексическую привязку `i`, поэтому один клик последовательно выводит `0`, `1`, `2`.

## Почему var выводил бы 3, 3, 3

`var` имеет функциональную, а не блочную область видимости. Все callbacks замыкаются над одной переменной. Они вызываются позже, когда цикл уже завершён и её значение равно `3`. `let` по спецификации создаёт новую привязку для каждой итерации, поэтому функции видят разные значения.

Альтернатива для старого кода с `var` — немедленно вызываемая функция, принимающая текущий индекс, но современный `let` проще и яснее.

## Граничные случаи и ошибки

- `document.getElementById("button")` может вернуть `null`; тогда `addEventListener` вызовет ошибку. В production-коде элемент проверяют.
- `button.click()` запускает все три зарегистрированных обработчика, а не выбирает один.
- Повторный запуск кода добавит ещё обработчики. Для очистки нужно сохранить функции и вызвать `removeEventListener` с теми же ссылками.
- Параметр события `e` в исходном решении не используется и не влияет на замыкание.
- Если внутри callback читать изменяемый внешний массив или объект, `let i` фиксирует только индекс; сами внешние данные останутся «живыми».
- Обработчики выполняются при событии, а не во время регистрации.

## Сложность

Регистрация `n` callbacks требует `O(n)` времени и памяти. Один клик вызывает все `n` обработчиков и также занимает `O(n)` времени.

## Что запомнить

Callback замыкается над привязками, а не над моментом написания функции. `let` в заголовке цикла создаёт привязку на итерацию; `var` оставляет одну общую переменную, изменённую к моменту события.
