## Что делает решение

```js
for (let i = 0; i < 10; i++) {
  setTimeout(() => console.log(i));
}
```

Код планирует десять callbacks. Сам цикл завершается синхронно, а функции таймеров выполняются позже. `let` создаёт отдельную привязку `i` для каждой итерации, поэтому выводятся числа `0...9`.

## Замыкание и очередь задач

`setTimeout` не приостанавливает цикл. Он регистрирует callback и возвращает управление. Только после освобождения текущего стека event loop сможет запускать таймеры. Даже задержка `0` означает «не раньше следующей доступной задачи», а не немедленный вызов.

С `var i` все десять функций ссылались бы на одну переменную. К моменту их запуска цикл довёл бы её до `10`, поэтому десять раз вывелось бы `10`.

## Граничные случаи и ошибки

- Порядок таймеров с одинаковой задержкой обычно соответствует регистрации, но точное время выполнения не гарантировано: основной поток может быть занят.
- `let` фиксирует привязку счётчика, но внешние объекты остаются общими и могут измениться до запуска callback.
- Большое число таймеров создаёт столько же функций и записей планировщика; это не бесплатный параллелизм.
- `setTimeout` без второго аргумента использует задержку, эквивалентную нулевой, но всё равно выполняется асинхронно.
- Если нужно отменять задачи, сохраняйте идентификаторы таймеров и вызывайте `clearTimeout`.
- В Node.js и браузере детали очередей различаются, но текущий синхронный стек всегда завершается раньше callbacks таймеров.

## Сложность

Создание `n` таймеров занимает `O(n)` времени и памяти; выполнение всех callbacks — ещё `O(n)` без учёта вывода.

## Что запомнить

Причина классической ошибки — сочетание позднего запуска callback и одной общей `var`-привязки. `let` создаёт значение счётчика на итерацию, но не делает таймер немедленным и не копирует всё внешнее окружение.
