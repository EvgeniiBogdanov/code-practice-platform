# Визуализация задач (Визуализатор)

`TaskVisualization` — переиспользуемый виджет с публичным API в
`src/widgets/task-visualization/index.ts`. Он используется вкладкой задачи и
полноэкранной страницей редактора. Виджет не зависит от роутера и не принимает
целую сущность `Task`.

```tsx
import { TaskVisualization } from "@/widgets/task-visualization";

<TaskVisualization
  taskId="algo35"
  solution={solutionSource}
  isActive={active}
  isFullscreen={false}
  onToggleFullscreen={openFullscreenRoute}
/>;
```

## Ответственность слоёв

| Слой / модуль                     | Ответственность                                                                                          |
| --------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `pages/task/TaskVisualizationTab` | Первое открытие вкладки, сохранение смонтированного виджета при переключениях, навигация fullscreen      |
| `pages/open-editor`               | Полноэкранный маршрут и возврат к задаче                                                                 |
| `widgets/task-visualization`      | Ленивая загрузка лаборатории, состояния загрузки и ошибки, композиция ввода, сцены, проигрывателя и кода |
| `features/algorithm-input`        | Черновик, выбор примера, валидация и фиксация новой трассы                                               |
| `features/trace-playback`         | Воспроизведение, шаги, скорость, клавиатура, отображение трассы и WebGL-fallback                         |
| `entities/algorithm-trace`        | Контракты, реестр алгоритмов, парсинг и построение трасс                                                 |
| `entities/task`                   | Выбор строкового исходника решения через `getTaskSolutionSource`                                         |
| `entities/ui-state`               | Существующие сохраняемые настройки масштаба, шрифта и пропорций панелей                                  |
| `shared/ui`                       | Управляемые UI-примитивы без зависимости от задачи или её стора                                          |

Между слайсами фич нет импортов. Их соединяет виджет. Все межслойные импорты
проходят через публичные API. Страница не импортирует внутренний `AlgorithmLab`.

## Повторное использование UI

Используются существующие `Card`, `PanelToolbar`, `CodeButton`, `Input`, `Button`,
`Tooltip`, `ResizableSplitPane`, `ExpandablePanel`, `UiSkeleton`, `ErrorBoundary`
и `NumberScene`. Существующий `CopyButton` расширен режимом `iconOnly`.

`ZoomControls` объединяет управление масштабом сцены и шрифтом кода.
`UiSelect` используется для примера и скорости; `UiRange` содержит оформление
нативного ползунка. Они управляются props и сохраняют нативную семантику.

`CodeStepViewer` входит в публичный API существующего `shared/ui/CodeViewer`.
Он переиспользует нормализацию и подсветку кода и добавляет активную строку,
прокрутку к ней и управление размером шрифта. Обычный `CodeViewer` сохраняет
своё поведение. Адаптер `TraceCodeViewer` в виджете связывает новый просмотрщик
с сохраняемыми настройками приложения; внутри shared нет подписки на Zustand.

## Жизненный цикл и границы

- `taskId` выбирает определение из реестра; неподдерживаемый ID показывает
  явное пустое состояние. Добавление нового алгоритма требует определения,
  примеров и построителя трассы в entity, без изменений страниц.
- Черновик, ошибка и текущая трасса локальны экземпляру. Некорректный ввод
  сохраняет предыдущую трассу; успешное применение и смена задачи сбрасывают шаг.
- `isActive={false}` останавливает воспроизведение; вкладка сохраняет DOM и черновик.
- Без `isFullscreen` виджет управляет локальным fullscreen через `ExpandablePanel`.
  `ResizableSplitPane` переключает `stack/split`, сохраняя canvas и шаг.
- При заданном `isFullscreen` режимом и навигацией управляет вызывающая страница
  через `onToggleFullscreen`; второй модальный диалог не создаётся.
- Переход между маршрутами создаёт новую сессию, как и до рефакторинга.
  Масштаб, шрифт и пропорции панелей остаются общими настройками пользователя.
- Сбой WebGL оставляет доступными массив, объяснение, код и управление шагами.
  Отдельная кнопка позволяет повторить создание сцены.
- `preloadTaskVisualization` прогревает тот же динамический импорт, что и виджет.
  3D-отображение находится в лениво загружаемой фиче воспроизведения: экспорт
  сцены через общий API entity приводил бы к ранней загрузке Three.js при
  проверке доступности вкладки.

Верификация: unit/component-тесты ввода, воспроизведения, публичного виджета,
двух независимых экземпляров, fullscreen, отказа загрузки и WebGL; FSD-линтер,
TypeScript и production-сборка. В браузере проверены обычный и полноэкранный
режимы, ошибка ввода, возврат к вкладке и узкий экран.

## Stack, Linked List, DFS, BFS и Backtracking

Добавлены все 22 внутренние задачи этих групп (всего реестр содержит 44 задачи).
Внешние ссылки на LeetCode остаются внешними заданиями.

| Группа | Задачи | Сцена и состояние |
| --- | --- | --- |
| Stack | `algo18–20`, `algo40` | Вертикальный стек с вершиной сверху, push/pop, ожидаемые скобки, сокращение пар, пара stack/minStack, монотонный стек индексов температур |
| Linked List | `algo21–23` | Постоянные ID узлов, направленные next, разворот ссылок, слияние двух цепочек, slow/fast и замыкание хвоста |
| DFS | `algo24–27`, `algo41` | Дерево с рёбрами L/R, активный вызов, стек рекурсии, возвращаемые высоты, инверсия потомков, синхронное сравнение двух деревьев |
| BFS | `algo28–30`, `algo42–43` | Очередь FIFO и уровни дерева, остановка на первом листе, сетки островов и заливки, одновременные источники и поминутные волны заражения |
| Backtracking | `algo31–34`, `algo44` | Растущее дерево решений, текущий путь, used, remaining, сохранение ответов, возврат к родителю и отсечение ветвей |

`TraceScene.structure` описывает узлы, рёбра, координаты сетки и состояния.
`createTraceRecorder` копирует узлы и рёбра каждого кадра, поэтому перемотка
назад восстанавливает прежние связи и значения. Тип результата поддерживает
строки и `null` для сериализации разреженных деревьев.

`UiDiagramScene` — управляемый 3D-примитив в `shared/ui`, без алгоритмической
логики и зависимости от entity. Деревья используют объёмные диски, списки и
сетки — блоки с фасками, перебор — ромбовидные узлы. У узлов есть корпус,
ободок и лицевая панель; направленные связи построены трубками и конусами.
Активный узел приподнимается над плоскостью, переход подсвечивает связи.
Освещение, тени и поворот камеры делают глубину видимой. Фоновая сетка следует
за целью камеры, поэтому остаётся видимой при любом ракурсе и панораме.

Левая кнопка мыши вращает сцену, правая перемещает камеру. Масштаб управляется
общим тулбаром, клавишами `+` / `−` и `Ctrl` / `Cmd` + колесо. `0` или двойной
клик возвращает исходный ракурс. Большие деревья сохраняют читаемый размер
узлов; камера следует за активной веткой. Сцена реагирует на размер панели
и смену темы. Анимация ограничена 650 мс после изменения; в фоне и скрытой
вкладке отрисовка останавливается. Reduced motion отключает переходы и импульс.

При отказе загрузки или потере WebGL-контекста `DiagramFallback` и `StackFallback`
показывают доступную SVG-схему того же кадра. Кнопка «Повторить 3D» восстанавливает
сцену без сброса шага. Пустые диаграммы обходятся без WebGL. Текстовое представление
узлов, связей и стеков доступно скринридеру в обоих режимах. Геометрия задаётся в
координатах Three.js / SVG, оформление — CSS Modules и дизайн-токенами.

Ввод проходит через общий `parseAlgorithmInput` и специализированный
`parseStructureInput`: деревья используют level-order с `null`, слияние и
сравнение — пару массивов, Min Stack — JSON-операции, BFS — прямоугольную сетку.
Отклоняются узлы без родителей, некорректные координаты, операции над пустым
стеком и несортированные списки. Ограничения указаны над сценой: сетки до 5×6,
подмножества до 5 элементов, перестановки до 4, бинарные строки до 4 разрядов,
скобки до 3 пар, Combination Sum — до 4 положительных кандидатов и target до 10.
Это ограничивает экспоненциальный рост без обрезания корректной трассы.

Новые сцены используют существующие `TaskVisualization`, `TracePlayer`,
fullscreen-маршрут, управление скоростью, клавиатуру, ползунок, подсветку кода,
сохраняемые масштаб и разделитель панелей. Проверка доступности вкладки
по-прежнему загружает только список ID. Лаборатория загружается динамически;
`NumberScene`, `UiDiagramScene` и `UiStackScene` лениво импортируют собственные
WebGL-runtime только при монтировании сцены; пустые диаграммы не загружают
Three.js. Общие текстуры подписей, чтение палитры, фоновая сетка и освобождение ресурсов
переиспользуются из `shared/lib/three-scene`.

Проверки включают результаты всех новых алгоритмов, перебор коротких входов
для списков и температур, полноту подмножеств и перестановок, крайний допустимый
размер дерева решений, валидность рёбер, строки исходного решения, ошибочный
ввод, независимость проигрывателей и перемотку в fullscreen без WebGL.

### Отдельная сцена Stack

Stack рендерится собственной 3D-сценой `shared/ui/UiStackScene` на Three.js,
собранной из тех же примитивов, что диаграммы и числовые сцены: элементы —
объёмные блоки с фасками, ободком и лицевой панелью; они стоят в полупрозрачном
контейнере, открытом сверху; над вершиной висит конус-указатель `top`, колонки
подписаны, под дном отмечено «дно · N эл.», пустой контейнер остаётся видимым.
Первая колонна окрашена основным акцентом, вторая (Min Stack) — дополнительным.
Освещение, мягкие тени и приподнятый ракурс камеры делают глубину видимой;
фоновая сетка — общая «бесконечная» стена из shared-фабрики, следующая за целью
камеры, поэтому не пропадает при панораме и наклоне. Левая кнопка мыши вращает сцену, правая перемещает камеру; масштаб
управляется тулбаром, клавишами `+` / `−` / `0`, двойным кликом и `Ctrl` / `Cmd`
+ колесом.

`TraceStructure.stacks` и `stackAction` содержат снимки обеих фаз операции,
поэтому сцена анимирует переход «до → после» без реконструкции алгоритма из
соседних кадров: `push` роняет новый блок в контейнер сверху, `pop` выносит
извлечённый блок наружу с оранжевым тоном и подписью «извлечён», `peek`
подсвечивает вершину кольцом и слегка приподнимает её. Финальное состояние
каждого шага всегда берётся из снапшота `stacks`, поэтому произвольная перемотка
остаётся корректной. Мин Stack показывает две колонны одновременно; чтение
вершины помечается как операция без изменения содержимого. Текущий символ или
день выделяется во входной последовательности. Reduced motion показывает
финальное состояние и извлечённый блок статично.

При отказе загрузки или потере WebGL-контекста сцена переключается на SVG-схему
`StackFallback` с фазами «до» и «после» и кнопкой «Повторить 3D». Текстовое
представление стеков доступно скринридеру в обоих режимах. WebGL-runtime
загружается лениво при монтировании сцены.
