# Визуализация задач (Визуализатор)

`TaskVisualization` — переиспользуемый виджет с публичным API в
`src/widgets/task-visualization/index.ts`. Он используется вкладкой задачи и
полноэкранной страницей редактора. Виджет не зависит от роутера и не принимает
целую сущность `Task`.

```tsx
import { TaskVisualization } from "@/widgets/task-visualization";

<TaskVisualization
  taskId="algo35"
  solution={solutionSource}
  isActive={active}
  isFullscreen={false}
  onToggleFullscreen={openFullscreenRoute}
/>;
```

## Ответственность слоёв

| Слой / модуль                     | Ответственность                                                                                          |
| --------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `pages/task/TaskVisualizationTab` | Первое открытие вкладки, сохранение смонтированного виджета при переключениях, навигация fullscreen      |
| `pages/open-editor`               | Полноэкранный маршрут и возврат к задаче                                                                 |
| `widgets/task-visualization`      | Ленивая загрузка лаборатории, состояния загрузки и ошибки, композиция ввода, сцены, проигрывателя и кода |
| `features/algorithm-input`        | Черновик, выбор примера, валидация и фиксация новой трассы                                               |
| `features/trace-playback`         | Воспроизведение, шаги, скорость, клавиатура, отображение трассы и WebGL-fallback                         |
| `entities/algorithm-trace`        | Контракты, реестр алгоритмов, парсинг и построение трасс                                                 |
| `entities/task`                   | Выбор строкового исходника решения через `getTaskSolutionSource`                                         |
| `entities/ui-state`               | Существующие сохраняемые настройки масштаба, шрифта и пропорций панелей                                  |
| `shared/ui`                       | Управляемые UI-примитивы без зависимости от задачи или её стора                                          |

Между слайсами фич нет импортов. Их соединяет виджет. Все межслойные импорты
проходят через публичные API. Страница не импортирует внутренний `AlgorithmLab`.

## Повторное использование UI

Используются существующие `Card`, `PanelToolbar`, `CodeButton`, `Input`, `Button`,
`Tooltip`, `ResizableSplitPane`, `ExpandablePanel`, `UiSkeleton`, `ErrorBoundary`
и `NumberScene`. Существующий `CopyButton` расширен режимом `iconOnly`.

`ZoomControls` объединяет управление масштабом сцены и шрифтом кода.
`UiSelect` используется для примера и скорости; `UiRange` содержит оформление
нативного ползунка. Они управляются props и сохраняют нативную семантику.

`CodeStepViewer` входит в публичный API существующего `shared/ui/CodeViewer`.
Он переиспользует нормализацию и подсветку кода и добавляет активную строку,
прокрутку к ней и управление размером шрифта. Обычный `CodeViewer` сохраняет
своё поведение. Адаптер `TraceCodeViewer` в виджете связывает новый просмотрщик
с сохраняемыми настройками приложения; внутри shared нет подписки на Zustand.

## Жизненный цикл и границы

- `taskId` выбирает определение из реестра; неподдерживаемый ID показывает
  явное пустое состояние. Добавление нового алгоритма требует определения,
  примеров и построителя трассы в entity, без изменений страниц.
- Черновик, ошибка и текущая трасса локальны экземпляру. Некорректный ввод
  сохраняет предыдущую трассу; успешное применение и смена задачи сбрасывают шаг.
- `isActive={false}` останавливает воспроизведение; вкладка сохраняет DOM и черновик.
- Без `isFullscreen` виджет управляет локальным fullscreen через `ExpandablePanel`.
  `ResizableSplitPane` переключает `stack/split`, сохраняя canvas и шаг.
- При заданном `isFullscreen` режимом и навигацией управляет вызывающая страница
  через `onToggleFullscreen`; второй модальный диалог не создаётся.
- Переход между маршрутами создаёт новую сессию, как и до рефакторинга.
  Масштаб, шрифт и пропорции панелей остаются общими настройками пользователя.
- Сбой WebGL оставляет доступными массив, объяснение, код и управление шагами.
  Отдельная кнопка позволяет повторить создание сцены.
- `preloadTaskVisualization` прогревает тот же динамический импорт, что и виджет.
  3D-отображение находится в лениво загружаемой фиче воспроизведения: экспорт
  сцены через общий API entity приводил бы к ранней загрузке Three.js при
  проверке доступности вкладки.

Верификация: unit/component-тесты ввода, воспроизведения, публичного виджета,
двух независимых экземпляров, fullscreen, отказа загрузки и WebGL; FSD-линтер,
TypeScript и production-сборка. В браузере проверены обычный и полноэкранный
режимы, ошибка ввода, возврат к вкладке и узкий экран.
